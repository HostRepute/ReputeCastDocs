Para enviar una newsletter con Mailgun desde ReputeCast, conectas una Private API key, la región en la que está tu
cuenta de Mailgun y el dominio de Mailgun desde el que envías. ReputeCast registra los webhooks en ese dominio, añade y
verifica los dominios de envío, detecta los dominios sandbox y mantiene las supresiones sincronizadas en ambos sentidos.

<ProviderMatrix family="email" id="mailgun" />

## Antes de empezar

- **Un dominio de Mailgun** (por ejemplo, `mg.acme.io`) que ya exista en tu cuenta de Mailgun, en la región que
  conectas. La conexión se comprueba con él, así que créalo primero en Mailgun, o conecta el dominio sandbox para hacer
  pruebas.
- **Una Private API key**, de Mailgun › API Security. Una Domain Sending key o la HTTP webhook signing key no funcionan.
- **Permisos.** Para conectar necesitas `providers:manage`; para añadir un dominio de envío nuevo, `domains:manage`.
- **Una dirección HTTPS pública** para los webhooks: `<public URL>/hooks/mailgun/<token>`. Si ReputeCast aún no es
  accesible desde internet, puede consultar cada minuto la API de eventos de Mailgun en su lugar.

Mailgun firma cada webhook con la HTTP webhook signing key de toda tu cuenta, que no es tu clave de API
([Mailgun: Securing webhooks](https://documentation.mailgun.com/docs/mailgun/user-manual/webhooks/securing-webhooks),
consultado en octubre de 2026). ReputeCast lee esa clave mediante la API, así que no tienes que pegarla, salvo que tu
clave de API no pueda leerla.

## Conectar Mailgun

<Steps>

1. Abre <UiPath path="nav.providers" />, elige <UiPath path="providers.overview.addProvider" /> y selecciona Mailgun en
   el catálogo. [Conectar un proveedor de envío](/es/providers/connect/) explica los pasos que comparten todos los
   proveedores.

2. Pega la <UiPath path="providers.fields.mailgun.apiKey" />, elige la <UiPath path="providers.fields.region" />
   (`US · api.mailgun.net` o `EU · api.eu.mailgun.net`, donde se creó el dominio) y escribe el
   <UiPath path="providers.fields.mailgun.domain" />. La configuración adicional de Mailgun contiene tu
   <UiPath path="providers.fields.monthlyLimit" /> (se usa para la barra de cuota cuando la cuenta no tiene un límite de
   envío personalizado) y la <UiPath path="providers.fields.mailgun.webhookSigningKey" />.

3. Elige <UiPath path="connect.connection.connect" />. ReputeCast lee el dominio con tu clave, después el límite de
   envío mensual de la cuenta, y guarda la clave cifrada. Si la comprobación falla, no se guarda nada.

4. En <UiPath path="connect.connection.webhooksTitle" />, ReputeCast registra la URL de su webhook en el dominio para
   `delivered`, `permanent_fail`, `temporary_fail`, `complained` y `unsubscribed`. Las aperturas y los clics no se
   registran: ReputeCast hace ese seguimiento por sí mismo. Antes comprueba que la dirección sea accesible desde
   internet; Mailgun no puede enviar un webhook de prueba a petición, así que el evento de entrega del envío de prueba
   confirma que sus eventos llegan. Si la dirección no es accesible, elige
   <UiPath path="connect.connection.usePolling" /> y corrige la URL pública más tarde.

   <Screenshot
     id="connect-mailgun-error"
     alt="Una conexión de Mailgun fallida: la Private API key se rechazó con 401 Unauthorized, y la dirección del webhook en localhost no es accesible desde internet, así que el registro se omite, con tres formas de solucionarlo: una URL pública, un túnel o la consulta periódica."
   />

5. Elige <UiPath path="connect.connection.continueDomain" /> y escribe tu dominio de envío. Si aún no está en Mailgun,
   ReputeCast lo añade (seguridad automática del remitente, DKIM de 2048 bits) y muestra los registros SPF, DKIM y MX que
   debes publicar. El CNAME de seguimiento de Mailgun se deja fuera porque ReputeCast hace por sí mismo el seguimiento de
   aperturas y clics.

6. En <UiPath path="connect.stepTest" />, envía una prueba y observa cómo llega el webhook `delivered`.

7. En <UiPath path="connect.stepStreams" /> y <UiPath path="connect.stepContacts" />, elige los flujos y deja marcada
   la opción de recibir los rebotes, las quejas y las bajas que ya tiene Mailgun.

</Steps>

## Comprobar que funciona

- La tarjeta de Mailgun en <UiPath path="nav.providers > providers.tabProviders" /> muestra
  <UiPath path="providers.statusHealthy" /> con tu dominio y su estado (por ejemplo, "Dominio mg.acme.io · active"). Un
  dominio sandbox muestra <UiPath path="providers.statusSandbox" /> en su lugar.
- En Mailgun, los webhooks del dominio incluyen tu URL de ReputeCast para los cinco eventos.
- Las entregas y los rebotes aparecen en <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast envía una llamada a la API por mensaje, con el seguimiento de aperturas, clics y bajas de Mailgun desactivado
en cada mensaje. Si el seguimiento de bajas está activado para el dominio, Mailgun añade su propio enlace de baja y su
pie junto a los de ReputeCast; la [revisión previa](/es/reference/glossary/#send-readiness) avisa de ello, y la
<UiPath path="providers.events.trackingTitle" /> de la pestaña de eventos y sincronización puede desactivarlo. Desde la
[lista de supresión](/es/reference/glossary/#suppression-list) compartida, ReputeCast envía los rebotes permanentes y las
quejas que se aplican a todo el correo a la tabla de bajas del dominio de envío (para todas las etiquetas), y los quita
de allí cuando salen de la lista compartida; las bajas y otras entradas solo de marketing se quedan en ReputeCast.
ReputeCast también lee, al conectar y cada día, las IP dedicadas de la cuenta asignadas al dominio de la conexión, y las
muestra como [IP de envío](/es/providers/senders-and-domains/#comprobar-las-ip-de-envío) de la tarjeta; si no hay
ninguna, el dominio envía desde el grupo de IP compartido de Mailgun.

El dominio sandbox de Mailgun solo entrega a destinatarios autorizados, hasta 5
([Mailgun: Sandbox domain](https://documentation.mailgun.com/docs/mailgun/user-manual/domains/domains-sandbox),
consultado en octubre de 2026). Mientras Mailgun está conectado con un dominio sandbox, la revisión previa bloquea los
Envíos masivos a través de él.

## Solución de problemas

- **"Mailgun rechazó esta clave"** con `401 Unauthorized`. Usa una Private API key de la misma cuenta, no una Sending
  key ni la webhook signing key.
- **"Mailgun rechazó esta clave"** con `404 Not Found · domain_not_found`. La clave es correcta, pero Mailgun no conoce
  el dominio de envío en la región seleccionada. Revisa cómo está escrito el dominio y la región, o crea primero el
  dominio en Mailgun.
- **"Mailgun admite tres URL por evento"** al registrar los webhooks. Uno de los eventos ya envía a tres direcciones.
  Quita una URL antigua en Mailgun y elige <UiPath path="connect.connection.registerAgain" />.
- **La dirección del webhook no es accesible desde internet** (por ejemplo, "localhost solo funciona en este equipo").
  Configura `REPUTECAST_PUBLIC_URL` con la dirección HTTPS que expone tu proxy inverso, usa un túnel mientras pruebas o,
  de momento, usa la consulta periódica. Consulta [Proxy inverso y TLS](/es/self-hosting/reverse-proxy/).
- **Los webhooks llegan, pero no pasan la verificación, y el proveedor pasa a "Webhooks sin eventos".** Tu clave de API
  no puede leer la webhook signing key de la cuenta. Cópiala desde Settings › API Security › HTTP webhook signing key en
  Mailgun y pégala en <UiPath path="providers.overview.settings > providers.overview.credentials" /> en la tarjeta del
  proveedor.
- **Los destinatarios de prueba se rechazan con `unauthorized_recipient`.** El dominio es el sandbox de Mailgun: añade
  la dirección como destinatario autorizado en Mailgun o conecta un dominio verificado.
- **Fallan los mensajes transaccionales con Cc, Bcc o archivos adjuntos.** El adaptador de Mailgun no puede enviar
  copias ni adjuntos; enruta esas plantillas a través de otro proveedor.
- **Desconectaste Mailgun.** ReputeCast quita su URL de cada evento de webhook. El dominio y las bajas enviadas se
  quedan en Mailgun.
