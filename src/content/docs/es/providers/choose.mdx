ReputeCast no entrega el correo por sí mismo: pasa cada mensaje a un
[proveedor de envío](/es/reference/glossary/#sending-provider) que conectas, como Amazon SES, Postmark o tu propio
servidor Postal. Esta página te ayuda a elegir un proveedor de envío de correo para newsletters comparando lo que puede
hacer cada [adaptador](/es/reference/glossary/#adapter) integrado. Puedes conectar varios y repartir el trabajo entre
ellos.

## Cómo describe el catálogo a un proveedor

Cuando abres <UiPath path="nav.providers > providers.overview.addProvider" />, el catálogo muestra todos los adaptadores
de tu compilación. Cada tarjeta muestra datos que el propio adaptador informa sobre sí mismo, así que el catálogo y esta
página siempre coinciden con el código.

<Screenshot
  id="providers-catalog"
  alt="El catálogo de proveedores: Ayúdame a elegir recomienda Amazon SES por unos 5,00 US$ al mes para 50.000 correos, con Resend como segunda opción, encima de las pestañas de canal, los filtros y las tarjetas de Amazon SES, Postmark y Mailgun, cada una con su línea de marketing masivo, su precio para 50.000 al mes y su tiempo de configuración."
/>

- **Marketing masivo** indica lo que permiten las condiciones de uso aceptable del proveedor para el correo masivo, con
  una marca: Permitido, Permitido tras el acceso de producción (Amazon SES), Permitido a través de la Broadcasts API
  (Resend), Solo flujos Broadcast (Postmark), No permitido · solo transaccional (Azure Communication Services), Tu propia
  política (tu propio servidor) o Depende del servidor (SMTP).
- **El precio para tu volumen** sale de la lista de precios del adaptador en dólares estadounidenses: un precio por cada
  1000 correos, el plan mensual que se ajusta al volumen, o "según tu contrato", "0 US$ por consumo" (tu propio
  servidor) y "según tu servidor o relay". Las condiciones y los precios se revisan cada trimestre y cambian, así que
  consulta la página de precios del propio proveedor antes de decidir.
- **Configuración** es el tiempo que suele llevar la conexión, contado con honestidad: por ejemplo, 10–15 minutos con
  una clave de API, más con Amazon SES fuera de AWS, y unas 3 semanas más de calentamiento para una IP nueva de Postal.
- **Detalles** abre las etiquetas de funciones: cómo vuelven los eventos (webhooks o un buzón de rebotes), cómo se
  configura el dominio de envío (mediante la API del proveedor o a mano), la sincronización de supresiones, el envío por
  lotes, las IP dedicadas, el tratamiento del sandbox y si ReputeCast puede leer tu cuota. Una etiqueta verde significa
  que se admite, una ámbar que se admite en parte (por ejemplo, "Dominio, DNS manual" o "Supresiones, solo recibir") y
  una gris y tachada que no se admite.
- **Los filtros** <UiPath path="connect.catalog.filterBulk" />, <UiPath path="connect.catalog.filterWebhooks" /> e
  <UiPath path="connect.catalog.filterDedicated" /> reducen la lista a los proveedores que cumplen esa condición.

## Ayúdame a elegir

En la parte superior del catálogo, <UiPath path="connect.catalog.chooseTitle" /> hace tres preguntas:
<UiPath path="connect.catalog.volumeLabel" /> (puedes escribir `50000`, `50k` o `1.5m`),
<UiPath path="connect.catalog.accountLabel" /> y <UiPath path="connect.catalog.dedicatedLabel" />. A partir de ahí,
cada tarjeta muestra su precio para ese volumen, y el panel indica un proveedor
<UiPath path="connect.catalog.recommended" /> con su precio mensual, sus condiciones y su tiempo de configuración, y una
<UiPath path="connect.catalog.runnerUp" />.

La clasificación compara, en este orden:

1. Las condiciones de marketing masivo: primero los que lo permiten y después los que lo limitan (solo en algunos flujos
   o según tu propia política). Nunca se recomiendan los proveedores cuyas condiciones no permiten el correo masivo.
2. Las funciones que usa ReputeCast: webhooks de eventos, configuración del dominio mediante la API, sincronización de
   supresiones bidireccional, detección de cuota y envío por lotes.
3. El precio para tu volumen, del más barato al más caro; un proveedor sin precio para ese volumen va al final.

Tu propio servidor Postal y los servidores o relays SMTP nunca se recomiendan, porque necesitan un servidor propio. Si
necesitas una IP dedicada, solo cuentan los proveedores que la ofrecen. La cuenta que ya tienes no cambia la
clasificación; añade una nota, por ejemplo que una cuenta de AWS existente puede tener ya acceso de producción a SES, así
que no hay que esperar 24 horas.

Debajo de los proveedores integrados, el catálogo muestra el [adaptador HTTP genérico](/es/providers/generic-http/) y los
[adaptadores de la comunidad](/es/adapters/overview/) que haya instalado quien administra la instancia. Los adaptadores
de la comunidad sin ninguna versión publicada en el último año no se ofrecen para conexiones nuevas.

## Comparar los adaptadores integrados

<ProviderMatrix family="email" label="Adaptadores de correo integrados" />

Qué significa cada columna:

- **Tipo**: API (la API HTTP de un proveedor alojado), Autoalojado (tu propio servidor de correo Postal), SMTP (cualquier
  servidor o relay SMTP) o HTTP (cualquier API HTTP de correo, asignada con el adaptador HTTP genérico).
- **Marketing masivo**: lo que permiten las condiciones del proveedor en la conexión. Consulta
  [Condiciones de marketing masivo](#condiciones-de-marketing-masivo) más abajo.
- **Webhooks de eventos**: cómo informa el proveedor de las entregas, los rebotes y las quejas, y cómo comprueba
  ReputeCast que un webhook viene realmente de él. SMTP no tiene webhooks, así que ReputeCast lee los rebotes de un
  [buzón de rebotes](/es/reference/glossary/#bounce-mailbox) por IMAP o POP3. Lee
  [Eventos de entrega y sincronización de supresiones](/es/providers/events-and-sync/).
- **Configuración del dominio**: API significa que ReputeCast añade tu dominio de envío en el proveedor y obtiene los
  registros DNS exactos que necesita. Postmark necesita para ello su token de cuenta. DNS manual significa que
  ReputeCast muestra los registros que debes publicar y que configuras el dominio en el panel del propio proveedor.
- **Sincronización de supresiones**: Bidireccional recibe las supresiones del proveedor en la
  [lista de supresión](/es/reference/glossary/#suppression-list) compartida de ReputeCast y le envía de vuelta los rebotes
  permanentes y las quejas que se aplican a todo el correo, y también cuando se quitan. Solo recibir lee la lista del
  proveedor, pero no puede escribir en ella (Brevo). Solo local significa que el proveedor no tiene API de supresiones;
  en su lugar, ReputeCast comprueba la lista compartida antes de cada envío. Lee
  [Eventos de entrega y sincronización de supresiones](/es/providers/events-and-sync/#sincronización-de-supresiones).
- **Tamaño de lote**: cuántos mensajes renderizados por separado van en una llamada a la API. Cada mensaje se renderiza
  para su destinatario (enlaces de seguimiento, enlace de baja, personalización), así que los proveedores cuyas
  llamadas por lotes comparten un mismo cuerpo para todos los destinatarios (Mailgun, SendGrid, SparkPost, Brevo)
  reciben una llamada por mensaje, con varias llamadas en curso a la vez.
- **Notas**: el tratamiento del sandbox, la detección de cuota, si puede recibir correo para ReputeCast y cualquier otra
  cosa que importe al conectarlo. El nombre de cada proveedor enlaza con su guía de configuración.

<Aside type="note">
ReputeCast no tiene un servicio de envío propio: cada mensaje pasa por un proveedor de envío que conectas.
</Aside>

## Condiciones de marketing masivo

Los boletines son correo masivo, y algunos proveedores solo lo permiten en determinadas conexiones. ReputeCast lee la
política de cada adaptador y la usa en tres lugares:

1. **El catálogo y la tabla de arriba** la muestran como Permitido, Solo flujos Broadcast o Tu propia política.
2. **Al conectar un proveedor**: si las condiciones no permiten el correo masivo, el asistente de conexión no ofrece el
   [flujo](/es/reference/glossary/#stream) Envíos masivos para ese proveedor. En Postmark, el correo masivo se permite en
   un flujo de mensajes Broadcast, y ReputeCast puede crear uno por ti en tu servidor de Postmark.
3. **En el enrutamiento**: si pones en la ruta Envíos masivos un proveedor cuyas condiciones no permiten el correo
   masivo, como parte de un reparto o como respaldo, ReputeCast te avisa antes de guardar y te ofrece una solución: crear
   el flujo Broadcast (Postmark), usar otro proveedor o guardar sin respaldo. Si aun así lo mantienes, la decisión queda
   en el registro de auditoría y la [revisión previa](/es/campaigns/send-readiness/) bloquea todos los envíos masivos
   hasta que cambies la ruta.

Tu propio servidor Postal, un servidor SMTP o una API HTTP que asignas tú mismo muestran Tu propia política: las reglas
son las tuyas y las de la red desde la que envías.

## Recepción de correo

Un proveedor de envío conectado también puede recibir las respuestas del espacio de trabajo, las bajas por `mailto:` y
los informes DMARC y de bucle de retroalimentación. Disponible a partir de la próxima versión después de la 1.6.0.

Postmark, Mailgun, SendGrid, Resend, SparkPost, Mailjet y Brevo configuran su recepción a través de ReputeCast; Amazon
SES y Postal necesitan unos pasos en su propia consola. Azure Communication Services, los servidores SMTP, el adaptador
HTTP genérico y los adaptadores de la comunidad no reciben correo, y un buzón IMAP o POP3 funciona con cualquiera de
ellos. Una sola ruta sirve a todo el espacio de trabajo, sean cuales sean los proveedores que envían. Lee
[configurar la recepción de correo](/es/providers/receiving-mail/).

## Usar varios proveedores

Puedes conectar tantos proveedores como quieras y enviar a través de varios a la vez. Una
[ruta](/es/reference/glossary/#route) decide qué proveedor lleva cada correo. Configuraciones habituales:

- **Un proveedor para cada tipo de correo.** Amazon SES para Envíos masivos y Automatizaciones, Postmark para el correo
  de Sistema y Transaccional, para que una campaña grande nunca retrase un restablecimiento de contraseña.
- **Un respaldo para cada flujo.** Si el proveedor principal se cae, el correo de Sistema, Automatizaciones y
  Transaccional conmuta automáticamente al respaldo; los Envíos masivos esperan tu decisión, salvo que elijas otra cosa.
  Lee [Estado de los proveedores y caídas](/es/providers/health-and-outages/).
- **Un reparto ponderado.** Envía el 90 % de los Envíos masivos a través de un proveedor y el 10 % a través de uno
  nuevo mientras está en [calentamiento](/es/providers/warm-up/), y luego aumenta su proporción.

Lee [Enrutar el correo entre proveedores](/es/providers/routing/) para configurarlo. Los rebotes y las quejas de todos los
proveedores llegan a una sola lista de supresión, así que una dirección que rebotó en un proveedor nunca se intenta en
otro.

## Cuándo elegir otra opción

- Tu proveedor no está en el catálogo, pero tiene una API HTTP: asígnalo con el
  [adaptador HTTP genérico](/es/providers/generic-http/) sin escribir código.
- Quieres un adaptador reutilizable para un proveedor, o uno con una lógica que una asignación no puede expresar:
  escribe un [adaptador de la comunidad](/es/adapters/community/).
- Ya tienes un servidor de correo o un relay: [envía a través de cualquier servidor SMTP](/es/providers/smtp/) o conecta
  tu [propio servidor Postal](/es/providers/postal/) mediante su API para recibir webhooks firmados.
