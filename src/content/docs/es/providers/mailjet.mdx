Para enviar una newsletter con Mailjet desde ReputeCast, conectas una clave de API de Mailjet y su secret key.
ReputeCast registra un callback para cada evento que necesita, configura tu dominio de envío, envía hasta 50 mensajes
por llamada con el seguimiento de Mailjet desactivado y mantiene las exclusiones de campañas de Mailjet al día con la
lista de supresión compartida.

<ProviderMatrix family="email" id="mailjet" />

## Antes de empezar

- **Una clave de API y su secret key**, de Mailjet › Account settings › API key management. Crea una clave que solo
  use ReputeCast: Mailjet admite una URL de callback por evento y clave de API, así que una clave compartida con otra
  herramienta choca con sus callbacks.
- **Permisos.** Para conectar necesitas `providers:manage`; para añadir un dominio de envío nuevo, `domains:manage`.
- **Una dirección HTTPS pública** para los callbacks: `<public URL>/hooks/mailjet/<token>`. La API de eventos de
  Mailjet envía a la URL que le das y recomienda HTTPS con credenciales de autenticación básica en la URL
  ([Mailjet: Event API](https://dev.mailjet.com/email/guides/webhooks/), consultado en octubre de 2026), que es como la
  registra ReputeCast.

## Conectar Mailjet

<Steps>

1. Abre <UiPath path="nav.providers" />, elige <UiPath path="providers.overview.addProvider" /> y selecciona Mailjet en
   el catálogo. [Conectar un proveedor de envío](/es/providers/connect/) explica los pasos que comparten todos los
   proveedores.

2. Pega la <UiPath path="providers.fields.apiKey" /> y la <UiPath path="providers.fields.mailjet.secretKey" />. Mailjet
   no tiene API para tu plan, así que escribe tu <UiPath path="providers.fields.monthlyLimit" /> en la configuración
   adicional de Mailjet si quieres una barra de cuota.

3. Elige <UiPath path="connect.connection.connect" />. ReputeCast comprueba el par de claves con una llamada de solo
   lectura y guarda ambos valores cifrados. La tarjeta muestra si la clave está activa.

4. En <UiPath path="connect.connection.webhooksTitle" />, ReputeCast comprueba que su dirección de webhook es accesible
   desde internet y después registra un callback para cada uno de `sent`, `bounce`, `blocked`, `spam` y `unsub`. Cada
   URL de callback lleva credenciales de autenticación básica
   (`https://reputecast:<secret>@<your host>/hooks/mailjet/<token>`), porque Mailjet no firma sus callbacks. Los eventos
   de apertura y de clic no se registran: ReputeCast hace ese seguimiento por sí mismo.

5. Elige <UiPath path="connect.connection.continueDomain" /> y escribe tu dominio de envío. ReputeCast añade un
   remitente de dominio (`*@<your domain>`) en Mailjet y muestra los registros que pide Mailjet: el registro TXT de
   propiedad, DKIM y SPF (con `include:spf.mailjet.com`), además de DMARC si el dominio no tiene ninguno.

6. En <UiPath path="connect.stepTest" />, envía una prueba y observa cómo el callback `sent` vuelve como una entrega.

7. En <UiPath path="connect.stepStreams" /> y <UiPath path="connect.stepContacts" />, elige los flujos y deja marcada
   la opción de recibir las exclusiones que ya tiene Mailjet.

</Steps>

## Recibir correo a través de Mailjet

Mailjet puede recibir las respuestas del espacio de trabajo, las bajas por `mailto:` y los informes DMARC y de bucle de
retroalimentación en un dominio de recepción como `reply.news.acme.io`. Disponible a partir de la próxima versión
después de la 1.6.0.

Cuando eliges Mailjet en la [recepción de correo](/es/providers/receiving-mail/), ReputeCast añade una parse route para
todas las direcciones del dominio de recepción, con autenticación básica en su URL, porque Mailjet no firma lo que
envía. El dominio debe estar validado en Mailjet (Account settings › Senders & domains), y la Parse API de Mailjet
requiere un plan de pago. El registro MX es `10 parse.mailjet.com`. Al dejar de recibir se elimina la parse route.

## Comprobar que funciona

- La tarjeta de Mailjet en <UiPath path="nav.providers > providers.tabProviders" /> muestra
  <UiPath path="providers.statusHealthy" /> y "Clave de API activa".
- En Mailjet, la configuración de notificación de eventos de esa clave de API dirige `sent`, `bounce`, `blocked`,
  `spam` y `unsub` a tu URL de ReputeCast.
- Las entregas y los rebotes aparecen en <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast envía a través de la Send API v3.1 de Mailjet, hasta 50 mensajes por llamada, con el seguimiento de
aperturas y clics desactivado en cada mensaje. El recuento mensual de la tarjeta es lo que esta clave envió este mes,
leído de las estadísticas de Mailjet.

<Aside type="note">
  La lista de exclusión de Mailjet solo se aplica a las campañas enviadas desde Mailjet, no a la Send API que usa
  ReputeCast. ReputeCast comprueba su propia [lista de supresión](/es/reference/glossary/#suppression-list) antes de
  cada envío; la sincronización mantiene alineadas con ella las campañas propias de Mailjet.
</Aside>

## Solución de problemas

- **"Mailjet rechazó esta clave"** con `401 Unauthorized`. La clave de API y la secret key van en pareja: comprueba
  ambas, aunque el error aparezca en el campo de la clave de API.
- **"Mailjet admite una URL de callback por evento y clave de API"** al registrar los webhooks. Otra herramienta (o
  una dirección antigua de ReputeCast) ya usa esos eventos con esta clave. Usa una clave de API que solo use ReputeCast
  o quita esos callbacks en Mailjet, y elige <UiPath path="connect.connection.registerAgain" />. Los eventos que no
  estaban ocupados se registran de todos modos.
- **La tarjeta dice "Clave de API inactiva" o "en cuarentena".** Mailjet ha limitado la clave. Resuélvelo en Mailjet
  antes de enrutar correo hacia él.
- **El dominio muestra "no está configurado en Mailjet".** El remitente de dominio se eliminó en Mailjet. Vuelve a
  crear el remitente `*@<your domain>` en Mailjet.
- **El catálogo muestra una insignia "Modo sandbox".** ReputeCast nunca envía a través del modo sandbox de Mailjet:
  todos los mensajes que entrega se envían de verdad.
- **Desconectaste Mailjet.** ReputeCast elimina los callbacks que apuntan a su URL. El remitente de dominio y las
  exclusiones se quedan en Mailjet.
