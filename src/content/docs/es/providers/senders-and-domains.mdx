Al añadir un dominio de envío en <UiPath path="nav.settings > settings.senders" />, ReputeCast obtiene los registros DNS
que necesita para ese dominio cada proveedor de envío conectado y los comprueba hasta que se verifican. Después añades
los [remitentes](/es/reference/glossary/#sender), las direcciones De desde las que sale tu correo, eliges cuál usa cada
flujo por defecto y compruebas las [IP de envío](/es/reference/glossary/#sending-ip) desde las que envía cada proveedor.
La misma página contiene los valores de envío predeterminados del espacio de trabajo.

## Antes de empezar

- Necesitas el permiso `domains:manage`. Con `providers:view` puedes ver los remitentes, los dominios y sus registros.
- Conecta al menos un proveedor de envío, para que haya alguien de quien obtener los registros. Lee
  [Conectar un proveedor de envío](/es/providers/connect/). El paso del dominio del asistente de conexión hace lo mismo
  que esta página para el proveedor que estás conectando.
- Ten acceso a los registros DNS del dominio, o un token de API de Cloudflare si el dominio usa Cloudflare.

## Añadir un dominio de envío

<Steps>

1. Abre <UiPath path="nav.settings > settings.senders" /> y, en <UiPath path="senders.domainsTitle" />, elige
   <UiPath path="senders.addDomain" />.

2. Escribe el <UiPath path="senders.domain" /> de tus direcciones De, por ejemplo `news.example.com`, y, si quieres,
   <UiPath path="senders.whatFor" /> ("dominio de envío principal"). Elige <UiPath path="senders.addDomain" />.

   Cada proveedor conectado con API de dominios (como Amazon SES, Mailgun o SendGrid) recibe el dominio y devuelve sus
   registros. Para los proveedores sin ella (como Postal o un servidor SMTP), ReputeCast te indica qué configurar en el
   panel del propio proveedor y qué include de SPF necesita el dominio.

3. Abre los <UiPath path="senders.records" /> del dominio. La página muestra los registros por proveedor, porque cada
   proveedor firma con su propia clave DKIM: DKIM, el return-path (MAIL FROM) con su registro SPF, SPF para el dominio de
   envío y DMARC. Elige la pestaña de un proveedor para ver solo sus registros, o <UiPath path="senders.allProviders" />.

   <Screenshot
     id="settings-sender-domain"
     alt="Registros DNS de news.acme.io para Amazon SES, Postmark y Postal: 11 de 11 verificados, con tres registros CNAME de DKIM, el registro MX de return-path y SPF para MAIL FROM, y botones para añadir todos los registros mediante la API de Cloudflare o copiar un archivo de zona."
   />

4. Publica los registros en tu proveedor de DNS. Si los servidores de nombres son de Cloudflare,
   <UiPath path="connect.domain.addViaCloudflare" /> añade los que faltan con un token que tenga el permiso Zone › DNS ›
   Edit; el token se usa una vez y nunca se guarda. Si no, copia cada valor o usa
   <UiPath path="connect.domain.copyZone" />. Lee [Configurar SPF, DKIM y DMARC](/es/deliverability/spf-dkim-dmarc/) para
   saber qué hace cada registro.

5. Observa la columna de estado. Mientras la página está abierta, ReputeCast comprueba los registros cada 30 segundos;
   cada uno muestra Verificado, Pendiente, Falta o "No se pudo comprobar", con el valor que encontró.

6. Opcional: en <UiPath path="connect.domain.optionalTitle" />, elige <UiPath path="connect.domain.addTracking" /> para
   usar un subdominio como `go.news.example.com`, con un CNAME hacia tu host de ReputeCast, para los enlaces y el píxel
   de apertura. La misma sección muestra si BIMI está configurado; lee [Configurar BIMI](/es/deliverability/bimi/).

   El CNAME solo demuestra que el host apunta a tu servidor de ReputeCast, no de quién es el host. Desde la versión
   1.5.0, un dominio de seguimiento que otro espacio de trabajo de la instancia verificó antes, o uno bajo la dirección
   propia de la instancia, necesita además el registro TXT `_reputecast.<tracking domain>` con el valor que muestra la
   sección ("Añade el registro TXT … para demostrar que el dominio es tuyo"). Hasta que exista, el dominio muestra
   "· sin usar", y los enlaces y el píxel de apertura siguen usando el predeterminado. Una de las direcciones propias de
   la instancia nunca se acepta, y un host que otro espacio de trabajo usa para sus páginas o sus enlaces no se puede
   añadir en absoluto.

</Steps>

Si más adelante conectas otro proveedor, abre los registros del dominio y obtén los registros de ese proveedor desde su
pestaña.

<Aside type="tip">
Dale al correo transaccional un subdominio propio, como `notify.example.com`, para que su reputación quede separada de
la de tus boletines. La [guía de configuración transaccional](/es/transactional/first-send/) lo marca como dominio
Transaccional; solo los remitentes de un dominio Transaccional pueden enviar plantillas transaccionales y correo por la
API.
</Aside>

## Añadir un remitente

<Steps>

1. En <UiPath path="senders.identitiesTitle" />, elige <UiPath path="senders.addSender" />.

2. Rellena los datos del remitente:
   - <UiPath path="senders.name" />: se muestra como remitente en las bandejas de entrada.
   - <UiPath path="senders.emailAddress" />: su dominio tiene que ser ya uno de tus dominios de envío. La dirección no se
     puede cambiar más adelante.
   - <UiPath path="senders.replyTo" />: adónde van las respuestas cuando no deben volver a la dirección De.
   - <UiPath path="senders.defaultSenderFor" />: los flujos (Envíos masivos, Automatizaciones, Sistema, y Transaccional
     para un remitente de un dominio Transaccional) que usan este remitente salvo que una campaña o un correo elija otro.
   - <UiPath path="senders.note" />: se muestra en la lista cuando el remitente no es el predeterminado de ningún flujo,
     por ejemplo "envíos personales".
   - <UiPath path="senders.sendsThrough" />: los proveedores que pueden enviar con esta dirección. Desmarca un proveedor
     para marcarlo como "Sin usar" para este remitente.

3. Elige <UiPath path="senders.addSender" />. Cada proveedor verifica el remitente mediante los registros del dominio.

</Steps>

<Screenshot
  id="settings-senders"
  alt="Identidades de remitente del espacio de trabajo Acme Newsletter: cada dirección De con su dirección de respuesta, los flujos de los que es predeterminada y su estado en Amazon SES, Postmark y Postal; un remitente está en Pendiente por su registro DKIM de acme.io y muestra un botón Verificar."
/>

La tabla tiene una columna por proveedor conectado: Verificado, Pendiente (con el registro que espera), Sin usar o Sin
configurar. Para un remitente pendiente, <UiPath path="senders.verify" /> abre los registros del dominio para ese
proveedor.

## Configurar los valores predeterminados

La tarjeta <UiPath path="senders.defaultsTitle" />, cerca de la parte inferior de la página, contiene:

- <UiPath path="senders.defaultFrom" />, y la dirección De predeterminada de las plantillas transaccionales (un remitente
  de un dominio Transaccional).
- <UiPath path="senders.replyHandling" />: reenviar todas las respuestas a una dirección, usar la dirección de respuesta
  propia de cada remitente o guardar las respuestas en ReputeCast (consulta
  [recibir respuestas en ReputeCast](#recibir-respuestas-en-reputecast)).
- <UiPath path="senders.footerAddress" />: la dirección postal que muestran los pies de los correos mediante el token
  `{{ footer_address }}` y que los correos de sistema añaden a su pie. Lee
  [Nociones básicas de consentimiento y leyes antispam](/es/deliverability/compliance/).
- <UiPath path="senders.trackingDomain" />: un dominio de seguimiento verificado para los enlaces y el píxel de apertura,
  o el predeterminado del proveedor (tu URL pública de ReputeCast).
- <UiPath path="senders.listUnsubscribeMailto" />: desactivado en todos los espacios de trabajo, también en los que ya
  existían, desde la versión 1.6.0. Desactivado, la cabecera `List-Unsubscribe` solo lleva el enlace de baja con un clic
  que usan Gmail, Yahoo y Outlook. Activado, añade una dirección `mailto:` para las aplicaciones de correo que dan de
  baja por correo: la dirección de respuesta o, si no la hay, la dirección De, y alguien en esa dirección tiene que dar
  de baja a esos lectores a mano en 10 días, algo que te recuerda la revisión previa. Una campaña toma este ajuste
  cuando empieza su envío; las automatizaciones y las copias de las pruebas de ubicación también lo siguen. Lee
  [baja con un clic](/es/deliverability/one-click-unsubscribe/).
- <UiPath path="senders.utmLinks" />: desactivado por defecto. Activado, ReputeCast añade `utm_source` (el slug del
  espacio de trabajo), `utm_medium=email` y `utm_campaign` (el nombre de la campaña o de la automatización, sin
  acentos) a cada enlace `http` y `https` de un correo, antes de compilar el correo. Un enlace conserva las etiquetas
  UTM que ya tiene, y los enlaces creados con Liquid se quedan como están. Las campañas lo usan desde su siguiente
  envío, las automatizaciones desde su siguiente publicación, y una campaña puede activarlo o desactivarlo solo para
  ella en [Revisar y enviar](/es/campaigns/schedule-and-send/). Las [reglas de envío](/es/campaigns/sending-rules/) del
  espacio de trabajo que piden etiquetas UTM cuentan como presentes las que se añaden.

Elige <UiPath path="common.save" /> para conservar los cambios. Cambiar estos valores requiere `domains:manage`.

### Recibir respuestas en ReputeCast

Debajo de los valores predeterminados, la tarjeta <UiPath path="senders.receiving.title" /> configura cómo recibe el
espacio de trabajo las respuestas, los correos de baja y los informes DMARC y de bucle de retroalimentación, a través de
un proveedor de envío o de un buzón. Disponible a partir de la próxima versión después de la 1.6.0.

- En cuanto la tarjeta indica <UiPath path="senders.receiving.statusReceiving" />,
  <UiPath path="senders.replyHandling" /> ofrece <UiPath path="senders.receiving.keepInInbox" />. Las campañas, los
  correos de automatización y las copias de las pruebas de ubicación llevan entonces una dirección Reply-To del dominio
  de recepción, y las respuestas llegan a <UiPath path="nav.audience > replies.tab" />.
- Mientras la ruta recibe, la dirección `mailto:` de `List-Unsubscribe` está en el dominio de recepción, y ReputeCast
  aplica esas bajas por sí mismo en menos de un minuto.
- Al dejar de recibir, la gestión de respuestas vuelve a reenviar las respuestas.

Lee [configurar la recepción de correo](/es/providers/receiving-mail/).

## Comprobar las IP de envío

Cada tarjeta de proveedor de <UiPath path="nav.providers > providers.tabProviders" /> muestra sus
<UiPath path="providers.overview.factIps" />: el grupo de IP compartido, comprobado a nivel de dominio, o sus IP
dedicadas, comprobadas una a una. La revisión previa comprueba cada IP dedicada en las listas de bloqueo de IP (una IP a
la que aún no han llegado las comprobaciones aparece como Desconocido), Entregabilidad y el calentamiento las leen, y una
IP dedicada que nunca ha enviado para este espacio de trabajo empieza una [fase canaria](/es/campaigns/live-monitor/) en
el siguiente envío.

<Screenshot
  id="providers-list"
  alt="Proveedores de envío: las IP de envío de la tarjeta de Amazon SES indican el grupo de IP compartido, comprobado a nivel de dominio, de Amazon SES y comprobado a diario; las de la tarjeta de Postmark indican el grupo de IP compartido, con la nota de que Postmark no las indica y un botón Editar."
/>

- **Amazon SES, SendGrid, Mailgun, SparkPost y Brevo** informan de las IP desde las que envía tu cuenta. ReputeCast las
  pide cuando se conecta el proveedor, cuando se repite su paso de conexión y cada día, y la tarjeta lo indica ("De
  Amazon SES, comprobadas a diario"). En Mailgun, solo cuentan las IP dedicadas asignadas al dominio de la conexión. Si
  una comprobación falla, la tarjeta conserva la última respuesta, explica el motivo y ofrece
  <UiPath path="providers.overview.checkIpsAgain" />.
- **Los demás proveedores** no las indican, y su tarjeta lo dice. Con `providers:manage`, elige
  <UiPath path="providers.overview.editIps" />, selecciona <UiPath path="providers.overview.ipsModeDedicated" /> o
  <UiPath path="providers.overview.ipsModeShared" />, escribe las IP dedicadas en
  <UiPath path="providers.overview.ipsLabel" /> (una por línea, IPv4 o IPv6, hasta 64) y elige
  <UiPath path="providers.overview.ipsSave" />. Un servidor autoalojado como Postal muestra "Dedicadas · aún sin
  definir" hasta que indicas sus IP.

## Comprobar que funciona

- La fila del dominio en <UiPath path="senders.domainsTitle" /> muestra DKIM, SPF, DMARC y el return-path como
  verificados para cada proveedor que lo usa.
- Cada remitente muestra Verificado para los proveedores que envían con él.
- La [revisión previa](/es/campaigns/send-readiness/) supera sus comprobaciones de autenticación para las campañas de
  ese dominio. ReputeCast vuelve a comprobar el DNS de todos los dominios cada 30 minutos, así que un cambio en tu
  proveedor de DNS aparece en la revisión previa en menos de una hora.

## Solución de problemas

- **"news.example.com aún no es un dominio de envío de este espacio de trabajo"**: añade primero el dominio y luego el
  remitente.
- **Un registro sigue en Pendiente**: el proveedor de DNS aún no lo ha publicado. Algunos tardan hasta 48 horas. Compara
  el valor encontrado con el que se muestra.
- **Un registro muestra un valor distinto**: existe un registro más antiguo con el mismo nombre, por ejemplo un segundo
  registro SPF. Un dominio solo puede tener un registro SPF; el valor de ReputeCast combina los includes que necesitas.
- **"1 remitente usa news.example.com. Elimínalo primero"**: un dominio solo se puede eliminar cuando ningún remitente
  lo usa. Al eliminarlo se detienen las comprobaciones; los registros se quedan en tu proveedor de DNS y en cada
  proveedor hasta que los quites allí.
- **Un proveedor aparece como Sin configurar para un remitente**: el proveedor aún no tiene el dominio. Abre los
  registros del dominio, elige la pestaña del proveedor y obtén sus registros.
- **El dominio de seguimiento muestra "· sin usar"**: otro espacio de trabajo de esta instancia verificó antes el host,
  o está bajo la dirección propia de la instancia. Añade el registro TXT que muestra la sección. Si indica que el host
  es una de las direcciones propias de la instancia, usa en su lugar un subdominio de tu dominio de envío.
- **"… ya lo usa otro espacio de trabajo de esta instancia de ReputeCast, para sus páginas o sus enlaces."**: el host es
  el dominio personalizado, el dominio de enlaces cortos, el dominio de seguimiento o el sitio web de ese espacio de
  trabajo. Quítalo allí primero o elige otro subdominio.
- **<UiPath path="senders.receiving.keepInInbox" /> aparece en gris**: configura la
  [recepción de correo](/es/providers/receiving-mail/) y espera a su primer mensaje, o envía un mensaje de prueba.
  Disponible a partir de la próxima versión después de la 1.6.0.
- **"No se pudo comprobar con …" en las IP de envío de un proveedor**: el proveedor no respondió, o la clave no puede
  listar las IP (en Amazon SES, permite `ses:GetDedicatedIps`). La tarjeta conserva las IP que conocía; corrige el acceso
  y elige <UiPath path="providers.overview.checkIpsAgain" />.
