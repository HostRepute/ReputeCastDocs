Postmark solo permite el correo masivo en un flujo de mensajes Broadcast, así que el flujo Broadcast de Postmark para tu
newsletter es el centro de esta configuración: conectas Postmark con un server token, y ReputeCast crea el flujo
Broadcast, registra webhooks en cada flujo, obtiene los registros DNS de tu dominio y mantiene las supresiones
sincronizadas.

<ProviderMatrix family="email" id="postmark" />

## Antes de empezar

- **Un servidor de Postmark y su Server API token** (Postmark › Servers › tu servidor › API Tokens). Mientras tu
  cuenta de Postmark está pendiente de aprobación, todos los destinatarios tienen que compartir el dominio de la
  dirección De ([Postmark API overview, error 412](https://postmarkapp.com/developer/api/overview), consultado en
  octubre de 2026), así que envía tus pruebas a una dirección de tu propio dominio hasta que Postmark apruebe la cuenta.
- **Opcional: un Account API token.** Con él, ReputeCast añade tu dominio de envío en Postmark y muestra sus registros
  DKIM y Return-Path. Sin él, añades tú mismo el dominio en Postmark.
- **Permisos.** Para conectar necesitas `providers:manage`; para añadir un dominio de envío nuevo, `domains:manage`.
- **Una dirección HTTPS pública.** Postmark envía los eventos a `<public URL>/hooks/postmark/<token>`. Postmark no tiene
  una API de eventos que ReputeCast pueda consultar en su lugar, así que la dirección tiene que ser accesible desde
  internet.

Postmark separa los flujos de mensajes Transactional (correo uno a uno que desencadena una acción del usuario) de los
flujos Broadcast (boletines y anuncios)
([Postmark: How to create and send through Message Streams](https://postmarkapp.com/support/article/how-to-create-and-send-through-message-streams),
consultado en octubre de 2026). ReputeCast envía el correo de Sistema, Automatizaciones y Transaccional por el flujo
Transactional de tu servidor, `outbound`, y los Envíos masivos solo por un flujo Broadcast.

## Conectar Postmark

<Steps>

1. Abre <UiPath path="nav.providers" />, elige <UiPath path="providers.overview.addProvider" /> y selecciona Postmark en
   el catálogo. [Conectar un proveedor de envío](/es/providers/connect/) recorre los pasos que comparten todos los
   proveedores.

   <Screenshot
     id="providers-catalog"
     alt="El catálogo de proveedores: la tarjeta de Postmark indica que el marketing masivo solo se permite en flujos Broadcast, que cuesta 55,00 US$ al mes para 50.000 correos con un plan de hasta 50.000 y que su configuración lleva 10–15 minutos con un server token y registros DNS."
   />

2. Pega el <UiPath path="providers.fields.postmark.serverToken" /> y deja
   <UiPath path="providers.fields.postmark.messageStream" /> en `outbound`. En la configuración adicional de Postmark
   puedes añadir el <UiPath path="providers.fields.postmark.accountToken" /> y tu
   <UiPath path="providers.fields.monthlyLimit" /> (se usa para la barra de cuota). Deja
   <UiPath path="providers.fields.postmark.broadcastStream" /> vacío: ReputeCast crea el flujo en el paso 8.

3. Elige <UiPath path="connect.connection.connect" />. ReputeCast comprueba el token con llamadas de solo lectura
   (`GET /server` y las estadísticas de salida de este mes) y lo guarda cifrado.

4. En <UiPath path="connect.connection.webhooksTitle" />, ReputeCast comprueba primero que su dirección de webhook es
   accesible desde internet y después registra un webhook en el flujo de mensajes con autenticación básica HTTP
   (usuario `reputecast`, con un secreto que genera ReputeCast). El webhook informa de Delivery, Bounce, SpamComplaint y
   SubscriptionChange; Open y Click siguen desactivados porque ReputeCast hace por sí mismo el seguimiento de aperturas
   y clics.

5. Elige <UiPath path="connect.connection.continueDomain" /> y escribe tu dominio de envío. Con un Account API token,
   ReputeCast añade el dominio en Postmark con el Return-Path `pm-bounces.<your domain>` y muestra el registro TXT de
   DKIM y el CNAME de Return-Path (hacia `pm.mtasv.net`), además de un registro DMARC si el dominio no tiene ninguno.

6. En <UiPath path="connect.stepTest" />, envía una prueba. Sale por el flujo `outbound`; la cronología espera el webhook
   Delivery de Postmark.

7. En <UiPath path="connect.stepStreams" /> y <UiPath path="connect.stepContacts" />, elige los flujos que lleva
   Postmark y si quieres recibir las supresiones que ya tiene Postmark. Los Envíos masivos aún no se ofrecen: las
   condiciones de Postmark solo permiten el correo masivo en un flujo Broadcast.

8. Para enviar boletines a través de Postmark, abre <UiPath path="nav.providers > providers.tabRouting" /> y pon
   Postmark como ruta (o como respaldo) de <UiPath path="providers.streamBroadcast" />. Al guardar, ReputeCast te ofrece
   crear el flujo: elige <UiPath path="providers.bulk.actionCreate" />. Crea en tu servidor de Postmark un flujo
   Broadcast llamado "ReputeCast Broadcasts" (con el ID de flujo `broadcast`, o `reputecast-broadcasts` si ese ID está
   ocupado), registra también el webhook en él y lo usa para la ruta.

</Steps>

<Aside type="caution">
  Escribir el ID de un flujo existente en el campo del flujo Broadcast no desbloquea los Envíos masivos; ReputeCast lo
  usa para enviar, pero sigue tratando Postmark como solo transaccional. Crea el flujo desde Enrutamiento como en el
  paso 8.
</Aside>

## Comprobar que funciona

- La tarjeta de Postmark en <UiPath path="nav.providers > providers.tabProviders" /> muestra
  <UiPath path="providers.statusHealthy" /> y el volumen de este mes.
- En Postmark, cada flujo que usa ReputeCast tiene un webhook que apunta a `/hooks/postmark/…` con autenticación
  básica, y tu servidor muestra el flujo "ReputeCast Broadcasts" una vez creado.
- Los eventos de entrega de ambos flujos aparecen en <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast envía hasta 500 mensajes por llamada al endpoint de lotes de Postmark, con `TrackOpens` desactivado y
`TrackLinks` en `None` en cada mensaje. Si la configuración de seguimiento propia de tu servidor está activada, la
<UiPath path="providers.events.trackingTitle" /> de la pestaña de eventos y sincronización lo muestra y puede
desactivarla mediante la API; hasta entonces, la [revisión previa](/es/reference/glossary/#send-readiness) avisa del
doble seguimiento. Las supresiones se sincronizan por flujo cada 15 minutos: ReputeCast envía a ambos flujos los rebotes
permanentes y las quejas que se aplican a todo el correo, reactiva allí las direcciones cuando salen de la lista
compartida (Postmark conserva las quejas de spam, que no se pueden quitar) y, si marcaste la opción de recibir, importa
los rebotes, las quejas de spam y las bajas de Postmark. Postmark no informa de las IP desde las que envía; si tienes IP
dedicadas, indícalas en las [IP de envío](/es/providers/senders-and-domains/#comprobar-las-ip-de-envío) de la tarjeta.

## Solución de problemas

- **"Postmark rechazó esta clave"** con `ErrorCode 10`. El token no es un Server API token, o pertenece a otro
  servidor. Copia el token del servidor con el que envías, no el Account token.
- **La tarjeta del webhook indica que la dirección no es accesible desde internet.** A Postmark no se le pueden
  consultar eventos, así que corrige la URL pública (o usa un túnel mientras pruebas) y elige
  <UiPath path="connect.connection.recheck" />. Postmark no puede enviar un webhook de prueba a petición, así que el
  evento de entrega del envío de prueba confirma que sus eventos llegan. Consulta
  [Proxy inverso y TLS](/es/self-hosting/reverse-proxy/).
- **Los mensajes de prueba se quedan en cola y se reintentan** mientras tu cuenta de Postmark está pendiente de
  aprobación. Postmark rechaza los destinatarios fuera del dominio De (error 412) y ReputeCast lo reintenta como un error
  temporal. Envía la prueba a una dirección de tu propio dominio o espera la aprobación de Postmark.
- **Los Envíos masivos no pueden usar Postmark** en el paso de flujos ni en Enrutamiento. Crea el flujo Broadcast como
  en el paso 8.
- **El paso del dominio no muestra ningún registro DKIM ni Return-Path.** Conectaste sin un Account API token. Añade el
  dominio en Postmark y publica el registro DKIM que muestra, o añade el token en
  <UiPath path="providers.overview.settings > providers.overview.credentials" /> en la tarjeta del proveedor.
- **"Postmark no creó el flujo"** porque los dos ID de flujo están ocupados. Crea un flujo Broadcast en Postmark y
  escribe su ID.
- **El catálogo muestra una insignia "Token de sandbox".** ReputeCast no tiene modo de prueba para Postmark: el envío de
  prueba de la configuración entrega un mensaje real.
- **Cambiaste la URL pública o desconectaste Postmark.** Una URL pública nueva añade un webhook para la nueva dirección;
  elimina el anterior en Postmark. Al desconectar se quitan los webhooks de ReputeCast, pero el flujo Broadcast, el
  dominio y las supresiones enviadas se quedan en Postmark.
