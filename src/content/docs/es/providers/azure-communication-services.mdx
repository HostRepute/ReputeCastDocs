ReputeCast envía correo con Azure Communication Services a través de tu recurso Email Communication y lee los informes
de entrega de una suscripción de Azure Event Grid. ReputeCast no puede crear nada en Azure por ti: configuras el dominio
de correo y la suscripción de Event Grid en Azure Portal, y ReputeCast te da la URL del webhook y comprueba que cada
entrega es auténtica.

<ProviderMatrix family="email" id="azureacs" />

<Aside type="caution" title="Azure Communication Services Email se retira">
  Microsoft retira Azure Communication Services como oferta independiente el 30 de septiembre de 2028, y ACS Email
  está en la lista de servicios retirados. A partir del 23 de octubre de 2026, Microsoft limita el alta de clientes que
  aún no tienen un recurso de Communication Services
  ([Microsoft Learn: Retirement and breaking changes guide](https://learn.microsoft.com/en-us/azure/communication-services/acs-retirement-and-breaking-changes-guide),
  consultado en octubre de 2026). Prevé un segundo proveedor de envío antes de depender de Azure.
</Aside>

## Antes de empezar

- **Un recurso de Communication Services con un dominio de correo personalizado verificado** conectado a él, y los
  nombres de usuario de remitente desde los que envías
  ([Microsoft Learn: Add custom verified email domains](https://learn.microsoft.com/en-us/azure/communication-services/quickstarts/email/add-custom-verified-domains),
  consultado en octubre de 2026). El nombre visible del campo De sale del nombre de usuario de remitente en Azure, no de
  ReputeCast.
- **Credenciales.** O bien la connection string del recurso (Azure Portal › tu recurso de Communication Services ›
  Keys), o bien un registro de aplicación de Microsoft Entra ID con un secreto de cliente y el rol Communication and
  Email Service Owner en el recurso.
- **Permisos.** Para conectar necesitas `providers:manage`; para añadir un dominio de envío nuevo, `domains:manage`.
- **Una dirección HTTPS pública.** Event Grid entrega en `<public URL>/hooks/azureacs/<token>`. A Azure no se le pueden
  consultar eventos pasados, así que la dirección tiene que ser accesible desde internet.

## Conectar Azure Communication Services

<Steps>

1. Abre <UiPath path="nav.providers" />, elige <UiPath path="providers.overview.addProvider" /> y selecciona Azure
   Communication Services en el catálogo. [Conectar un proveedor de envío](/es/providers/connect/) explica los pasos que
   comparten todos los proveedores.

2. Escribe un único conjunto de credenciales:
   - la <UiPath path="providers.fields.azureacs.connectionString" /> (`endpoint=https://…/;accesskey=…`), o
   - en la configuración adicional de Azure, el <UiPath path="providers.fields.azureacs.endpoint" />
     (`https://<resource>.communication.azure.com`), <UiPath path="providers.fields.azureacs.tenantId" />,
     <UiPath path="providers.fields.azureacs.clientId" /> y <UiPath path="providers.fields.azureacs.clientSecret" />.
     Si rellenas ambos, se usa Entra ID.

   Escribe también los límites que Azure da a tu dominio: <UiPath path="providers.fields.azureacs.perMinute" /> pasa a
   ser la velocidad de envío de ReputeCast para Azure (el formulario sugiere 30 para un dominio personalizado nuevo hasta
   que Azure lo aumente), y <UiPath path="providers.fields.azureacs.perHour" /> se muestra en la tarjeta.

3. Elige <UiPath path="connect.connection.connect" />. ReputeCast hace una llamada de solo lectura a tu recurso y guarda
   las credenciales cifradas. La tarjeta muestra "Communication Services · accesible" y tus límites.

4. En <UiPath path="connect.connection.webhooksTitle" />, ReputeCast comprueba que su dirección de webhook es accesible
   desde internet y después muestra la URL del webhook que debes añadir en Azure. Elige
   <UiPath path="connect.connection.copyUrl" />.

5. Decide cómo demuestra Event Grid que cada entrega viene de tu suscripción:
   - **Un secreto compartido.** Elige <UiPath path="connect.connection.createSecret" /> y copia el secreto; se muestra
     una sola vez, y uno nuevo reemplaza al anterior. Event Grid lo enviará como cabecera de entrega personalizada
     `X-ReputeCast-Secret` (o como `Authorization: Bearer <secret>`).
   - **Microsoft Entra ID.** Escribe la <UiPath path="providers.fields.azureacs.eventGridAudience" /> (el ID de la
     aplicación o su URI `api://`) y, cuando esa aplicación está en otro tenant, el
     <UiPath path="providers.fields.azureacs.eventGridTenant" />. ReputeCast solo acepta entonces tokens de Entra emitidos
     para esa aplicación con el rol `AzureEventGridSecureWebhookSubscriber`.

6. En Azure Portal, abre tu recurso de Communication Services › Events › Add Event Subscription y crea una suscripción
   con:
   - el tipo de evento **Email Delivery Report Received** (`Microsoft.Communication.EmailDeliveryReportReceived`);
   - el esquema de eventos **Event Grid Schema**;
   - el tipo de endpoint **Web Hook**, con la URL que copiaste;
   - para un secreto compartido, una propiedad de entrega (cabecera personalizada) `X-ReputeCast-Secret` con el secreto
     como valor y "Is secret?" marcado; para Entra ID, la autenticación de Microsoft Entra con la aplicación del paso 5.

   ReputeCast responde por sí mismo al handshake de validación de Event Grid, así que la suscripción se crea de
   inmediato. Consulta
   [Microsoft Learn: Handle email events](https://learn.microsoft.com/en-us/azure/communication-services/quickstarts/email/handle-email-events),
   [Set custom headers on delivered events](https://learn.microsoft.com/en-us/azure/event-grid/delivery-properties)
   y [Deliver events to Microsoft Entra protected endpoints](https://learn.microsoft.com/en-us/azure/event-grid/secure-webhook-delivery)
   (consultado en octubre de 2026).

7. Elige <UiPath path="connect.connection.continueDomain" />. Los registros DKIM y de verificación de Azure salen de
   Azure Portal, así que el paso del dominio solo comprueba lo que ReputeCast puede comprobar (se sugiere DMARC si el
   dominio no tiene ninguno).

8. En <UiPath path="connect.stepTest" />, envía una prueba. El asistente te deja continuar antes de configurar Event
   Grid, así que este paso es la prueba: la cronología espera el primer informe de entrega de Azure.

9. Termina <UiPath path="connect.stepStreams" /> y <UiPath path="connect.stepContacts" />. No hay nada que recibir:
   ReputeCast no lee ni escribe la lista de supresión de Azure.

</Steps>

## Comprobar que funciona

- La cronología del envío de prueba muestra el informe de entrega de Azure.
- La tarjeta de Azure en <UiPath path="nav.providers > providers.tabProviders" /> muestra
  <UiPath path="providers.statusHealthy" />.
- En Azure Portal, las métricas de la suscripción de eventos muestran eventos entregados y ningún fallo de entrega.

ReputeCast envía una llamada a la API por mensaje con el seguimiento de interacción de Azure desactivado; hace por sí
mismo el seguimiento de aperturas y clics. Los informes de entrega se corresponden con eventos de ReputeCast: Delivered
con una entrega, Bounced con un rebote permanente (un rebote temporal cuando el receptor bloqueó al remitente),
Suppressed con un rechazo, y FilteredSpam, Quarantined y Failed con rebotes temporales. Azure no informa de quejas ni de
bajas, así que estas solo llegan desde los enlaces de baja propios de ReputeCast. La
[lista de supresión](/es/reference/glossary/#suppression-list) compartida se aplica antes de cada envío. La firma DKIM de
Azure no cubre las cabeceras `List-Unsubscribe` que añade ReputeCast, así que puede que Gmail y Yahoo no ofrezcan la baja
con un clic en el correo enviado a través de Azure; la [revisión previa](/es/campaigns/send-readiness/) avisa cuando un
envío enruta una parte a través de Azure.

## Solución de problemas

- **"Esta configuración no se puede usar: … the connection string needs endpoint= and accesskey=".** Copia la
  connection string completa de la página Keys del recurso.
- **"Azure Communication Services rechazó esta clave".** La clave de acceso se regeneró, o el secreto de cliente o los
  ID de la app de Entra son incorrectos. Con Entra ID, comprueba también que la app tenga el rol Communication and Email
  Service Owner.
- **La prueba espera indefinidamente el primer evento.** Comprueba la suscripción en Azure: el tipo de evento, el
  esquema Event Grid, la URL exacta del webhook y la cabecera `X-ReputeCast-Secret` (o la autenticación de Entra). Las
  entregas sin una autenticación válida reciben `401` de ReputeCast.
- **Las entregas empezaron a fallar después de crear un secreto nuevo.** Cada secreto nuevo reemplaza al anterior de
  inmediato. Pega el secreto nuevo en la cabecera de entrega de la suscripción.
- **El correo llega con un nombre de remitente incorrecto.** Azure usa el nombre visible del nombre de usuario de
  remitente configurado en Azure. Cámbialo allí.
- **Fallan los mensajes transaccionales con Cc, Bcc o archivos adjuntos.** El adaptador de Azure no puede enviar copias
  ni adjuntos; enruta esas plantillas a través de otro proveedor.
- **Cambiaste la URL pública o desconectaste Azure.** ReputeCast no cambia nada en Azure. Actualiza o elimina tú mismo
  la suscripción de eventos.
