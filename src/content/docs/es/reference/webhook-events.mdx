Esta página enumera los tipos de eventos de webhook a los que puede suscribirse un endpoint de <UiPath path="nav.settings > settings.webhooks" />, y el sobre que usa cada entrega. [Recibir webhooks](/es/developers/webhooks/) muestra cómo crear un endpoint y verificar las firmas.

## Sobre

Cada entrega es un `POST` con un cuerpo JSON de cinco campos:

| Campo        | Valor                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------- |
| `id`         | El ID del evento (UUID). Todos los endpoints que reciben el evento reciben el mismo ID; úsalo para descartar duplicados. |
| `type`       | El tipo de evento, por ejemplo `email.bounced`.                                               |
| `created_at` | Cuándo ocurrió el evento, en UTC (RFC 3339).                                                  |
| `workspace`  | El slug del espacio de trabajo.                                                               |
| `data`       | El payload del evento. Su forma depende del tipo; seis eventos que usan las integraciones tienen un payload de ejemplo en su fila de abajo. |

Al probar un endpoint se envía un evento `webhook.test`:

```json title="webhook.test"
{
  "id": "01934f6e-8b2a-7c3d-9e4f-5a6b7c8d9e0f",
  "type": "webhook.test",
  "created_at": "2026-10-22T09:30:00.482913Z",
  "workspace": "acme-newsletter",
  "data": {
    "message": "Test event from ReputeCast. Verify the signature, then answer 2xx."
  }
}
```

Un endpoint con <UiPath path="webhooks.batchLabel" /> activado recibe sus eventos `email.*` en entregas `email.batch`:
`data.count` indica cuántos eventos lleva, hasta 100, y `data.events` los enumera, cada uno con el sobre de arriba, en el
orden en que ocurrieron. No es posible suscribirse a `email.batch` por separado. Consulta
[recibir los eventos de correo en lotes](/es/developers/webhooks/#recibir-los-eventos-de-correo-en-lotes).

## Cabeceras

| Cabecera                 | Valor                                                                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `Content-Type`           | `application/json`                                                                                                                     |
| `User-Agent`             | `ReputeCast-Webhooks/<version>`                                                                                                        |
| `X-ReputeCast-Event`     | El tipo de evento.                                                                                                                     |
| `X-ReputeCast-Delivery`  | El ID de la entrega: uno por endpoint y evento, sin cambios entre reintentos.                                                          |
| `X-ReputeCast-Timestamp` | Tiempo Unix, en segundos, en que se hizo este intento.                                                                                 |
| `X-ReputeCast-Signature` | HMAC-SHA256 en hexadecimal y minúsculas de `<timestamp>.<raw body>`, con el secreto `whsec_…` completo como clave. Rechaza las marcas de tiempo con más de 5 minutos de diferencia. Durante las 24 horas siguientes a una rotación del secreto, dos firmas separadas por comas, primero la del secreto nuevo; acepta cualquiera de las dos. |

## Entrega y reintentos

- Una respuesta `2xx` en menos de 10 segundos cuenta como entregada. Cualquier otro estado, un tiempo agotado o un error de conexión se reintenta.
- Un evento se intenta hasta 8 veces, con esperas de 1, 2, 4, 8, 30, 90 y 225 minutos entre intentos (unas seis horas en total). Tras el octavo fallo pasa a la cola de entregas fallidas, desde donde puedes volver a enviarlo.
- Un endpoint en pausa sigue acumulando eventos en cola, lotes incluidos; cuando lo reanudas, los eventos en cola se entregan en orden.
- Un endpoint que falla durante una hora, o cuya entrega pasa a la cola de entregas fallidas, avisa a quienes gestionan los webhooks con <UiPath path="notify.event.webhook_failing" />.
- El evento `webhook.test` se intenta una vez y nunca se reintenta.

## Suscribirse a eventos

Un endpoint se suscribe a entre 1 y 40 entradas. Cada entrada es un tipo de evento exacto (`email.bounced`), todos los eventos de un grupo (`email.*`, que coincide con la parte anterior al primer punto) o todos los eventos (`*`). `email.*` incluye `email.replied` y `email.received`, que aparecen más abajo en Respuestas. Disponible a partir de la próxima versión después de la 1.6.0.

Cada evento necesita el permiso de lectura de los datos que lleva, y los eventos que llevan contactos necesitan acceso a todas las listas: suscribirse a uno que no puedes ver responde `403 permission_denied`, y un endpoint se pone en pausa cuando la persona en cuyo nombre envía pierde ese acceso. Consulta [en nombre de quién envía un endpoint](/es/developers/webhooks/#en-nombre-de-quién-envía-un-endpoint).
