Esta página enumera todos los comandos de la CLI de reputecast (`reputecast`), el único binario que ejecuta el servidor, los procesos de trabajo y las tareas de mantenimiento.

En la imagen Docker, ejecuta un comando dentro del contenedor de la aplicación: `docker compose exec app /usr/local/bin/reputecast <command>`. La configuración sale de las mismas fuentes que `reputecast serve` (consulta [configurar ReputeCast](/es/self-hosting/configuration/)), así que pasa `--config` o las variables `REPUTECAST_*` que usa el servidor.

## Códigos de salida

| Código | Significado                                                                                                                                                                                                                                                                                               |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`    | El comando terminó correctamente.                                                                                                                                                                                                                                                                         |
| `1`    | El comando falló: un error de base de datos, de red o de configuración, una opción desconocida o un número de argumentos incorrecto. También `healthcheck` cuando el proceso no está listo, `doctor` cuando falla una comprobación, `secrets reseal` cuando hay valores que se abren sin ninguna clave configurada y `storage migrate` cuando no se copió un archivo. |
| `2`    | ReputeCast rechazó la solicitud antes de hacer nada: `user reset-2fa` sin `--reason`, una `--password` que incumple la política de contraseñas, un `seed --sample` desconocido, `storage migrate --to` con algo distinto de `s3`, o `seed` (sin `--force`) o `demo send` fuera de `REPUTECAST_ENV=development`.                                              |

Cada error se escribe en la salida de error estándar como `Error: <message>`.
