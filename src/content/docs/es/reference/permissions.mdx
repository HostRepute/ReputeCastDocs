Esta página enumera todas las claves de los permisos de ReputeCast que puede tener un [rol](/es/reference/glossary/#role), una [clave de API](/es/reference/glossary/#api-key) o un [agente MCP](/es/reference/glossary/#mcp-agent), agrupadas como en el editor de roles de <UiPath path="nav.settings > settings.roles" />.

Cada operación de la API indica el permiso que necesita, y los miembros, las claves de API y los agentes MCP pasan por la misma comprobación. Una acción rechazada indica quién puede ayudar, no la clave; las claves aparecen donde las defines (ámbitos de las claves de API, permisos de los agentes MCP, ámbitos de las claves de integración y el editor de roles), en el [registro de auditoría](/es/team/audit-log/) y en el campo `permission` del problema `permission_denied` de la API. Los [permisos delicados](/es/reference/glossary/#sensitive-permission) llevan la marca ⚑ en la aplicación y activan la política de verificación en dos pasos: cuando la instancia exige la verificación en dos pasos para los permisos delicados, todos los miembros cuyo rol tenga alguno deben usarla. **Incluye** enumera los permisos que vienen automáticamente con una clave.

## Quién puede tener un permiso

La columna **Quién puede tenerlo** usa cuatro reglas:

- **Personas, claves de API y agentes de IA**: cualquier rol, clave de API o agente MCP puede tenerlo.
- **Personas y claves de API, no agentes de IA**: los agentes MCP nunca lo tienen, aunque lo tenga quien los creó.
- **Solo personas**: solo lo tienen los miembros, a través de su rol. Las claves de API y los agentes MCP no pueden tenerlo.
- **Solo el Propietario**: solo lo tiene el rol integrado Propietario. No se puede añadir a un rol personalizado, a una clave de API ni a un agente, y el rol Administrador tiene todos los demás permisos.

Una clave de API o un agente MCP nunca hace más de lo que puede hacer en ese momento el miembro que lo creó. Cuando el rol de ese miembro pierde un permiso, la clave también lo pierde; cuando el miembro sale del espacio de trabajo, la clave pierde todos sus permisos.

Las claves del grupo **Agencia (instancia)** pertenecen a la instancia, no a un espacio de trabajo. El personal de la agencia las tiene a través de los roles Responsable de agencia y Responsable de cuentas cuando el modo agencia está activado.

## Roles integrados

Los roles integrados no se pueden editar; duplica uno para crear un [rol personalizado](/es/reference/glossary/#custom-role). Cada fila de abajo es un permiso y cada columna, un rol integrado: los roles del espacio de trabajo (Propietario, Administrador, Editor, Lector), los roles para los clientes de los espacios de trabajo de clientes de una agencia y los roles de agencia de la instancia.
