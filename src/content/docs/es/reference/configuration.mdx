Esta página enumera todas las claves de configuración que lee ReputeCast, con las variables de entorno de ReputeCast que las definen y sus valores predeterminados.

ReputeCast construye su configuración a partir de cinco capas; una capa posterior prevalece sobre una anterior:

1. Los valores predeterminados integrados (la columna **Predeterminado** de abajo).
2. El archivo YAML indicado por `--config` o `REPUTECAST_CONFIG`.
3. Las variables de entorno `REPUTECAST_*`. Un doble guion bajo separa los niveles: `REPUTECAST_HTTP__ADDR` define `http.addr`.
   La URL pública es la excepción: `REPUTECAST_PUBLIC_URL` define `http.public_url`, y su nombre anterior,
   `REPUTECAST_HTTP__PUBLIC_URL`, sigue funcionando cuando `REPUTECAST_PUBLIC_URL` no está definida.
4. `DATABASE_URL`, solo cuando `REPUTECAST_DATABASE__URL` no está definida. Del mismo modo, `PORT` define `http.addr`
   como `:<PORT>` cuando `REPUTECAST_HTTP__ADDR` no está definida. Disponible a partir de la próxima versión después de la 1.6.0.
5. Las opciones de línea de comandos que pasas de forma explícita: `--role`, `--addr`, `--database-url` y `--log-level`.

En las claves de lista (`roles`, `http.trusted_proxies`, `secrets.previous_keys`, `dns.servers`), separa los valores con comas en una variable de entorno. ReputeCast se niega a arrancar cuando no puede interpretar un valor, cuando un rol no es `web`, `worker` ni `ingest`, cuando `http.public_url` no es una URL absoluta, cuando `secrets.key` no es una clave de 32 bytes codificada en base64, cuando `auth.password_min_length` es inferior a 8, cuando `metrics.token` tiene menos de 16 caracteres, cuando `PORT` no es un número de puerto o cuando las claves de [almacenamiento](/es/reference/configuration/#storage) no encajan entre sí. Una entrada de `http.trusted_proxies` que no es una dirección, un rango ni `private` se registra y se ignora. [Configurar ReputeCast](/es/self-hosting/configuration/) explica las capas con un ejemplo de YAML completo.
