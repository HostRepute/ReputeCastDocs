Los servidores MCP remotos dan al [asistente de IA](/es/integrations/ai-assistant/) de ReputeCast las herramientas de
servicios externos, como un gestor de incidencias, una wiki o una base de conocimientos. Cada herramienta espera la
revisión de quien administra. Las herramientas que solo leen se ejecutan una vez aprobadas; las que escriben preguntan a
la persona cada vez, con los argumentos exactos. Los servidores nunca reciben las claves de ReputeCast, y lo que
devuelven se trata como datos no fiables. Disponible desde la versión 1.8.0.

<Aside type="caution" title="Todavía sin probar con servidores públicos">
  Los servidores MCP se probaron con los propios controladores de servidor del SDK de Go de MCP y con un servidor de
  autorización simulado en loopback, incluidas las variantes de descubrimiento y la revocación que se describen abajo.
  Todavía no se ha probado ningún servidor MCP público ni ningún servidor de autorización público. Lee
  [qué espera ReputeCast de un servidor OAuth](#qué-espera-reputecast-de-un-servidor-oauth) antes de añadir uno.
</Aside>

ReputeCast tiene tres funciones MCP. Esta página trata de la primera:

| Función | Sentido | Dónde |
|---|---|---|
| Servidores MCP | El asistente de ReputeCast llama a las herramientas de un servidor externo | <UiPath path="nav.settings > settings.integrations > mcpservers.title" /> |
| [El servidor MCP de ReputeCast](/es/developers/mcp/) | Un agente externo llama a las herramientas de ReputeCast con un token de agente | <UiPath path="nav.settings > settings.keys" /> |
| [Conexiones externas](/es/developers/mcp-connections/) | ChatGPT, Claude u otro cliente MCP inicia sesión con OAuth y propone borradores | <UiPath path="nav.settings > settings.keys" /> |

## Antes de empezar

- Para añadir, editar, sincronizar y quitar servidores, y para revisar herramientas, hace falta `integrations:manage`
  (Propietario y Administrador). Las personas con `integrations:view` ven la página en modo de solo lectura: los
  servidores, sus herramientas y cómo se permite cada una. Con `ai:use` pueden conectar su propia cuenta a un servidor
  OAuth.
- Para usar las herramientas de un servidor en una conversación hace falta `ai:use` y un servidor permitido para el rol
  de la persona.
- Ten a mano el endpoint MCP del servidor (Streamable HTTP, o HTTP con SSE) y su credencial, si la necesita. Solo se
  pueden añadir servidores remotos: los servidores de proceso local (stdio) no se admiten.
- Para los servidores que identifican a los miembros con OAuth, la URL pública de la instancia tiene que usar `https://`
  y ser accesible desde los navegadores de las personas
  ([la dirección de redirección de OAuth](#la-dirección-de-redirección-de-oauth)).

## Añadir un servidor

<Steps>

2. Completa <UiPath path="mcpservers.addTitle" />:

Cada solicitud que hace ReputeCast a un servidor o a su servidor de autorización pasa por la protección SSRF, que
comprueba la dirección en cada conexión. Los servidores en direcciones privadas o de loopback necesitan el ajuste de la
instancia [`providers.allow_private_networks`](/es/reference/configuration/); las direcciones link-local y de metadatos
de la nube se rechazan siempre. ReputeCast acepta direcciones `http://`, pero entonces el secreto de cabecera o el
token viajan sin cifrar: usa `https://`.

Después de añadirlo, <UiPath path="mcpservers.edit" /> cambia el nombre, quién puede usarlo, el valor del secreto de
cabecera (<UiPath path="mcpservers.replace" />), el cliente OAuth y <UiPath path="mcpservers.enabled" /> (desactivado:
las conversaciones dejan de ofrecer sus herramientas; no se elimina nada). La dirección, el tipo de inicio de sesión y
el nombre de la cabecera no se pueden cambiar: quita el servidor y vuelve a añadirlo.
<UiPath path="mcpservers.removeServer" />, dentro de Editar, elimina sus herramientas y el inicio de sesión de cada
miembro en él; sus tokens de renovación se [revocan](#revocar-los-inicios-de-sesión-eliminados) donde el servidor de
autorización lo permite, y una llamada que espera confirmación ya no se puede permitir, solo denegar.

| Tipo | A quién ve el servidor | Notas |
|---|---|---|
| <UiPath path="mcpservers.optNone" /> | Solicitudes anónimas | Para servidores que no necesitan credenciales. |
| <UiPath path="mcpservers.optHeader" /> | El espacio de trabajo, como una sola identidad | Un <UiPath path="mcpservers.fieldHeaderName" /> (`Authorization` de forma predeterminada) y un <UiPath path="mcpservers.fieldHeaderValue" />. El valor es de solo escritura: "ReputeCast nunca lo vuelve a mostrar y solo lo envía a este servidor." Todas las personas que pueden usar el servidor actúan con esa misma credencial. |

Los secretos de cabecera, los secretos de cliente y los tokens se guardan cifrados con la clave secreta de la instancia
y la API nunca los devuelve.

### La dirección de redirección de OAuth

El servidor de autorización devuelve a las personas a la misma dirección para todos los servidores y espacios de
trabajo:

```text title="Dirección de redirección de OAuth"
<public URL>/api/v1/ai/mcp/oauth/callback
```

Por ejemplo `https://news.example.com/api/v1/ai/mcp/oauth/callback`. La URL pública es la que está guardada en
<UiPath path="shell.userMenuInstanceAdmin > admin.instance" />, o
[`REPUTECAST_PUBLIC_URL`](/es/self-hosting/configuration/).

- Cuando ReputeCast se registra en el servidor de autorización (registro dinámico de clientes), registra esta
  dirección. No tienes que escribir nada.
- Cuando el servidor necesita un cliente que registraste tú, abre <UiPath path="mcpservers.clientSummary" />, escribe el
  <UiPath path="mcpservers.fieldClientId" /> y, si lo tiene, el <UiPath path="mcpservers.fieldClientSecret" />, y
  registra la dirección de arriba como dirección de redirección del cliente. Después de añadir el servidor,
  <UiPath path="mcpservers.edit" /> la muestra como "Dirección de redirección que hay que registrar: …".

La especificación de autorización de MCP exige que las direcciones de redirección usen https (o localhost), y los
servidores de autorización pueden rechazar otras
([autorización de MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), comprobado en
noviembre de 2026). Si la URL pública cambia, la dirección de redirección cambia con ella: registra la nueva en un
cliente que hayas introducido tú. Un cliente que registró ReputeCast conserva la dirección antigua, así que borra su ID
de cliente en Editar y el siguiente inicio de sesión registrará un cliente nuevo. Cuenta con que los miembros tengan
que volver a iniciar sesión.

### Qué espera ReputeCast de un servidor OAuth

ReputeCast sigue el flujo de autorización de MCP con PKCE (S256), el indicador de recurso (RFC 8707) y un state
vinculado a la sesión de la persona que sirve una sola vez y durante diez minutos. El descubrimiento se ejecuta en el
primer inicio de sesión en el servidor, y de nuevo después de borrar su ID de cliente:

1. Envía al servidor una solicitud MCP `initialize` sin credenciales. Si la respuesta es un 401, lee
   `resource_metadata` y `scope` de su desafío Bearer de `WWW-Authenticate`.
2. Lee los metadatos del recurso protegido (RFC 9728) de, por este orden: la dirección que indicó el 401;
   `https://<host>/.well-known/oauth-protected-resource<path>`, construida a partir de la dirección del servidor; y la
   raíz `https://<host>/.well-known/oauth-protected-resource`. Un documento de las dos primeras tiene que indicar la
   dirección del servidor como su `resource`; el documento raíz tiene que indicar el origen del servidor, que pasa a ser
   el recurso para el que ReputeCast pide tokens. Se rechaza un documento que indique cualquier otro recurso.
3. Toma el primer servidor de autorización de la lista y lee sus metadatos: primero OAuth (RFC 8414) y después el
   descubrimiento de OpenID Connect. Los metadatos tienen que incluir `S256` en `code_challenge_methods_supported`.
4. Sin un cliente introducido por ti, el servidor de autorización necesita un `registration_endpoint`. Los documentos
   de metadatos de ID de cliente (Client ID metadata documents) no se admiten.
5. Pide el scope que indicó el 401 o, si no, todos los scopes de `scopes_supported` del recurso.
6. La autenticación del cliente es ninguna, o HTTP basic con el secreto de cliente. `client_secret_post` y
   `private_key_jwt` no se admiten.
7. Las direcciones de los metadatos tienen que ser https (http simple solo en loopback).
8. Guarda el `revocation_endpoint` del servidor de autorización, si tiene uno, para
   [revocar los inicios de sesión eliminados](#revocar-los-inicios-de-sesión-eliminados).

Cuando falla cualquiera de estos pasos, el inicio de sesión indica "No se pudo configurar el inicio de sesión de …: su
servidor de autorización no respondió como se esperaba. Revisa la dirección o introduce un cliente registrado."

contener lo que adjuntó una persona. Otros estados son <UiPath path="mcpservers.stateChanged" />
([abajo](#cuando-cambia-una-herramienta)) y <UiPath path="mcpservers.stateRemoved" /> (la última lista del servidor no
la incluía; no se ofrece). Si la herramienta cambió en el servidor mientras la revisabas, la decisión no se guarda y la
página muestra la versión nueva: "Esta herramienta cambió en el servidor mientras la revisabas."

## Cuando cambia una herramienta

Una decisión se guarda con el hash de la descripción, el esquema de entrada y las anotaciones de la herramienta tal como
los revisaste. ReputeCast compara las herramientas de un servidor con lo decidido en tres momentos:

- **Antes de cada llamada.** En la propia sesión de la llamada, ReputeCast lista primero las herramientas del servidor.
  Si la herramienta ya no aparece, o difiere de la versión decidida, la llamada no se envía.
- **Cada hora**, para los servidores con inicio de sesión <UiPath path="mcpservers.optNone" /> o
  <UiPath path="mcpservers.optHeader" /> que están activados y se sincronizaron antes (la tarea `mcp.servers_sync`, como
  máximo 20 servidores por ejecución). Los servidores OAuth se listan en nombre de una persona, así que solo los cubren
  la comprobación antes de cada llamada y el Sincronizar herramientas de quien administra.
- **Cuando quien administra elige <UiPath path="mcpservers.sync" />.**

Cuando uno de ellos detecta que una herramienta aprobada o bloqueada cambió, la herramienta queda como
<UiPath path="mcpservers.stateChanged" />: ninguna conversación la ofrece, y una llamada que espera confirmación no
puede ejecutarse. Los miembros que gestionan integraciones reciben una notificación ("Cambiaron herramientas de …"), y
las conversaciones cuya llamada se topó con ella muestran <UiPath path="assistant.mcp.changedTitle" />.
<UiPath path="assistant.mcp.reviewChange" /> muestra **Antes** y **Después** para la descripción, el esquema de entrada
y las anotaciones, con <UiPath path="mcpservers.blockTool" /> y <UiPath path="mcpservers.approveNew" />. Una
herramienta que el servidor ya no lista pasa a <UiPath path="mcpservers.stateRemoved" />, sin notificación.

## Usar servidores en una conversación

Los miembros eligen los servidores de una conversación en el selector de servidores del panel
([elegir el modelo y los servidores MCP](/es/integrations/ai-assistant/#elegir-el-modelo-y-los-servidores-mcp)). Un
servidor limitado a algunos roles indica "Solo … pueden usarlo" en su fila; un servidor desactivado, o que no es para el
rol de la persona, no se ofrece. Cada llamada vuelve a comprobar que la persona puede usar el servidor.

La conversación ofrece las herramientas aprobadas de los servidores elegidos después de las de ReputeCast, dentro de las
40 herramientas por solicitud, ordenadas por nombre de servidor y después por nombre de herramienta; el resto no se
ofrece. En un servidor OAuth, solo los miembros que iniciaron sesión reciben sus herramientas. Cada llamada abre su
propia sesión con el servidor, en nombre de la persona propietaria de la conversación: ReputeCast lista primero las
herramientas del servidor y después llama a la herramienta, y las dos cosas juntas tienen 30 segundos. Las filas de
herramientas indican "Servidor · herramienta" y cuánto tardó, o qué salió mal.

## Resultados no fiables

Lo que devuelve un servidor son datos, nunca instrucciones:

- Solo texto. Las imágenes, el audio y los recursos incrustados se convierten en una nota como `[image removed]`, y el
  HTML se convierte en su texto, sin scripts ni estilos.
- Como máximo 32 KB. Una respuesta más grande no se entrega al modelo.
- Envuelto en delimitadores `<untrusted_content source="Server · tool">` que el texto no puede cerrar, y al modelo se
  le indica que nunca siga instrucciones de su interior, ni llame a una herramienta ni comparta datos porque se lo pidan.
- La descripción de una herramienta llega al modelo precedida de "From the MCP server …, outside ReputeCast", con
  1000 caracteres como máximo; los esquemas de entrada de más de 8 KB no se ofrecen.

Los delimitadores reducen el riesgo; no hacen a un modelo inmune a un texto que intenta dirigirlo. Por eso las
herramientas que escriben preguntan cada vez y no existe "permitir siempre".

## Qué reciben los servidores

- Los argumentos de las llamadas a sus propias herramientas, tal como los escribió el modelo. En una herramienta que
  escribe, exactamente los argumentos que permitió la persona.
- Su credencial: la cabecera compartida, o el propio token OAuth del miembro.
- En los servidores OAuth: una solicitud MCP `initialize` sin credenciales durante el descubrimiento, y el token de
  renovación de un inicio de sesión eliminado en el endpoint de revocación del servidor de autorización.

Nada más: ninguna clave de ReputeCast, y nada de la conversación salvo que el modelo lo ponga en los argumentos de una
llamada. ReputeCast rechaza el muestreo (sampling: un servidor que pide al modelo de ReputeCast que genere texto) y la
elicitación (elicitation: un servidor que pide datos a la persona), y no lista los recursos ni los prompts de los
servidores.

Cada llamada queda en el [registro de auditoría](/es/team/audit-log/) como `mcp_tool.called`, con la persona, la
conversación, el servidor, el resultado, la duración y un hash de los argumentos con el ID de la llamada como sal, nunca
los argumentos ni el resultado. Los cambios en los servidores, las sincronizaciones, las decisiones sobre herramientas,
los inicios de sesión y las confirmaciones también quedan auditados.

## Los inicios de sesión de cada miembro

En un servidor OAuth, cada miembro inicia sesión por su cuenta:

- <UiPath path="mcpservers.connect" /> en la fila del servidor, o **Iniciar sesión en …** en el selector de servidores
  de una conversación, abre la página de inicio de sesión del servidor. Vuelve a Servidores MCP con "Conectado a …",
  "Cancelaste el inicio de sesión en …" o "… no completó el inicio de sesión".
- La fila indica entonces "Conectado como …", con <UiPath path="mcpservers.reconnect" /> y
  <UiPath path="mcpservers.disconnect" />.
- ReputeCast renueva el token por su cuenta poco antes de que caduque. Cuando se rechaza la renovación, o el servidor
  responde 401 o 403, el inicio de sesión se elimina y las conversaciones muestran **Vuelve a iniciar sesión en …**.
- <UiPath path="mcpservers.disconnect" /> elimina los tokens que guarda ReputeCast.

Los inicios de sesión de un miembro en un espacio de trabajo se eliminan cuando lo deja, se le quita de él o se le
desactiva. Desactivar a una persona en la administración de la instancia elimina sus inicios de sesión en todos los
espacios de trabajo, y quitar un servidor elimina el inicio de sesión de cada miembro en él.

### Revocar los inicios de sesión eliminados

Cuando el servidor de autorización anunció un `revocation_endpoint`, ReputeCast también revoca el token de renovación
de cada inicio de sesión que elimina (RFC 7009): al desconectar, cuando el miembro se va, se le quita o se le
desactiva, cuando se quita el servidor y cuando el servidor rechazó el inicio de sesión. Al desconectar procesa la cola
al momento (hasta 10 tokens, durante hasta 10 segundos); la tarea `mcp.tokens_revoke` envía lo que queda cada minuto.
Es un mejor esfuerzo: cada token se intenta una vez, una revocación fallida se registra sin el token, y el inicio de
sesión desaparece en cualquier caso. Los tokens de acceso no se revocan; dejan de valer cuando caducan. Sin un
`revocation_endpoint`, no se revoca nada: usa los ajustes del propio servidor.

## Comprobar que funciona

- La fila del servidor muestra su número de herramientas, y <UiPath path="mcpservers.showTools" /> enumera las
  herramientas que revisaste como <UiPath path="mcpservers.stateApproved" /> o <UiPath path="mcpservers.stateAsks" />.
- En el [panel del asistente](/es/integrations/ai-assistant/), el selector de servidores muestra el servidor, y pedir
  algo que sus herramientas pueden responder muestra una fila "Servidor · herramienta".

| <UiPath path="assistant.mcp.changedTitle" /> (<UiPath path="assistant.mcp.changedBadge" />) | El servidor cambió una herramienta después de que se aprobara. | Quien administra elige <UiPath path="assistant.mcp.reviewChange" />. |

| **… es inaccesible**, o la insignia <UiPath path="mcpservers.badgeUnreachable" /> del servidor | El servidor no respondió. | Vuelve a preguntar más tarde, o revisa la dirección y el servidor. |
| **… tardó demasiado** | La herramienta no respondió en 30 segundos. | Vuelve a preguntar más tarde. |
| **… envió demasiado** | La respuesta superaba los 32 KB, así que el modelo no la recibió. | Haz una pregunta más concreta. |
| "No se pudo configurar el inicio de sesión de …" | Falló el descubrimiento o el registro. | Revisa [qué espera ReputeCast](#qué-espera-reputecast-de-un-servidor-oauth), o introduce un cliente registrado. |
| "No se puede conectar a una dirección privada" | El servidor está en tu propia red. | Un operador define `providers.allow_private_networks`. |

</TableScroll>

Una fila de herramienta también puede indicar "Denegaste …. No se envió nada a …." o "Puede que … se ejecutara, pero
su resultado se perdió. Comprueba … antes de volver a preguntar." Lo segundo significa que la llamada se envió y que el
worker se perdió antes de guardar su resultado; ReputeCast nunca la vuelve a enviar.
