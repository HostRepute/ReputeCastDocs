Esta página enumera todos los campos de la asignación del adaptador HTTP genérico de correo: el objeto `http` que indica a ReputeCast cómo llamar a la API HTTP de un [proveedor de envío](/es/reference/glossary/#sending-provider) y cómo leer sus webhooks, sin escribir código. Para los pasos en la aplicación, consulta [conectar cualquier API HTTP de correo](/es/providers/generic-http/).

Una asignación llega a ReputeCast de una de estas tres formas:

- **El formulario** de <UiPath path="nav.providers > providers.tabAdapters > providers.adapters.httpTitle" />. <UiPath path="providers.adapters.saveAsAdapter" /> la guarda como adaptador instalado de tipo `http` para todos los espacios de trabajo de la instancia. Cubre el endpoint de envío, las cabeceras de la solicitud, la plantilla del cuerpo, la ruta del ID del mensaje, la asignación del webhook y la autenticación del webhook. Todos los demás campos de esta página necesitan un manifest.
- **Un manifest** de tipo `http`, instalado desde su URL `https://` con <UiPath path="nav.providers > providers.tabAdapters > providers.adapters.installFromRegistry" />. `reputecast adapter install` solo instala [adaptadores de la comunidad](/es/adapters/community/) de tipo `remote`.
- **La configuración del propio proveedor** (`{"http": {…}}`), para un proveedor conectado mediante el adaptador integrado `httpgeneric`.

Para guardar, instalar y probar una asignación hace falta [quien administra la instancia](/es/reference/glossary/#instance-admin), con `providers:manage`. Después, los espacios de trabajo conectan proveedores a través de ella desde <UiPath path="nav.providers > providers.overview.addProvider" /> con sus propias credenciales.

## Manifest

Un adaptador HTTP instalado es un manifest JSON cuyo objeto `http` es la asignación.

<TableScroll label="Campos del manifest" wrap>

| Campo                                         | Reglas                                                                                                                                                                                                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                                        | Obligatorio. La clave en el registro es `community:` seguido del nombre en minúsculas y dígitos unidos por guiones: "Example ESP" se convierte en `community:example-esp`. La clave aparece en las URL de los webhooks. El formulario admite de 2 a 60 caracteres. |
| `version`                                     | Obligatorio para instalar desde una URL. Se muestra en la pestaña Adaptadores. El formulario guarda `0.1.0`.                                                                                                                                                |
| `maintainer`                                  | Se muestra como `community · <maintainer>`; `unknown` si está vacío. El formulario guarda `local · <your name>`.                                                                                                                                           |
| `kind`                                        | `"http"`.                                                                                                                                                                                                                                                   |
| `capabilities`                                | Lista opcional de etiquetas para la pestaña Adaptadores, como `["webhooks"]`. Las insignias del catálogo salen de la propia asignación.                                                                                                                      |
| `source_url`, `latest_version`, `last_release` | Opcionales. Un `latest_version` más reciente muestra una actualización. Un `last_release` (RFC 3339) de hace más de 365 días marca el adaptador como Sin mantenimiento, y deja de ofrecerse para conexiones nuevas.                                         |
| `terms`                                       | `bulk` es `allowed`, `broadcast_streams_only`, `forbidden` o `your_policy` (predeterminado). `note` y `url` (la política de uso aceptable del proveedor) se muestran a su lado. Con `forbidden` o `broadcast_streams_only`, el proveedor solo se ofrece para los flujos Automatizaciones y Sistema. |
| `pricing`                                     | Texto opcional para el catálogo, como "$0.80 per 1,000". Predeterminado: "lo fija tu proveedor".                                                                                                                                                           |
| `http`                                        | La asignación: todos los campos siguientes.                                                                                                                                                                                                                 |

</TableScroll>

ReputeCast no puede leer las condiciones de un proveedor asignado, así que sin `terms` la pantalla de enrutamiento te pide que revises la política de uso aceptable del proveedor antes de enrutar hacia él el flujo Envíos masivos. Un manifest instalado desde una URL debe estar en una dirección `https://` pública y ocupar como máximo 256 KiB.

Los textos del manifest (`name`, `terms.note`, `pricing`, y `label` y `help` de sus `fields`) se muestran tal como los
escribiste, en todos los idiomas. Sin `terms.note` o sin `pricing`, se muestra en su lugar el texto propio de ReputeCast,
en el idioma de cada lector, como el resto de lo que dice sobre la asignación.

## Solicitud de envío

<TableScroll label="Campos de la solicitud de envío" wrap>

| Campo                | Reglas                                                                                                                                                                                                                                                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `method`             | `POST` (predeterminado), `PUT` o `PATCH`.                                                                                                                                                                                                                                                                       |
| `url`                | Una URL `https://`. Escribe el host completo; los campos de plantilla solo pueden aparecer en la ruta y en la consulta. Sin `#fragment`. Un manifest puede usar `http://` para un servidor de pruebas en loopback (`localhost`, `127.0.0.1`), al que la instancia solo llega con `providers.allow_private_networks`. El formulario solo acepta `https://`. |
| `headers`            | Nombre de la cabecera → plantilla del valor, como `"Authorization": "Bearer {{ secrets.api_key }}"`. `Content-Type` es `application/json` por defecto. `Host`, `Content-Length`, `Transfer-Encoding` y `Connection` no se pueden definir. El formulario admite hasta 20 cabeceras.                           |
| `body`               | Obligatorio. La plantilla JSON del cuerpo. Debe ser JSON válido una vez completados sus campos: al guardar se comprueba con un mensaje de ejemplo, y un mensaje cuyo cuerpo no se renderiza como JSON se rechaza con el código `Template`. El formulario admite hasta 20.000 caracteres.                    |
| `message_id_path`    | Ruta del ID del mensaje del proveedor en el cuerpo de una respuesta 2xx, como `$.data.id`.                                                                                                                                                                                                                      |
| `message_id_header`  | Una cabecera de la respuesta que lleva el ID del mensaje en su lugar. Usa una de las dos, no ambas. Se quitan los corchetes angulares alrededor del ID. Sin ninguna de las dos, se usa en su lugar el ID de mensaje de ReputeCast.                                                                              |
| `error_code_path`    | Ruta del código de error del proveedor en una respuesta fallida.                                                                                                                                                                                                                                                |
| `error_message_path` | Ruta del mensaje de error del proveedor. Sin estas dos rutas, el cuerpo de la respuesta es el mensaje de error.                                                                                                                                                                                                 |
| `check.url`          | `GET` opcional que responde 2xx mientras las credenciales son válidas. ReputeCast lo llama al conectar un proveedor y desde la tarea de comprobación de estado de los proveedores. Sin él, el estado sale solo de los resultados de los envíos.                                                                |
| `check.headers`      | Cabeceras de la solicitud de comprobación. Predeterminado: las cabeceras de la solicitud de envío.                                                                                                                                                                                                              |
| `fields`             | Campos de conexión adicionales: `key`, `label`, `secret`, `required`, `options`, `help`. Las plantillas leen un campo secreto como `secrets.<key>` y cualquier otro campo como `settings.<key>`.                                                                                                                |

</TableScroll>

El formulario de conexión siempre tiene dos campos secretos opcionales: **Clave de API** (`secrets.api_key`) y **Secreto de firma del webhook** (`secrets.webhook_signing_key`). Los secretos son de solo escritura: se guardan sellados y nunca se devuelven.

ReputeCast envía una solicitud por mensaje y lee la respuesta así:

| Respuesta         | Qué hace ReputeCast                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 2xx               | Aceptado. El ID del mensaje sale de `message_id_path` o de `message_id_header`.                                           |
| 401, 403          | Se rechazaron las credenciales: el envío falla y el estado del proveedor lo indica.                                       |
| 429               | Limitación de velocidad: ese mensaje se reintenta más tarde.                                                             |
| 408, 5xx          | Una caída del proveedor: consulta [estado de los proveedores y caídas](/es/providers/health-and-outages/).              |
| Cualquier otro 4xx | Ese mensaje falló definitivamente, con el código y el mensaje que leen las rutas de error.                              |

## Campos de plantilla

Las plantillas solo usan etiquetas de salida al estilo de Liquid: `{{ name }}`, con filtros opcionales. No hay etiquetas `{% %}`; una asignación describe una única solicitud fija.

| Campo                                                | Valor                                                                                                                       |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `sender`                                             | El remitente (From) como `"Name" <address>`, o solo la dirección si no hay nombre.                                          |
| `sender_email`, `sender_name`                        | La dirección y el nombre de From.                                                                                           |
| `recipient`, `recipient_name`, `recipient_formatted` | La dirección y el nombre de To, y `"Name" <address>`.                                                                       |
| `reply_to`, `reply_to_name`                          | La dirección y el nombre de Reply-To, vacíos si no hay.                                                                     |
| `subject`, `html`, `text`                            | El mensaje renderizado y personalizado.                                                                                     |
| `headers`, `headers_json`                            | Las cabeceras del mensaje como objeto: `List-Unsubscribe`, `List-Unsubscribe-Post` y las demás que define ReputeCast, más `X-ReputeCast-Message`. |
| `headers_list`                                       | Las mismas cabeceras como `[{"name": …, "value": …}]`, ordenadas por nombre.                                                |
| `tags`                                               | Las etiquetas del mensaje como objeto.                                                                                      |
| `message_id`                                         | El ID de mensaje de ReputeCast. Envíalo al proveedor para que sus webhooks puedan devolverlo.                              |
| `stream`                                             | `broadcast`, `automation` o `system`.                                                                                       |
| `settings.<key>`, `secrets.<key>`                    | La configuración y las credenciales del proveedor conectado.                                                               |

Envía todas las cabeceras de `headers_json` o `headers_list`: los proveedores de buzón exigen las cabeceras de [baja con un clic](/es/deliverability/one-click-unsubscribe/). Desactiva en el cuerpo el seguimiento de aperturas y clics del propio proveedor si su API lo permite, porque ReputeCast hace su propio seguimiento de aperturas y clics.

### Filtros

Escribe un filtro después de una barra vertical: `{{ settings.region | default: 'eu' }}`. Los filtros se aplican de izquierda a derecha, y un argumento es una cadena entre comillas (`'…'` o `"…"`) o el nombre de un campo.

<TableScroll label="Filtros y sus resultados" wrap>

| Filtro          | Argumento | Resultado                                                                             |
| --------------- | --------- | ------------------------------------------------------------------------------------- |
| `default`       | 1         | El argumento cuando el valor falta o es una cadena vacía, o un objeto o una lista vacíos. |
| `prepend`       | 1         | El argumento y después el valor.                                                      |
| `append`        | 1         | El valor y después el argumento.                                                      |
| `base64_encode` | ninguno   | Base64 estándar.                                                                      |
| `url_encode`    | ninguno   | Codificación de consulta de URL.                                                      |
| `downcase`      | ninguno   | Minúsculas.                                                                           |
| `upcase`        | ninguno   | Mayúsculas.                                                                           |
| `strip`         | ninguno   | Sin espacios al principio ni al final.                                                |
| `json`          | ninguno   | El valor codificado como texto JSON.                                                  |

</TableScroll>

Cualquier otro filtro se rechaza al guardar. Esta cabecera crea un valor de autenticación básica a partir de la clave de API:

```json title="Basic auth header"
"Authorization": "Basic {{ 'api:' | append: secrets.api_key | base64_encode }}"
```

### Escape

Los valores se escapan según dónde aparecen, para que los datos no puedan romper la solicitud:

- **Dentro de una cadena JSON** (`"subject": "{{ subject }}"`), el valor se escapa como JSON.
- **Fuera de una cadena** (`"headers": {{ headers_json }}`), el valor se codifica como JSON: los objetos siguen siendo objetos y un valor que falta se convierte en `null`.
- **En la URL**, los valores se escapan como ruta, o como consulta después de `?`.
- **En las cabeceras**, los saltos de línea se convierten en espacios.

Para enviar un `{{` literal dentro de una cadena JSON (los marcadores propios de una API), escribe `\{{`: `"Hi \{{first_name}}"` envía `"Hi {{first_name}}"`. `{{ '{{' }}` hace lo mismo en cualquier lugar.

<UiPath path="providers.adapters.testSample" /> renderiza la solicitud para un mensaje de ejemplo (de Acme Newsletter a Linh Nguyen) con todos los secretos mostrados como `••••`. No se envía nada.

## Sintaxis de las rutas

Los campos `*_path` usan un subconjunto de JSONPath:

| Sintaxis                        | Selecciona                             |
| ------------------------------- | -------------------------------------- |
| `$`                             | La raíz.                               |
| `.name`, `['name']`, `["name"]` | Un miembro.                            |
| `[0]`                           | Un elemento de un array (0 o más).     |
| `[*]`, `.*`                     | Todos los elementos de un array o un objeto. |

Los filtros (`[?(…)]`), el descenso recursivo (`..`), los slices y los índices negativos se rechazan al guardar. Cuando una ruta selecciona varios valores, se usa el primero, salvo en `events_path`. Los números se leen exactamente, así que los ID de proveedor mayores que 2^53 conservan todos sus dígitos.

## Autenticación del webhook

`webhook.auth` indica cómo demuestra una solicitud de webhook que viene del proveedor. El formulario ofrece los mismos cinco modos en <UiPath path="providers.adapters.webhookAuth" />.

| `auth`                  | La solicitud se acepta cuando                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hmac` (predeterminado) | `signature_header` (por defecto `X-Signature`) contiene el HMAC de `signed_payload` calculado con el secreto. `signed_payload` usa `{body}` y `{timestamp}`; por defecto es `{body}`, o `{timestamp}.{body}` cuando se define `timestamp_header`. `algorithm` es `sha256` (predeterminado), `sha1` o `sha512`. `encoding` es `hex` (predeterminado) o `base64`. `signature_prefix` (como `sha256=`) se quita primero. La cabecera puede incluir varias firmas separadas por comas o espacios; basta con que coincida una. |
| `standard`              | La solicitud lleva una firma [Standard Webhooks](https://www.standardwebhooks.com/) válida (`webhook-id`, `webhook-timestamp`, `webhook-signature`, o las cabeceras `svix-`) calculada con un secreto `whsec_`.                                                                                                                                                                                  |
| `basic`                 | Su usuario de autenticación básica es `username` (por defecto `reputecast`) y su contraseña es el secreto.                                                                                                                                                                                                                                                                                       |
| `header`                | `token_header` contiene el secreto tal cual. ReputeCast nunca guarda esa cabecera con el evento sin procesar.                                                                                                                                                                                                                                                                                  |
| `none`                  | Nada más que la URL del webhook, que no se puede adivinar. Úsalo solo cuando el proveedor no ofrezca ninguna de las opciones anteriores.                                                                                                                                                                                                                                                         |

Con `hmac` y un `timestamp_header`, o con `standard`, una marca de tiempo (segundos o milisegundos Unix) de hace más de cinco minutos o adelantada más de cinco minutos se rechaza como repetición.

El secreto es la plantilla `secret` cuando está definida (puede leer `secrets.<key>` y `settings.<key>`). Si no, es el **Secreto de firma del webhook** de la conexión y, si tampoco existe, el secreto de webhook que ReputeCast generó para el proveedor. Si no hay ningún secreto, se rechazan todas las solicitudes.

Apunta el webhook del proveedor a la URL de la tarjeta del proveedor: `<public URL>/hooks/community:<name>/<token>` para un proveedor conectado mediante un adaptador HTTP instalado, o `<public URL>/hooks/httpgeneric/<token>`. Los cuerpos de los webhooks están limitados a 5 MiB.

## Payloads de los webhooks

`webhook_mapping` elige cómo se leen los eventos: `status` (predeterminado) o `jsonpath`. En el formulario, <UiPath path="providers.adapters.webhookMapping" /> ofrece `status → delivered | bounced | complained` y <UiPath path="providers.adapters.mappingJsonpath" />.

Una asignación sin ningún campo de webhook (`webhook_mapping`, `webhook.auth`, `webhook.signature_header`, `webhook.type_path`, `webhook.types`) no tiene webhooks: el proveedor envía, pero no informa de entregas, rebotes ni quejas.

<TableScroll label="Campos de los payloads de los webhooks" wrap>

| Campo                        | Lee                                                      | Predeterminado con `status`    |
| ---------------------------- | -------------------------------------------------------- | ------------------------------ |
| `webhook.events_path`        | Los eventos de una solicitud                             | `$` (ambas asignaciones)       |
| `webhook.type_path`          | El tipo de evento (obligatorio con `jsonpath`)           | `$.status`                     |
| `webhook.recipient_path`     | El destinatario                                          | `$.recipient`, después `$.email` |
| `webhook.message_id_path`    | El ID del mensaje del proveedor                          | `$.message_id`                 |
| `webhook.reputecast_id_path` | El ID de mensaje de ReputeCast devuelto                  | `$.reputecast_id`              |
| `webhook.code_path`          | La respuesta SMTP o el código propio del proveedor       | `$.code`                       |
| `webhook.diagnostic_path`    | El texto de diagnóstico                                  | `$.reason`                     |
| `webhook.time_path`          | Cuándo ocurrió                                           | `$.timestamp`                  |
| `webhook.url_path`           | El enlace de un clic                                     | `$.url`                        |
| `webhook.user_agent_path`    | El user agent de una apertura o un clic                  | `$.user_agent`                 |

</TableScroll>

Con `jsonpath`, solo se leen las rutas que definas. La asignación personalizada del formulario define <UiPath path="providers.adapters.pathEvents" />, <UiPath path="providers.adapters.pathType" />, <UiPath path="providers.adapters.pathRecipient" /> y <UiPath path="providers.adapters.pathMessageId" />.

`events_path` puede seleccionar un evento, un array de eventos o varios de cualquiera de los dos; los arrays se aplanan. El destinatario se pasa a minúsculas. El ID de ReputeCast devuelto tiene que ser un ID de mensaje de ReputeCast (un UUID) para que coincida. Las horas son segundos o milisegundos Unix, RFC 3339 o `YYYY-MM-DD hh:mm:ss`; si no hay ninguna, se usa la hora a la que llegó el evento.

### Tipos de evento

Con `status`, el valor del tipo (en mayúsculas o minúsculas) se convierte en un [evento normalizado](/es/providers/events-and-sync/):

| Valor del proveedor                                                   | Evento                            |
| --------------------------------------------------------------------- | --------------------------------- |
| `delivered`, `delivery`                                               | `delivered`                       |
| `deferred`, `delayed`, `delivery_delayed`                             | `deferred`                        |
| `bounced`, `bounce`, `failed`                                         | lo decide su código (ver abajo)   |
| `hard_bounce`, `hard_bounced`, `hardbounce`, `permanent_failure`      | `hard_bounce`                     |
| `soft_bounce`, `soft_bounced`, `softbounce`, `temporary_failure`      | `soft_bounce`                     |
| `complained`, `complaint`, `spam`, `spam_report`, `spamreport`        | `complaint`                       |
| `rejected`, `dropped`, `blocked`                                      | `rejected`                        |
| `opened`, `open`                                                      | `open`                            |
| `clicked`, `click`                                                    | `click`                           |
| `unsubscribed`, `unsubscribe`                                         | `unsubscribe`                     |

Cualquier otro valor se ignora. Con `jsonpath`, `webhook.types` convierte los tipos del proveedor (en mayúsculas o minúsculas) en `delivered`, `deferred`, `hard_bounce`, `soft_bounce`, `bounce`, `complaint`, `rejected`, `open`, `click`, `unsubscribe` o `ignore`. Un tipo que no incluyas recurre a la tabla anterior y, si no está en ella, se ignora.

### Rebotes

ReputeCast solo suprime una dirección con pruebas, porque los [rebotes permanentes](/es/reference/glossary/#hard-bounce) y las quejas van a la [lista de supresión](/es/audience/suppressions/) compartida:

- Un rebote genérico (`bounced` o `bounce`) es permanente salvo que su código diga lo contrario. Una respuesta SMTP decide por su clase: 5xx es permanente y 4xx es temporal. Un código propio del proveedor (`invalid_recipient`, `mailbox_full`) solo es permanente cuando nombra un buzón o un dominio desconocido o dice "hard" o "permanent"; cualquier otro código es temporal. Sin código, es permanente.
- Un `hard_bounce` con una respuesta SMTP 4xx pasa a ser temporal.
- Un rebote permanente causado por el remitente (clasificado como bloqueo por spam, por reputación o por política) pasa a ser temporal, sea cual sea su código.

Los rebotes, los aplazamientos y los rechazos reciben una [clase de rebote](/es/reference/glossary/#bounce-class) según su código y su diagnóstico.

## Ejemplo completo

Este manifest asigna un proveedor ficticio, Example ESP. Envía un mensaje por cada `POST`, lee el ID del mensaje de la respuesta, comprueba las credenciales con un endpoint de la cuenta, pide un ID de cuenta al conectar un proveedor y lee webhooks firmados con HMAC con una asignación de tipos personalizada.

```json title="example-esp.manifest.json"
{
  "name": "Example ESP",
  "version": "1.0.0",
  "maintainer": "you@example.com",
  "kind": "http",
  "source_url": "https://github.com/you/example-esp-mapping",
  "terms": {
    "bulk": "allowed",
    "note": "Opted-in lists only.",
    "url": "https://example-esp.com/aup"
  },
  "pricing": "$0.80 per 1,000",
  "http": {
    "method": "POST",
    "url": "https://api.example-esp.com/v1/{{ settings.account }}/messages",
    "headers": {
      "Authorization": "Bearer {{ secrets.api_key }}"
    },
    "body": "{\"from\": \"{{ sender }}\", \"to\": [{\"email\": \"{{ recipient }}\", \"name\": \"{{ recipient_name }}\"}], \"reply_to\": {{ reply_to | default: sender_email }}, \"subject\": \"{{ subject }}\", \"html\": \"{{ html }}\", \"text\": \"{{ text }}\", \"headers\": {{ headers_json }}, \"metadata\": {\"reputecast_id\": \"{{ message_id }}\", \"stream\": \"{{ stream }}\"}, \"tracking\": {\"opens\": false, \"clicks\": false}}",
    "message_id_path": "$.data.id",
    "error_code_path": "$.error.code",
    "error_message_path": "$.error.message",
    "check": {
      "url": "https://api.example-esp.com/v1/{{ settings.account }}/me"
    },
    "fields": [
      {
        "key": "account",
        "label": "Account ID",
        "required": true,
        "help": "Example ESP › Settings › Account."
      }
    ],
    "webhook_mapping": "jsonpath",
    "webhook": {
      "auth": "hmac",
      "signature_header": "X-Example-Signature",
      "signature_prefix": "sha256=",
      "timestamp_header": "X-Example-Timestamp",
      "events_path": "$.events[*]",
      "type_path": "$.event",
      "recipient_path": "$.recipient",
      "message_id_path": "$.message_id",
      "reputecast_id_path": "$.metadata.reputecast_id",
      "code_path": "$.smtp.code",
      "diagnostic_path": "$.smtp.message",
      "time_path": "$.ts",
      "url_path": "$.link",
      "types": {
        "delivered": "delivered",
        "delayed": "deferred",
        "bounce_permanent": "hard_bounce",
        "bounce_temporary": "soft_bounce",
        "complaint": "complaint",
        "click": "click",
        "sent": "ignore"
      }
    }
  }
}
```

Para el mensaje de ejemplo, el cuerpo se renderiza así:

```json title="Rendered request body"
{
  "from": "\"Acme Newsletter\" <news@news.acme.io>",
  "to": [{ "email": "linh@example.com", "name": "Linh Nguyen" }],
  "reply_to": "news@news.acme.io",
  "subject": "Your October update",
  "html": "<p>Hello \"Linh\" — this is a <b>sample</b>.</p>",
  "text": "Hello \"Linh\" — this is a sample.",
  "headers": {
    "List-Unsubscribe": "<https://news.acme.io/p/acme/unsubscribe/abc>",
    "List-Unsubscribe-Post": "List-Unsubscribe=One-Click",
    "X-ReputeCast-Message": "0199d5a8-2b6e-7c41-9a0e-5b8f1c2d3e40"
  },
  "metadata": { "reputecast_id": "0199d5a8-2b6e-7c41-9a0e-5b8f1c2d3e40", "stream": "broadcast" },
```

## Notas

- El adaptador HTTP genérico envía un mensaje por solicitud, configura los dominios con registros DNS manuales y aplica la [lista de supresión](/es/reference/glossary/#suppression-list) localmente (Solo local); no tiene detección de cuota. Cuando un proveedor necesite lotes, una API de dominios, sincronización de supresiones o varias llamadas por mensaje, escribe un [adaptador de la comunidad](/es/adapters/community/).
- Al guardar, se rechaza una asignación con un problema y se nombra el campo (`body`, `url`, `webhook.type_path`…). El registro de auditoría registra el método, la URL, los nombres de las cabeceras, la asignación del webhook y el modo de autenticación, nunca los valores de las cabeceras.
- Cada adaptador instalado aparece en <UiPath path="nav.providers > providers.overview.addProvider" /> en todos los espacios de trabajo, con sus condiciones, sus precios y sus campos de conexión. Cada proceso vuelve a leer los adaptadores instalados cada 15 segundos.

<Aside type="danger">
  Las plantillas de las cabeceras suelen contener credenciales. Léelas de `secrets.<key>` (se introducen al conectar un proveedor y se guardan selladas) en lugar de escribir una clave en la asignación, que puede leer cualquier persona que administre la instancia.
</Aside>
