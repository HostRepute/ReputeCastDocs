Para desplegar ReputeCast en Easypanel, esta guía crea dos servicios en un proyecto: el servicio Postgres de Easypanel y
un servicio App que ejecuta la imagen Docker de ReputeCast detrás del proxy de Easypanel, con HTTPS. Comprobado con
Easypanel 2.38.0, en octubre de 2026.

## Antes de empezar

- Un servidor con Easypanel (Ubuntu, al menos 2 GB de RAM, puertos 80 y 443 libres) que cumpla los
  [requisitos del sistema](/es/self-hosting/requirements/) de ReputeCast, y una cuenta de administración de Easypanel:
  solo quien administra puede crear proyectos.
- Un nombre DNS como `news.example.com` con un registro `A` que apunte al servidor. El proxy de Easypanel obtiene el
  certificado de Let's Encrypt a través del puerto 80, así que el registro debe resolverse antes de añadir el dominio.

## Desplegar ReputeCast

<Steps>

1. En el panel de Easypanel, selecciona **Create Project**, introduce el **Name** `reputecast` y selecciona **Create**.

2. En el proyecto, selecciona **Service** y después **Postgres**. Introduce el **Service Name** `db`, deja vacíos los
   demás campos y selecciona **Create**. Easypanel da a la base de datos el nombre del proyecto, usa el usuario
   `postgres`, genera la contraseña y ejecuta `postgres:18`.

3. Abre la pestaña **Credentials** del servicio `db` y copia la **Internal Connection URL**, como
   `postgres://postgres:<password>@reputecast_db:5432/reputecast?sslmode=disable`. El host `<project>_<service>` está en
   la red privada de Easypanel; PostgreSQL no se publica a menos que uses **Expose**.

4. Genera la clave secreta que cifra las credenciales de los proveedores y otros datos secretos en la base de datos con
   `openssl rand -base64 32` (o `docker run --rm ghcr.io/hostrepute/reputecast:v1.6.0 secrets generate-key`).

   <Aside type="caution">
     Guarda la clave en tu gestor de contraseñas. Sin ella, ReputeCast no puede descifrar lo que almacenó, ni siquiera
     desde una [copia de seguridad](/es/self-hosting/backups/).
   </Aside>

5. En el proyecto, selecciona **Service** y después **App**. Introduce el **Service Name** `app` y selecciona **Create**.

6. En **Source**, selecciona **Docker Image**, introduce la **Image** `ghcr.io/hostrepute/reputecast:v1.6.0` y
   selecciona **Save**. La imagen es pública: deja vacíos **Username** y **Password**.

7. Abre **Environment**, introduce estas variables con tus valores y selecciona **Save**:

   ```sh title="Environment"
   REPUTECAST_DATABASE__URL=postgres://postgres:<password>@reputecast_db:5432/reputecast?sslmode=disable
   REPUTECAST_PUBLIC_URL=https://news.example.com
   REPUTECAST_ADMIN_EMAIL=you@company.com
   REPUTECAST_SECRETS__KEY=<the key from step 4>
   ```

   Con la clave definida aquí, ReputeCast nunca necesita un archivo de clave. Para las demás opciones, consulta
   [configurar ReputeCast](/es/self-hosting/configuration/).

8. Abre **Domains**. Selecciona **Edit** en el dominio que Easypanel añadió al servicio, o **Add Domain** si no hay
   ninguno. Deja **HTTPS** activado, define **Host** como `news.example.com`, deja los dos campos **Path** en `/` y, en
   **Destination**, define **Protocol** como `HTTP` y **Port** como `8080` (Easypanel rellena `80`). Selecciona **Save**
   o **Create**.

9. Abre **Storage**, selecciona **Add Volume Mount**, introduce el **Name** `data` y el **Mount Path**
   `/var/lib/reputecast`, y selecciona **Create**. Conserva los archivos subidos. Easypanel hace que la carpeta de un
   volumen admita escritura para cualquier usuario, así que el usuario de la aplicación (uid 65532) puede escribir en
   ella.

10. Selecciona **Deploy**: la configuración guardada solo llega al servicio en marcha cuando despliegas. En su primer
    arranque, ReputeCast aplica las migraciones de la base de datos y crea el primer Propietario.

11. Selecciona **Logs** en la barra de herramientas del servicio y busca el aviso, que se muestra una sola vez al crearse
    el primer Propietario:

    ```txt title="Logs"
      ReputeCast is installed.

      Sign in at  https://news.example.com
      Email       you@company.com
      Password    SHLn-zHfR-cf6j-NEm5   (temporary: you'll replace it at first sign-in)
    ```

12. Abre la URL pública e inicia sesión. El [primer inicio de sesión](/es/self-hosting/first-run/) te pide reemplazar la
    contraseña, añadir una llave de acceso o una aplicación de autenticación, guardar los códigos de recuperación,
    confirmar la URL pública y crear el primer espacio de trabajo.

</Steps>

Easypanel no documenta las direcciones desde las que se conecta su proxy, así que `REPUTECAST_HTTP__TRUSTED_PROXIES` se
queda sin definir y ReputeCast ve la dirección del proxy para cada visitante
([proxies de confianza](/es/self-hosting/reverse-proxy/#configurar-la-url-pública-y-los-proxies-de-confianza)).

### Usar un servicio Compose en su lugar

Para ejecutar los dos contenedores desde un solo archivo, selecciona **Service** y después **Compose** (marcado como
Beta), introduce un **Service Name** y selecciona **Create**. Pega esto en **Source** › **docker-compose.yml** ›
**Content** y selecciona **Save**:

```yaml title="docker-compose.yml"
services:
  postgres:
    image: postgres:18-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: reputecast
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: reputecast
    volumes:
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U reputecast -d reputecast"]
      interval: 5s
      timeout: 3s
      retries: 20
  app:
    image: ghcr.io/hostrepute/reputecast:v1.6.0
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      REPUTECAST_DATABASE__URL: postgres://reputecast:${POSTGRES_PASSWORD}@postgres:5432/reputecast?sslmode=disable
      REPUTECAST_PUBLIC_URL: ${REPUTECAST_PUBLIC_URL}
      REPUTECAST_ADMIN_EMAIL: ${REPUTECAST_ADMIN_EMAIL}
      REPUTECAST_SECRETS__KEY: ${REPUTECAST_SECRETS__KEY}
    volumes:
      - appdata:/var/lib/reputecast
volumes:
  pgdata:
  appdata:
```

En **Environment**, define `POSTGRES_PASSWORD` (letras y dígitos: `openssl rand -hex 24`), `REPUTECAST_PUBLIC_URL`,
`REPUTECAST_ADMIN_EMAIL` y `REPUTECAST_SECRETS__KEY`, activa **Create .env file** y selecciona **Save**. Añade el
dominio (**Compose Service** `app`, **Port** `8080`) antes de seleccionar **Deploy**: Easypanel conecta los servicios
Compose a su proxy al desplegar, y solo los que tienen un dominio. Las copias de seguridad de bases de datos de Easypanel
no cubren este PostgreSQL.

## Comprobar que funciona

- `https://news.example.com/healthz` responde `ok`; `/readyz` responde `ready`, o 503 con el motivo, como
  `database unavailable`.
- El servicio App de Easypanel no tiene opción de comprobación de estado: Docker Swarm, que ejecuta el servicio, usa la
  comprobación propia de la imagen (`reputecast healthcheck`, que consulta `/readyz`) y reemplaza un contenedor que
  sigue fallando ([Docker](https://docs.docker.com/engine/swarm/how-swarm-mode-works/services/), comprobado en noviembre
  de 2026). Apunta también un monitor de disponibilidad a `/readyz`
  ([comprobaciones de estado, métricas y registros](/es/self-hosting/monitoring/)).

## Actualizar

1. Haz una copia de seguridad: la pestaña **Backups** del servicio `db` envía copias de la base de datos a un proveedor
   de almacenamiento, y **Storage** › **Volume Backups** replica el volumen `data`
   ([copias de seguridad y restauración](/es/self-hosting/backups/)).
2. En **Source** del servicio `app`, cambia la etiqueta de **Image** por la nueva versión (en un servicio Compose, la
   etiqueta del archivo), selecciona **Save** y después **Deploy**. ReputeCast aplica las migraciones nuevas al arrancar
   ([actualizar ReputeCast](/es/self-hosting/upgrades/)). La actualización a 1.3.0 convierte `delivery_events` en
   particiones mensuales y mantiene el bloqueo de migración mientras se ejecuta
   ([actualizar a 1.3.0](/es/self-hosting/upgrades/#actualizar-a-130)). Swarm reemplaza un contenedor del servicio App
   que no está listo unos 3 minutos después de arrancar, así que, con una tabla muy grande, conviértela antes como se
   describe en esa sección.

No cambies la imagen de `db` a una nueva versión mayor de PostgreSQL: Easypanel advierte que una actualización mayor
requiere una migración, no solo una etiqueta nueva.

## Solución de problemas

- **El dominio muestra una página de error en lugar de ReputeCast**: el dominio sigue apuntando al puerto `80`. En
  **Domains**, selecciona **Edit** y define **Port** como `8080`.
- **La aplicación se reinicia y registra `Error: secret key file /var/lib/reputecast/secret.key: … permission denied`**:
  falta `REPUTECAST_SECRETS__KEY` y en `/var/lib/reputecast` hay un bind mount en el que la aplicación no puede
  escribir. Añade la clave en **Environment** (o usa un volume mount) y selecciona **Deploy**.
- **`/readyz` responde `database unavailable`**: `REPUTECAST_DATABASE__URL` no coincide con el servicio `db`, por
  ejemplo después de que **Edit** en **Credentials** cambiara la contraseña. Vuelve a copiar la
  **Internal Connection URL** y despliega.
- **Necesitas la CLI de ReputeCast, por ejemplo porque los registros no muestran el aviso** (la base de datos ya tenía
  usuarios): la **Console** de Easypanel necesita un shell, y la imagen no tiene ninguno. Ejecuta el comando por SSH en
  el servidor ([recuperar el acceso](/es/self-hosting/account-recovery/)):

  ```sh
  docker exec "$(docker ps -q -f name=reputecast_app)" /usr/local/bin/reputecast user reset-password --email you@company.com
  ```
