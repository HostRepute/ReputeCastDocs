Una prueba de ubicación en la bandeja de entrada envía una copia de un correo a cada
[buzón de prueba](/es/reference/glossary/#seed-mailbox) que tienes, inicia sesión en esos buzones e indica dónde llegó
cada copia: a la bandeja de entrada, a una pestaña como Promotions, a la carpeta de spam o a ninguna parte, contado por
proveedor de buzón. Úsala para comparar correos y proveedores de envío antes de que una campaña llegue a tu lista. Las
pruebas se ejecutan cuando alguien inicia una, o cuando el [envío canario](/es/reference/glossary/#canary) de un envío
incluye los buzones de prueba; nada se ejecuta de forma programada.

## Antes de empezar

- Para añadir, volver a conectar y quitar buzones de prueba necesitas `placement:manage`, un permiso delicado, porque la
  contraseña o el token de un buzón de prueba permiten leer todo el buzón. Para ejecutar una prueba necesitas
  `placement:run`. Solo las personas pueden iniciar pruebas y gestionar buzones de prueba: las claves de API pueden leer
  los resultados de las pruebas, y los agentes de IA no pueden tener ninguno de los dos permisos.
- Usa buzones que existan solo para pruebas. ReputeCast solo busca mensajes que llevan un token de prueba y solo abre la
  bandeja de entrada, la carpeta de spam y las pestañas de Gmail, pero las credenciales dan acceso a todo el buzón.
- El contenido que pruebas necesita un remitente verificado en el flujo que usa
  ([Añadir dominios de envío y remitentes](/es/providers/senders-and-domains/)).
- Para conectar buzones de prueba de Gmail, Google Workspace, Outlook.com o Microsoft 365 con OAuth,
  [quien administra la instancia](/es/reference/glossary/#instance-admin) añade primero un URI de redirección a las
  aplicaciones de inicio de sesión de la instancia (consulta
  [Configurar las aplicaciones de inicio de sesión para buzones de prueba con OAuth](#configurar-las-aplicaciones-de-inicio-de-sesión-para-buzones-de-prueba-con-oauth)).

## Cómo se conecta cada buzón de prueba

<TableScroll label="Cómo se conecta cada buzón de prueba" wrap>

| Proveedor de buzón         | Conectar con                                    | Notas                                                                                                   |
| -------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Gmail                      | Contraseña de aplicación IMAP (recomendado) u OAuth | Las pestañas (Primary, Promotions, Updates, Social, Forums) se leen a partir de las etiquetas de Gmail. |
| Google Workspace           | OAuth o contraseña de aplicación IMAP           | OAuth a través de una aplicación de la misma organización de Workspace evita los límites de Google para las aplicaciones sin verificar. |
| Outlook.com, Microsoft 365 | OAuth                                           | Se lee a través de Microsoft Graph, que distingue Focused de Other. Microsoft rechaza las contraseñas por IMAP. |
| Yahoo, AOL                 | Contraseña de aplicación IMAP                   | Se crea en la configuración de seguridad de la cuenta.                                                  |
| iCloud                     | Contraseña específica de app                    | El Apple ID necesita la autenticación de doble factor.                                                  |
| GMX, Web.de                | La contraseña de la cuenta, con IMAP activado   | Activa primero IMAP en la configuración del buzón.                                                      |

</TableScroll>

ReputeCast rellena el servidor y el puerto IMAP de cada proveedor. Las contraseñas y los tokens se sellan con la clave
secreta de la instancia y son de solo escritura: la API nunca los devuelve.

Microsoft desactivó la autenticación básica, incluidas las contraseñas de aplicación, para IMAP en Exchange Online
([Microsoft Learn, "Deprecation of Basic authentication in Exchange Online"](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-basic-authentication-exchange-online),
comprobado en octubre de 2026), y el cuadro de diálogo para añadir de ReputeCast rechaza una contraseña de aplicación
para los buzones de prueba de Outlook.com y Microsoft 365.

## Configurar las aplicaciones de inicio de sesión para buzones de prueba con OAuth

Los buzones de prueba con OAuth reutilizan las aplicaciones de inicio de sesión de Google y Microsoft de la instancia,
en <UiPath path="shell.userMenuInstanceAdmin > admin.authentication" />; no hay que registrar ninguna aplicación aparte.
Cada aplicación necesita un segundo URI de redirección junto al del inicio de sesión:

```text title="Redirect URI for seed mailboxes"
<public URL>/api/v1/placement/oauth/callback
```

<Steps>

1. En la aplicación de Google, añade el URI de redirección anterior y el ámbito `https://mail.google.com/` a su pantalla
   de consentimiento. El acceso IMAP con OAuth necesita ese ámbito.

2. En la aplicación de Microsoft, añade el URI de redirección y el permiso delegado de Microsoft Graph `Mail.ReadWrite`
   (con `offline_access`). Admite las cuentas personales de Microsoft además de las cuentas profesionales, o los buzones
   de prueba de Outlook.com no podrán iniciar sesión.

3. Configura las propias aplicaciones como se describe en
   [Inicio de sesión con Google, Microsoft y GitHub](/es/self-hosting/social-sign-in/).

</Steps>

<Aside type="note" title="Los límites de Google para las aplicaciones sin verificar">
`https://mail.google.com/` es un ámbito restringido. Mientras la pantalla de consentimiento de una aplicación de Google
tenga el tipo de usuario externo y el estado de publicación "Testing", Google emite tokens de actualización que caducan
a los 7 días ([Google, "Using OAuth 2.0 to access Google APIs"](https://developers.google.com/identity/protocols/oauth2),
comprobado en octubre de 2026), así que un buzón de prueba así aparece con la sesión cerrada cada semana. Conecta los
buzones de prueba de gmail.com con una contraseña de aplicación. Las aplicaciones que solo se usan dentro de una
organización de Google Workspace (tipo de usuario interno) no necesitan verificación
([Ayuda de Google Cloud, "Unverified apps"](https://support.google.com/cloud/answer/7454865), comprobado en octubre de
2026), así que un buzón de prueba de Google Workspace de esa organización puede usar OAuth sin estos límites.
</Aside>

## Añadir buzones de prueba

<Steps>

1. Abre <UiPath path="nav.deliverability > placement.placementTests" /> y selecciona
   <UiPath path="placement.pillSeeds" />.

2. Selecciona <UiPath path="placement.addSeed" /> y elige el proveedor de buzón.

3. En <UiPath path="placement.connectWith" />, elige <UiPath path="placement.viaImap" /> o
   <UiPath path="placement.viaOAuth" /> cuando el proveedor ofrezca ambos.

   - **Contraseña de aplicación:** introduce la dirección y la contraseña y selecciona
     <UiPath path="placement.checkAndAdd" />. ReputeCast inicia sesión y enumera las carpetas que ha encontrado, como la
     bandeja de entrada, las pestañas y la carpeta de spam.
   - **OAuth:** inicia sesión en el buzón de prueba en Google o Microsoft y permite que ReputeCast lea y modifique su
     correo. Termina en un plazo de 10 minutos; después, el navegador vuelve a ReputeCast y se añade el buzón de prueba.

4. Añade un buzón de prueba en cada proveedor de buzón que usen tus lectores. Una prueba puede enviar a hasta 100
   buzones de prueba.

</Steps>

## Ejecutar una prueba de ubicación

<Steps>

1. Selecciona <UiPath path="placement.runTest" />. También puedes iniciar una prueba desde
   [Revisar y enviar](#probar-desde-revisar-y-enviar) de la campaña, desde el menú <UiPath path="placement.sendTest" />
   del editor o desde el planificador de calentamiento.

2. Elige qué probar: una campaña, una plantilla de campaña, la próxima edición de un boletín periódico o una plantilla
   transaccional. Elige la versión cuando el correo tenga variantes A/B, versiones de idioma o contenido condicional.

3. Elige cómo salen las copias:

   - Con <UiPath path="placement.throughRouteTitle" />, cada buzón de prueba recibe el proveedor de envío que la ruta
     elegiría para él.
   - Con <UiPath path="placement.throughOneTitle" />, pruebas un solo proveedor de envío por separado.
   - Con <UiPath path="placement.throughCompareTitle" />, cada buzón de prueba recibe una copia por proveedor, con 2
     minutos de diferencia, alternando qué proveedor va primero. Puedes comparar hasta 6 proveedores.

4. Elige el remitente y los buzones de prueba (todos los conectados o algunos). El cuadro de diálogo muestra el número
   de copias, su costo y, para un proveedor en calentamiento, cuánto del límite de calentamiento de hoy consumen.

5. Selecciona <UiPath path="placement.startTest" />.

</Steps>

Las copias son envíos reales con las mismas cabeceras y el mismo seguimiento de enlaces que la campaña. Sus aperturas y
clics nunca se cuentan, nunca aparecen en los informes ni en las cronologías de los contactos, y los rebotes o las
quejas de un buzón de prueba nunca lo suprimen. Una prueba nunca cambia un envío ni el veredicto de su
[revisión previa](/es/reference/glossary/#send-readiness).

## Probar desde Revisar y enviar

La página [Revisar y enviar](/es/reference/glossary/#review-and-send) de una campaña tiene una tarjeta
<UiPath path="placement.entryTitle" /> junto a las comprobaciones. Es opcional y nunca cambia el veredicto de la
[revisión previa](/es/campaigns/send-readiness/).

- La tarjeta indica a cuántos buzones de prueba llega una prueba y en qué proveedores de buzón, cuántos requieren
  atención (su inicio de sesión falló o caducó, así que las pruebas los omiten) y que una prueba tarda unos 3 minutos.
- <UiPath path="placement.runTest" /> abre el cuadro de diálogo de prueba configurado para esta campaña tal como está
  programada: a través de la ruta, o comparando los proveedores de envío cuando la ruta usa más de uno. Para ejecutar
  una prueba necesitas `placement:run`; sin ese permiso, el botón indica quién puede hacerlo.
- El último resultado de la campaña muestra una línea por proveedor de buzón, que cuenta la bandeja de entrada, la
  pestaña propia del proveedor para el correo masivo (Promotions en Gmail, Other en Outlook.com) y el spam, por ejemplo
  "Gmail · Bandeja de entrada 2 · Promotions 2 · Spam 0", con una barra. Cuando la ruta comparó proveedores, sigue una
  línea por proveedor de envío, como "A través de SES: Bandeja de entrada 8 · Pestaña 2".
  <UiPath path="placement.entryViewResults" /> abre el resultado completo.

## Ubicación en los buzones de prueba durante un envío canario

Cuando un envío empieza con un envío canario y este incluye buzones de prueba, ReputeCast inicia una prueba de
ubicación de la campaña a través de su ruta hacia todos los buzones de prueba conectados, igual que una iniciada desde
Revisar y enviar. El control de ubicación en los buzones de prueba del envío canario en el
[monitor en tiempo real](/es/campaigns/live-monitor/) la lee por proveedor de buzón, así que las copias que llegan a
spam pueden retener el envío antes de que lo reciba todo el mundo. La prueba aparece en la lista de pruebas como
cualquier otra.

  escribió en las cabeceras de la copia. Abre una copia para leer sus cabeceras y los eventos del proveedor de envío.
- Las copias de los buzones de prueba se eliminan por defecto 24 horas después de cada prueba. Cámbialo en

  necesita `placement:manage`), o elimina las copias de una prueba con <UiPath path="placement.deleteCopiesNow" />.

## Comprobar que funciona

- El estado de la prueba es <UiPath path="placement.statusFinished" /> y cada buzón de prueba tiene un resultado.
- Cada buzón de prueba en <UiPath path="placement.pillSeeds" /> muestra <UiPath path="placement.seedConnected" /> y
  cuándo se usó por última vez.

## Solución de problemas

- **Un buzón de prueba muestra <UiPath path="placement.seedFailed" />.** El proveedor de buzón rechazó la contraseña de
  aplicación, a menudo porque se revocó o cambió la contraseña de la cuenta. Las pruebas omiten el buzón de prueba hasta
  que seleccionas <UiPath path="placement.reconnect" /> y pegas una contraseña de aplicación nueva.
- **Un buzón de prueba muestra <UiPath path="placement.seedExpired" />.** El proveedor de buzón terminó el acceso OAuth
  de ReputeCast. Un buzón de prueba de gmail.com conectado a través de una aplicación en estado Testing caduca cada 7
  días; vuelve a conectarlo con una contraseña de aplicación.
- **OAuth indica que el inicio de sesión de Google o Microsoft no está configurado.** La aplicación de inicio de sesión
  de la instancia aún no tiene ID de cliente ni secreto. Quien administra la instancia los añade en
  <UiPath path="shell.userMenuInstanceAdmin > admin.authentication" />; hasta entonces, conecta los buzones de prueba de
  Gmail y Google Workspace con una contraseña de aplicación.
- **Outlook.com rechaza la contraseña de aplicación.** Es lo esperado: conecta los buzones de prueba de Outlook.com y
  Microsoft 365 con OAuth.
- **La prueba no puede empezar.** El cuadro de diálogo indica por qué: no hay ningún buzón de prueba conectado, no hay
  un remitente verificado para el flujo en un proveedor elegido, un proveedor está caído o las copias superarían un
  límite de calentamiento.
- **Las copias llegan a spam en un proveedor de buzón.** Revisa los resultados de autenticación en las cabeceras de la
  copia y, después, [SPF, DKIM y DMARC](/es/deliverability/spf-dkim-dmarc/) y las
  [inclusiones en listas de bloqueo](/es/deliverability/blocklists/) del dominio de envío.
