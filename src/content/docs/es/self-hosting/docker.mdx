Esta guía instala ReputeCast con Docker Compose, PostgreSQL y la aplicación, en un servidor, y lo prepara para un
proxy inverso. Para una prueba de diez minutos en tu propio equipo, sigue el
[inicio rápido](/es/getting-started/quickstart/).

## Antes de empezar

- Un servidor que cumpla los [requisitos del sistema](/es/self-hosting/requirements/), con Docker Engine y el plugin
  de Docker Compose (`docker compose`).
- Un nombre DNS para ReputeCast, como `news.example.com`, que apunte al servidor.
- Un proxy inverso que termine el TLS, o un plan para tenerlo: [proxy inverso y TLS](/es/self-hosting/reverse-proxy/)
  incluye configuraciones para Caddy, nginx y Traefik.

## Instalar ReputeCast

<Steps>

1. Crea una carpeta para ReputeCast y descarga en ella el archivo Compose:

   ```sh
   mkdir -p /opt/reputecast && cd /opt/reputecast
   curl -fsSL https://raw.githubusercontent.com/hostrepute/reputecast/main/deploy/docker-compose.yml -o docker-compose.yml
   ```

2. Crea junto a él un archivo `.env` con, como mínimo, tu URL pública, el correo del primer Propietario y una
   contraseña para la base de datos (consulta
   [configuración de producción en .env](#configuración-de-producción-en-env)).

3. Arranca el stack:

   ```sh
   docker compose up -d
   ```

   Compose arranca PostgreSQL, espera a que esté en buen estado y después arranca la aplicación. En su primer arranque,
   la aplicación crea su clave secreta, aplica las migraciones de la base de datos y crea el primer Propietario.

4. Lee en los logs la contraseña temporal del primer Propietario:

   ```sh
   docker compose logs app | grep -A4 "ReputeCast is installed"
   ```

   ```txt title="Salida"
   app-1  |   ReputeCast is installed.
   app-1  |
   app-1  |   Sign in at  https://news.example.com
   app-1  |   Email       you@company.com
   app-1  |   Password    SHLn-zHfR-cf6j-NEm5   (temporary: you'll replace it at first sign-in)
   ```

   El banner se muestra una sola vez, cuando se crea el primer Propietario.

5. Pon tu [proxy inverso](/es/self-hosting/reverse-proxy/) delante del puerto 8080, abre la URL pública e inicia
   sesión. El [primer inicio de sesión](/es/self-hosting/first-run/) te pide que sustituyas la contraseña temporal,
   añadas una llave de acceso o una aplicación de autenticación, guardes los códigos de recuperación, confirmes los
   datos básicos de la instancia y crees el primer espacio de trabajo.

</Steps>

## El archivo Compose, línea por línea

Este es `deploy/docker-compose.yml` tal como se publica:

```yaml title="docker-compose.yml"
# Production-style stack: `docker compose -f deploy/docker-compose.yml up -d`
# Set REPUTECAST_PUBLIC_URL and REPUTECAST_ADMIN_EMAIL (in .env next to this
# file or your shell) before the first start; the first Owner's temporary
# password is printed in the logs: docker compose logs app | grep Password
name: reputecast

services:
  postgres:
    image: postgres:18-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: reputecast
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-reputecast}
      POSTGRES_DB: reputecast
    volumes:
      - pgdata:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U reputecast -d reputecast"]
      interval: 5s
      timeout: 3s
      retries: 20

  app:
    # REPUTECAST_IMAGE=reputecast with REPUTECAST_VERSION=local runs an image
    # built from a checkout (make docker VERSION=local).
    image: ${REPUTECAST_IMAGE:-ghcr.io/hostrepute/reputecast}:${REPUTECAST_VERSION:-latest}
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "${REPUTECAST_PORT:-8080}:8080"
    environment:
      REPUTECAST_DATABASE__URL: postgres://reputecast:${POSTGRES_PASSWORD:-reputecast}@postgres:5432/reputecast?sslmode=disable
      REPUTECAST_PUBLIC_URL: ${REPUTECAST_PUBLIC_URL:-http://localhost:8080}
      REPUTECAST_ADMIN_EMAIL: ${REPUTECAST_ADMIN_EMAIL:-admin@example.com}
      REPUTECAST_AUTO_MIGRATE: "true"
      REPUTECAST_AUTO_INSTALL: "true"
      # Set when ReputeCast runs behind a reverse proxy (CIDRs or IPs):
      # REPUTECAST_HTTP__TRUSTED_PROXIES: 172.16.0.0/12
      # Prometheus metrics listen on port 9464 inside the container (not
      # published). To scrape the main port instead, set a bearer token:
      # REPUTECAST_METRICS__TOKEN: change-me-at-least-16-chars
    volumes:
      - appdata:/var/lib/reputecast
    # Ready once the database answers and its schema has every migration
    # this release needs (/readyz); a worker-only container answers on the
    # metrics port, which `reputecast healthcheck` tries next.
    healthcheck:
      test: ["CMD", "/usr/local/bin/reputecast", "healthcheck"]
      interval: 15s
      timeout: 5s
      retries: 4
      start_period: 2m

  # To run background workers in their own container, add --role=web,ingest
  # to the app (command: ["serve", "--role=web,ingest"]) and uncomment:
  # worker:
  #   image: ${REPUTECAST_IMAGE:-ghcr.io/hostrepute/reputecast}:${REPUTECAST_VERSION:-latest}
  #   restart: unless-stopped
  #   command: ["worker"]
  #   depends_on:
  #     app:
  #       condition: service_healthy
  #   environment:
  #     REPUTECAST_DATABASE__URL: postgres://reputecast:${POSTGRES_PASSWORD:-reputecast}@postgres:5432/reputecast?sslmode=disable
  #     REPUTECAST_PUBLIC_URL: ${REPUTECAST_PUBLIC_URL:-http://localhost:8080}
  #   volumes:
  #     - appdata:/var/lib/reputecast
  #   healthcheck:
  #     test: ["CMD", "/usr/local/bin/reputecast", "healthcheck"]
  #     interval: 15s
  #     timeout: 5s
  #     retries: 4

volumes:
  pgdata:
  appdata:
```

- **Comentario de cabecera.** `grep Password` muestra solo la línea de la contraseña; `grep -A4 "ReputeCast is installed"`
  muestra el banner entero con la dirección de inicio de sesión y el correo.
- **`name: reputecast`** fija el nombre del proyecto, se llame como se llame la carpeta. Docker llama a los volúmenes
  `reputecast_pgdata` y `reputecast_appdata`, y a la red `reputecast_default`.
- **`postgres`** ejecuta PostgreSQL 18 con una base de datos y un usuario que se llaman los dos `reputecast`.
  `restart: unless-stopped` lo vuelve a arrancar después de un reinicio. La contraseña viene de `POSTGRES_PASSWORD`
  (por defecto `reputecast`: cámbiala).
- **`pgdata:/var/lib/postgresql`** es donde las imágenes de PostgreSQL 18 guardan sus datos (las imágenes anteriores
  usaban `/var/lib/postgresql/data`).
- **`healthcheck`** ejecuta `pg_isready` cada 5 segundos, hasta 20 veces. `depends_on … condition: service_healthy`
  hace que la aplicación lo espere.
- **`image`** es `ghcr.io/hostrepute/reputecast:latest`, salvo que definas `REPUTECAST_IMAGE` o
  `REPUTECAST_VERSION`. Las etiquetas de la imagen son las etiquetas de las versiones (con su `v` inicial) y `latest`.
- **`ports`** publica el puerto 8080 de la aplicación en el puerto del host indicado en `REPUTECAST_PORT` (por defecto
  `8080`).
- **`REPUTECAST_DATABASE__URL`** apunta la aplicación al servicio `postgres` con la misma contraseña.
- **`REPUTECAST_PUBLIC_URL`** llega tal cual desde `.env` y define `http.public_url`. ReputeCast la usa para los
  webhooks de los proveedores, las redirecciones de SSO, las llaves de acceso, las páginas públicas y todos los
  enlaces de los correos. Con el valor predeterminado `http://localhost:8080`, nada de esto funciona desde fuera del
  servidor. Los archivos Compose anteriores a la 1.2.0 la pasan como `REPUTECAST_HTTP__PUBLIC_URL`, su nombre anterior,
  que sigue funcionando cuando `REPUTECAST_PUBLIC_URL` no está definida.
- **`REPUTECAST_ADMIN_EMAIL`** es el correo del primer Propietario, y solo se usa mientras la base de datos no tiene
  usuarios.
- **`REPUTECAST_AUTO_MIGRATE`** y **`REPUTECAST_AUTO_INSTALL`** activan las migraciones al arrancar y la creación del
  primer Propietario. El comando de la imagen, `serve --auto-migrate --auto-install`, ya pasa las dos opciones.
- **`REPUTECAST_HTTP__TRUSTED_PROXIES`** está comentada; consulta [proxies de confianza](#proxies-de-confianza).
- **`REPUTECAST_METRICS__TOKEN`** está comentada. Las métricas de Prometheus escuchan en el puerto 9464 dentro del
  contenedor, que el archivo no publica; consulta
  [comprobaciones de estado, métricas y logs](/es/self-hosting/monitoring/).
- **`appdata:/var/lib/reputecast`** guarda la clave secreta (`secret.key`) y los archivos subidos (`files/`). La imagen
  apunta ahí `REPUTECAST_SECRETS__KEY_FILE`, escribe los logs en JSON (`REPUTECAST_LOG__FORMAT=json`) y se ejecuta como
  el usuario `nonroot` (uid 65532).
- **El `healthcheck` de la aplicación** ejecuta `reputecast healthcheck` cada 15 segundos, la misma comprobación que
  declara la imagen. El contenedor pasa a `healthy` en cuanto `/readyz` responde: PostgreSQL es accesible y todas las
  migraciones están aplicadas. No cuenta los fallos de los primeros 2 minutos, para que las migraciones del arranque
  tengan tiempo; después, 4 fallos seguidos lo marcan como `unhealthy`.
- **`worker`** está comentado. Quita el comentario, con `command: ["serve", "--role=web,ingest"]` en `app`, para
  ejecutar las tareas en segundo plano en su propio contenedor
  ([escalar con los roles web, ingest y worker](/es/self-hosting/scaling/)).

## Configuración de producción en .env

Compose lee `.env` de la carpeta del proyecto para rellenar los marcadores `${…}` del archivo:

```sh title=".env"
# The address people and sending providers use, without a trailing slash.
REPUTECAST_PUBLIC_URL=https://news.example.com
# The first Owner (used only on the first start).
REPUTECAST_ADMIN_EMAIL=you@company.com
# Database password: letters and digits only, because it is part of a URL.
POSTGRES_PASSWORD=replace-with-the-output-of-openssl-rand-hex-24
# Listen on the loopback interface only, for a reverse proxy on this server.
REPUTECAST_PORT=127.0.0.1:8080
# Pin the release you run instead of latest.
REPUTECAST_VERSION=v1.5.0
```

- Genera la contraseña de la base de datos con `openssl rand -hex 24`. Defínela antes del primer arranque: la imagen
  de PostgreSQL solo aplica `POSTGRES_PASSWORD` cuando crea un volumen de datos vacío
  ([documentación de la imagen postgres](https://hub.docker.com/_/postgres), comprobado en octubre de 2026).
- `REPUTECAST_PORT=127.0.0.1:8080` publica `127.0.0.1:8080:8080`, así que solo un proxy en el mismo servidor llega a
  la aplicación. No la definas cuando el proxy se ejecuta como otro servicio de este proyecto de Compose.
- `.env` solo rellena los marcadores. Una variable que el archivo Compose no menciona, como `REPUTECAST_LOG__LEVEL`,
  nunca llega al contenedor desde `.env`. Añádelas a `docker-compose.override.yml`.

### Otra configuración en docker-compose.override.yml

Compose fusiona automáticamente un `docker-compose.override.yml` de la misma carpeta con `docker-compose.yml`
([reglas de fusión](https://docs.docker.com/compose/how-tos/multiple-compose-files/merge/), comprobado en octubre de
2026). Si guardas ahí tus cambios, puedes sustituir `docker-compose.yml` por una copia más reciente sin tener que
volver a editarlo:

```yaml title="docker-compose.override.yml"
services:
  app:
    environment:
      REPUTECAST_HTTP__TRUSTED_PROXIES: 172.18.0.0/16
      REPUTECAST_DNS__SERVERS: 10.0.0.53:53
```

Cada opción de configuración tiene una variable de entorno: consulta la
[referencia de configuración](/es/reference/configuration/) y [configurar ReputeCast](/es/self-hosting/configuration/).

## Proxies de confianza

ReputeCast usa la dirección IP del cliente para los límites de frecuencia del inicio de sesión, los bloqueos de
acceso, las sesiones y el registro de auditoría. Detrás de un proxy, todas las solicitudes llegan desde el proxy, así
que ReputeCast lee `X-Forwarded-For` (o `X-Real-IP`), pero solo desde direcciones de `http.trusted_proxies`. Si viene
de cualquier otra, la cabecera se ignora, así que no se puede falsificar. Hasta que el proxy figura en la lista, las
aperturas y los clics también parecen venir de una sola dirección, y el filtro de bots no puede distinguir a los
lectores; ReputeCast detecta una dirección privada que sigue reenviando solicitudes y envía a quienes administran la
instancia una notificación que la identifica.

<Steps>

1. Busca la subred de la red del proyecto:

   ```sh
   docker network inspect reputecast_default --format '{{(index .IPAM.Config 0).Subnet}}'
   ```

   Un proxy que se ejecuta como contenedor en esta red se conecta desde una dirección de ella. Un proxy en el propio
   servidor llega al puerto publicado a través de la puerta de enlace de Docker, que está en la misma subred.

2. Defínela como `REPUTECAST_HTTP__TRUSTED_PROXIES` en `docker-compose.override.yml` (para varios valores, sepáralos
   con comas, como `172.18.0.0/16,10.0.0.5`).

3. Aplícalo con `docker compose up -d`.

</Steps>

## Comprobar que funciona

- `docker compose ps` muestra `postgres` y `app` como `healthy`.
- `curl http://127.0.0.1:8080/readyz` responde `ready` (si no, 503 con el motivo, como `database unavailable`).
- `docker compose exec app /usr/local/bin/reputecast migrate status` no muestra ninguna migración como `pending`.
- La URL pública abre la página de inicio de sesión de ReputeCast a través de tu proxy.

## Solución de problemas

- **El banner dice `Sign in at http://localhost:8080`**: `REPUTECAST_PUBLIC_URL` no estaba definida. Añádela a `.env`
  y ejecuta `docker compose up -d`; también puedes corregir la URL pública durante el primer inicio de sesión, en el
  paso <UiPath path="setup.instanceBasics" />.
- **`grep` no encuentra ningún banner**: la base de datos ya tenía usuarios, por ejemplo porque el volumen
  `reputecast_pgdata` es de una instalación anterior. Restablece la contraseña del Propietario desde el servidor:
  `docker compose exec app /usr/local/bin/reputecast user reset-password --email you@company.com`
  ([recuperar el acceso](/es/self-hosting/account-recovery/)).
- **El contenedor de la aplicación se detiene con `Error: owner email: missing (pass --email or set REPUTECAST_ADMIN_EMAIL)`**:
  la base de datos está vacía y no llegó al contenedor ningún correo de Propietario. Define `REPUTECAST_ADMIN_EMAIL` y
  vuelve a arrancarlo.
- **La aplicación no puede conectarse a PostgreSQL después de cambiar `POSTGRES_PASSWORD`**: el volumen todavía tiene
  la contraseña antigua. Vuelve a poner el valor antiguo, o cambia la contraseña del usuario en PostgreSQL para que
  coincida (`docker compose exec postgres psql -U reputecast -c "ALTER USER reputecast PASSWORD '…'"`).
- **`Bind for 0.0.0.0:8080 failed: port is already allocated`**: otro servicio usa el puerto 8080. Define
  `REPUTECAST_PORT` con un puerto libre y apunta el proxy a él.
- **Todos los visitantes aparecen con la dirección del proxy en las sesiones y en el registro de auditoría**:
  configura los [proxies de confianza](#proxies-de-confianza).

<Aside type="caution">
  `docker compose down -v` elimina los volúmenes `reputecast_pgdata` y `reputecast_appdata`: la base de datos y la
  clave secreta. [Haz antes una copia de seguridad](/es/self-hosting/backups/).
</Aside>
