The HostRepute integration connects a workspace to [HostRepute](/reference/glossary/#hostrepute), the email-reputation
service built by the team behind ReputeCast. Once connected, HostRepute checks your sending domains and IPs on 84
blocklists every hour and brings Google Postmaster Tools, Microsoft SNDS and DMARC report data into Deliverability and
[Send Readiness](/reference/glossary/#send-readiness). Connecting is optional: every ReputeCast feature works without
it, with the [built-in checks](/deliverability/blocklists/) instead.

## What is shared and what you get

HostRepute is a separate service with its own account and plans. ReputeCast sends it only what it needs to monitor:

| Sent to HostRepute                                                                    | Never sent                                 |
| ------------------------------------------------------------------------------------- | ------------------------------------------ |
| Sending domains and their organization domains                                        | Contacts or any personal data              |
| Dedicated sending IPs                                                                 | Email content, subjects or templates       |
| Self-hosted server hostnames, only when someone selects <UiPath path="hostrepute.addToMonitoring" /> | Campaign reports, events or statistics |

In return, the workspace receives:

- Blocklist status from 84 sources, checked hourly instead of 8 sources once a day, with listing history and delisting
  requests you file from ReputeCast.
- Google Postmaster Tools data for your sending domains (domain and IP reputation, spam rate, authentication, flagged
  campaigns) and Microsoft SNDS data for your dedicated IPs (filter result, complaint rate, spam trap hits).
- [DMARC aggregate report](/reference/glossary/#dmarc-aggregate-report) summaries
  (see [Read DMARC aggregate reports](/deliverability/dmarc-reports/)).
- With Postmaster Tools data for the sending domain, the bulk-sender check of Send Readiness shows Google's own
  compliance status, and the [complaint watch](/campaigns/live-monitor/) after a send can read Gmail's daily spam rate.
- Alerts for new listings, delistings and reputation drops, delivered as ReputeCast notifications to members who can
  see Deliverability.

## Before you begin

- You need `integrations:hostrepute`. Owners and Admins have it.
- You need a HostRepute account and team. Your HostRepute plan sets how many assets the team can monitor; that is a
  HostRepute limit, and nothing in ReputeCast depends on it.
- The instance's public URL must open in your browser, because HostRepute sends you back to
  `<public URL>/api/v1/integrations/hostrepute/callback` after you approve. Operators set it with `http.public_url`
  ([Configuration reference](/reference/configuration/)).

## Connect with HostRepute

<Steps>

1. Open <UiPath path="nav.settings > settings.integrations > integrations.hostrepute" />, or select
   <UiPath path="deliverability.connectHostRepute" /> on <UiPath path="nav.deliverability" />.

2. Read the lists of what is shared and what is received, then select
   <UiPath path="hostrepute.connectWith" />.

3. Sign in to HostRepute and approve the request for the scopes `monitor:read`, `alerts:read` and `assets:write`. The
   request expires after 15 minutes.

4. Back in ReputeCast, the page names the HostRepute team you connected and starts the first sync, which takes about a
   minute. Assets HostRepute doesn't monitor yet are listed as suggestions; select
   <UiPath path="hostrepute.addToMonitoring" /> for each one you want checked.

</Steps>

Only the person who started the connection can finish it. The sign-in uses OAuth 2 with PKCE and a single-use state,
and the tokens are stored encrypted with the instance's secret key; the API never returns them.

## Connect with an API key instead

Use an API key when the browser can't reach HostRepute and come back, for example on an instance without a public URL.

<Steps>

1. In HostRepute, create an API key with the scopes `monitor:read`, `alerts:read` and `assets:write`.

2. In ReputeCast, open the connect page as above and select <UiPath path="hostrepute.useApiKey" />.

3. Paste the key (it starts with `hr_live_`) and select <UiPath path="hostrepute.keyConnect" />. ReputeCast checks the
   key with HostRepute before it saves it.

</Steps>

The key is write-only: you can replace it but never read it back. ReputeCast can't revoke an API key. When you
disconnect, ReputeCast forgets it, and you revoke it in HostRepute.

## Check that it worked

- <UiPath path="nav.settings > settings.integrations > integrations.hostrepute" /> shows the connected team, the granted
  scopes, the assets HostRepute monitors and when it last synced.
- The header of <UiPath path="nav.deliverability" /> says HostRepute is connected with hourly checks, and the blocklist
  table lists 84 sources.
- To fetch new data at once, select <UiPath path="hostrepute.syncNow" />. Otherwise ReputeCast syncs every hour.

## When HostRepute can't be reached

- **HostRepute is unreachable.** ReputeCast keeps showing the last data, marked stale, retries every hour and runs the
  built-in blocklist check as a fallback. Send Readiness never calls HostRepute during a run: it reads the results the
  hourly sync and the built-in checks stored. When HostRepute data can't be refreshed and no newer built-in result
  exists, it marks the domain and IP blocklist checks <UiPath path="review.statusUnknown" /> instead of passing them.
  Select <UiPath path="review.retryBlocklist" />, or <UiPath path="review.continueProvider" />, which records the
  skipped checks in the campaign's audit trail and looks them up again at the send-time recheck ([when checks can't
  run](/campaigns/send-readiness/)).
- **The token was revoked or expired.** The connection shows that it needs reconnecting, members with
  `integrations:hostrepute` get a notification, and the built-in checks take over. Send Readiness shows the reputation
  check as <UiPath path="review.statusUnknown" />, never as a <UiPath path="review.statusBlock" />. Select
  <UiPath path="hostrepute.reconnectWith" /> to restore it.

<Aside type="note" title="What stops when you disconnect">
<UiPath path="hostrepute.disconnect" /> revokes the OAuth tokens and deletes the data that came from HostRepute:
the 84-source blocklist results, the Postmaster Tools, SNDS and DMARC panels and HostRepute alerts. The built-in checks
start at once, and every other feature keeps working, including provider health, routing,
[guarded sending](/reference/glossary/#guarded-sending) and reports. Your HostRepute team keeps monitoring on
hostrepute.com; nothing is deleted there.
</Aside>

## Troubleshooting

- **"You declined the request on HostRepute."** Nothing was connected, or an existing connection is unchanged. Start
  again and approve.
- **"This handoff was started by someone else."** The OAuth return must come back to the person who started it. Sign in
  as yourself and start again.
- **HostRepute didn't accept the approval.** The request expired after 15 minutes or was already used. Start again.
- **The monitoring limit is reached.** Your HostRepute team's plan is full. Raise the limit in HostRepute, or swap an
  asset: ReputeCast suggests one it could stop monitoring, such as an organization domain, to make room for one that
  sends mail.
- **The API key is refused.** Paste the whole key without spaces; it starts with `hr_live_` and needs all three scopes.
- **Data shows as stale.** HostRepute couldn't be reached at the last sync. The error and the time are shown on the
  integration page; ReputeCast retries every hour.
