When your sending provider isn't built into ReputeCast but has an HTTP API for sending and JSON webhooks for events,
the [generic HTTP adapter](/reference/glossary/#generic-http-adapter) is a custom email API integration you set up in
a form, without writing code. You map the send request, where the response puts the message ID, and how webhooks are
read and authenticated; ReputeCast saves it as an adapter that every workspace on the instance can connect.

<ProviderMatrix family="email" id="httpgeneric" />

## Before you begin

- **Pick the right kind of adapter.** The generic HTTP adapter sends one request per message and reads webhooks. If
  your provider also has an SMTP endpoint, [an SMTP connection](/providers/smtp/) may be simpler; if you need batch
  sending, a domain API or suppression sync, write a [community adapter](/adapters/community/).
  [Provider adapters](/adapters/overview/) compares the three.
- **Instance admin.** Adapters apply to every workspace on the instance, so only instance admins with
  `providers:manage` can save one. Others see the form read-only.
- **From your provider's API documentation:** the send endpoint, how it authenticates (usually an API key in a
  header), the JSON body it expects, where its response carries the message ID, and the shape of its webhook events.
- **A public HTTPS address** for the webhook. ReputeCast can't poll an HTTP mapping, so the address must be reachable
  from the internet.

## Map and connect the API

<Steps>

1. Open <UiPath path="nav.providers > providers.tabAdapters" /> and scroll to
   <UiPath path="providers.adapters.httpTitle" />.

   <Screenshot
     id="providers-adapters"
     alt="The Adapters tab: the eleven built-in adapters with their events, domain setup and suppression sync, then the community adapters installed on this instance."
   />

2. Fill in the mapping:
   - <UiPath path="providers.adapters.sendEndpoint" />: the method and an `https://` URL, for example
     `POST https://api.example-esp.com/v1/messages` (POST, PUT or PATCH).
   - <UiPath path="providers.adapters.requestHeaders" />: one per line, as `Name: value`, for example
     `Authorization: Bearer {{ secrets.api_key }}`. `{{ secrets.api_key }}` is the key entered when a workspace
     connects the adapter.
   - <UiPath path="providers.adapters.bodyTemplate" />: the JSON body with `{{ }}` fields such as `{{ sender }}`,
     `{{ recipient }}`, `{{ subject }}`, `{{ html }}` and `{{ headers_json }}`. Values are escaped for JSON. Include
     `{{ message_id }}` if the provider can echo it back in webhooks.
   - <UiPath path="providers.adapters.messageIdPath" />: a JSONPath into the response, for example `$.data.id`.
   - <UiPath path="providers.adapters.webhookMapping" />: the preset for webhooks that carry a `status` field, or a
     <UiPath path="providers.adapters.mappingJsonpath" /> with the paths of the
     <UiPath path="providers.adapters.pathType" />, <UiPath path="providers.adapters.pathRecipient" />,
     <UiPath path="providers.adapters.pathMessageId" /> and, for batched webhooks,
     <UiPath path="providers.adapters.pathEvents" />.
   - <UiPath path="providers.adapters.webhookAuth" />: <UiPath path="providers.adapters.authHmac" />,
     <UiPath path="providers.adapters.authStandard" />, <UiPath path="providers.adapters.authBasic" />,
     <UiPath path="providers.adapters.authHeader" />, or <UiPath path="providers.adapters.authNone" />.

3. Choose <UiPath path="providers.adapters.testSample" />. ReputeCast renders the request it would send for a sample
   message, with secrets shown as `••••`. Nothing is sent: this checks the mapping, not the provider.

4. Choose <UiPath path="providers.adapters.saveAsAdapter" />, give it a <UiPath path="providers.adapters.name" /> such
   as the provider's name, and save. The adapter appears in Add provider for every workspace.

5. In the workspace that sends, open <UiPath path="nav.providers" />, choose
   <UiPath path="providers.overview.addProvider" /> and find your adapter under
   <UiPath path="connect.catalog.communityTitle" />. Choose <UiPath path="connect.connection.connect" />, paste the
   <UiPath path="providers.fields.apiKey" /> and, if the provider signs webhooks with a secret of its own, its
   <UiPath path="providers.fields.webhookSigningSecret" /> under the extra settings. A form-made mapping has no
   credential check, so a wrong key shows up only at the test send.

6. In <UiPath path="connect.connection.webhooksTitle" />, ReputeCast checks that its webhook address can be reached from the internet. Choose
   <UiPath path="connect.connection.copyUrl" /> and add that URL as a webhook in your provider. If you didn't enter
   the provider's own signing secret, choose <UiPath path="connect.connection.createSecret" />, copy it (it's shown
   only once) and set it up in the provider the way your webhook authentication says.

7. Finish <UiPath path="connect.connection.continueDomain" /> with the DNS records your provider documents;
   ReputeCast suggests DMARC if the domain has none. In <UiPath path="connect.stepTest" />, send a test: it's a real
   message through your mapping, and the timeline waits up to 30 minutes for the provider's first webhook.

</Steps>

<Aside type="note">
  The form covers the common case. A health check, extra connection fields, error-code paths, terms and custom event
  names need a manifest; see the [generic HTTP adapter reference](/adapters/generic-http/).
</Aside>

## Check that it worked

- The test send's timeline shows the delivery event from your provider.
- Your adapter's card on <UiPath path="nav.providers > providers.tabProviders" /> shows
  <UiPath path="providers.statusHealthy" />, and events arrive under
  <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast sends one request per message, at up to 20 per second. A `401` or `403` from the provider marks it down
with failed credentials, `429` slows it down, and `408` or `5xx` count toward an outage. Copies and attachments
aren't supported through a mapping. ReputeCast can't read your provider's terms, so check its acceptable-use policy
before you route Broadcasts to it.

## Troubleshooting

- **"Enter an https:// URL, for example POST https://api.example-esp.com/v1/messages."** The form needs the method
  and an `https://` address. Plain `http://` works only in a manifest, for a test server on loopback.
- **"The body template isn't valid JSON once its `{{ }}` fields are filled in."** Check the commas and quotes. Inside a
  JSON string a field is escaped in place (`"subject": "{{ subject }}"`); outside a string it is JSON-encoded, so
  `"headers": {{ headers_json }}` becomes an object.
- **"… is already registered as …".** Another adapter has that name. Choose another one.
- **The test send fails with "… didn't accept the test".** The provider's answer follows the message: often a wrong
  key, a missing header or a body field the API rejects. Compare the request from
  <UiPath path="providers.adapters.testSample" /> with the provider's documentation.
- **Webhooks get `401`.** The provider's requests don't match the webhook authentication you chose, or it still uses
  an old secret. After <UiPath path="senders.providers.rotateSecrets" /> in
  <UiPath path="nav.settings > settings.providers" />, paste the new secret into the provider, because ReputeCast can't
  update it there.
- **You disconnected the adapter.** ReputeCast changes nothing at the provider. Remove the webhook pointing at
  ReputeCast there.
