To connect email sending provider accounts such as Amazon SES, Postmark or an SMTP server, ReputeCast walks you through
a six-step wizard: provider, connection, domain verification, test send, streams and contacts. Most setups take 10–15
minutes; Amazon SES takes longer when ReputeCast doesn't run on AWS, and a new AWS account can wait up to 24 hours for
production access. The wizard remembers where you stopped.

You don't need a provider to start writing: in a new workspace you can create and edit campaigns right away, and
scheduling and sending unlock once a provider carries the Broadcasts stream. To look around first, the first-run
Overview offers <UiPath path="overview.exploreDemo" />, which loads the Acme sample data into a separate demo workspace
that you own; its providers are demo connections, so nothing is sent.

## Before you begin

- You need the `providers:manage` permission. Members with `providers:view` can open the catalog and follow a setup
  someone else started, but can't change it.
- Have an account at the [sending provider](/reference/glossary/#sending-provider) and its API key (or, for SMTP, the
  server details) ready. [Choose a sending provider](/providers/choose/) compares what each one supports.
- ReputeCast's public URL must be reachable over HTTPS from the internet, because the provider reports deliveries,
  bounces and complaints by calling it (Amazon SES can deliver them through an SQS queue instead). Set it with
  `REPUTECAST_PUBLIC_URL`, the public URL's one name for the binary, the container and Docker Compose's `.env` file
  (the `http.public_url` setting); read [Reverse proxy and TLS](/self-hosting/reverse-proxy/).
- To verify your sending domain, you need access to its DNS records.

## Connect the provider

<Steps>

1. Open <UiPath path="nav.providers > providers.overview.addProvider" />. On an empty workspace the button reads
   <UiPath path="providers.overview.connectProvider" />. Sending providers has one channel menu next to its title: it
   shows <UiPath path="channels.email" /> and switches to <UiPath path="channels.sms" />,
   <UiPath path="channels.push" /> or <UiPath path="channels.whatsapp" />, opening a channel's setup when it isn't set
   up yet.

2. **Provider.** If you aren't sure which provider to use, answer the three questions under
   <UiPath path="connect.catalog.chooseTitle" />: <UiPath path="connect.catalog.volumeLabel" />,
   <UiPath path="connect.catalog.accountLabel" /> and <UiPath path="connect.catalog.dedicatedLabel" />. Every card then
   shows its price at your volume, and the panel names a <UiPath path="connect.catalog.recommended" /> provider and a
   <UiPath path="connect.catalog.runnerUp" />. [Choose a sending provider](/providers/choose/#help-me-choose) explains how
   they are ranked. Pick the provider and choose its Connect button. If a setup for it is already open, the wizard
   carries on where it stopped.

   <Screenshot
     id="providers-catalog"
     alt="Step 1 of 6, the provider catalog: Help me choose with 50,000 emails per month, no existing account and no dedicated IP recommends Amazon SES at about $5.00 a month, with Resend as the runner-up; below, cards for Amazon SES, Postmark and Mailgun show their bulk-marketing terms, price at 50,000 a month and honest setup time."
   />

3. **Connection.** Enter the credentials the provider asks for. ReputeCast checks them with a read-only call before it
   stores them, encrypted; they are never shown again. Then it registers the webhooks at the provider for you and proves
   from outside that the provider can reach them: providers that can send a test webhook on request (SendGrid and
   SparkPost) are asked for one, and <UiPath path="connect.connection.continueDomain" /> unlocks when it arrives, or
   when you switch to polling. For the others, the delivery event of the test send in step 4 confirms it; for Amazon SES,
   the SNS subscription's confirmation and a delivery event from the SES mailbox simulator do. Before any of that,
   ReputeCast looks at the address itself and stops early when no provider could reach it (`localhost`, a private
   address or a name that doesn't resolve). For Amazon SES, events can also come through an SQS queue ReputeCast polls,
   which needs no public address.

   <Screenshot
     id="connect-ses-connection"
     alt="The Amazon SES connection step: IAM access keys are recommended because ReputeCast isn't running on AWS, the CloudFormation stack is chosen with its role connected, the region has production access, and the next card asks how SES events reach ReputeCast, by webhook or an SQS queue."
   />

   Each provider's guide covers its own fields, for example [Amazon SES](/providers/amazon-ses/) (IAM keys or a
   CloudFormation stack, the region, how events arrive, the workspace's tenant and configuration sets) and [any SMTP server](/providers/smtp/) (the outgoing
   server and a bounce mailbox, because SMTP has no webhooks). For Azure Communication Services and the generic HTTP
   adapter, ReputeCast can't register the webhook itself: it shows the webhook URL and a secret to paste into the
   provider. The secret is shown once.

   Choose <UiPath path="connect.connection.continueDomain" />. For Amazon SES, the setup finishes only once a real
   delivery event has arrived.

4. **Domain verification.** Enter the domain in your From address. ReputeCast asks the provider which DNS records that
   domain needs, or works them out when the provider has no domain API, and checks them every 30 seconds while the page
   is open.

   <Screenshot
     id="connect-domain"
     alt="The domain step for news.acme.io: seven DNS records for Amazon SES (three DKIM, return-path, two SPF and DMARC), all marked Verified."
   >
     1. DKIM, the first of three records that let Amazon SES sign mail for your domain.
     2. The return-path (MAIL FROM) record, so bounces and SPF align with your domain.
     3. SPF for the sending domain.
     4. DMARC, which Gmail and Yahoo require of bulk senders.
     5. The live status: all records verified, and when they were last checked.
   </Screenshot>

   Publish the records at your DNS host. Most DNS hosts publish within minutes; some take up to 48 hours. If the domain
   uses Cloudflare, <UiPath path="connect.domain.addViaCloudflare" /> adds the missing records and fixes wrong ones with
   a Cloudflare API token that has Zone › DNS › Edit permission on the zone; the token is used once and never stored.
   For other DNS hosts, <UiPath path="connect.domain.copyZone" /> gives you every record at once. Read
   [Set up SPF, DKIM and DMARC](/deliverability/spf-dkim-dmarc/) for what each record does.

   Under <UiPath path="connect.domain.optionalTitle" /> you can add a custom link-tracking domain and see whether BIMI is
   set up. If DNS isn't ready yet,
   choose <UiPath path="connect.domain.skip" />.

5. **Test send.** Check From, To and Subject, then choose <UiPath path="connect.steps.sendTest" />. The delivery
   timeline fills in as the provider hands the message over and the delivery event comes back, and shows how the
   receiving mailbox provider saw your authentication. <UiPath path="connect.steps.sendSeeds" /> sends the same test to
   your own addresses at each mailbox provider.

   <Screenshot
     id="connect-test-send"
     alt="The test-send step: the test message from hello@news.acme.io on the left with the authentication Gmail saw (DKIM, SPF and DMARC pass), and a delivery timeline on the right from Queued by ReputeCast to Delivered."
   />

6. **Streams.** Choose which [streams](/reference/glossary/#stream) the provider carries: Broadcasts (campaigns),
   Automations, System (double opt-in confirmations, preference links, team invites) and Transactional (mail from your
   product). Each stream has its own route and failover policy, so a bad campaign never blocks a password reset.

   <Screenshot
     id="connect-streams"
     alt="The streams step of a finished Amazon SES setup, shown read-only: Broadcasts, Automations and System are on with SES as primary, each with its configuration set and failover; Transactional is off."
   />

   When another provider already carries a stream, pick this provider's role: <UiPath path="connect.steps.rolePrimary" />
   (it replaces the current one), <UiPath path="connect.steps.roleFallback" /> (it takes over when the primary fails) or,
   for Broadcasts only, <UiPath path="connect.steps.roleSplit" /> with its share. If the provider's terms don't allow bulk
   marketing, Broadcasts can't be switched on for it.

7. **Contacts.** Bring your contacts with an import, pull the suppressions the provider already holds (recommended, so
   ReputeCast never tries those addresses on any provider), or start empty. Imports keep consent: unsubscribed, bounced
   and complained contacts become suppressions and are never subscribed again. Choose
   <UiPath path="connect.steps.finish" /> or <UiPath path="connect.steps.startEmpty" />.

</Steps>

The summary lists what was configured, all of it reversible from Sending providers, and what to do before your first
campaign: add another provider, connect HostRepute and create a signup form.

### Finish later or cancel

- <UiPath path="connect.connection.saveLater" /> or <UiPath path="connect.exitSetup" /> leaves the setup open. Pick
  the same provider in the catalog to carry on at the step you left.
- There is no cancel button in the app. To cancel an unfinished setup, call the
  [cancel-provider-setup](/api/operations/cancel-provider-setup/) API operation: a provider the setup connected that no
  route uses yet is disconnected again, and the cancellation is recorded in the audit log.

### Change or remove a provider later

Each provider card on <UiPath path="nav.providers > providers.tabProviders" /> has a
<UiPath path="providers.overview.settings" /> button. There you can give the provider a label, replace credentials
(the new ones are checked with the provider before they replace the old ones), set how you pay for it, and choose
<UiPath path="providers.overview.removeProvider" />. Removing a provider asks you to pick a replacement for every route it
is part of, deletes its credentials and removes its webhook where the provider's API allows. The suppressions it
contributed, its past events and its reports stay.

## Check that it worked

- <UiPath path="nav.providers > providers.tabProviders" /> shows the provider with a status of Healthy, Sandbox or
  Warming up, its webhook line ("last event …"), its sending IPs and the streams it carries.
- The test send's timeline ended with a delivered event, and the summary marks the provider's events
  <UiPath path="connect.stateVerified" />.
- <UiPath path="nav.settings > settings.senders" /> shows the domain's records as verified. Read
  [Add sending domains and senders](/providers/senders-and-domains/).

## Troubleshooting

- **"Endpoint not reachable from the internet"** or **"Test webhook didn't arrive"**: the provider can't reach
  ReputeCast's public URL; the card names the likely cause, such as a name that resolves to a private address. Set
  `REPUTECAST_PUBLIC_URL` to the HTTPS address your reverse proxy serves and restart, then choose
  <UiPath path="connect.connection.recheck" /> or ask the provider for another test. While testing on a laptop, paste a
  Cloudflare Tunnel or ngrok URL that points at port 8080 instead: the provider's webhooks use it instead of
  `REPUTECAST_PUBLIC_URL` until you remove it. Providers with an events API (Mailgun, SparkPost) also offer
  <UiPath path="connect.connection.usePolling" />: ReputeCast asks for new events every minute, so bounce protection
  during a send lags by up to a minute.
- **"ReputeCast won't connect to that address"**: the server you entered resolves to a loopback or private address.
  An operator can allow those with [`providers.allow_private_networks`](/reference/configuration/); link-local and cloud
  metadata addresses are always refused.
- **The key is rejected**: the connection step names the key type the provider needs (for example, a Postmark server
  token rather than the account token). Check the provider's guide.
- **Records stay Pending**: the DNS host hasn't published them yet. Compare the "Found" value under a record with the
  value ReputeCast expects, and give the DNS host up to 48 hours.
- **The test send never shows a delivery event**: ReputeCast waits up to 30 minutes for it, then says what to check. A
  provider that never reported an event is flagged on Sending providers once mail is 30 minutes overdue; read
  [Provider health and outages](/providers/health-and-outages/).
- **Broadcasts can't be switched on**: the provider's terms don't allow bulk marketing on this connection. For Postmark,
  create a Broadcast message stream first. Read [Choose a sending provider](/providers/choose/#bulk-marketing-terms).
