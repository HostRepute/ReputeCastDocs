<UiPath path="nav.settings > settings.providers" /> holds the email auto-pause thresholds, the pause scope and the
per-mailbox-provider [throttles](/reference/glossary/#throttle) that every new campaign in the workspace starts from,
plus the rotation of your providers' webhook signing secrets. Each campaign can still override the thresholds in Review
& send.

## Before you begin

- You need the `providers:manage` permission. With `providers:view` you can see the page but not change it.
- Rotating webhook secrets has to be done by a signed-in member; API keys can't do it.
- Read [Monitor a send and auto-pause](/campaigns/live-monitor/) for what happens when a threshold trips.

## Change the defaults

<Steps>

1. Open <UiPath path="nav.settings > settings.providers" />. The top of the page summarizes each connected provider
   (and any SMS, push or WhatsApp channel): its status, the streams it carries, when it was connected and its cost this
   month. Health, routing, warm-up and events live on <UiPath path="senders.providers.openProviders" />.

   <Screenshot
     id="settings-providers"
     alt="Settings, Providers tab: summary cards for Amazon SES, Postmark and Postal with their status, streams, account and cost this month, followed by the SMS providers Twilio and Vonage with the monthly SMS budget."
   />

2. Under <UiPath path="senders.providers.defaultsTitle" />, set the
   [auto-pause thresholds](/reference/glossary/#auto-pause-thresholds):
   - <UiPath path="senders.providers.bounce" />: hard and soft bounces per message sent.
   - <UiPath path="senders.providers.complaint" />: complaints per message delivered.
   - <UiPath path="senders.providers.mailboxComplaint" />: the same rate for each mailbox provider (Gmail, Outlook,
     Yahoo, iCloud, other) on its own. It follows the overall complaint rate unless you set it.

3. Choose the <UiPath path="senders.providers.pauseScope" />: <UiPath path="senders.providers.pauseRoute" /> (the
   default: the rest of the campaign keeps sending) or <UiPath path="senders.providers.pauseCampaign" />.

4. Under <UiPath path="senders.providers.throttlesTitle" />, set the most messages per second each mailbox provider gets,
   written as "5 per second", or "no limit". Throttles apply on every route.

5. Choose <UiPath path="senders.providers.saveDefaults" />. New campaigns start from the new values; a send that has
   already started keeps the thresholds and throttles it started with.

</Steps>

<Aside type="caution">
Three fields on this card are saved but have no effect in this release:

- <UiPath path="senders.providers.providerError" />: a provider's share of a send is held after its calls have failed
  for 3 minutes (at least 5 calls), or when the provider is marked down, whatever this field says. The live monitor shows
  the value next to the provider's error rate for reference.
- <UiPath path="senders.providers.confirmOver" />: typing the recipient count to confirm is required for every send to
  1,000 recipients or more, whatever this field says.
- <UiPath path="senders.providers.suppressionSync" />: suppression sync runs every 15 minutes and soon after new
  bounces, even if you choose <UiPath path="senders.providers.sync1h" />.
</Aside>

## Rotate the webhook signing secrets

Each provider signs, or authenticates, the events it posts to ReputeCast with a secret. Rotate the secrets if one may
have leaked, or as routine.

<Steps>

1. Under <UiPath path="senders.providers.secrets" />, check when they were last rotated and choose
   <UiPath path="senders.providers.rotate" />.

2. Confirm with <UiPath path="senders.providers.rotateSecrets" />. ReputeCast makes a new secret for each provider and
   registers the webhook again with it wherever the provider's API allows. If registering fails at a provider, that
   provider keeps its old secret and the result names it.

</Steps>

<Aside type="danger">
The new secret replaces the old one at once; there is no overlap. Providers whose webhook you set up by hand (Azure
Communication Services, the generic HTTP adapter) get a new secret too, but ReputeCast can't register it there and the
rotation doesn't show it, so their events are refused from then on. To fix that, remove the provider and connect it
again: the connection step issues a secret you can paste. The rotation is recorded in the [audit log](/team/audit-log/).
</Aside>

## Check that it worked

- A "Sending defaults saved" message appears, and the card shows the new values after a reload.
- In a new campaign's [Review & send](/campaigns/schedule-and-send/), the thresholds start from your new defaults.
- After a rotation, the card says when the secrets were rotated, and
  <UiPath path="nav.providers > providers.tabEvents" /> keeps receiving events from every provider. Read
  [Delivery events and suppression sync](/providers/events-and-sync/).

## Troubleshooting

- **"Each threshold needs a number, like 2.0 %"**: enter a percentage in each threshold field.
- **A throttle isn't accepted**: write it as "5 per second", or as "no limit".
- **A provider's events stop after a rotation**: its webhook was set up by hand, so it doesn't have the new secret. Read
  the danger note above, and [Provider health and outages](/providers/health-and-outages/) for the Degraded state it
  shows meanwhile.
- **A running campaign ignores a new threshold**: thresholds are fixed when a send starts. The new values apply from the
  next campaign.
