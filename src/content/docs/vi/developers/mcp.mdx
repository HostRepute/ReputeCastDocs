ReputeCast có sẵn một máy chủ [Model Context Protocol](https://modelcontextprotocol.io/) (MCP), để trợ lý AI có thể
đọc báo cáo, kiểm tra Độ sẵn sàng gửi, soạn nháp chiến dịch hoặc tạm dừng một lượt gửi trong không gian làm việc của
bạn: một MCP server cho email marketing mà nhóm của bạn kiểm soát được. Mỗi
[tác tử MCP](/vi/reference/glossary/#mcp-agent) có token và quyền riêng, không bao giờ nhiều hơn người đã tạo ra nó,
và mọi thao tác có thể gửi thư đều được chuyển tới một người dưới dạng đề xuất thay vì tự chạy.

## Trước khi bắt đầu

- Bạn cần quyền `mcp:manage` trong không gian làm việc (một [quyền nhạy cảm](/vi/reference/glossary/#sensitive-permission)).
  Bạn chỉ có thể cấp cho tác tử những quyền mà chính bạn đang có.
- Hệ thống của bạn cần một URL công khai mà MCP client truy cập được qua HTTPS. Endpoint là `<public URL>/mcp`, do vai
  trò web phục vụ.
- Nếu ReputeCast chạy sau reverse proxy, `/mcp` phải truyền phản hồi theo luồng (streaming) mà không đệm. Xem
  [Reverse proxy và TLS](/vi/self-hosting/reverse-proxy/).

## Tạo tác tử

<Steps>

1. Mở <UiPath path="nav.settings > settings.keys" />. Thẻ MCP ở trên cùng hiển thị endpoint, ví dụ
   `https://reputecast.example.com/mcp`.

2. Chọn <UiPath path="keys.addAgent" />. Đặt cho tác tử một cái tên cho biết ai dùng nó, chẳng hạn "Claude: analytics".

3. Chọn quyền cho tác tử. Hãy bắt đầu với quyền đọc, chẳng hạn `reports:view` và `deliverability:view`, rồi bổ sung
   sau. Quyền bạn không có sẽ bị khóa. Tác tử không bao giờ được giữ `subscribers:verify`, `placement:run`,
   `placement:manage`, `coupons:manage`, `comments:moderate`, `replies:view` và `replies:manage` (khóa API thì được),
   cũng như `integrations:manage`, `ai:use` hay các quyền agency (chỉ con người). Thư trả lời, bình luận trên trang web và
   kho mã giảm giá vẫn thuộc về con người. Có từ bản phát hành tiếp theo sau 1.6.0.

4. Nếu muốn, hãy giới hạn tác tử trong một số danh sách, đặt thời hạn và điền <UiPath path="keys.allowedIpsLabel" />
   ([giới hạn tác tử trong các IP được phép](#giới-hạn-tác-tử-trong-các-ip-được-phép)), rồi tạo tác tử.

5. Sao chép token, `rc_agent_…`. Token chỉ hiển thị một lần; ReputeCast chỉ giữ mã băm SHA-256 của nó.

</Steps>

## Kết nối MCP client

Máy chủ dùng transport **Streamable HTTP** của MCP. Mọi yêu cầu đều mang token của tác tử dưới dạng bearer token:

```http title="Header của yêu cầu"
Authorization: Bearer rc_agent_…
```

Tại đây ReputeCast chỉ chấp nhận token tác tử: khóa API (`rc_live_…`) hoặc cookie phiên đăng nhập đều bị từ chối. Hãy
chọn client của bạn bên dưới. Các ví dụ đọc token từ biến môi trường `REPUTECAST_AGENT_TOKEN`; hãy thay
`reputecast.example.com` bằng URL công khai của bạn.

<Tabs syncKey="mcp-client">
<TabItem label="Claude Code">

```sh title="Terminal"
claude mcp add --transport http reputecast https://reputecast.example.com/mcp \
  --header "Authorization: Bearer $REPUTECAST_AGENT_TOKEN"
```

Để chia sẻ máy chủ với cả dự án, hãy thêm nó vào `.mcp.json` ở thư mục gốc của dự án. Claude Code cần
`"type": "http"` cho máy chủ có `url`; mục không có `type` sẽ bị hiểu là lệnh cục bộ và bị bỏ qua:

```json title=".mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Chạy `claude mcp get reputecast` để kiểm tra kết nối. Nguồn:
[tài liệu MCP của Claude Code](https://code.claude.com/docs/en/mcp), kiểm tra tháng 10/2026.

</TabItem>
<TabItem label="Cursor">

Thêm máy chủ vào `~/.cursor/mcp.json` (cho mọi dự án) hoặc `.cursor/mcp.json` (cho một dự án):

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${env:REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Cursor điền `${env:NAME}` từ môi trường của bạn. Nguồn:
[tài liệu MCP của Cursor](https://cursor.com/docs/context/mcp), kiểm tra tháng 10/2026.

</TabItem>
<TabItem label="VS Code">

Thêm máy chủ vào `.vscode/mcp.json` trong workspace VS Code của bạn. VS Code hỏi token một lần và lưu trữ nó an toàn:

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "reputecast-agent-token",
      "description": "ReputeCast agent token (rc_agent_…)",
      "password": true
    }
  ],
  "servers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${input:reputecast-agent-token}" }
    }
  }
}
```

Nguồn: [tài liệu tham chiếu cấu hình MCP của VS Code](https://code.visualstudio.com/docs/copilot/reference/mcp-configuration),
kiểm tra tháng 10/2026.

</TabItem>
<TabItem label="Client khác">

Mọi client kết nối tới MCP server từ xa bằng URL và cho phép bạn đặt header yêu cầu đều dùng được. Hầu hết dùng cấu
trúc dưới đây; hãy xem tài liệu của client để biết tên tệp và liệu nó có cần thêm `"type": "http"` không:

```json title="mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer rc_agent_…" }
    }
  }
}
```

Client chỉ khởi chạy được máy chủ cục bộ (stdio) cần một cầu nối cục bộ tới máy chủ HTTP từ xa; ReputeCast không cung
cấp cầu nối này.

</TabItem>
</Tabs>

<Aside type="danger" title="Bảo vệ token như mật khẩu">
Bất kỳ ai có token đều có thể hành động với tư cách tác tử. Đừng để token trong kho mã dùng chung: hãy dùng biến môi
trường hoặc lời nhắc nhập khóa bí mật của client, như ở trên. Nếu token bị lộ, hãy thu hồi tác tử trong
<UiPath path="nav.settings > settings.keys" />.
</Aside>

## Tác tử làm được gì

Máy chủ cung cấp 61 công cụ (tool), 3 tài nguyên (resource) và 2 prompt. Mỗi công cụ kiểm tra một quyền, giống hệt
khóa API, và bạn có thể chỉ định chiến dịch bằng tên hoặc ID. Danh sách đầy đủ, kèm quyền và tác động của từng công cụ,
nằm trong [Công cụ, tài nguyên và prompt MCP](/vi/reference/mcp-tools/).

- **Đọc**: danh sách và báo cáo chiến dịch, Độ sẵn sàng gửi, số liệu gửi trực tiếp, tình trạng nhà cung cấp, định
  tuyến, khả năng vào hộp thư, kiểm tra vị trí thư, một liên hệ theo ID hoặc địa chỉ, danh sách, biểu mẫu đăng ký, tự
  động hóa kèm số liệu của thẻ <UiPath path="automations.flow.tabStats" />, hàng đợi phê duyệt, bản tin tổng hợp, bình
  chọn, tăng trưởng, doanh thu, ưu đãi và nội dung website.
- **Thay đổi**: tạo bản nháp chiến dịch, SMS, thông báo đẩy, WhatsApp và bài viết website; cập nhật nội dung chiến
  dịch; tạo phân khúc; thêm địa chỉ vào danh sách chặn gửi; thay đổi tỷ trọng định tuyến; tạm dừng và tiếp tục lượt
  gửi; tạo liên kết chỉ xem có thời hạn đến báo cáo, bằng `share_campaign_report` (cần `reports:share`).
- **Bản nháp như của trình soạn thảo**: bản nháp chiến dịch mà tác tử tạo hoặc thay đổi được lưu giống cách
  [trình soạn thảo](/vi/campaigns/composer/#máy-chủ-kiểm-tra-những-gì) lưu bản nháp của một người. Máy chủ biên dịch
  MJML (MJML bị lỗi sẽ bị từ chối), kiểm tra nó, giữ tiêu đề và dòng xem trước trong phần head của MJML, và lưu mỗi thay
  đổi thành một phiên bản mới trong lịch sử, được ghi là do khóa API hoặc tác tử thực hiện. Thay đổi không bao giờ hủy
  phê duyệt hay yêu cầu phê duyệt đang chờ của một người: lệnh gọi thất bại với `409 approval_would_cancel`.
- **Gửi thử**: `send_test_email` chỉ gửi bản thử của chiến dịch tới thành viên của không gian làm việc, qua luồng Hệ
  thống.
- **Email giao dịch**: chỉ đọc. Tác tử liệt kê và kết xuất mẫu, tìm kiếm trong nhật ký thư, nhưng không bao giờ gửi
  thư giao dịch.
- **Tài nguyên**: MJML của một chiến dịch, một báo cáo dạng CSV và 100 mục mới nhất của nhật ký kiểm tra.

`get_campaign_report` trả về đúng báo cáo mà ứng dụng hiển thị, do cùng một đoạn mã dựng nên: lượt mở bởi người đọc, lượt
mở được bảo vệ quyền riêng tư và lượt mở của trình quét được tách riêng, tỷ lệ mở trên số đo được, khiếu nại chỉ ở nơi nhà
cung cấp hộp thư có báo cáo, liên kết (theo từng biến thể với thử nghiệm nội dung) và quyết định A/B kèm độ tin cậy. Tác tử
trả lời dựa trên các con số đó, giống cách [báo cáo chiến dịch](/vi/campaigns/reports/) trình bày chúng.

Quyền của tác tử được kiểm tra lại ở mọi lệnh gọi, đối chiếu với vai trò hiện tại của người tạo. Khi người tạo mất một
quyền, tác tử cũng mất quyền đó; khi người tạo rời không gian làm việc hoặc bị vô hiệu hóa, tác tử không làm được gì
nữa.

Danh sách của tác tử theo cùng quy tắc (từ bản 1.5.0): ở mọi lệnh gọi, chúng bị cắt bớt cho bằng các danh sách và tên
miền người gửi mà người tạo truy cập được vào thời điểm đó. Một tác tử bị giới hạn trong một số danh sách chỉ tìm thấy
các liên hệ trên những danh sách đó bằng `search_contacts` và `get_contact`, và `resume_campaign` chỉ tiếp tục một chiến
dịch nằm trong các danh sách và tên miền người gửi của nó, như một người bị giới hạn theo cùng cách làm được trong
ReputeCast.

## Giới hạn tác tử trong các IP được phép

Một tác tử có thể bị giới hạn trong các địa chỉ mà client của nó gọi từ đó: tối đa 50 địa chỉ và mạng IPv4 hoặc IPv6,
như `203.0.113.7` hoặc `203.0.113.0/24` (từ bản 1.6.0). Danh sách trống, mặc định, cho phép mọi địa chỉ.

<Steps>

1. Trong ma trận tác tử, chọn <UiPath path="keys.allowedIpsButton" /> trên hàng của tác tử.

2. Nhập mỗi dòng một địa chỉ hoặc một mạng. Ô nhập hiện nơi token được dùng lần gần nhất và địa chỉ của chính bạn theo
   ReputeCast, mỗi mục kèm một liên kết để thêm nó.

3. Lưu. Một danh sách không có địa chỉ mà token được dùng lần gần nhất sẽ hỏi trước; chỉ chọn
   <UiPath path="keys.saveAnyway" /> khi client đó cần bị từ chối.

</Steps>

Việc kiểm tra chạy sau khi token được xác minh. Một lệnh gọi từ địa chỉ khác, hoặc từ một địa chỉ mà ReputeCast không xác
định được, trả về `401` với
`this agent can't be used from <address>; add the address to its allowed IPs in Settings › Keys & MCP`, và được đếm.
Phía sau reverse proxy, hãy liệt kê proxy trong `http.trusted_proxies` trước, nếu không mọi lệnh gọi có vẻ như đến từ
proxy; hộp thoại cảnh báo khi điều đó có thể xảy ra. Cho phép gọi tác tử từ nhiều nơi hơn cần mọi quyền mà tác tử có và
danh sách của nó nằm trong phạm vi của chính bạn, như khi xoay vòng nó. Một người đã đăng nhập đặt danh sách này, ở đây
hoặc bằng `PUT /api/v1/workspaces/<workspace>/mcp-agents/<keyId>/allowed-ips`; thay đổi có trong nhật ký kiểm tra dưới
dạng `agent.updated`. Các quy tắc giống với
[khóa API](/vi/developers/api-authentication/#giới-hạn-khóa-trong-các-ip-được-phép).

## Đề xuất cho mọi thao tác gửi thư

Tác tử không bắt đầu lượt gửi.

- `schedule_campaign` không bao giờ lên lịch. Công cụ này ghi lại một đề xuất cho thành viên đầu tiên có quyền
  `campaigns:send`; người này nhận thông báo ("Claude: analytics đề xuất lên lịch gửi Weekly Digest #142") kèm liên kết
  tới chiến dịch. Người đó lên lịch chiến dịch trong ReputeCast, nơi Độ sẵn sàng gửi và phê duyệt được áp dụng như
  bình thường. `propose_send` làm tương tự với bản nháp tin nhắn SMS, thông báo đẩy hoặc WhatsApp, để gửi ngay hoặc vào
  thời điểm bạn chọn.
- Lệnh gọi mà tác tử không có quyền sẽ bị từ chối. Tác tử nhận lỗi nêu tên quyền còn thiếu, việc từ chối được ghi vào
  nhật ký kiểm tra, và một đề xuất được gửi tới thành viên đầu tiên có quyền đó.
- Thông báo nêu rõ thời điểm đề xuất hết hạn: mặc định 2 giờ, có thể đặt từ 1 đến 168 giờ trong
  <UiPath path="keys.changeLimits" />. ReputeCast không bao giờ tự thực hiện đề xuất, nên thời hạn chỉ cho người nhận
  biết yêu cầu còn hiệu lực trong bao lâu; khi hết hạn, không có gì xảy ra.
- `pause_campaign` cần `campaigns:pause` và tạm dừng ngay. `resume_campaign` cần `campaigns:send` và tiếp tục gửi
  ngay: chỉ cấp `campaigns:send` cho tác tử nếu nó được phép khởi động lại một lượt gửi đã tạm dừng.

## Nhật ký kiểm tra và giới hạn

Mọi lệnh gọi công cụ đều được ghi vào nhật ký kiểm tra với tác tử là người thực hiện, tên công cụ và kết quả, kể cả
lệnh gọi bị từ chối. <UiPath path="keys.recentAgentActions" /> trên cùng trang hiển thị các lệnh gọi gần nhất; mở
[nhật ký kiểm tra](/vi/team/audit-log/) để xem phần còn lại.

<UiPath path="keys.changeLimits" /> đặt số lệnh gọi mỗi phút cho mỗi tác tử và thời hạn đề xuất của không gian làm
việc, đồng thời cho phép tắt MCP server. Khi máy chủ tắt, mọi token tác tử đều bị từ chối. Tác tử vượt giới hạn nhận
`429` kèm `Retry-After: 60`.

## Kiểm tra kết quả

- Hãy yêu cầu trợ lý liệt kê các công cụ của máy chủ `reputecast`, hoặc gọi `list_campaigns`. Kết quả phải là danh
  sách chiến dịch của bạn.
- Trong <UiPath path="nav.settings > settings.keys" />, lệnh gọi gần nhất của tác tử xuất hiện trong ma trận tác tử và
  trong <UiPath path="keys.recentAgentActions" />.

## Khắc phục sự cố

- **401 "use an MCP agent token (rc_agent_…)"**: client gửi khóa API hoặc không gửi header. Hãy tạo tác tử và dùng
  token của nó.
- **401 "this agent was revoked" hoặc "… expired"**: tạo tác tử mới hoặc xoay vòng token của nó trong
  <UiPath path="nav.settings > settings.keys" />.
- **401 "the MCP server is off"**: bật máy chủ trong <UiPath path="keys.changeLimits" />.
- **401 "this agent can't be used from …"**: client gọi từ ngoài các IP được phép của tác tử. Hãy thêm địa chỉ mà lỗi
  nêu bằng <UiPath path="keys.allowedIpsButton" />, hoặc liệt kê reverse proxy của bạn trong `http.trusted_proxies` khi
  địa chỉ đó là của proxy.
- **Client kết nối được nhưng mọi công cụ đều bị từ chối**: tác tử thiếu quyền, hoặc người tạo không còn quyền đó.
  Thông báo lỗi nêu tên quyền.
- **Tác tử không tìm thấy liên hệ nào, hoặc ít hơn dự kiến**: tác tử, hoặc thành viên đã tạo nó, bị giới hạn trong một
  số danh sách.
- **Claude Code bỏ qua máy chủ**: mục trong `.mcp.json` có `url` nhưng không có `"type": "http"`.
- **Lệnh gọi bị treo hoặc hết thời gian chờ khi đi qua proxy**: proxy đang đệm phản hồi của `/mcp`. Hãy tắt đệm cho
  đường dẫn đó.
- **Lỗi 429**: tác tử gọi nhiều hơn mức không gian làm việc cho phép mỗi phút. Hãy nâng giới hạn hoặc giảm tốc độ của
  tác tử.
