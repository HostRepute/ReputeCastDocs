A signup form A/B test shows two or three versions of an embedded form or a popup to different visitors and tells you
which one gets more signups per view. Variant A is the form itself; B and C change its copy, its steps and its popup
timing, and everything else stays the same. Available from the next release after 1.6.0.

## Before you begin

- You need the `forms:edit` permission. Owners, Admins and Editors have it.
- The form must be an embedded form or a popup. Hosted pages always show variant A, so they can't run a test.
- Only visitors who see the form in its own language take part, because variants aren't translated. Visitors who see a
  translation see A and aren't counted in the test. See [send each reader their language](/campaigns/languages/).
- A test needs traffic: by default every variant needs 500 views before a winner can be called.

## Start a test

<Steps>

1. Open <UiPath path="nav.forms > forms.tabs.signupForms" /> and pick the form.

2. Above the preview, select <UiPath path="forms.builder.addVariant" />. Variant B starts as a copy of A's copy, steps
   and popup timing, the visitors split 50/50, and B is selected.

3. Edit B's heading, description and button in the preview itself: select the text and type. <kbd>Enter</kbd> or
   moving away keeps it, <kbd>Esc</kbd> puts it back. When the form shows a message after a signup, select
   <UiPath path="forms.builder.showAfterSubmit" /> to edit what B says.

4. Change B's <UiPath path="forms.builder.steps" /> if you want to test steps, and for a popup its
   <UiPath path="forms.builder.opensAfter" />, <UiPath path="forms.builder.orScrolled" /> and
   <UiPath path="forms.builder.exitIntent" />. The fields, lists, consent, spam protection, after-submit and where and
   when sections say <UiPath path="forms.builder.sameInEvery" /> and are locked while B or C is selected.

5. For a third variant, select <UiPath path="forms.builder.addVariant" /> again. The split becomes 34/33/33.

6. Select <UiPath path="forms.builder.savePublish" />. The test starts, and its results count from today.

</Steps>

A variant changes only these:

- the heading, description, button and after-submit message;
- the steps: one or several, which fields each step has, and each step's heading, description and button (see
  [split a signup form into steps](/forms/form-steps/));
- a popup's <UiPath path="forms.builder.opensAfter" />, <UiPath path="forms.builder.orScrolled" /> and exit intent.

Fields, lists, consent, double opt-in, spam protection, the after-submit action, where and when, and how long a closed
popup stays closed are the form's, in every variant. A field you add or remove changes every variant's steps with it.

<Aside type="note">
  The builder splits the visitors evenly. The API takes any split that adds up to 100%, each variant between 1% and
  99%: see [save a signup form's A/B test](/api/operations/save-signup-form-ab-test/).
</Aside>

## How visitors are split

- The embed script gives each browser a random id the first time it asks to show a form, and keeps it in local storage.
  The server picks the variant from the form and that id, against the split, so a browser keeps seeing the same variant
  while the split stays. Another browser, or a browser whose site data was cleared, can get another variant.
- While a test runs, the embed script asks the server which variant to show before it shows the form.
- Visitors who see a translation of the form and visitors of the hosted page see A, and aren't counted in the test.
- Each view, submission and confirmation is counted for its variant.

## Read the results

While a test runs, the <UiPath path="forms.builder.abTitle" /> card shows under the builder's last 30 days: each
variant's submissions per view as a bar, how many of its views signed up and, with
[double opt-in](/reference/glossary/#double-opt-in), how many have confirmed so far.
<UiPath path="forms.builder.showTable" /> shows the views, submissions, rate and confirmations per variant.

The result counts from the day the test started. It starts again from today when you save a change to a variant, the
split or A's copy, steps or popup timing, because the numbers so far compared other versions; the builder shows the new
date before you save. Changing what a winner needs, or whether the test ends on its own, keeps the numbers.

ReputeCast decides with the rule campaign [A/B tests](/campaigns/ab-testing/) use. Every variant needs at least the
views in <UiPath path="forms.builder.abMinViews" /> (500 by default, 100 to 100,000), and the leader's rate must beat
the runner-up's in a two-sided two-proportion z-test at the <UiPath path="forms.builder.abConfidence" /> you pick (90%,
95% or 99%; 95% by default). The rate is submissions per view; confirmations don't decide. The card then says one of:

| The card says                                       | Means                                                                |
| --------------------------------------------------- | -------------------------------------------------------------------- |
| "B gets 4.1% vs 3.2% for A (+28%), 97% confidence." | B leads, its rate 28% above A's, and the lead passes the confidence. |
| <UiPath path="forms.builder.abNotSignificant" />    | Every variant has its views, but the lead could still be chance.     |
| "Too few views yet: 212 of 500 per variant."        | The variant with the fewest views hasn't reached the minimum yet.    |

## End the test

<Steps>

1. On the <UiPath path="forms.builder.abTitle" /> card, select <UiPath path="forms.builder.abEnd" />, or the button
   that keeps the leader when the card names a winner.

2. In <UiPath path="forms.builder.endTitle" />, check the variant to keep (the leader is picked) and confirm.

</Steps>

<Screenshot
  id="form-ab-end"
  alt="The End the A/B test dialog: the kept variant's text, steps and popup timing become the form's, the other variants are deleted with their numbers kept in the audit log, and visitors see the kept version from the next page load; Keep B is picked."
/>

The kept variant's copy, steps and popup timing become the form's, and the other variants are deleted. The audit log
keeps their numbers in a `form.ab_ended` entry: each variant's views, submissions, confirmations and rate, the result
and its confidence. Visitors see the kept version from their next page load.

### End a test on its own

Tick <UiPath path="forms.builder.abAutoEnd" /> on the card and select <UiPath path="forms.builder.savePublish" />. Once
a day, ReputeCast ends every such test whose card names a winner, keeps the leader and tells the people who can edit
forms: "A/B test ended on Footer mini form", with "B won: 4.1% of views signed up, with 97% confidence. Its version is
now the form's." The audit entry names ReputeCast as the one who ended it. The notification is
<UiPath path="notify.event.form_test_ended" /> (`form_test_ended`), emailed by default; see
[notifications](/team/notifications/).

## Use the API

The builder saves the test with the form. With an API key, the same operations are:

- [Get a signup form's A/B test](/api/operations/get-signup-form-ab-test/) and its results.
- [Start or change a test](/api/operations/save-signup-form-ab-test/): 2 or 3 variants keyed A, B and C in that order,
  B and C with their content, weights that add up to 100, `autoEnd`, `minViews` and `confidence` (`0.9`, `0.95` or
  `0.99`).
- [End a test](/api/operations/end-signup-form-ab-test/), keeping the variant in `keep`.

They answer `409` with `form.ab_hosted` for a hosted page and `form.ab_none` when ending a form that has no test running.
Saving a running test's form as a hosted page answers `409` with `form.ab_running`: end the test first.

## Check that it worked

1. The <UiPath path="forms.builder.abTitle" /> card shows <UiPath path="forms.builder.abRunning" /> and the day the
   results count from.
2. Open a page with the form and reload it a few times: the browser keeps showing the same variant.
3. After a few visits, the card counts views for each variant.

## Troubleshooting

- **<UiPath path="forms.builder.addVariant" /> is unavailable and says <UiPath path="forms.builder.hostedShowsA" />**
  The form is a hosted page. Test an embedded form or a popup instead.
- **Saving the form as a hosted page says "End the A/B test before making this form a hosted page: hosted pages always
  show A."** End the test first.
- **The card keeps saying "Too few views yet".** One variant hasn't reached the views per variant. Wait, or lower
  <UiPath path="forms.builder.abMinViews" />.
- **The results started over.** A change to a variant, the split or A's copy, steps or popup timing restarts the count
  from that day.
- **Most visitors aren't counted.** They see the form in another language than its own. Test where the form's own
  language is the one most visitors see.
