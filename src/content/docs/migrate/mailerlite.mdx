To migrate from MailerLite, you connect ReputeCast to your MailerLite account with an API token and import each group into a ReputeCast list, with its subscribers' fields, opt-in dates and statuses. ReputeCast only reads from the MailerLite API; nothing changes in MailerLite.

## Before you begin

- You need the `subscribers:import` permission (Owner, Admin and Editor have it).
- Create a MailerLite API token. In MailerLite, open **Integrations**, choose **MailerLite API** and click **Generate new token**. Copy it at once: MailerLite shows it only once. A token belongs to the user who created it and stops working if that user is removed from the account. Source: [MailerLite developers, Getting started](https://developers.mailerlite.com/getting-started) (checked October 2026).
- The importer reads the MailerLite API at `connect.mailerlite.com`. MailerLite Classic accounts use an older API, which the importer doesn't support; export a CSV from them and [import the file](/audience/import/) instead.
- Read [how a migration carries consent](/migrate/overview/) if this is your first import.

## Import your MailerLite groups

<Steps>

1. Open <UiPath path="shell.importContacts" /> and choose **MailerLite**. The wizard links to MailerLite's API page if you still need a token.

2. Paste the token and select <UiPath path="imports.connect" />. The wizard lists your groups with their subscribed, unsubscribed, cleaned (bounced) and pending counts.

3. Tick the groups to import and pick the ReputeCast list each one goes into. Keep pulling suppressions from your sending providers on, then continue to field mapping.

4. Map the fields. `email` is required; MailerLite fields such as `name` and `last_name` are matched by name and sample values, and new custom fields are created for the rest.

5. On the consent step, check what each status becomes (see the next section). The opt-in date and IP from MailerLite are kept as consent evidence unless you choose <UiPath path="imports.repermission" />.

6. Run the preview and start the import.

</Steps>

## What moves from MailerLite

- **Groups** become the ReputeCast lists you chose. Subscribers who aren't in any group aren't read: add them to a group in MailerLite before you import, or export them as a CSV.
- **Fields** become contact fields.
- **Opt-in evidence:** the opt-in date and IP address are stored as consent evidence, and the subscription date becomes the contact's creation date.

| MailerLite status | Becomes in ReputeCast                                                                 |
| ----------------- | ------------------------------------------------------------------------------------- |
| `active`          | Subscribed · confirmed, with the opt-in date and IP as evidence (or pending, or Skip) |
| `unconfirmed`     | Subscribed · pending, with a re-permission email (or Skip)                            |
| `bounced`         | Suppressed · hard bounce, all streams (locked)                                        |
| `junk`            | Suppressed · complaint, all streams (locked)                                          |
| `unsubscribed`, or any other status | Suppressed · unsubscribed: no Broadcasts or Automations, System mail allowed (locked) |

New suppressions keep the reason from MailerLite, such as "cleaned in MailerLite" for a bounced subscriber. When the rows are in, the import pushes all of them, unsubscribes included, to each connected sending provider whose suppression list accepts new entries; after that, the regular [suppression sync](/providers/events-and-sync/) pushes only hard bounces and complaints that apply to all mail.

### What stays in MailerLite

Campaigns and their reports, automations, segments, forms, landing pages and templates are not imported. Rebuild them with [segments](/audience/segments/), [automations](/automations/overview/), [signup forms](/forms/signup-forms/) and the [composer](/campaigns/composer/).

## Rate limits

The MailerLite API allows 120 requests a minute and answers 429 Too Many Attempts above it, with a `Retry-After` header. Source: [MailerLite developers, Getting started](https://developers.mailerlite.com/getting-started) (checked October 2026). ReputeCast reads 1,000 subscribers per request, one request at a time, waits for `Retry-After` when MailerLite asks it to, and pauses the import when the source keeps refusing:

<LimitsTable area="imports" />

<UiPath path="imports.slowDown" /> sends at most 3 requests a second, which is still above MailerLite's average of 2 a second, so a large account may still pause now and then. Each pause resumes by itself.

## Check that it worked

- The summary shows how many contacts were imported, merged, suppressed, left pending and skipped, and how many each list now has. <UiPath path="imports.downloadReport" /> lists every row with what happened to it.
- Open <UiPath path="nav.audience > audience.tabSuppressions" />: bounced, junk and unsubscribed subscribers are there with the reason from MailerLite.

## Troubleshooting

- **"MailerLite rejected the API key"**: the token was deleted, or the user who created it left the account. Generate a new token and paste it.
- **A group is missing**: the importer lists every group of the account the token belongs to. Check that you created the token in the right MailerLite account.
- **Subscribers missing from the import**: they are in no group, or their status made them a suppression. Unconfirmed subscribers come in as pending and get no marketing mail until they confirm.
- **"MailerLite is rate-limiting us (429), import paused"**: another integration is using the same account's limit. Wait for the automatic resume, or select <UiPath path="imports.resumeNow" />.
