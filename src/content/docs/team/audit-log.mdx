The [audit log](/reference/glossary/#audit-log) records who did what, to what, from where, and whether it was
allowed, for each workspace in <UiPath path="nav.settings > settings.audit" /> and for the instance in
<UiPath path="shell.userMenuInstanceAdmin > admin.audit" />.

## Access

| Log       | Who can read it                                    | Who can change retention and streaming                     |
| --------- | -------------------------------------------------- | ---------------------------------------------------------- |
| Workspace | Members, API keys and MCP agents with `audit:view` (Owner, Admin, Editor, Viewer; not the client roles) | Signed-in members with `workspace:manage`                  |
| Instance  | Instance admins, signed in                         | Instance admins                                            |

The instance log shows every workspace's entries plus instance-level ones: sign-ins, single sign-on, policies, users
and agency mode. Instance admins can switch between the two with <UiPath path="audit.instanceView" />.

## What an entry records

<TableScroll label="Audit entry fields">

| Field              | Content                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| Time               | When it happened (UTC in exports).                                                                          |
| Actor              | Type (member, API key, MCP agent, or automatic for the system), ID and name.                                |
| Action             | A dotted name such as `role.updated`, `member.removed` or `audit.exported`.                                 |
| Target             | Type, ID and name of what changed.                                                                           |
| Result             | `allowed`, `denied` or `error`, with the reason (for example the missing permission).                       |
| Before and after   | The changed values; the detail panel shows them as a diff.                                                  |
| Source             | Client IP address (as resolved through your trusted proxies), user agent and request ID.                    |
| Metadata           | Extra context, such as an export's entry count.                                                             |

</TableScroll>

## Notes on recording

- An action and its entry are saved in the same database transaction.
- Entries are immutable: a database trigger refuses updates and deletes, except the retention cleanup. The app has no
  way to edit or delete them.
- Entries outlive the workspace, user or key they name.
- Denied changes are always recorded. Denied reads are recorded only when they need a sensitive permission, such as an
  export. Most plain reads are not recorded.
- Secrets (API keys, webhook and provider secrets) never appear in entries.
- Exports are themselves recorded as `audit.exported`.
- A [Send Readiness](/reference/glossary/#send-readiness) run someone asked for (`readiness.run`, or
  `readiness.send_time_check` when a scheduled send is checked again) names who asked: the member, or the API key or MCP
  agent itself. One-click fixes are recorded as the changes they make, and undoing them as `readiness.fixes_undone`.
- A canary phase records how it ended: `campaign.canary_passed`, `campaign.canary_continued`, `campaign.canary_held` or
  `campaign.canary_extended`.
- Workspace [sending rules](/campaigns/sending-rules/) (`sending_rule.created`, `.updated`, `.deleted`),
  [traffic rules](/providers/traffic-rules/) (`traffic_rules.updated`), the [brand kit](/campaigns/brand-kit/) and its
  synced blocks (`brand_kit.save`, `synced_block.*`) and rendering services (`rendering.connect`,
  `.test`, `.disconnect`) are recorded in the workspace log. Changes to the bot filter's networks and user agents
  (`tracking_network.*`, `tracking_user_agent.*`) are instance entries.
- Campaign management is recorded as `campaign.delete`, `.restore`, `.archive`, `.unarchive`, `campaign.rescheduled`,
  `campaign.tags` and `campaign.follow_up`. Contact work adds `contact.remove_from_list`, the bulk
  `contacts.remove_from_list` and `contacts.remove_tag`, `contacts.export_downloaded`, `contact_view.update`,
  `field.restore`, `field.values_removed` and `suppression.upload_remove`. Automations add `automation.contact_remove`
  (with the reason) and `automation.test_send`, and `automation.resume` keeps the choice made for overdue contacts.
- Other workspace entries: `marketing_cap.updated`, `transactional.message_cancelled` and
  `.message_rescheduled`, `payments.webhook_events_added`, and the exports `gift.exported`, `conversion.exported`,
  `payment_events.exported`, `sponsor.bookings_exported` and `sponsor.report_exported`. A change in
  <UiPath path="nav.settings > settings.general > workspace.retentionTitle" /> is recorded as `workspace.updated`.
- Retrying, cancelling or deleting a failed job in <UiPath path="shell.userMenuInstanceAdmin > admin.system" />
  (`instance.job_retried`, `.job_cancelled`, `.job_deleted`) and `reputecast secrets reseal`
  (`instance.secrets_resealed`) are instance entries.
- Access changes since 1.5.0: deactivating or removing a member revokes the invitations they sent, each as
  `team.invite_revoked` with the reason; an outgoing webhook paused because the person it sends for can no longer see
  its data is `webhook.paused`; a WhatsApp account's callback URL is `whatsapp.callback_created`, `.callback_moved`
  (Meta called the new address) and `.callback_rotated`. Wrong authenticator and recovery codes are instance entries
  `signin.failed` with the reason. When the server's operator pins the public URL, the move at start is the instance
  entry `instance.public_url_pinned`.
- Limiting an API key or MCP agent to [allowed IP addresses](/developers/api-authentication/) is recorded as
  `apikey.updated` or `agent.updated`, with the list before and after. A member's
  [sending summary](/team/notifications/#get-a-sending-summary-by-email) is `report_summary.set` or `.remove`, and a
  change of [theme](/team/appearance/) is the instance entry `account.appearance_update`.

Three categories join the action filter: Receiving & replies, Discount codes and Lead ads. The detail panel links to
the reply, pool, comments, post import, lead ads connection or tracked sites an entry names.
Available since 1.7.0.

### Entries for AI drafts, the agent and external connections

[Drafts from a brief](/integrations/ai-drafts/), the [AI agent](/integrations/ai-agent/), the
[brand voice](/campaigns/brand-voice/) and [external connections](/developers/mcp-connections/) add these entries.
None holds the text shared with a model or a client, nor a token. Available since 1.7.0.

<TableScroll label="Audit actions for AI drafts, the agent and external connections">

| Actions | What they record |
|---|---|
| `ai.sharing.reviewed` | Someone confirmed what goes to the model before brand voice learning or a draft from a brief |
| `ai.draft.propose`, `ai.draft.reject` | A draft from a brief was proposed, or its proposal rejected |
| `ai.agent.*` | Each step and decision of an agent run, such as `ai.agent.start`, `.plan`, `.build`, `.pause` and `.discarded`, with the run's ID; `ai.agent.settings` and `ai.agent.tools_tested` for the agent settings and the tool-calling test |
| `ai.usage_reconciled` | Someone reconciled a [reserved AI request](/integrations/ai-models/#reserved-requests-and-unknown-usage): the reservation before, the token counts after |
| `brand_voice.save`, `.suggest`, `.reject` | A voice revision was saved, a voice was learned from sent campaigns, or the suggestion was rejected |
| `mcp_connect.granted`, `.revoked`, `.source_selected`, `.proposed` | A person allowed a connection; it was revoked, with the reason (by a person, by the client, or for a reused refresh token); a person shared a source with it; its client proposed a draft |
| `mcp_connect.kept`, `.discarded`, `.accepted`, `.rejected` | A person decided on an external proposal |
| `mcp_connect.client_registered`, `.denied` | An MCP client was registered, by itself or by an instance admin, or a person denied its request: instance entries |

</TableScroll>

A draft that a person keeps or accepts is recorded as the usual action, such as `campaign.create`,
`campaign.content.save`, `segment.create`, `post.created` or `automation_email.create`, with the person as the actor.
Its metadata says where it came from: `via` is `ai_assistant`, `ai_agent` or `external_mcp`, with the ID of the
proposal, the run or the connection.

### Entries for AI models, the assistant and MCP servers

From 1.8.0, [AI models](/integrations/ai-models/), the
[AI assistant](/integrations/ai-assistant/) and its [MCP servers](/integrations/mcp-servers/) add these entries. None
holds a key, a secret, a thread's title or messages, a call's arguments or a tool's result.

<TableScroll label="Audit actions for AI models, the assistant and MCP servers">

| Actions | What they record |
|---|---|
| `ai_account.add`, `.key_replaced`, `.remove` | A model account was added, its key replaced, or the account removed (a personal key's entries say so) |
| `ai_model.add`, `.prices_updated`, `.remove` | A model was added to an account, its prices changed, or it was removed |
| `ai_feature.model_changed` | A feature's default model changed, or a member's own pick for a feature |
| `ai_personal_keys.enabled`, `.disabled`, `.cap_updated` | Managers allowed or turned off personal keys, or changed the personal cap |
| `ai_assistant.settings_updated` | The assistant was switched on or off, or its limits changed |
| `ai_assistant_thread.created`, `.updated`, `.deleted` | A member started, renamed (or changed the model or MCP servers of) or deleted a thread |
| `ai_assistant_context.add`, `.remove` | A report or a draft was attached to a thread, or removed: its kind and ID |
| `ai_assistant_turn.created`, `.cancelled` | A message started an answer, or the answer was stopped |
| `ai_assistant_confirmation.approved`, `.rejected`, `.expired` | A member chose Allow once or Deny for a tool that writes, or the call expired after 24 hours (the system's entry) |
| `mcp_server.created`, `.updated`, `.deleted` | A manager added, edited, synced or removed an MCP server; the hourly sync and the check before a call write `.updated` as the system when the server's tools changed |
| `mcp_server.connect`, `.disconnect` | A member signed in to an OAuth server, or disconnected |
| `mcp_tool.approved`, `.revoked` | A manager approved a tool as read-only or writes, or blocked it |
| `mcp_tool.called` | A tool was called: the person, the thread, the server, the outcome, the duration and a digest of the arguments salted with the call's ID |

</TableScroll>

The `ai.*` entries are in the <UiPath path="auditlog.category.ai" /> category of the action filter. From 1.8.0,
so are the `ai_account.*`, `ai_model.*`, `ai_feature.*`, `ai_personal_keys.*`,
`ai_assistant*`, `mcp_server.*` and `mcp_tool.*` entries. `brand_voice.*` and
`mcp_connect.*` entries belong to no category: they show under <UiPath path="audit.anyAction" />, and the API finds
them with `action=brand_voice` or `action=mcp_connect`.

## Filters

| Filter       | Values                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| Search       | Target or actor name (contains), target ID or request ID (exact). The instance log also matches the sign-in reference ID shown on error pages. |
| Actor type   | Members, API keys, MCP agents, System                                                                   |
| Action       | 22 categories, from Sending and Team & access to Agency; 25 since 1.7.0, which adds Receiving & replies, Discount codes and Lead ads |
| Result       | Allowed, Denied, Error (instance log: Allowed, Denied)                                                   |
| Date range   | Last 24 hours, 7 days (default), 30 days, 90 days, all retained, or custom dates in the workspace timezone |
| Workspace    | Instance log only: all workspaces, one workspace or instance-only entries                                |

## Export

<UiPath path="audit.exportCsv" /> and <UiPath path="audit.exportJson" /> download the entries that match the current
filters, with no row limit, as `audit-<workspace>-<date>.csv` or `.json` (instance: `audit-instance-<date>`). The CSV
columns are `occurred_at, actor_type, actor_name, actor_id, action, target_type, target_id, target_name, result,
reason, summary, ip, user_agent, request_id, before, after`; the instance export adds `workspace`. A cell that starts
with `=`, `+`, `-`, `@`, a tab or a carriage return gets a single quote in front, so a spreadsheet never runs it as a
formula. The API equivalent
is `GET /api/v1/workspaces/<workspace>/audit/export?format=csv|json` with the same filters (see the
[API reference](/api/)).

## Audit stream

The workspace's <UiPath path="audit.streamDialog" /> dialog, with <UiPath path="audit.streamToggle" />, sends new
entries to an HTTPS endpoint, such as a SIEM or a warehouse. Instance admins set up a separate stream for
instance-level entries with <UiPath path="audit.streamInstance" />.

- Every 30 seconds, ReputeCast posts up to 500 new entries per workspace, oldest first, as
  `{"workspace": "<id>", "sent_at": "…", "events": [ … ]}`.
- Each request is signed like [workspace webhooks](/developers/webhooks/): headers `X-ReputeCast-Timestamp`,
  `X-ReputeCast-Event: audit.batch` and `X-ReputeCast-Signature`, the HMAC-SHA256 of `<timestamp>.<raw body>` with the
  `whsec_…` secret shown once after saving.
- A batch counts as delivered on any 2xx answer. Until then, the same batch is retried every 30 seconds, in order, and
  nothing is dropped.
- Turning the stream on or changing its URL starts from that moment; older entries are not sent.
- Private and loopback addresses are refused unless the operator sets `webhooks.allow_private_networks`.

## Retention

Set <UiPath path="audit.keepEntriesFor" /> in the workspace dialog, or <UiPath path="audit.changeRetention" /> for the
instance log. Cleanup runs every hour.
