Import an email list from a CSV or XLSX file in five steps (Source, Map fields, Consent, Preview, Import), then read
the summary. Every row keeps its [consent](/reference/glossary/#consent): addresses that unsubscribed, bounced or
complained in the old tool go straight to the [suppression list](/audience/suppressions/) and an import can never
subscribe them again.

The screens are the same for a file and for an API source such as Mailchimp or Brevo; the screenshots below show API
imports. To bring contacts from another platform's API, see [Move to ReputeCast without losing
consent](/migrate/overview/).

## Before you begin

- You need `subscribers:import`. The Owner, Admin and Editor roles have it; a Viewer does not.
- Prepare a `.csv` or `.xlsx` file. The first non-empty row must be the headers. XLSX files are read from the first
  sheet only; `.xls` files are not supported, so save them as XLSX or CSV first.
- Connect your [sending providers](/providers/connect/) first if you can. The import then pulls the bounces,
  complaints and unsubscribes they already block before it adds anyone.
- Optional: connect an address [verification service](/audience/verification/) to check new addresses in the
  preview.

### How ReputeCast reads the file

- **Delimiter**: comma, semicolon, tab or pipe, whichever appears most in the first line.
- **Encoding**: UTF-8 (a byte-order mark is ignored); anything that is not valid UTF-8 is read as Latin-1.
- **Email column**: a header named `email`, `e-mail`, `email address` or `mail`. Without one, ReputeCast picks the
  column with the most valid addresses in its first 20 values.
- **Status column**: a header named `status`, `consent`, `subscribed`, `subscription status`, `opt-in status` or
  `email status`. Its values decide what each row becomes in the Consent step (see the table there).
- **Tags column**: a header named `tags`, `tag`, `labels` or `label`. Values are split on commas, semicolons or pipes
  and lower-cased.

<Aside type="caution">
  In a status column, any value ReputeCast doesn't recognize counts as **unsubscribed**, so that row is suppressed.
  Check the counts in the Consent step before you continue, and rename the column if it isn't a subscription status.
</Aside>

## Import the file

<Steps>

1. Select <UiPath path="shell.importContacts" /> in the sidebar, or <UiPath path="nav.audience > audience.tabContacts > audience.contacts.import" />.
   Under <UiPath path="imports.stepSource" />, drop the file on the page or select <UiPath path="imports.chooseFile" />.

   <Screenshot
     id="import-source"
     alt="Step 1 of 5, Source: tiles for Brevo, Mailchimp, MailerLite, listmonk, Keila, Notifuse and CSV or XLSX, with a table that sends each source list to a ReputeCast list."
   />

   If a CSV row has a different number of columns than the header (usually an unquoted comma inside a value), the
   page names the row. Skip those rows, download them, or upload a fixed file.

2. In <UiPath path="imports.chooseTitle" />, pick the list the file goes into under
   <UiPath path="imports.intoList" />: an existing list, or a new list named after the file. Leave
   <UiPath path="imports.pullSuppressions" /> on, then select <UiPath path="imports.continueFields" />.

3. Under <UiPath path="imports.stepFields" />, check the guesses. Each column maps to a built-in field (first name,
   last name, name, company, country, time zone, language, phone, SMS consent), an existing custom field, a new
   custom field (text, number, date or boolean), or **Skip**. Exactly one column must map to email.

   <Screenshot
     id="import-fields"
     alt="Map fields: each source field with sample values, the ReputeCast field it maps to, its type and a Mapped, New field or Skipped badge."
   />

   A language column is converted to language codes ("Spanish", "español" and "ES" become `es`). Values that aren't
   languages are left empty and counted under the column. Select <UiPath path="imports.continueConsent" />.

4. Under <UiPath path="imports.stepConsent" />, check what each status becomes. Unsubscribed, cleaned (bounced) and
   complained rows are locked: they become suppressions.

   <TableScroll label="What each file status becomes">

   | Value in the status column | Becomes | Effect |
   | --- | --- | --- |
   | Empty, `subscribed`, `active`, `yes`, `true`, `1`, `confirmed`, `opted in`, `opt-in`, `enabled` | Subscribed (you can choose pending or Skip instead) | Gets Broadcasts and Automations right away |
   | `pending`, `unconfirmed`, `not confirmed` | Pending, with a re-permission email, or Skip | No marketing mail until they confirm |
   | `bounced`, `cleaned`, `hard bounce`, `invalid`, `undeliverable` | Suppressed as a hard bounce (locked) | All streams blocked |
   | `complained`, `spam`, `abuse`, `junk` | Suppressed as a complaint (locked) | All streams blocked |
   | `transactional` | Skip, or Subscribed · pending | Not imported, or pending |
   | Any other value | Suppressed as unsubscribed (locked) | Broadcasts and Automations blocked; System mail allowed |

   </TableScroll>

   Under <UiPath path="imports.evidenceTitle" />, choose one:

   - Trust the file's opt-in: only when every contact opted in. Contacts are subscribed with single opt-in consent.
   - <UiPath path="imports.repermission" />: contacts are imported as pending and get one confirmation email through
     the System stream after the import. Safer for old or single opt-in lists.

   Keep <UiPath path="imports.pullBefore" /> and <UiPath path="imports.recordHistory" /> on, then select
   <UiPath path="imports.continuePreview" />.

   <Screenshot
     id="import-consent"
     alt="Consent: each source status with its contact count and what it becomes; unsubscribed and cleaned rows are locked as suppressions, with the re-permission choice below."
   />

5. Under <UiPath path="imports.stepPreview" />, read the dry run. Nothing is written yet. The tiles count rows that
   will be imported, merged with existing contacts, suppressed, skipped as invalid, and risky.

   <Screenshot
     id="import-preview"
     alt="Preview of 40,649 rows: tiles for imported, merged, suppressed, invalid and risky rows, then the risky address groups with an action for each."
   />

   Choose an action for each risky group:

   <TableScroll label="Risky address groups">

   | Group | What it catches | Default action |
   | --- | --- | --- |
   | Role addresses | `info@`, `sales@`, `support@`, `noreply@` and similar | Import, excluded from Broadcasts automatically |
   | Disposable domains | Throwaway mailbox domains | Skip |
   | Likely typos | One letter away from gmail.com, outlook.com, hotmail.com, yahoo.com, icloud.com and others | Fix the domain and import, tagged `review-typo` |
   | Known spam-trap patterns | Local parts such as `spamtrap` or `honeypot` | Skip (recommended) |

   </TableScroll>

   Duplicates are matched on email, ignoring case. Under <UiPath path="imports.onConflict" />, keep
   <UiPath path="imports.conflictFill" /> to fill only empty fields, or overwrite or keep the values in ReputeCast. A
   merge adds the list and the tags; it never changes a contact's consent. Invalid rows (no domain, no MX record, not
   an address) are skipped; <UiPath path="imports.downloadThese" /> gives you the list.

   With a verification service connected, you can check the new addresses first, with the cost shown, or select
   <UiPath path="verification.importWithout" />.

6. Select **Import _N_ contacts**. The import runs in the background in batches of 500 rows. Select
   <UiPath path="imports.leaveRunning" /> to use the app meanwhile; contacts already imported are usable right away and
   you get a notification with the report when it finishes. <UiPath path="imports.stopImport" /> keeps the rows already
   imported; a stopped import can't be resumed, but you can start a new one.

7. Read the summary. It counts imported, merged, suppressed, pending and skipped rows, explains every skipped or
   changed group, and offers two downloads:

   - **Download skipped rows · CSV**: `row,value,source_status,reason`.
   - <UiPath path="imports.downloadReport" />: `row,email,source_status,outcome,reason` for every row.

   <Screenshot
     id="import-report"
     alt="Import summary: 39,402 contacts imported, 1,033 suppressed, 6,716 pending re-permission and 214 skipped, with the reason for each skipped or changed group."
   />

   New suppressions are pushed to the sending providers that accept them, so the next campaign can't reach those
   addresses on any provider.

</Steps>

## Check that it worked

- <UiPath path="nav.audience > audience.tabContacts" /> shows the new contacts. Filter
  <UiPath path="audience.contacts.source" /> by <UiPath path="audience.contacts.sourceCsv" /> to see them, and
  <UiPath path="audience.contacts.consent" /> by <UiPath path="audience.consentPendingFilter" /> to see who still has
  to confirm.
- Each list named in the summary shows its new contact count.
- <UiPath path="nav.audience > audience.tabSuppressions" /> shows the imported suppressions grouped under the import,
  with <UiPath path="audience.suppressions.viewRows" /> to open them.

## Troubleshooting

- **"Row _N_ has _X_ columns, the header has _Y_"** → a value contains an unquoted comma. Skip the rows or quote the
  value and upload again.
- **"That file is over 100 MB"** → split the file, or import from the source's API.
- **The wrong column was used for email** → rename that column's header to `email` and upload again.
- **Many rows became suppressed** → the status column has values ReputeCast doesn't recognize. Rename the column so it
  isn't read as a status, or change the values to `subscribed`.
- **Pending contacts never got a confirmation email** → no System provider is connected. Connect one in
  [routing](/providers/routing/), then select <UiPath path="audience.contacts.resendOptin" /> for them in Contacts.
- **Tags are missing** → only a column headed `tags`, `tag`, `labels` or `label` is read as tags.

<Aside type="note">
  Pending contacts stay pending until they confirm; ReputeCast does not suppress them after a deadline by itself. To
  follow up or remove non-responders, build an [automation](/automations/overview/).
</Aside>
