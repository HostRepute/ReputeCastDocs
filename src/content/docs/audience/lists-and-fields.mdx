<UiPath path="nav.audience > audience.listsFields.tab" /> holds what your contacts subscribe to and what you know
about them: create and rename [lists](/reference/glossary/#list), set each list's opt-in mode, and add, edit, delete
and restore custom contact fields. Before a field goes, the page shows everything that uses it.

## Before you begin

- Every change on this tab needs `lists:manage` (Owner, Admin and Editor). Anyone who can see contacts can see the
  tab.
- To read how each opt-in mode works, see [Lists, consent and double opt-in](/audience/lists-and-consent/).

## Create or rename a list

<Steps>

1. Go to <UiPath path="nav.audience > audience.listsFields.tab" /> and select
   <UiPath path="audience.listsFields.newList" />.

2. Enter a <UiPath path="audience.listsFields.listName" /> and, if you like, a
   <UiPath path="audience.listsFields.listDescription" />.

3. Choose the opt-in: double opt-in (the default; new subscribers confirm by email) or single opt-in.

4. Select <UiPath path="audience.listsFields.createList" />.

</Steps>

<UiPath path="audience.listsFields.rename" /> on a list's row changes its name and description.

## Change a list's opt-in mode

Select <UiPath path="audience.listsFields.optInMode" /> on the list's row, pick
<UiPath path="audience.consentDouble" /> or <UiPath path="audience.consentSingle" />, and save. The change applies to
new signups only; everyone already subscribed stays subscribed. Signup forms keep their own double opt-in switch.

## Delete a list

<UiPath path="audience.listsFields.deleteList" /> on a list's row opens the same dialog as on List health: type the
list's name, see which forms, automations and scheduled campaigns it affects, and restore it later if you need to.
See [Health per list](/audience/list-health/#health-per-list).

## Add a custom field

<Steps>

1. In the custom fields card, select <UiPath path="audience.listsFields.newField" />.

2. Enter a <UiPath path="audience.listsFields.fieldLabel" />. The <UiPath path="audience.listsFields.fieldKey" /> is
   filled in from it: lower-case letters, digits and `_`, used in [Liquid](/campaigns/personalization/) as
   `{{ contact.plan }}`. You can't change the key once the field exists.

3. Pick the <UiPath path="audience.listsFields.fieldType" />: <UiPath path="audience.listsFields.typeText" />,
   <UiPath path="audience.listsFields.typeNumber" />, <UiPath path="audience.listsFields.typeDate" />,
   <UiPath path="audience.listsFields.typeBoolean" /> or <UiPath path="audience.listsFields.typeSelect" />. For a
   choice, list the values under <UiPath path="audience.listsFields.fieldOptions" />.

4. Select <UiPath path="audience.listsFields.createField" />.

</Steps>

<UiPath path="audience.listsFields.edit" /> changes a field's label and, for a choice, its values; the key and type
stay. Each row shows <UiPath path="audience.listsFields.colFilled" />, how many contacts have a value, and
<UiPath path="audience.listsFields.colUsedBy" />, for example "2 segments · 1 form · scoring rules", or
<UiPath path="audience.listsFields.nothing" />.

## Delete or restore a custom field

<Steps>

1. Select <UiPath path="audience.listsFields.deleteField" /> on the field's row. The dialog lists everything that
   uses the field, each with <UiPath path="audience.listsFields.open" />: segments and automations with a condition on
   it, forms and scoring rules that set or read it, saved views that show it as a column, SQL segments that name it,
   and Liquid in digests, transactional templates and campaigns not sent yet (email, SMS, push and WhatsApp).

2. Fix or accept those uses, then select <UiPath path="audience.listsFields.deleteField" />.

</Steps>

The field stays in the card as "Deleted · restorable until _date_", with its values kept. Select
<UiPath path="audience.listsFields.restore" /> to bring it back as it was. After that date the hourly maintenance pass
removes its values from every contact, and the field is gone. See the limits in
[Manage contacts](/audience/contacts/#defaults-and-limits).

Deleting a segment shows the same list of uses first; see [Build segments](/audience/segments/#use-a-segment).

## Check that it worked

- A new list appears in the Lists card, the Contacts list filter and the campaign audience picker.
- A new field appears in the custom fields card, in Contacts' <UiPath path="audience.contacts.columns" /> chooser and
  among the segment conditions.
- List and field changes are in <UiPath path="nav.settings > settings.audit" />.

## Troubleshooting

- **The buttons are disabled** → your role lacks `lists:manage`. Ask an Owner or Admin.
- **<UiPath path="audience.listsFields.notCounted" /> under Filled in** → counting took too long on this audience. The
  field works as usual.
- **"A field with the key `…` already exists"** or **"`…` is a built-in field"** → pick another key.
- **"A deleted field still has the key `…`"** → restore that field, or wait until its values are removed on the date
  the message names.
- **"That saved view was deleted"** after <UiPath path="audience.listsFields.open" /> → someone deleted the view
  after the list of uses was read, so it no longer uses the field.
