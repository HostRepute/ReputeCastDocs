`n8n-nodes-reputecast` est le paquet de nœud n8n pour newsletter de ReputeCast : le nœud **ReputeCast Trigger** lance des
workflows à partir d’événements ReputeCast, et le nœud **ReputeCast** ajoute des contacts, les tague, enregistre des
événements et envoie des e-mails transactionnels. Les nœuds sont gratuits, fonctionnent avec n8n auto-hébergé (et n8n
Cloud une fois que n8n les a vérifiés) et n’utilisent que l’API publique de ReputeCast.

## Avant de commencer

- Vous avez besoin de `integrations:manage` (Propriétaire ou Admin). Lisez
  [Connecter d’autres outils](/fr/integrations/overview/) pour comprendre le fonctionnement des clés, des états et du
  journal d’appels.
- n8n n’a besoin de joindre votre instance que pour les actions : n8n et ReputeCast peuvent donc partager un réseau
  privé. Les déclencheurs vont dans l’autre sens (ReputeCast envoie les événements à n8n) : voir
  [n8n sur un réseau privé](#n8n-sur-un-réseau-privé).

## Ce que l’intégration peut faire

**ReputeCast Trigger** lance un workflow quand :

| Événement | Événement ReputeCast | Nécessite |
|---|---|---|
| Contact Subscribed | `contact.subscribed` | `subscribers:view` |
| Contact Unsubscribed | `contact.unsubscribed` | `subscribers:view` |
| Contact Updated | `contact.updated` | `subscribers:view` |
| Form Submitted (n’importe quel formulaire, ou un seul) | `form.submitted` | `subscribers:view` |
| Campaign Sent | `campaign.completed` | `campaigns:view` |
| Transactional Message Bounced | `message.bounced` | `transactional:view` |

Activer le workflow crée un webhook dans ReputeCast, qui apparaît en lecture seule comme « Gérée par n8n » dans
<UiPath path="nav.settings > settings.webhooks" /> ; le désactiver le retire. Chaque livraison est vérifiée avec le secret
de signature du webhook : une livraison qui ne correspond pas, ou qui date de plus de 5 minutes, est refusée et ne lance
rien.

**ReputeCast** fait ceci :

| Ressource › Opération | Ce qu’elle fait | Nécessite |
|---|---|---|
| Contact › Create or Update | Recherche par e-mail ; définit les noms, les champs personnalisés, la langue et les tags ; ajoute à des listes en opt-in simple ou double opt-in | `subscribers:create`, `subscribers:edit` |
| Contact › Add to List | Opt-in simple ou double opt-in | `subscribers:edit` |
| Contact › Add Tag | Un ou plusieurs tags | `subscribers:edit` |
| Event › Record | Un événement d’API avec des propriétés ; démarre les automatisations qui l’attendent | `subscribers:edit` |
| Transactional Email › Send | Un modèle publié, un destinataire, ses variables (associées champ par champ) et une langue facultative | `transactional:send` (sensible) |

L’AI Agent de n8n peut utiliser le nœud ReputeCast comme outil. Il ne peut faire que ce que la clé autorise, et l’envoi
d’e-mails transactionnels est désactivé au départ quand vous connectez n8n.

## Installer les nœuds

Dans n8n, ouvrez **Settings › Community nodes › Install**, saisissez `n8n-nodes-reputecast` et confirmez. n8n
auto-hébergé peut aussi les installer avec `npm install n8n-nodes-reputecast` dans `~/.n8n/nodes`. Sur n8n Cloud, les
nœuds apparaissent dans le panneau des nœuds une fois que n8n les a vérifiés.

## Connecter n8n

<Steps>

1. Dans ReputeCast, ouvrez <UiPath path="nav.settings > settings.integrations" />, trouvez n8n sous
   <UiPath path="integrations.groupAutomation" /> et choisissez <UiPath path="integrations.connect" />.

2. Choisissez ce que n8n peut faire. Send a transactional email est désactivé au départ, car il nécessite l’autorisation
   sensible `transactional:send`. Choisissez <UiPath path="integrations.createKey" /> et copiez la clé (`rc_live_…`) ;
   elle n’est affichée qu’une fois.

3. Dans n8n, ajoutez un identifiant **ReputeCast API** avec :

   - **Instance URL** : votre adresse ReputeCast, par exemple `https://reputecast.acme.io`.
   - **Key** : la clé de l’étape 2.

4. Enregistrez. n8n teste la connexion (`GET /api/v1/integration`), et la boîte de dialogue de connexion de ReputeCast
   affiche l’arrivée de l’appel. L’identifiant apprend à quel espace de travail appartient la clé et le conserve.

</Steps>

### n8n sur un réseau privé

Quand n8n tourne sur une adresse privée (par exemple `n8n.acme.internal`), ReputeCast refuse de lui envoyer les
événements des déclencheurs tant qu’un exploitant n’a pas autorisé les webhooks vers des adresses privées avec
[`webhooks.allow_private_networks`](/fr/reference/configuration/) (`REPUTECAST_WEBHOOKS__ALLOW_PRIVATE_NETWORKS=true`).
Les actions fonctionnent dans les deux cas. Lisez [Sécurité et durcissement](/fr/self-hosting/security/) avant de
l’activer.

## Bon à savoir

- **Noms des workflows.** Chaque appel porte `X-ReputeCast-Workflow: <workflow name>; id=<workflow ID>` : ReputeCast
  liste ainsi les workflows qui l’utilisent, avec leurs appels et leurs erreurs, sur sa page n8n.
- **Le consentement est respecté.** ReputeCast ne réinscrit jamais quelqu’un à une liste qu’il a quittée, n’ajoute jamais
  d’adresse exclue et ne lui envoie pas d’e-mail transactionnel. Un tel élément ressort sous la forme
  `{ "skipped": true, "code": "unsubscribed", "reason": "rob@example.net left Beta Program on 2 Oct…" }`, et le workflow
  continue avec les autres éléments.
- **Des erreurs formulées par ReputeCast.** Les autres refus font échouer le nœud avec la phrase de ReputeCast : une
  variable de modèle manquante, une action désactivée (« Change what n8n can do in Settings › Integrations »),
  une clé révoquée (« Reconnect n8n… ») ou une clé dont le propriétaire est parti (« …take it over… »). Activez
  **Continue On Fail** pour continuer malgré tout.
- **Idempotence.** Transactional Email › Send accepte une **Idempotency Key** facultative, comme l’ID de l’événement
  déclencheur. ReputeCast n’envoie rien de nouveau quand la même valeur revient dans les 24 heures.
- **Renouveler** la clé dans ReputeCast laisse l’ancienne fonctionner pendant 24 heures : collez la nouvelle dans
  l’identifiant d’ici là.
- **Les clés limitées à une liste** ne peuvent pas activer les déclencheurs de contact et de formulaire : leurs
  événements portent des contacts de toutes les listes. Un déclencheur a aussi besoin de l’autorisation de consultation
  de ce que porte son événement, comme tout webhook.

## Dépannage

- **Un déclencheur ne se déclenche jamais** : vérifiez que le workflow est actif et que le webhook est listé dans
  <UiPath path="nav.settings > settings.webhooks" />. Pour n8n sur une adresse privée, voir
  [n8n sur un réseau privé](#n8n-sur-un-réseau-privé).
- **« Reconnect n8n… »** : la clé a été révoquée ou a expiré. Choisissez <UiPath path="integrations.reconnect" /> dans
  ReputeCast et collez la nouvelle clé dans l’identifiant.
- **« …take it over… »** : la personne qui a connecté n8n est partie. Choisissez <UiPath path="integrations.takeOver" />.
  Les webhooks des workflows, que ReputeCast avait mis en pause au départ de cette personne, fonctionnent de nouveau et
  envoient ce qui attendait.
