ReputeCast inclut un serveur [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) : un assistant IA peut
lire les rapports, consulter le contrôle avant envoi, rédiger des campagnes ou mettre un envoi en pause dans votre
espace de travail. C’est un serveur MCP e-mail marketing que les équipes gardent sous contrôle. Chaque
[agent MCP](/fr/reference/glossary/#mcp-agent) a son propre jeton et ses propres autorisations, jamais plus que la
personne qui l’a créé, et tout ce qui enverrait des e-mails est transmis à une personne sous forme de proposition au
lieu de s’exécuter.

## Avant de commencer

- Il vous faut `mcp:manage` dans l’espace de travail (une
  [autorisation sensible](/fr/reference/glossary/#sensitive-permission)). Vous ne pouvez donner à un agent que des
  autorisations que vous détenez vous-même.
- Votre instance a besoin d’une URL publique que votre client MCP peut joindre en HTTPS. L’endpoint est
  `<public URL>/mcp`, servi par le rôle web.
- Si ReputeCast tourne derrière un reverse proxy, `/mcp` doit diffuser les réponses en continu, sans mise en mémoire
  tampon. Voir [Reverse proxy et TLS](/fr/self-hosting/reverse-proxy/).

## Créer un agent

<Steps>

1. Ouvrez <UiPath path="nav.settings > settings.keys" />. La carte MCP, en haut, affiche l’endpoint, par exemple
   `https://reputecast.example.com/mcp`.

2. Sélectionnez <UiPath path="keys.addAgent" />. Donnez à l’agent un nom qui indique qui l’utilise, comme
   « Claude: analytics ».

3. Choisissez ses autorisations. Commencez par un accès en lecture, comme `reports:view` et `deliverability:view`, et
   ajoutez-en plus tard. Une autorisation que vous ne détenez pas est verrouillée. Les agents ne peuvent jamais
   détenir `subscribers:verify`, `placement:run`, `placement:manage`, `coupons:manage`, `comments:moderate`,
   `replies:view` ni `replies:manage` (les clés API le peuvent), ni `integrations:manage`, `ai:use` ou les
   autorisations d’agence (réservées aux personnes). Les réponses, les commentaires du site web et les réserves de codes
   de réduction restent l’affaire des personnes. Disponible à partir de la prochaine version après la 1.6.0.

4. Si besoin, limitez l’agent à certaines listes, définissez une expiration et remplissez
   <UiPath path="keys.allowedIpsLabel" /> ([limiter un agent à des IP autorisées](#limiter-un-agent-à-des-ip-autorisées)),
   puis créez-le.

5. Copiez le jeton, `rc_agent_…`. Il n’est affiché qu’une fois ; ReputeCast n’en garde que le hash SHA-256.

</Steps>

## Connecter votre client MCP

Le serveur utilise le transport **Streamable HTTP** de MCP. Chaque requête porte le jeton de l’agent comme jeton
bearer :

```http title="En-têtes de requête"
Authorization: Bearer rc_agent_…
```

ReputeCast n’accepte ici que les jetons d’agent : une clé API (`rc_live_…`) ou un cookie de session est refusé.
Choisissez votre client ci-dessous. Les exemples lisent le jeton dans la variable d’environnement
`REPUTECAST_AGENT_TOKEN` ; remplacez `reputecast.example.com` par votre URL publique.

<Tabs syncKey="mcp-client">
<TabItem label="Claude Code">

```sh title="Terminal"
claude mcp add --transport http reputecast https://reputecast.example.com/mcp \
  --header "Authorization: Bearer $REPUTECAST_AGENT_TOKEN"
```

Pour partager le serveur avec un projet, ajoutez-le plutôt à `.mcp.json` à la racine du projet. Claude Code a besoin
de `"type": "http"` sur un serveur qui a une `url` ; une entrée sans `type` est lue comme une commande locale et
ignorée :

```json title=".mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Lancez `claude mcp get reputecast` pour vérifier la connexion. Source :
[documentation MCP de Claude Code](https://code.claude.com/docs/en/mcp), vérifiée en octobre 2026.

</TabItem>
<TabItem label="Cursor">

Ajoutez le serveur à `~/.cursor/mcp.json` (tous les projets) ou à `.cursor/mcp.json` (un seul projet) :

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${env:REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Cursor remplit `${env:NAME}` à partir de votre environnement. Source :
[documentation MCP de Cursor](https://cursor.com/docs/context/mcp), vérifiée en octobre 2026.

</TabItem>
<TabItem label="VS Code">

Ajoutez le serveur à `.vscode/mcp.json` dans votre espace de travail. VS Code demande le jeton une fois et le stocke de
façon sécurisée :

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "reputecast-agent-token",
      "description": "ReputeCast agent token (rc_agent_…)",
      "password": true
    }
  ],
  "servers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${input:reputecast-agent-token}" }
    }
  }
}
```

Source : [référence de configuration MCP de VS Code](https://code.visualstudio.com/docs/copilot/reference/mcp-configuration),
vérifiée en octobre 2026.

</TabItem>
<TabItem label="Autres clients">

Tout client qui se connecte à un serveur MCP distant par URL et vous laisse définir un en-tête de requête fonctionne.
La plupart utilisent cette forme ; consultez la documentation de votre client pour le nom du fichier et pour savoir
s’il a aussi besoin de `"type": "http"` :

```json title="mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer rc_agent_…" }
    }
  }
}
```

Un client qui ne démarre que des serveurs locaux (stdio) a besoin d’une passerelle locale vers un serveur HTTP
distant ; ReputeCast n’en fournit pas.

</TabItem>
</Tabs>

<Aside type="danger" title="Traitez le jeton comme un mot de passe">
Toute personne qui possède le jeton peut agir en tant qu’agent. Gardez-le hors des dépôts partagés : utilisez une
variable d’environnement ou la saisie de secret de votre client, comme ci-dessus. S’il fuit, révoquez l’agent dans
<UiPath path="nav.settings > settings.keys" />.
</Aside>

## Ce qu’un agent peut faire

Le serveur propose 61 outils, 3 ressources et 2 prompts. Chaque outil vérifie une autorisation, exactement comme une
clé API, et les campagnes peuvent être désignées par leur nom ou leur ID. La liste complète, avec l’autorisation et
l’effet de chaque outil, se trouve dans [outils, ressources et prompts MCP](/fr/reference/mcp-tools/).

- **Lecture** : listes et rapports de campagnes, contrôle avant envoi, statistiques d’envoi en direct, santé des
  fournisseurs, routage, délivrabilité, tests de placement, un contact par ID ou par adresse, listes, formulaires
  d’inscription, automatisations avec les chiffres de leur onglet <UiPath path="automations.flow.tabStats" />, la file
  des approbations, récapitulatifs, sondages, croissance, revenus, offres et contenu du site web.
- **Modification** : créer des brouillons de campagne, de SMS, de notification push, de WhatsApp et d’article du site
  web ; mettre à jour le contenu d’une campagne ; créer des segments ; ajouter des adresses à la liste de
  suppression ; modifier les poids du routage ; mettre en pause et reprendre des envois ; créer des liens de rapport
  en lecture seule qui expirent, avec `share_campaign_report` (nécessite `reports:share`).
- **Des brouillons comme ceux de l’éditeur** : un brouillon de campagne qu’un agent crée ou modifie est stocké comme
  l’[éditeur](/fr/campaigns/composer/#ce-que-vérifie-le-serveur) stocke celui d’une personne. Le serveur compile le
  MJML (une erreur MJML est refusée), le contrôle, conserve l’objet et le texte d’aperçu dans l’en-tête MJML, et
  enregistre chaque modification comme une nouvelle version dans l’historique, marquée comme faite par une clé API ou
  un agent. Une modification n’annule jamais l’approbation ou la demande en attente d’une personne : l’appel échoue
  avec `409 approval_would_cancel`.
- **Envoyer un test** : `send_test_email` n’envoie un test de campagne qu’aux membres de l’espace de travail, via le
  flux Système.
- **E-mail transactionnel** : en lecture seule. Les agents listent les modèles, en font le rendu et cherchent dans le
  journal des messages, mais n’envoient jamais de messages transactionnels.
- **Ressources** : le MJML d’une campagne, un rapport en CSV et les 100 dernières entrées du journal d’audit.

`get_campaign_report` renvoie le rapport qu’affiche l’application, construit par le même code : les ouvertures
humaines, celles protégées par la confidentialité et celles des scanners séparées, le taux d’ouverture mesurable, les
plaintes uniquement là où les fournisseurs de messagerie les signalent, les liens (par variante pour un test de
contenu) et la décision A/B avec son niveau de confiance. Un agent répond à partir de ces chiffres, comme les
présentent les [rapports de campagne](/fr/campaigns/reports/).

Les autorisations d’un agent sont revérifiées à chaque appel par rapport au rôle actuel de son créateur. Quand le
créateur perd une autorisation, l’agent la perd aussi ; quand le créateur quitte l’espace de travail ou est désactivé,
l’agent ne peut plus rien faire.

Ses listes suivent la même règle (depuis la version 1.5.0) : à chaque appel, elles sont réduites aux listes et aux
domaines d’expéditeur que son créateur atteint à ce moment-là. Un agent limité à certaines listes ne trouve que les
contacts qui y figurent avec `search_contacts` et `get_contact`, et `resume_campaign` ne reprend qu’une campagne dans ses
listes et ses domaines d’expéditeur, comme le peut dans ReputeCast une personne limitée de la même façon.

## Limiter un agent à des IP autorisées

Un agent peut être limité aux adresses depuis lesquelles son client appelle : jusqu’à 50 adresses et réseaux IPv4 ou
IPv6, comme `203.0.113.7` ou `203.0.113.0/24` (depuis la version 1.6.0). Une liste vide, la valeur par défaut, autorise
toutes les adresses.

<Steps>

1. Dans la matrice des agents, sélectionnez <UiPath path="keys.allowedIpsButton" /> sur la ligne de l’agent.

2. Saisissez une adresse ou un réseau par ligne. Le champ indique d’où le jeton a été utilisé pour la dernière fois et
   votre propre adresse telle que ReputeCast la voit, chacune avec un lien pour l’ajouter.

3. Enregistrez. Une liste qui omet l’adresse depuis laquelle le jeton a été utilisé pour la dernière fois demande
   d’abord confirmation ; ne choisissez <UiPath path="keys.saveAnyway" /> que si ce client doit être refusé.

</Steps>

Le contrôle a lieu après la vérification du jeton. Un appel depuis une autre adresse, ou depuis une adresse que
ReputeCast ne peut pas déterminer, répond `401` avec
`this agent can't be used from <address>; add the address to its allowed IPs in Settings › Keys & MCP`, et il est
compté. Derrière un reverse proxy, listez d’abord le proxy dans `http.trusted_proxies`, sinon chaque appel semble venir
du proxy ; la boîte de dialogue avertit quand cela peut être le cas. Permettre d’appeler l’agent depuis davantage
d’endroits nécessite toutes les autorisations que détient l’agent et des listes dans votre propre portée, comme son
renouvellement. C’est une personne connectée qui définit la liste, ici ou avec
`PUT /api/v1/workspaces/<workspace>/mcp-agents/<keyId>/allowed-ips` ; le changement figure dans le journal d’audit sous
`agent.updated`. Les règles sont les mêmes que pour les
[clés API](/fr/developers/api-authentication/#limiter-une-clé-à-des-ip-autorisées).

## Des propositions pour tout ce qui envoie

Les agents ne lancent pas d’envois.

- `schedule_campaign` ne programme jamais. Il enregistre une proposition pour le premier membre qui détient
  `campaigns:send`, qui reçoit une notification (« Claude: analytics propose de programmer “Weekly Digest #142” ») avec
  un lien vers la campagne. Cette personne la programme dans ReputeCast, où le contrôle avant envoi et les approbations
  s’appliquent comme d’habitude. `propose_send` fait de même pour un brouillon SMS, push ou WhatsApp, à envoyer
  maintenant ou à l’heure que vous indiquez.
- Un appel pour lequel l’agent n’a pas l’autorisation est refusé. L’agent reçoit une erreur qui nomme l’autorisation
  manquante, le refus est consigné dans le journal d’audit, et une proposition part vers le premier membre qui la
  détient.
- La notification indique quand la proposition expire : 2 heures par défaut, de 1 à 168 heures sous
  <UiPath path="keys.changeLimits" />. ReputeCast n’exécute jamais une proposition lui-même : l’expiration indique donc
  à la personne combien de temps la demande reste d’actualité ; rien ne se passe une fois ce délai dépassé.
- `pause_campaign` nécessite `campaigns:pause` et met en pause immédiatement. `resume_campaign` nécessite
  `campaigns:send` et reprend immédiatement : ne donnez `campaigns:send` à un agent que s’il a le droit de relancer un
  envoi en pause.

## Audit et limites

Chaque appel d’outil est consigné dans le journal d’audit avec l’agent comme acteur, le nom de l’outil et le résultat,
y compris les appels refusés. <UiPath path="keys.recentAgentActions" />, sur la même page, affiche les derniers
appels ; ouvrez le [journal d’audit](/fr/team/audit-log/) pour le reste.

<UiPath path="keys.changeLimits" /> définit le nombre d’appels par minute et par agent et l’expiration des
propositions pour l’espace de travail, et permet de désactiver le serveur MCP. Tant qu’il est désactivé, tous les
jetons d’agent sont refusés. Un agent qui dépasse sa limite reçoit `429` avec `Retry-After: 60`.

## Vérifier le résultat

- Demandez à votre assistant de lister les outils du serveur `reputecast`, ou d’appeler `list_campaigns`. Il doit
  lister vos campagnes.
- Dans <UiPath path="nav.settings > settings.keys" />, le dernier appel de l’agent apparaît dans la matrice des agents
  et sous <UiPath path="keys.recentAgentActions" />.

## Dépannage

- **401 « use an MCP agent token (rc_agent_…) »** : le client envoie une clé API ou aucun en-tête. Créez un agent et
  utilisez son jeton.
- **401 « this agent was revoked » ou « … expired »** : créez un nouvel agent ou renouvelez son jeton dans
  <UiPath path="nav.settings > settings.keys" />.
- **401 « the MCP server is off »** : activez-le sous <UiPath path="keys.changeLimits" />.
- **401 « this agent can’t be used from … »** : le client appelle en dehors des IP autorisées de l’agent. Ajoutez
  l’adresse que nomme l’erreur avec <UiPath path="keys.allowedIpsButton" />, ou listez votre reverse proxy dans
  `http.trusted_proxies` quand l’adresse est celle du proxy.
- **Le client se connecte, mais chaque outil est refusé** : l’agent n’a pas l’autorisation, ou son créateur ne la
  détient plus. L’erreur nomme l’autorisation.
- **L’agent ne trouve aucun contact, ou moins que prévu** : l’agent, ou le membre qui l’a créé, est limité à certaines
  listes.
- **Claude Code ignore le serveur** : l’entrée de `.mcp.json` a une `url` mais pas de `"type": "http"`.
- **Les appels restent bloqués ou expirent derrière un proxy** : le proxy met en mémoire tampon les réponses de
  `/mcp`. Désactivez la mise en mémoire tampon pour ce chemin.
- **Erreurs 429** : l’agent a fait plus d’appels par minute que l’espace de travail n’en autorise. Relevez la limite ou
  ralentissez l’agent.
