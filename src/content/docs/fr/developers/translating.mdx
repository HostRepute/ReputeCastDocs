L’interface de ReputeCast existe en anglais, allemand, espagnol, français et vietnamien (allemand, espagnol et
français à partir de la version qui suit la 1.3.1) : l’application, les pages de connexion et d’invitation, les
messages du serveur aux membres (erreurs avec leur correction, « qui peut aider », notifications) et les e-mails que
ReputeCast envoie aux membres. Ce guide montre aux traducteurs et aux développeurs comment traduire ReputeCast dans
une autre langue, ou en terminer une, et comment vérifier le résultat.

Ce qu’un espace de travail envoie à ses contacts (campagnes, e-mails transactionnels, pages publiques et formulaires)
est traduit par l’espace de travail lui-même, sous forme de versions linguistiques dans l’éditeur. Voir
[Envoyer à chaque lecteur sa langue](/fr/campaigns/languages/).

## Avant de commencer

- Une copie locale de ReputeCast qui s’exécute depuis les sources
  ([Exécuter ReputeCast depuis les sources](/fr/developers/contributing/)).
- Le glossaire de votre langue, s’il existe. Le glossaire vietnamien,
  [`docs/i18n/glossary-vi.md`](https://github.com/hostrepute/reputecast/blob/main/docs/i18n/glossary-vi.md), fixe
  les mots de chaque écran ; les glossaires allemand, espagnol et français (`glossary-de.md`, `glossary-es.md`,
  `glossary-fr.md`) suivent ses sections. Traduisez d’abord les termes du glossaire, puis les écrans.

<Aside type="note" title="Les langues que l’on peut choisir">
Les versions publiées ne proposent que les langues complètes : rien de manquant et aucun texte codé en dur restant.
Aujourd’hui, ce sont l’anglais et le vietnamien ; à partir de la version qui suit la 1.3.1, l’allemand, l’espagnol et
le français aussi. Voir [Changer la langue de l’application et le format régional](/fr/team/language-and-region/).
</Aside>

## Où se trouve le texte

<TableScroll label="Où se trouve le texte" wrap>

| Quoi                                         | Source anglaise                                              | Traduction                                 |
| -------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------ |
| L’application web                            | `web/src/**/messages.ts`, `web/src/**/<screen>.messages.ts`  | `messages.<code>.ts` à côté de la source   |
| Les messages du serveur et les e-mails aux membres | `internal/<package>/messages/en.json`                  | `internal/<package>/messages/<code>.json`  |
| Les mots qu’utilise ReputeCast               |                                                              | `docs/i18n/glossary-<code>.md`             |

</TableScroll>

Une source web déclare ses messages avec un ID (`namespace.key`) :

```ts title="web/src/features/campaigns/messages.ts"
export const m = defineMessages('campaigns', {
  newCampaign: 'New campaign',
  blockingIssues: '{count, plural, one {# blocking issue} other {# blocking issues}}',
})
```

Sa traduction reprend les clés qu’elle traduit :

```ts title="web/src/features/campaigns/messages.vi.ts"
export default translate(m, {
  newCampaign: 'Chiến dịch mới',
  blockingIssues: '{count} lỗi chặn gửi',
})
```

Une source qui définit plusieurs groupes (`mb`, `m`, `mp`) reçoit un `translate()` par groupe, réunis ensemble :
`export default { ...translate(mb, { … }), ...translate(m, { … }) }`.

Un catalogue serveur est un objet JSON de la forme `"key": "text"`, ou `"key": { "message": "text", "note": "for translators" }`
quand l’anglais a besoin d’explications. Lisez les notes : elles disent ce que contient un argument. Quelques clés sont
construites à partir de données, comme `short.<event type>` dans `internal/notify/messages`. Un nouveau type
d’événement affiche son anglais depuis le code tant que sa clé n’a pas été ajoutée à `en.json` : ajoutez-la donc quand
vous ajoutez le type.

Une clé absente d’une traduction s’affiche en anglais : un écran n’est donc jamais vide.

## Rédiger une traduction

Les messages utilisent [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/) :

- **Les arguments** entre accolades sont remplis par l’application : `{name}`, `{count}`, `{date}`. Gardez-les écrits
  exactement comme dans l’anglais et placez-les là où votre langue les met : `edited {time} by {name}` devient
  `{name} sửa lúc {time}`.
- **Les pluriels** : `{count, plural, one {# day} other {# days}}`. Utilisez les catégories de pluriel de votre langue
  (CLDR). Le vietnamien n’a que `other` : `{count} ngày` suffit donc. `=1 {…}` correspond à un nombre exact quand la
  formulation change.
- **Les choix** : `{status, select, drafts {…} sent {…} other {…}}`. Gardez les valeurs de gauche (`drafts`, `sent`,
  `other`) et traduisez le texte entre accolades.
- **Les balises** marquent le texte que l’application met en forme ou transforme en lien : `<b>…</b>`,
  `<link>…</link>`, `<mono>…</mono>`, `<k>…</k>`, `<kbd>…</kbd>`. Gardez chaque balise autour des mots qui jouent le
  même rôle.
- Un message est une phrase ou un libellé entier. Ne le découpez pas, et ne comptez pas sur deux messages affichés
  côte à côte dans un certain ordre.
- **Les noms de langues** (`{language}`, `{languages}`) arrivent sous la forme de libellé que votre langue utilise
  seule. Le vietnamien écrit « tiếng » en minuscules à l’intérieur d’une phrase, et l’application le fait d’après la
  place de l’argument : écrivez donc `{language}`, jamais `tiếng {language}`.
- Une apostrophe peut rester telle quelle (`isn't`, `l'été`). Pour afficher une accolade comme du texte, mettez-la
  entre apostrophes : `'{'`.

**Ne traduisez jamais** le contenu des espaces de travail (noms de campagnes, de listes, de segments, de modèles, de
formulaires et de rôles personnalisés), les noms et les adresses e-mail des personnes, les clés d’autorisation
(`campaigns:send`), les noms d’actions d’audit, les codes d’erreur de l’API, les noms et codes des fournisseurs
(Amazon SES, Postal, Postmark), les noms de produits (ReputeCast, HostRepute, Gmail, Outlook), les enregistrements DNS
et leurs types (SPF, DKIM, DMARC, BIMI, CNAME), les en-têtes (`List-Unsubscribe`), les exemples de code, la sortie de
la CLI, ni les termes MCP, 2FA, TOTP, IdP, SSO, JIT, A/B, HTML, CSS, API et webhook.

**Les nombres, les dates et les heures** viennent du format régional du lecteur, jamais d’une traduction : écrivez
`{date}`, pas une date. Les formats régionaux sont indépendants de la langue : un membre peut donc lire l’anglais avec
les formats vietnamiens.

## Vérifier votre traduction

<Steps>

1. Lancez le contrôle depuis le dossier `web` :

   ```sh title="Terminal"
   cd web
   pnpm run i18n:check              # every missing message, by file
   pnpm run i18n:check --lang vi    # one language
   pnpm run i18n:check --summary    # one line per language
   pnpm run i18n:check --hardcoded  # every hard-coded string, with its line
   ```

   Il lit les sources et les traductions web ainsi que les catalogues du serveur. Il liste les messages qui manquent
   à chaque langue, regroupés par le fichier qui définit leur anglais, et compte le texte codé en dur qui reste dans
   les écrans (texte JSX, et chaînes simples dans les attributs que les personnes lisent, comme `title`, `label`,
   `placeholder` et `aria-label`). Un littéral qui n’est pas du texte à traduire, comme un format, va dans une
   expression : `placeholder={'xxxx-xxxx-xxxx'}`.

2. Corrigez ce qui échoue. Le contrôle échoue sur un message qui n’est pas de l’ICU valide, sur une clé traduite que
   l’anglais n’a pas, et sur un argument ou une balise que l’anglais n’utilise pas. Un catalogue serveur est aussi
   vérifié au chargement de son package : une traduction cassée arrête donc le serveur et tous les tests Go à la fois.

3. Commitez `web/src/i18n/status.gen.ts` quand il change. Le contrôle l’écrit avec les langues complètes dans ce
   build, et chaque build lance d’abord le contrôle.

4. Regardez les écrans. Changez votre propre langue d’application dans
   <UiPath path="shell.userMenuAccount > language.title" />, et lisez les écrans de test de résistance
   (<UiPath path="nav.campaigns" />, <UiPath path="composer.reviewSend" /> et
   <UiPath path="nav.settings > settings.team" />) en 1440 et 390 px. Les mots longs doivent passer à la ligne ou se
   raccourcir, jamais déborder ni être coupés ; la section « Text expansion » de `docs/dev/CONVENTIONS.md` montre
   comment faire.

</Steps>

### Trouver le texte non traduit avec la pseudo-locale

La pseudo-locale <UiPath path="language.pseudoLocale" /> accentue chaque lettre, rallonge chaque message d’environ
40 % et l’entoure de ⟦ ⟧ :
« ⟦Šçĥéðûļé šéñð ţö 31,604 ŕéçîþîéñţš ·········⟧ ». Un texte sans les crochets n’est pas passé par le système de
traduction ; un ⟧ manquant signale un texte coupé.

Elle figure dans le sélecteur de langue en développement. Sur un serveur de préproduction, activez-la avec
`i18n.pseudo_locale` (`REPUTECAST_I18N__PSEUDO_LOCALE=true` ; voir la
[référence de configuration](/fr/reference/configuration/)).

## Ajouter une langue

<Steps>

1. Rédigez d’abord le glossaire, `docs/i18n/glossary-<code>.md`, en suivant les sections du glossaire vietnamien.

2. Ajoutez la langue à `web/src/i18n/languages.ts` (`APP_LANGUAGES`, avec son nom dans sa propre langue) et à
   `internal/i18n/locale.go` (`appLocales`), et choisissez le format régional qu’elle utilise par défaut
   (`defaultRegionFor` dans l’application web, `DefaultRegion` sur le serveur). Les règles de pluriel viennent du CLDR
   des deux côtés.

3. Si son format régional manque, ajoutez-le à `internal/i18n/region.go` et à `web/src/i18n/regions.ts`, avec des
   vecteurs de test dans `internal/i18n/testdata/regions.json` que les deux côtés doivent passer.

4. Ajoutez des fichiers `messages.<code>.ts` pour l’application web et `messages/<code>.json` pour les packages du
   serveur, et lancez `pnpm run i18n:check --lang <code>` jusqu’à ce qu’il ne liste plus rien.

5. Vérifiez les polices. IBM Plex couvre le latin, le vietnamien, le cyrillique et le grec ; une autre écriture
   nécessite un sous-ensemble de police dans `web/src/styles/fonts.css`.

</Steps>

Une personne de langue maternelle relit une langue avant qu’elle soit livrée dans une version. ReputeCast ne prend pas
encore en charge les langues qui s’écrivent de droite à gauche.

## Vérifier le résultat

- `pnpm run i18n:check --lang <code> --summary` ne signale rien de manquant et aucun texte codé en dur.
- Avec votre langue choisie dans <UiPath path="shell.userMenuAccount > language.title" />, les écrans que vous avez
  traduits n’affichent pas d’anglais ni rien entre crochets ⟦ ⟧.

## Dépannage

- **Un écran affiche encore de l’anglais** : sa clé manque dans votre fichier (le contrôle la liste), ou le texte est
  codé en dur dans l’écran (`--hardcoded` le liste).
- **Le serveur ne démarre plus après une modification d’un catalogue `.json`** : le catalogue contient de l’ICU non
  valide, une clé inconnue ou un argument que l’anglais n’a pas. L’erreur nomme la clé.
- **Votre langue n’est pas dans le sélecteur d’une version publiée** : elle n’est pas encore complète. Les builds de
  développement affichent toutes les langues.
