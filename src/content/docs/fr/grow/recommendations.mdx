Les recommandations de newsletters présentent d’autres newsletters à vos lecteurs juste après la confirmation de leur
abonnement, ainsi que dans vos e-mails. Une [recommandation](/fr/reference/glossary/#recommendation) est soit un simple
lien vers la page d’inscription de n’importe quelle newsletter, soit un lien partenaire vers une newsletter hébergée sur
une autre instance ReputeCast, où les lecteurs s’abonnent en un clic et confirment via le double opt-in du partenaire.

## Avant de commencer

- Ajouter des recommandations de type lien, les ordonner et choisir où elles s’affichent nécessite l’autorisation
  `grow:edit`. Les Propriétaires, les Admins et les Éditeurs l’ont.
- Les liens partenaires nécessitent `grow:connect`, une autorisation sensible que seuls les Propriétaires et les Admins
  ont. Seules des personnes peuvent utiliser ces autorisations ; les clés API et les agents ne peuvent pas modifier les
  recommandations.
- Pour les liens partenaires, les deux newsletters utilisent ReputeCast, et les deux instances ont une URL publique
  définie par un admin de l’instance.

## Choisir entre lien et partenaire

- **Lien :** la page d’inscription de n’importe quelle newsletter. Les lecteurs s’abonnent sur l’autre site, vous ne
  voyez donc que les clics.
- **Partenaire sur ReputeCast :** les lecteurs s’abonnent depuis vos pages en un clic, et le partenaire leur écrit pour
  qu’ils confirment. Vous voyez les demandes et les confirmations ; aucune des deux parties ne voit les lecteurs de
  l’autre.

## Ajouter un lien

<Steps>

1. Ouvrez <UiPath path="nav.grow > grow.tabRecommendations" /> et sélectionnez
   <UiPath path="grow.recommendations.addRecommendation" />.
2. Sélectionnez <UiPath path="grow.recommendations.addLink" />.
3. Saisissez la page d’inscription de la newsletter (une adresse `https://` ; les adresses privées et de loopback sont
   refusées) et sélectionnez <UiPath path="grow.recommendations.prefill" /> pour récupérer son nom, sa description et
   son logo.
4. Vérifiez le nom et la description destinés aux lecteurs (120 caractères au maximum), puis choisissez où la
   recommandation s’affiche : la page de confirmation, le bloc Recommandations des e-mails, ou les deux.
5. Sélectionnez <UiPath path="grow.recommendations.addRecommendation" />. Elle s’affiche dès maintenant pour les
   lecteurs.

</Steps>

## Connecter une newsletter partenaire

La newsletter que vous recommandez crée un code partenaire, et vous le collez.

<Steps>

1. **Le partenaire** ouvre <UiPath path="nav.grow > grow.tabRecommendations" />, sélectionne
   <UiPath path="grow.recommendations.letRecommend" />, indique à qui le code est destiné, la liste proposée et une
   limite quotidienne (50 par défaut), puis sélectionne <UiPath path="grow.recommendations.codeCreate" />. Le code
   s’affiche une seule fois, ne sert qu’une fois et expire au bout de 7 jours. Le partenaire vous l’envoie.
2. **Vous** sélectionnez <UiPath path="grow.recommendations.addRecommendation" />, puis
   <UiPath path="grow.recommendations.addPartner" />, et vous collez le code.
3. ReputeCast demande son profil à l’instance du partenaire via HTTPS et affiche son nom, sa description, sa liste et
   sa limite quotidienne. Sélectionnez <UiPath path="grow.recommendations.connect" />.

</Steps>

Pendant la connexion, les deux instances conviennent d’un secret de signature via HTTPS. Il est stocké chiffré des deux
côtés et n’est jamais affiché.

### Fonctionnement d’une inscription via un partenaire

1. Un lecteur appuie sur S’abonner sur votre page de confirmation ou sur la page hébergée vers laquelle renvoie un
   e-mail.
2. Votre instance envoie au partenaire une demande d’abonnement signée qui ne contient que l’adresse e-mail du lecteur
   et le nom de votre newsletter comme source.
3. Le partenaire ajoute l’adresse en attente et envoie son propre e-mail de confirmation sur son flux Système. Le
   lecteur n’est abonné qu’après avoir confirmé. Une adresse déjà présente dans la liste du partenaire ne reçoit aucun
   e-mail, et la réponse est la même dans les deux cas : vous ne savez donc jamais qui la lit déjà. Ces e-mails
   respectent la [limite d’e-mails de confirmation](/fr/forms/signup-forms/#confirmation-du-double-opt-in) par adresse du
   partenaire ; une demande qui la dépasse attend que le prochain e-mail puisse partir.
4. Le partenaire signale chaque confirmation par un avis signé qui désigne la demande, jamais le lecteur. Votre
   instance ne conserve que des totaux.

Les demandes sont signées avec HMAC-SHA256 sur un horodatage, la méthode, le chemin et le corps ; un horodatage décalé
de plus de 5 minutes est refusé. Une demande restée sans réponse est réessayée pendant 24 heures. Quand la limite
quotidienne du partenaire est atteinte, la recommandation est masquée jusqu’à 00:00 UTC. Le journal des demandes
partenaires conserve 90 jours de demandes et n’affiche jamais d’adresses.

## Où s’affichent les recommandations

- **La page de confirmation :** sous « Pendant que vous êtes là : les newsletters recommandées par… », jusqu’à
  3 recommandations dans votre ordre. Désactivez-la avec <UiPath path="grow.recommendations.whereConfirmSwitch" />.
  Les cartes partenaires ont un bouton S’abonner et indiquent que l’adresse e-mail du lecteur sera transmise à cette
  newsletter ; les cartes de type lien ouvrent l’autre site.
- **Les e-mails :** ajoutez le bloc <UiPath path="grow.composer.blockRecommendations" /> depuis les blocs
  <UiPath path="grow.composer.group" /> de l’éditeur. Ses boutons ouvrent une page hébergée où le lecteur confirme, si
  bien que les scanners de liens ne peuvent abonner personne. Cette page personnelle reste valable 30 jours. Le bloc
  se masque quand rien ne peut s’afficher.

Pour changer l’ordre, faites glisser une recommandation par sa poignée dans
<UiPath path="grow.tabRecommendations" />, ou placez le focus sur la poignée et appuyez sur les flèches du clavier. Le
nouvel ordre s’affiche aussitôt ; s’il ne peut pas être enregistré, la liste revient en arrière et affiche l’erreur.

Affichages compte les pages de confirmation et les e-mails délivrés, pas les ouvertures, car les ouvertures
automatiques le gonfleraient. Consultez [lire les rapports de campagne](/fr/campaigns/reports/) pour savoir comment
ReputeCast distingue les ouvertures humaines des ouvertures automatiques.

## Gérer les liens partenaires

Depuis le menu d’une recommandation partenaire, vous pouvez
<UiPath path="grow.recommendations.menuPausePartner" />, la reprendre, ou
<UiPath path="grow.recommendations.menuEnd" />. Y mettre fin est irréversible : un nouveau partenariat nécessite un
nouveau code partenaire. Le partenaire peut <UiPath path="grow.recommendations.menuChangeLimit" /> pour le lien qu’il
vous a donné. Supprimer une recommandation partenaire met aussi fin à son lien.

Un lien partenaire affiche Connectée tant qu’il fonctionne. Les autres états sont En pause, En pause chez le
partenaire, Limite quotidienne atteinte, Injoignable, Lien invalide et Terminée. Les personnes disposant de
`grow:connect` reçoivent une notification quand un partenaire est injoignable depuis 30 minutes.

## Vérifier le résultat

1. Abonnez-vous à votre propre newsletter avec une adresse qui vous appartient, puis confirmez. La page de
   confirmation liste vos recommandations.
2. Appuyez sur S’abonner sur une carte partenaire. L’e-mail de confirmation du partenaire arrive et cite votre
   newsletter comme source.
3. Dans <UiPath path="grow.tabRecommendations" />, la recommandation compte une demande, puis une confirmation.

## Dépannage

- **« Code expiré » ou « Code déjà utilisé ».** Demandez un nouveau code partenaire au partenaire.
- **« Adresse privée refusée ».** Le code partenaire pointe vers une adresse privée ou de loopback. Demandez au
  partenaire de définir comme URL publique de son instance une adresse joignable depuis Internet.
- **Lien invalide.** L’instance du partenaire rejette votre signature, par exemple après un changement de serveur ou
  la fin du partenariat. Collez un nouveau code partenaire qu’il vous fournit, ou supprimez la recommandation.
- **Limite quotidienne atteinte.** Le partenaire n’accepte plus de demandes de votre part jusqu’à 00:00 UTC. Il peut
  relever la limite.
