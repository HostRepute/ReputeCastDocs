Un reverse proxy pour ReputeCast termine TLS pour votre URL publique et transmet chaque requête au port 8080 de
ReputeCast avec l’en-tête `Host` d’origine, en laissant passer les réponses en streaming sans mise en mémoire tampon.
Les configurations ci-dessous ont été testées avec `caddy:2` (2.11), `nginx:stable-alpine` (1.30) et `traefik:v3`
(3.7) devant ReputeCast en octobre 2026.

## Ce que le proxy doit faire

- **Terminer TLS** pour l’hôte de l’URL publique, et pour les [domaines personnalisés](#domaines-personnalisés) si des
  espaces de travail en utilisent.
- **Transmettre tous les chemins** à ReputeCast : l’application et l’API, `/hooks/…` (les webhooks des fournisseurs
  d’envoi), `/p/…` (les pages publiques), `/t/…` (le suivi des ouvertures et des clics), `/mcp` et `/healthz`, que
  récupère la vérification de l’URL publique.
- **Conserver l’en-tête `Host`.** ReputeCast s’en sert pour reconnaître les domaines personnalisés.
- **Envoyer `X-Forwarded-For`.** ReputeCast ne le lit que depuis les
  [proxys de confiance](#définir-lurl-publique-et-les-proxys-de-confiance), que le proxy prolonge la ligne du client
  ou ajoute sa propre ligne d’en-tête. Il n’a pas besoin de `X-Forwarded-Proto` : il sait qu’il est en HTTPS grâce à
  `http.public_url`.
- **Diffuser sans mise en mémoire tampon** deux types de réponses :
  - le suivi en direct, des Server-Sent Events sur
    `GET /api/v1/workspaces/{workspace}/campaigns/{campaignId}/live/stream` (un battement de cœur toutes les
    15 secondes, `retry: 3000`) ;
  - l’[endpoint MCP](/fr/developers/mcp/) `/mcp` (Streamable HTTP), dont les réponses sont en `text/event-stream`.
- **Accepter des corps de requête volumineux.** ReputeCast fixe une limite par opération ; la plus grande est de
  105 Mio (l’import de modèles transactionnels), et les imports de contacts acceptent 100 Mio.
- **Parler HTTP/2 aux navigateurs.** L’application web charge le code d’un écran en de nombreux petits fichiers : en
  HTTP/2, un navigateur les demande tous à la fois, en HTTP/1.1 six par six. Sur un réseau mobile lent, Contacts
  s’affichait au bout d’environ 6 secondes au lieu de 12. Caddy active HTTP/2 de lui-même ; nginx a besoin de
  `http2 on`.
- **Laisser `/metrics` de côté.** Les métriques Prometheus ont leur propre port, 9464 : ne le faites jamais passer
  par le proxy et ne le publiez jamais. Le port principal répond `404` sur `/metrics`, sauf si un
  [jeton de métriques](/fr/self-hosting/monitoring/) est défini.

## Avant de commencer

- ReputeCast tourne avec [Docker Compose](/fr/self-hosting/docker/) ou en tant que [binaire](/fr/self-hosting/binary/).
- Le nom d’hôte public (ici `news.example.com`) pointe vers le serveur, et les ports 80 et 443 sont ouverts pour
  l’autorité de certification et vos visiteurs.

## Configurer le proxy

Les exemples Caddy et Traefik ajoutent le proxy au projet Compose dans `docker-compose.override.yml`, pour qu’il
joigne ReputeCast sous `app:8080`. Quand le proxy tourne sur le serveur lui-même (une installation du binaire, ou
Compose avec `REPUTECAST_PORT=127.0.0.1:8080`), utilisez plutôt `127.0.0.1:8080`.

<Tabs syncKey="proxy">
<TabItem label="Caddy">

Caddy obtient et renouvelle le certificat lui-même, conserve l’en-tête `Host`, définit `X-Forwarded-For` et transmet
immédiatement les réponses `text/event-stream` : le suivi en direct et MCP n’ont donc besoin d’aucune ligne
supplémentaire ([documentation de reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy),
vérifié en octobre 2026).

```txt title="Caddyfile"
{
	email you@company.com
	on_demand_tls {
		ask http://app:8080/p/_/tls-check
	}
}

news.example.com {
	reverse_proxy app:8080
}

# Workspaces' custom domains for public pages: a certificate only for verified domains.
https:// {
	tls {
		on_demand
	}
	reverse_proxy app:8080
}
```

```yaml title="docker-compose.override.yml"
services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
  app:
    environment:
      # The subnet of the reputecast_default network (see below).
      REPUTECAST_HTTP__TRUSTED_PROXIES: 172.18.0.0/16

volumes:
  caddy_data:
  caddy_config:
```

Omettez le bloc `https://` si aucun espace de travail n’utilise de domaine personnalisé.

</TabItem>
<TabItem label="nginx">

Cette configuration s’adresse à nginx 1.25.1 ou ultérieur (la directive `http2` ; avant la 1.25.1, écrivez
`listen 443 ssl http2;`) sur le serveur lui-même, avec un certificat Let’s Encrypt à l’emplacement par défaut de
Certbot. Par défaut, nginx met en mémoire tampon les réponses qu’il relaie : les deux chemins de streaming désactivent
donc la mise en mémoire tampon.

```nginx title="/etc/nginx/conf.d/reputecast.conf"
upstream reputecast {
    server 127.0.0.1:8080;
    keepalive 16;
}

server {
    listen 80;
    server_name news.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name news.example.com;

    ssl_certificate     /etc/letsencrypt/live/news.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/news.example.com/privkey.pem;

    # ReputeCast enforces its own size limit per operation (largest: 105 MiB).
    client_max_body_size 110m;

    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection "";

    location / {
        proxy_pass http://reputecast;
    }

    # Live monitor (Server-Sent Events) and the MCP endpoint: no buffering.
    location ~ ^/api/v1/workspaces/[^/]+/campaigns/[^/]+/live/stream$ {
        proxy_pass http://reputecast;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 1h;
    }

    location = /mcp {
        proxy_pass http://reputecast;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 1h;
    }
}
```

- Avec la mise en mémoire tampon activée, les événements du suivi en direct arrivaient en retard et par morceaux dans
  le navigateur pendant les tests ; avec la configuration ci-dessus, ils arrivent chaque seconde.
- Le `client_max_body_size` par défaut de nginx est de 1 Mio, trop peu pour les imports de contacts et les pièces
  jointes.
- Quand nginx tourne comme service Compose, utilisez `server app:8080;` et démarrez-le après l’application
  (`depends_on: [app]`) : nginx résout le nom de l’upstream à son démarrage.

</TabItem>
<TabItem label="Traefik">

Traefik lit ses routes dans les labels du conteneur de l’application, obtient le certificat auprès de Let’s Encrypt,
conserve l’en-tête `Host`, définit `X-Forwarded-For` et diffuse les Server-Sent Events sans réglage supplémentaire
([documentation de Traefik](https://doc.traefik.io/traefik/), vérifié en octobre 2026).

```yaml title="docker-compose.override.yml"
services:
  traefik:
    image: traefik:v3
    restart: unless-stopped
    command:
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false
      - --entrypoints.web.address=:80
      - --entrypoints.web.http.redirections.entrypoint.to=websecure
      - --entrypoints.websecure.address=:443
      - --certificatesresolvers.le.acme.email=you@company.com
      - --certificatesresolvers.le.acme.storage=/letsencrypt/acme.json
      - --certificatesresolvers.le.acme.httpchallenge.entrypoint=web
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - letsencrypt:/letsencrypt
  app:
    labels:
      - traefik.enable=true
      - traefik.http.routers.reputecast.rule=Host(`news.example.com`)
      - traefik.http.routers.reputecast.entrypoints=websecure
      - traefik.http.routers.reputecast.tls.certresolver=le
      - traefik.http.services.reputecast.loadbalancer.server.port=8080
    environment:
      # The subnet of the reputecast_default network (see below).
      REPUTECAST_HTTP__TRUSTED_PROXIES: 172.18.0.0/16

volumes:
  letsencrypt:
```

## Définir l’URL publique et les proxys de confiance

<Steps>

1. Définissez `http.public_url` sur l’adresse HTTPS, sans barre oblique finale :
   `REPUTECAST_PUBLIC_URL=https://news.example.com`, dans le `.env` de Compose ou dans l’environnement du binaire.
   L’ancien nom `REPUTECAST_HTTP__PUBLIC_URL` fonctionne toujours quand `REPUTECAST_PUBLIC_URL` n’est pas défini. Avec
   une URL publique en `https://`, ReputeCast envoie HSTS et marque son cookie de session comme Secure.

2. Définissez `http.trusted_proxies` sur les adresses depuis lesquelles le proxy se connecte : `127.0.0.1` pour un
   proxy sur le même serveur que le binaire, ou le sous-réseau du réseau Compose :

   ```sh
   docker network inspect reputecast_default --format '{{(index .IPAM.Config 0).Subnet}}'
   ```

3. Redémarrez ReputeCast (`docker compose up -d`, ou redémarrez le service).

</Steps>

ReputeCast assemble dans l’ordre toutes les lignes d’en-tête `X-Forwarded-For`, lit les adresses de droite à gauche et
retient la première qui n’est pas un proxy de confiance, puis se rabat sur `X-Real-IP`. Un proxy qui ajoute son saut
sous la forme de sa propre ligne d’en-tête (`option forwardfor` de HAProxy) fonctionne comme un proxy qui prolonge la
ligne du client, et les lignes envoyées par un client ne l’emportent jamais sur les sauts ajoutés par vos proxys.
Derrière une chaîne de proxys (un CDN, puis nginx), faites confiance à chaque saut.

Sans ce réglage, les sessions, les limites de débit et le journal d’audit affichent l’adresse du proxy pour tout le
monde : pendant les tests, une session ouverte via nginx affichait l’adresse `172.19.0.6` du conteneur du proxy jusqu’à
ce que le sous-réseau soit déclaré de confiance. Chaque ouverture et chaque clic porte aussi cette adresse, si bien que
le [filtre anti-robots](/fr/reference/glossary/#bot-filter) ne peut pas distinguer les réseaux de scanners ou le proxy
de confidentialité d’Apple des lecteurs.

### L’avis de proxy non approuvé

ReputeCast surveille les requêtes qui portent `X-Forwarded-For`, `X-Real-IP` ou `Forwarded` depuis une adresse que
`http.trusted_proxies` ne liste pas. Quand une adresse privée continue de se comporter comme un proxy, minute après
minute, chaque admin de l’instance reçoit la notification « Des requêtes passent par un proxy auquel ReputeCast ne
fait pas confiance », qui nomme l’adresse, l’en-tête et le paramètre à modifier. Ajoutez cette adresse à
`http.trusted_proxies` et redémarrez.

Une adresse publique qui transmet la majeure partie du trafic pendant longtemps donne lieu à un autre avis : s’il
s’agit de votre CDN ou de votre répartiteur de charge, faites confiance aux plages d’adresses que publie son
fournisseur ; si vous ne la reconnaissez pas, laissez-la de côté, car n’importe qui peut envoyer des en-têtes de
transfert. Un pic bref ne nomme personne. Consultez
[corriger les requêtes passant par un proxy non approuvé](/fr/self-hosting/instance-admin/#corriger-les-requêtes-passant-par-un-proxy-non-approuvé)
pour les deux avis et le moment où ils apparaissent.

## Domaines personnalisés

Un espace de travail peut servir sa page d’inscription, son centre de préférences, ses archives et ses autres pages
publiques à la racine de son propre domaine, configuré sous <UiPath path="nav.forms > forms.tabs.branding" />
([personnaliser vos pages et utiliser votre propre domaine](/fr/forms/branding-and-domain/)). Le domaine pointe vers
votre serveur par un `CNAME` vers l’hôte de l’URL publique. Pour le proxy, cela signifie :

- **Transmettre le domaine à ReputeCast avec son en-tête `Host`.** ReputeCast recherche l’hôte parmi les domaines
  vérifiés et sert les pages de cet espace de travail ; un hôte inconnu obtient l’application.
- **Servir un certificat pour ce domaine.** Avec Caddy, le bloc `https://` émet des certificats à la demande. Avant
  chacun, Caddy appelle `http://app:8080/p/_/tls-check?domain=<name>`, qui répond `200` pour un domaine personnalisé
  vérifié et `404` pour tout le reste, si bien que des certificats ne sont émis que pour des domaines vérifiés.
  Vérifiez vous-même un domaine avec `curl -i "http://127.0.0.1:8080/p/_/tls-check?domain=news.acme.io"`.
- **nginx et Traefik** n’ont pas ce contrôle : ajoutez chaque domaine vérifié à `server_name` avec son certificat
  (nginx), ou à la règle du routeur, comme dans ``Host(`news.example.com`) || Host(`news.acme.io`)`` (Traefik).

Les e-mails continuent de pointer vers l’URL publique ; le domaine personnalisé sert aux pages publiques.

## Ports du SMTP relay

Le [SMTP relay](/fr/transactional/smtp-relay/) parle lui-même SMTP sur 587 (STARTTLS) et 465 (TLS), avec son propre
certificat : les proxys HTTP ne le transportent donc pas.

- Publiez les ports directement depuis le conteneur de l’application, par exemple dans
  `docker-compose.override.yml` :

  ```yaml title="docker-compose.override.yml"
  services:
    app:
      ports:
        - "587:587"
        - "465:465"
  ```

  Ou transférez-les en couche 4 (TCP) sans terminer TLS. Le SMTP relay prend l’adresse du client dans la connexion TCP et
  ne lit pas le protocole PROXY : derrière un redirecteur TCP, la dernière adresse utilisée par la clé est donc celle du
  redirecteur.
- Pour un certificat Let’s Encrypt, ReputeCast répond au challenge HTTP-01 pour le nom d’hôte du SMTP relay sur
  `/.well-known/acme-challenge/…` sur son port web. Let’s Encrypt le récupère via le port 80 et suit les redirections
  vers HTTPS ([types de challenges](https://letsencrypt.org/docs/challenge-types/), vérifié en octobre 2026) : le
  proxy doit donc transmettre ce chemin pour le nom d’hôte du SMTP relay. Si votre proxy répond lui-même à ce chemin,
  fournissez plutôt au SMTP relay des fichiers de certificat.

## Vérifier le résultat

- `curl -sI https://news.example.com/healthz` répond `HTTP/2 200` avec un en-tête `Strict-Transport-Security`, et
  `https://news.example.com/metrics` répond `404`.
- La vérification de l’URL publique dans <UiPath path="shell.userMenuInstanceAdmin > admin.instance" /> affiche DNS,
  TLS et Joignable comme réussis
  ([première connexion](/fr/self-hosting/first-run/#la-vérification-de-lurl-publique)).
- Le flux en direct envoie des données immédiatement. Avec une clé API disposant de `campaigns:view` :

  ```sh
  curl -N -H "Authorization: Bearer rc_live_…" \
    https://news.example.com/api/v1/workspaces/acme-newsletter/campaigns/<campaign id>/live/stream
  ```

  Vous voyez `retry: 3000` et `: connected` immédiatement, puis `: heartbeat …` toutes les 15 secondes.
- Les sessions actives de votre compte affichent votre propre adresse IP, et non celle du proxy.
- Les admins de l’instance ne reçoivent aucune notification « Des requêtes passent par un proxy auquel ReputeCast ne
  fait pas confiance ».

## Dépannage

- **Le suivi en direct ne bouge pas, ou saute toutes les quelques secondes** : le proxy met le flux en mémoire
  tampon. Dans nginx, ajoutez la `location` du flux en direct avec `proxy_buffering off`.
- **`413 Request Entity Too Large` lors des imports ou des envois de fichiers** : augmentez le
  `client_max_body_size` de nginx.
- **Les écrans mettent de nombreuses secondes à s’afficher sur les téléphones** : le proxy parle HTTP/1.1 aux
  navigateurs. Dans nginx, ajoutez `http2 on;` au bloc `server`.
- **Tout le monde apparaît avec l’adresse du proxy** : `http.trusted_proxies` n’inclut pas l’adresse depuis laquelle
  le proxy se connecte.
- **Les admins de l’instance reçoivent « Des requêtes passent par un proxy auquel ReputeCast ne fait pas
  confiance »** : ajoutez l’adresse indiquée à `http.trusted_proxies` (`REPUTECAST_HTTP__TRUSTED_PROXIES`) et
  redémarrez. L’avis cesse dès que l’adresse est de confiance.
- **Un domaine personnalisé ouvre l’application ReputeCast au lieu des pages publiques** : le proxy remplace l’en-tête
  `Host`, ou le domaine n’est pas encore vérifié.
- **Caddy refuse TLS pour un domaine personnalisé** (`tlsv1 alert internal error`) : `/p/_/tls-check` a répondu
  `404` parce que le domaine n’est pas encore vérifié dans ReputeCast.
- **`502 Bad Gateway` de nginx dans Docker après la recréation de l’application** : nginx a gardé l’ancienne adresse
  du conteneur. Redémarrez nginx (`docker compose restart nginx`).
- **La vérification de l’URL publique avertit `Answered with HTTP …`** : le proxy répond mais ne transmet pas
  `/healthz` à ReputeCast.
