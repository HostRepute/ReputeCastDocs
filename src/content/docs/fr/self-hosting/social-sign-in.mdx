Enregistrez une application OAuth Google, une inscription d’application Microsoft ou une application OAuth GitHub,
collez son ID client et son secret dans ReputeCast, et les personnes qui ont déjà un compte peuvent se connecter avec
ce fournisseur au lieu d’un mot de passe.

<Aside type="note" title="La connexion sociale ne crée jamais de comptes">
  Elle connecte les personnes qui ont été invitées ou qui ont déjà un compte. Pour créer automatiquement des comptes
  pour votre organisation, utilisez plutôt [l’authentification unique avec OIDC](/fr/self-hosting/sso/).
</Aside>

## Avant de commencer

- Vous êtes [admin de l’instance](/fr/reference/glossary/#instance-admin).
- L’URL publique est définitive et joignable en `https://`
  (<UiPath path="shell.userMenuInstanceAdmin > admin.instance > admin.publicUrl" />). Les URI de redirection en sont
  dérivées.
- Vous pouvez créer des applications OAuth dans la console Google Cloud, le centre d’administration Microsoft Entra ou
  GitHub.

Chaque fournisseur a sa propre URI de redirection :

<TableScroll label="URI de redirection et scopes par fournisseur" wrap>

| Fournisseur | URI de redirection                              | Scopes demandés par ReputeCast                           |
| ----------- | ----------------------------------------------- | -------------------------------------------------------- |
| Google      | `<public URL>/auth/social/google/callback`      | `openid email profile`                                   |
| Microsoft   | `<public URL>/auth/social/microsoft/callback`   | `openid email profile`                                   |
| GitHub      | `<public URL>/auth/social/github/callback`      | `read:user user:email`, plus `read:org` avec une restriction à une organisation |

</TableScroll>

## Configurer un fournisseur

<Screenshot
  id="instance-auth"
  alt="Les méthodes de connexion autorisées dans Administration de l’instance, Authentification : Google est activé, Microsoft est désactivé, GitHub est activé et réservé à une organisation ; chacun a un bouton crayon pour ses paramètres."
/>

<Steps>

1. Ouvrez <UiPath path="shell.userMenuInstanceAdmin > admin.authentication" />. Dans
   <UiPath path="admin.signInMethods" />, choisissez le bouton crayon à côté de Google, Microsoft ou GitHub. La boîte
   de dialogue affiche l’<UiPath path="sso.redirectUri" /> à copier.

2. Créez l’application chez le fournisseur :

   <Tabs syncKey="social">
   <TabItem label="Google">

   Dans la console Google Cloud, ouvrez APIs & Services › Credentials et créez un **OAuth client ID** de type
   **Web application**. Ajoutez l’URI de redirection sous **Authorized redirect URIs**, puis copiez l’ID client et le
   secret ([Google Cloud : configurer OAuth 2.0](https://support.google.com/cloud/answer/6158849), vérifié en
   octobre 2026).

   ReputeCast utilise OpenID Connect avec `https://accounts.google.com` et n’accepte que les adresses e-mail que
   Google marque comme vérifiées.

   </TabItem>
   <TabItem label="Microsoft">

   Dans le centre d’administration Microsoft Entra, ouvrez App registrations › **New registration**, choisissez la
   plateforme Web et saisissez l’URI de redirection ; créez ensuite un secret client
   ([inscrire une application dans Microsoft Entra ID](https://learn.microsoft.com/entra/identity-platform/quickstart-register-app),
   vérifié en octobre 2026). Choisissez **Supported account types** en accord avec le paramètre
   <UiPath path="admin.socialAccounts" /> de ReputeCast :

   - Comptes personnels et professionnels (par défaut)
   - Comptes professionnels et scolaires uniquement
   - Comptes Microsoft personnels uniquement
   - Un seul locataire (saisissez son ID)

   </TabItem>
   <TabItem label="GitHub">

   Dans GitHub, ouvrez Settings › Developer settings › OAuth Apps › **New OAuth App**. Saisissez l’URI de redirection
   comme **Authorization callback URL**, puis générez un secret client
   ([GitHub : créer une application OAuth](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app),
   vérifié en octobre 2026).

   Vous pouvez aussi saisir une organisation dans ReputeCast : seuls les membres actifs de cette organisation GitHub
   peuvent alors se connecter, et ReputeCast demande aussi `read:org` pour le vérifier. Si l’organisation restreint
   les applications OAuth, un propriétaire de l’organisation doit approuver l’application. Seule l’adresse e-mail
   principale et vérifiée du compte compte.

   </TabItem>
   </Tabs>

3. Dans la boîte de dialogue de ReputeCast, collez l’ID client et le secret client, puis enregistrez. Le secret est
   chiffré et ne peut qu’être remplacé, jamais relu.

4. Activez l’interrupteur du fournisseur et choisissez <UiPath path="admin.savePolicies" />. Un fournisseur sans ID
   client ni secret ne peut pas être activé.

</Steps>

## Comment les personnes associent leur compte

- **Google et GitHub :** quand le fournisseur confirme une adresse e-mail qui appartient à un compte existant, la
  première connexion associe les deux et connecte la personne.
- **Microsoft :** Microsoft ne vérifie pas l’adresse e-mail qu’il transmet, ReputeCast n’associe donc jamais par
  adresse e-mail. Les personnes l’associent via un lien d’invitation ou dans
  <UiPath path="shell.userMenuAccount > account.connectedSignIns" /> avec <UiPath path="account.link" />.
- **Invitations :** la page d’invitation propose les fournisseurs activés ; l’adresse e-mail du fournisseur doit
  correspondre à l’adresse invitée.
- Chacun peut dissocier un fournisseur dans <UiPath path="account.connectedSignIns" />, sauf si c’est son seul moyen
  de connexion.

Sur les domaines où le [SSO est imposé](/fr/self-hosting/sso/#imposer-le-sso-pour-vos-domaines), la connexion sociale
est désactivée pour tout le monde sauf les Propriétaires avec compte d’urgence, et renvoie les personnes vers le
fournisseur d’identité.

## Réutiliser les applications pour les boîtes témoins

Les [tests de placement](/fr/deliverability/placement-tests/) peuvent lire les boîtes témoins Gmail et Microsoft 365 via
les mêmes applications Google et Microsoft, même quand leur interrupteur de connexion est désactivé. Ajoutez une
seconde URI de redirection, `<public URL>/api/v1/placement/oauth/callback`, et l’accès à la messagerie que demande la
page de placement : le scope `https://mail.google.com/` pour Google, l’autorisation déléguée Microsoft Graph
`Mail.ReadWrite` pour Microsoft.

## Vérifier le résultat

- Déconnectez-vous. La page de connexion affiche le bouton du fournisseur sous « ou continuer avec ».
- Connectez-vous avec, puis ouvrez <UiPath path="shell.userMenuAccount > account.connectedSignIns" /> : le fournisseur
  indique « Associé en tant que… ».

## Dépannage

- **« Aucun compte pour… »** : la personne n’a pas de compte ReputeCast. Invitez-la d’abord ; la connexion sociale
  n’en crée jamais.
- **Une connexion Microsoft ne trouve pas le compte** : associez d’abord Microsoft, depuis l’invitation ou depuis
  <UiPath path="account.connectedSignIns" />.
- **« La connexion GitHub est réservée aux membres de l’organisation… »** : la personne n’est pas un membre actif de
  l’organisation définie dans ReputeCast.
- **« … Un propriétaire de l’organisation… doit approuver l’application OAuth de ReputeCast. »** : l’organisation
  restreint les applications OAuth tierces. Un propriétaire de l’organisation approuve l’application dans GitHub.
- **« Votre compte GitHub n’a pas d’adresse e-mail principale vérifiée. »** : la personne vérifie son adresse e-mail
  principale dans GitHub.
- **Le fournisseur signale une URI de redirection qui ne correspond pas** : l’URL publique a changé, ou l’URI contient
  une faute de frappe. Copiez-la de nouveau depuis la boîte de dialogue.
