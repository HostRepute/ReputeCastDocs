Cette page liste toutes les clés d’autorisations ReputeCast qu’un [rôle](/fr/reference/glossary/#role), une [clé API](/fr/reference/glossary/#api-key) ou un [agent MCP](/fr/reference/glossary/#mcp-agent) peut détenir, regroupées comme dans l’éditeur de rôles sous <UiPath path="nav.settings > settings.roles" />.

Chaque opération de l’API nomme l’autorisation dont elle a besoin, et les membres, les clés API et les agents MCP passent par le même contrôle. Une action refusée indique qui peut vous aider plutôt que la clé ; les clés apparaissent là où vous les définissez (portées des clés API, autorisations des agents MCP, portées des clés d’intégration et éditeur de rôles), dans le [journal d’audit](/fr/team/audit-log/) et dans le champ `permission` du problème `permission_denied` de l’API. Les [autorisations sensibles](/fr/reference/glossary/#sensitive-permission) sont marquées ⚑ dans l’application et déclenchent la politique d’authentification à deux facteurs : quand l’instance exige l’authentification à deux facteurs pour les autorisations sensibles, chaque membre dont le rôle en détient une doit l’utiliser. **Inclut** liste les autorisations qui accompagnent automatiquement une clé.

## Qui peut détenir une autorisation

La colonne **Qui peut la détenir** suit quatre règles :

- **Personnes, clés API et agents IA** : tout rôle, toute clé API ou tout agent MCP peut la détenir.
- **Personnes et clés API, pas les agents IA** : les agents MCP ne la détiennent jamais, même quand leur créateur la détient.
- **Personnes uniquement** : seuls les membres la détiennent, par leur rôle. Les clés API et les agents MCP ne le peuvent pas.
- **Propriétaire uniquement** : seul le rôle intégré Propriétaire la détient. Elle ne peut pas être ajoutée à un rôle personnalisé, à une clé API ou à un agent, et le rôle Admin a toutes les autres autorisations.

Une clé API ou un agent MCP ne fait jamais plus que ce que le membre qui l’a créé peut faire à cet instant. Quand le rôle de ce membre perd une autorisation, la clé la perd aussi ; quand le membre quitte l’espace de travail, la clé perd toutes ses autorisations. De même, sa portée en listes et en domaines d’expéditeur est la plus étroite entre la sienne et la portée actuelle de son créateur : restreindre la portée d’un membre restreint donc aussi ses clés et ses agents.

Les clés du groupe **Agence (instance)** appartiennent à l’instance, pas à un espace de travail. Le personnel de l’agence les détient par les rôles Responsable d’agence et Responsable de compte quand le mode agence est activé.

## Rôles intégrés

Les rôles intégrés ne peuvent pas être modifiés ; dupliquez-en un pour créer un [rôle personnalisé](/fr/reference/glossary/#custom-role). Chaque ligne ci-dessous est une autorisation, chaque colonne un rôle intégré : les rôles de l’espace de travail (Propriétaire, Admin, Éditeur, Observateur), les rôles des clients dans les espaces de travail clients d’une agence, et les rôles d’agence au niveau de l’instance.
