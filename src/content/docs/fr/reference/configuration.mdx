Cette page liste toutes les clés de configuration que lit ReputeCast, avec les variables d’environnement ReputeCast qui les définissent et leurs valeurs par défaut.

ReputeCast construit sa configuration à partir de cinq couches ; une couche ultérieure remplace une couche antérieure :

1. Les valeurs par défaut intégrées (la colonne **Par défaut** ci-dessous).
2. Le fichier YAML désigné par `--config` ou `REPUTECAST_CONFIG`.
3. Les variables d’environnement `REPUTECAST_*`. Un double tiret bas sépare les niveaux : `REPUTECAST_HTTP__ADDR` définit `http.addr`.
   L’URL publique fait exception : `REPUTECAST_PUBLIC_URL` définit `http.public_url`, et son ancien nom
   `REPUTECAST_HTTP__PUBLIC_URL` fonctionne encore quand `REPUTECAST_PUBLIC_URL` n’est pas définie.
4. `DATABASE_URL`, seulement quand `REPUTECAST_DATABASE__URL` n’est pas définie. De la même façon, `PORT` définit
   `http.addr` sur `:<PORT>` quand `REPUTECAST_HTTP__ADDR` n’est pas définie. Disponible à partir de la prochaine
   version après la 1.6.0.
5. Les options de ligne de commande que vous passez explicitement : `--role`, `--addr`, `--database-url` et `--log-level`.

Pour les clés de type liste (`roles`, `http.trusted_proxies`, `secrets.previous_keys`, `dns.servers`), séparez les valeurs par des virgules dans une variable d’environnement. ReputeCast refuse de démarrer quand une valeur ne peut pas être analysée, qu’un rôle n’est pas `web`, `worker` ou `ingest`, que `http.public_url` n’est pas une URL absolue, que `secrets.key` n’est pas une clé de 32 octets encodée en base64, que `auth.password_min_length` est inférieur à 8, que `metrics.token` fait moins de 16 caractères, que `PORT` n’est pas un numéro de port ou que les clés de [stockage](/fr/reference/configuration/#storage) ne vont pas ensemble. Une entrée de `http.trusted_proxies` qui n’est ni une adresse, ni une plage, ni `private` est journalisée et ignorée. [Configurer ReputeCast](/fr/self-hosting/configuration/) explique les couches avec un exemple YAML complet.
