Cette page liste toutes les commandes de la CLI reputecast, le binaire unique `reputecast` qui exécute le serveur, les workers et les tâches de maintenance.

Dans l’image Docker, exécutez une commande dans le conteneur de l’application : `docker compose exec app /usr/local/bin/reputecast <command>`. La configuration vient des mêmes sources que pour `reputecast serve` (voir [configurer ReputeCast](/fr/self-hosting/configuration/)) : passez donc `--config` ou les variables `REPUTECAST_*` qu’utilise le serveur.

<CliReference />

## Codes de sortie

| Code | Signification                                                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`  | La commande a réussi.                                                                                                                                                                                                                                                           |
| `1`  | La commande a échoué : une erreur de base de données, de réseau ou de configuration, une option inconnue ou un mauvais nombre d’arguments. C’est aussi le code de `healthcheck` quand le processus n’est pas prêt, de `doctor` quand un contrôle échoue et de `secrets reseal` quand des valeurs s’ouvrent sans aucune clé configurée. |
| `2`  | ReputeCast a refusé la demande avant de faire quoi que ce soit : `user reset-2fa` sans `--reason`, un `--password` qui enfreint la politique de mots de passe, un `seed --sample` inconnu, ou `seed` (sans `--force`) ou `demo send` en dehors de `REPUTECAST_ENV=development`. |

Chaque erreur s’affiche sur la sortie d’erreur standard sous la forme `Error: <message>`.
