Cette page liste les fournisseurs d’e-mail pris en charge et tous les autres services externes auxquels ReputeCast se connecte, avec un tableau par type de service. Chaque connexion utilise votre propre compte et vos propres clés chez ce service ; un nom renvoie vers son guide de configuration quand il en existe un.

Les outils d’automatisation (Zapier, Make, n8n) et WordPress se connectent par les [intégrations](/fr/integrations/overview/), et [HostRepute](/fr/deliverability/hostrepute/) ajoute des données de réputation. Aucun d’eux n’est un fournisseur : ils ne sont donc pas listés ici, à l’exception des données de Gmail Postmaster Tools qu’apporte HostRepute (voir [listes de blocage et données de réputation](#listes-de-blocage-et-données-de-réputation)).

## Fournisseurs d’envoi d’e-mails

Les e-mails partent par un ou plusieurs [fournisseurs d’envoi](/fr/reference/glossary/#sending-provider). **Marketing de masse** indique ce que les conditions du fournisseur autorisent pour les newsletters : _Autorisé_, _Flux Broadcast uniquement_ (les envois en masse doivent passer par le flux Broadcast du fournisseur) ou _Votre propre politique_ (votre serveur ou votre relais, vos règles). **Webhooks d’événements** indique comment le fournisseur signe les événements de livraison qu’il renvoie. **Configuration du domaine** indique si ReputeCast ajoute votre domaine d’envoi par l’API du fournisseur ou si vous ajoutez vous-même les enregistrements DNS. **Synchronisation de la liste de suppression** indique si les suppressions circulent dans les deux sens, sont seulement importées depuis le fournisseur ou restent dans ReputeCast. [Choisir un fournisseur d’envoi](/fr/providers/choose/) les compare, et [adaptateurs de fournisseurs](/fr/adapters/overview/) explique comment ajouter un service qui n’est pas listé.

## Réception des e-mails

Un espace de travail peut recevoir les réponses à ses e-mails, les désabonnements par `mailto:`, les rapports agrégés
DMARC et les rapports de plainte par une seule route entrante : la réception d’un fournisseur d’envoi connecté, ou une
boîte aux lettres que ReputeCast lit. Voir [configurer la réception des e-mails](/fr/providers/receiving-mail/).
Disponible à partir de la prochaine version après la 1.6.0.

| Route | Configuration |
|---|---|
| Mailgun, Postmark, SendGrid, Resend, SparkPost, Mailjet, Brevo | ReputeCast enregistre lui-même la route auprès du fournisseur d’envoi |
| Amazon SES, Postal | ReputeCast affiche les étapes à suivre chez le fournisseur d’envoi |
| Une boîte aux lettres IMAP ou POP3 | Votre propre boîte aux lettres, lue toutes les minutes |

## Fournisseurs SMS

Les campagnes SMS et les étapes d’automatisation envoient par l’un de ces comptes. ReputeCast traite les réponses par mot-clé comme STOP et HELP ; il n’a pas de boîte de réception SMS bidirectionnelle. Voir [envoyer des campagnes SMS](/fr/channels/sms/).

## Services de rendu

Les rendus réels montrent la campagne enregistrée dans de vrais clients de messagerie, à côté des aperçus intégrés de l’éditeur, qui sont des approximations. Un espace de travail connecte un service avec sa propre clé ; ce sont les personnes qui gèrent les intégrations qui le connectent. Voir [concevoir des e-mails dans l’éditeur](/fr/campaigns/composer/).

## Paiements

Les abonnements payants, les cadeaux et les produits numériques sont vendus par le compte Stripe de l’éditeur ; ReputeCast ne prend aucune commission et ne stocke jamais les données de carte. Paddle et Lemon Squeezy apparaissent dans l’application comme non disponibles : vous ne pouvez pas les connecter. Voir [connecter Stripe](/fr/earn/connect-stripe/).

<ProviderMatrix family="payments" label="Prestataires de paiement" />

## Publicités à formulaire

Les prospects des formulaires de publicité Facebook et Instagram deviennent des contacts par votre propre app Meta (de
type Business) et le jeton d’un utilisateur système, via la Graph API de Meta. Voir
[collecter des prospects avec Meta Lead Ads](/fr/integrations/meta-lead-ads/). Disponible à partir de la prochaine
version après la 1.6.0.

| Service | Remarques |
|---|---|
| Meta Lead Ads | Une connexion par espace de travail ; les prospects arrivent instantanément par le webhook `leadgen` des Pages, avec une interrogation toutes les 15 minutes tant que le webhook ne livre rien |

## Notifications push web

Les notifications du navigateur sont intégrées et ne demandent aucun compte externe : elles utilisent le standard Web Push avec des clés VAPID générées pour chaque espace de travail, et chaque navigateur les distribue par son propre service push. Voir [envoyer des notifications push web](/fr/channels/web-push/).

## Stockage objet

Les fichiers des produits, les cadeaux d’inscription, les importations par morceaux et les exports de l’audience
restent par défaut dans le dossier des fichiers. Avec `storage.backend: s3`, ils vont plutôt dans un bucket compatible
S3, pour que plusieurs processus web et worker les partagent. Voir
[stocker les fichiers dans un stockage objet compatible S3](/fr/self-hosting/object-storage/). Disponible à partir de la
prochaine version après la 1.6.0.

| Service | Remarques |
|---|---|
| AWS S3 | Clés d’accès ou chaîne d’identifiants AWS par défaut ; chiffrement côté serveur facultatif avec KMS |
| MinIO | Nécessite l’adressage de type chemin (`storage.s3.path_style`) |
| Cloudflare R2, DigitalOcean Spaces, Backblaze B2, Wasabi | Définissez `storage.s3.endpoint` sur l’URL du service |

## Bases de données GeoIP

Un fichier de base de données que fournit l’exploitant situe les ouvertures et les clics par pays et par ville dans les
rapports de campagne, et permet de n’afficher les formulaires d’inscription que dans certains pays. ReputeCast ne le
télécharge jamais. Voir [ajouter une base de données GeoIP](/fr/self-hosting/geoip/).

| Base de données | Éditeur |
|---|---|
| GeoLite2-City, GeoLite2-Country | MaxMind (compte gratuit) |
| DB-IP Lite City, DB-IP Lite Country | DB-IP |
