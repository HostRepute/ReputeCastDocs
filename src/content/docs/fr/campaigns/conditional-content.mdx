Le contenu conditionnel dans les e-mails permet à une seule campagne de contenir des blocs que seuls certains lecteurs voient : l’annonce d’une bêta pour la liste Beta Program, un mot pour les contacts qui n’ouvrent plus, ou une section pour les abonnés payants. Chaque lecteur reçoit un seul e-mail, où chaque bloc conditionnel est affiché ou masqué pour lui, et ReputeCast vérifie chaque version avant l’envoi.

## Avant de commencer

- Modifier qui voit un bloc demande `campaigns:edit`. Prévisualiser en tant que vrai contact et voir son nom dans les motifs demande `subscribers:view`.
- Les règles de [visibilité](/fr/reference/glossary/#visibility) fonctionnent dans les campagnes standard et les numéros de récapitulatif récurrent. Les modèles transactionnels et les e-mails d’automatisation ne les prennent pas en charge.
- Créez les [segments](/fr/audience/segments/), les [listes et champs personnalisés](/fr/audience/lists-and-fields/) ou les tags qu’utiliseront vos conditions.

## Définir qui voit un bloc

<Steps>

1. Dans l’[éditeur](/fr/campaigns/composer/), sélectionnez une section, ou un bloc à l’intérieur (texte, image, bouton, séparateur, espacement, réseaux sociaux, barre de navigation, HTML brut ou tableau). Les colonnes et les groupes ne peuvent pas avoir de règle.

2. Ouvrez <UiPath path="composer.tabSettings" /> et repérez <UiPath path="conditional.title" />.

3. Choisissez qui voit le bloc :

   - Tout le monde : <UiPath path="conditional.showEveryone" /> (par défaut).
   - Uniquement les contacts auxquels vos conditions correspondent : <UiPath path="conditional.showOnly" />.
   - Tout le monde sauf ces contacts : <UiPath path="conditional.showExcept" />.
   - Les lecteurs selon leur accès payant, si vous vendez des [abonnements payants](/fr/earn/paid-subscriptions/) : <UiPath path="earn.composer.show" />, puis n’importe quelle formule payante, une formule et les formules supérieures, ou les abonnés gratuits uniquement.

4. Choisissez si un contact doit remplir <UiPath path="conditional.matchAll" /> ou <UiPath path="conditional.matchAny" /> des conditions.

5. Sélectionnez <UiPath path="conditional.addCondition" />, choisissez une condition, son opérateur et sa valeur. Ajoutez-en d’autres si nécessaire.

6. Lisez le nombre sous les conditions, par exemple « 584 destinataires sur 29 832 voient ce bloc ». Il est calculé sur l’audience de la campagne et mis à jour environ une seconde après chaque modification.

</Steps>

Les blocs conditionnels reçoivent une marque d’œil barré dans <UiPath path="composer.canvas.tabLayers" /> et un badge sur le canevas avec la règle en toutes lettres, comme « liste Beta Program ». Retirer la dernière condition retire la règle, et le bloc s’affiche de nouveau pour tout le monde.

### Conditions

| Condition              | Opérateurs                                                 | Remarques                                                                                                                                                                          |
| ---------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dans un segment        | fait partie de, ne fait pas partie de                      | Tout [segment](/fr/audience/segments/) enregistré.                                                                                                                                 |
| Dans une liste         | inclut, exclut                                             | Affichée sur le bloc comme **Appartenance à une liste**.                                                                                                                           |
| A un tag               | a, n’a pas                                                 | Suggère les tags existants ; vous pouvez en saisir un nouveau.                                                                                                                     |
| Un champ               | Selon le type du champ (ci-dessous)                        | Tout champ personnalisé, affiché comme **Champ personnalisé ·** suivi de son nom.                                                                                                  |
| Langue                 | est, n’est pas                                             | L’une des langues de contenu de l’espace de travail, comparée sur le code de base (`es-MX` compte comme `es`). Un contact sans langue ne correspond jamais à **est**.              |
| Niveau d’engagement    | est, n’est pas                                             | Actif, En baisse, À risque ou Arrêt progressif ; voir [garder une liste saine](/fr/audience/list-health/).                                                                         |
| Score                  | est au moins, est au plus, est entre                       | Un nombre entier de 0 à 100 ; voir [noter les contacts selon leur intérêt](/fr/audience/scoring/).                                                                                 |
| Niveau de score        | est, n’est pas                                             | Chaud, Tiède ou Froid.                                                                                                                                                             |

Opérateurs des champs selon leur type :

- **Texte** : est, n’est pas, contient, est vide, est renseigné.
- **Nombre** : est, n’est pas, est supérieur à, est inférieur à, est vide, est renseigné.
- **Date** : est avant, est après, est vide, est renseigné.
- **Booléen** : est vrai, est faux.
- **Liste de choix** : est, n’est pas, est vide, est renseigné.

Tant que le scoring n’est pas configuré, personne n’a de score : les conditions de score et « niveau de score est » ne correspondent jamais, et « niveau de score n’est pas » correspond toujours. **Accès payant** compte les lecteurs en essai, ceux qui ont un accès offert ou cadeau, et ceux dont Stripe retente encore le paiement ; une formule supérieure inclut le contenu payant d’une formule inférieure.

## Prévisualiser la version de chaque lecteur

- Dans la barre d’outils du canevas, **Afficher tous les blocs** montre tout pendant la modification, et **Afficher comme le voit un contact** masque ce que le contact choisi dans <UiPath path="composer.preview.previewAs" /> ne recevrait pas. Quand l’e-mail contient des blocs conditionnels, <UiPath path="composer.preview.previewAs" /> propose un contact qui reçoit chaque version, celles qui ont le plus de destinataires d’abord, puis un pour chaque autre langue ; voir les limites ci-dessous.
- Dans <UiPath path="composer.preview" />, activez <UiPath path="conditional.showWhy" />. Chaque bloc masqué se réduit à une ligne en pointillés qui en donne la raison, par exemple « Masqué : Beta corner · Olga n’est pas dans la liste Beta Program ». L’en-tête nomme la version et le nombre de destinataires qui la reçoivent, et signale quand le contact ne fait pas partie de l’audience de cette campagne.

## Vérifier les versions

La barre d’état sous le canevas compte les combinaisons, par exemple « 3 blocs conditionnels · 6 versions ». Sélectionnez-la (en mode Design) pour ouvrir le panneau des versions :

- une ligne par combinaison présente dans l’audience, avec ce qu’elle affiche, ses destinataires et sa taille,
- un badge **Gmail la tronque** sur toute version de plus de 102 Ko, avec une correction pour minifier le CSS en ligne,
- **Prévisualiser cette version** sur chaque ligne,
- combien de combinaisons possibles n’existent pas dans cette audience.

Les combinaisons qu’aucun contact ne reçoit ne sont ni comptées ni vérifiées.

## Règles à connaître

- **Le pied de page est toujours affiché.** Une règle sur le bloc de pied de page est ignorée, si bien que chaque version garde le lien de désabonnement et l’adresse postale.
- **Un bloc placé dans un bloc masqué est masqué avec lui.**
- **Qui reçoit quoi est décidé une seule fois,** quand l’envoi construit son audience. Les modifications ultérieures d’un contact (un nouveau tag, un changement de liste) ne changent pas un e-mail déjà en file d’attente.
- **La version texte brut correspond.** La partie texte de chaque destinataire est construite à partir de sa propre version du HTML.
- **Les copies en ligne suivent les règles.** Le lien **version en ligne** d’un lecteur affiche sa propre version. Les [archives](/fr/forms/public-pages/) publiques traitent le visiteur comme ne remplissant aucune condition : les blocs réservés aux **contacts correspondants** sont masqués, les blocs pour **tous sauf** sont affichés.

## Ce que vérifie le contrôle avant envoi

Le groupe **Contenu conditionnel** du [contrôle avant envoi](/fr/campaigns/send-readiness/) génère et vérifie chaque version :

- **Bloquant** quand une condition utilise un segment, une liste ou un champ supprimé. Les corrections en choisissent un autre, retirent la condition ou masquent le bloc pour tout le monde.
- **Bloquant** quand une version n’a rien entre l’en-tête et le pied de page. Les corrections affichent le bloc pour tout le monde ou prévisualisent cette version.
- **Avertissement** quand une version dépasse la taille de troncature de Gmail (102 Ko). Vous en prenez acte, ou vous minifiez le CSS en ligne.
- **Avertissement** quand une règle ne peut pas être lue ; ces blocs sont affichés pour tout le monde.
- **Inconnu** quand les versions n’ont pas pu être comptées à temps (10 secondes). Relancez les contrôles.

Les liens sont vérifiés une seule fois pour l’ensemble des versions.

## Vérifier le résultat

- Le bloc affiche une marque d’œil barré dans Calques et un badge avec sa règle sur le canevas.
- Prévisualisez en tant que contact qui correspond et en tant que contact qui ne correspond pas : le bloc apparaît pour le premier et est réduit avec une raison pour le second.
- Le panneau des versions liste les combinaisons attendues, chacune avec ses destinataires.

## Dépannage

- **Il n’y a pas de choix Visibilité.** Une colonne ou un groupe est sélectionné ; sélectionnez la section ou un bloc à l’intérieur. Dans un modèle transactionnel, l’option n’existe pas.
- **Les boutons radio sont grisés.** Le pied de page est sélectionné, ou il manque `campaigns:edit` à votre rôle.
- **« Personne n’a de score tant que le scoring n’est pas configuré ».** Configurez le [scoring](/fr/audience/scoring/), ou utilisez plutôt un segment ou un tag.
- **« … a supprimé ce segment ».** Choisissez un autre segment ou retirez la condition ; le contrôle avant envoi bloque la campagne tant que ce n’est pas fait.
- **Une version n’a rien entre l’en-tête et le pied de page.** Chaque bloc de cette combinaison est masqué. Affichez un bloc pour tout le monde, ou modifiez les règles.
- **Prévisualiser en tant que ne propose que des contacts fictifs.** Il manque `subscribers:view` à votre rôle.
