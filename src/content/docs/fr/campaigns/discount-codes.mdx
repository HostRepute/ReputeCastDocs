Une [réserve de codes de réduction](/fr/reference/glossary/#discount-code-pool) distribue des codes de réduction uniques : chaque lecteur d’une campagne ou d’un e-mail d’automatisation reçoit un code bien à lui au moment de l’envoi, parmi des codes que vous importez ou que ReputeCast crée dans votre boutique Shopify ou WooCommerce connectée. La réserve compte ensuite les codes envoyés, les codes utilisés et le chiffre d’affaires des commandes qui les ont utilisés. Disponible à partir de la prochaine version après la 1.6.0.

## Avant de commencer

- Voir les réserves et leurs chiffres exige `campaigns:view`. Créer une réserve, ajouter, créer, retirer ou exporter ses codes et l’archiver exige `coupons:manage`, dont disposent les rôles Propriétaire, Admin et Éditeur. C’est une autorisation sensible réservée aux personnes : les clés API et les agents peuvent lire les réserves, jamais les modifier. Voir [rôles et autorisations](/fr/team/roles-and-permissions/).
- Placer un code dans un e-mail exige `campaigns:edit`.
- Pour des codes créés dans une boutique, [connectez d’abord la boutique](/fr/integrations/shopify-woocommerce/). Une boutique Shopify doit autoriser les codes de réduction : <UiPath path="coupons.allowDiscounts" /> demande à Shopify les portées `write_discounts` et `read_discounts` et exige `integrations:manage`. Une boutique WooCommerce a besoin d’une clé REST avec l’accès Read/Write.

## Créer une réserve

<Steps>

1. Ouvrez <UiPath path="nav.campaigns" />, sélectionnez <UiPath path="coupons.title" /> à côté du champ de recherche, puis <UiPath path="coupons.newPool" />.

2. Donnez-lui un <UiPath path="coupons.name" /> (80 caractères au plus). Le <UiPath path="coupons.slug" /> se remplit à partir du nom (« Spring 20% » devient `spring_20`) : de 1 à 32 minuscules, chiffres ou `_`, utilisé dans les modèles sous la forme `coupons.spring_20.code`. Il ne peut plus changer une fois la réserve créée.

3. Choisissez la <UiPath path="coupons.source" /> :

   - <UiPath path="coupons.srcUpload" />, pour des codes que vous avez déjà.
   - **Créer dans Shopify** ou **Créer dans WooCommerce**, une carte par boutique connectée. Une boutique qui ne peut pas créer de codes indique pourquoi, avec <UiPath path="coupons.allowDiscounts" /> pour une boutique Shopify qui ne les a pas autorisés, ou <UiPath path="coupons.replaceKey" /> pour une clé WooCommerce en lecture seule.

4. Pour une boutique, définissez la réduction qu’accorde chaque code : le <UiPath path="coupons.kind" /> (<UiPath path="coupons.kindPercentage" />, <UiPath path="coupons.kindFixed" /> dans la devise de la boutique, ou <UiPath path="coupons.kindFree" />), la <UiPath path="coupons.value" />, une <UiPath path="coupons.minimum" /> facultative, <UiPath path="coupons.endsAfter" /> un nombre de jours (de 1 à 365 ; vide, la réduction n’expire jamais) et le champ <UiPath path="coupons.appliesTo" /> (<UiPath path="coupons.allProducts" /> ou une collection). Chaque code sert une fois, pour un client. Ajoutez un <UiPath path="coupons.prefix" /> de 12 majuscules, chiffres ou `-` au plus : les codes sont le préfixe suivi de 8 caractères sans confusion possible (pas de 0, O, 1 ni I), comme `WELCOME-7KQ4M2XA`.

5. Pour des codes importés, ajoutez si vous le souhaitez une <UiPath path="coupons.applyUrl" /> : un lien qui applique un code dans votre boutique, avec `{code}` à la place du code, comme `https://shop.example.com/discount/{code}`. Sans adresse, le lien de la réserve est vide et le bloc n’affiche pas de bouton.

6. Laissez <UiPath path="coupons.onePerContact" /> activé (par défaut) pour qu’un contact qui reçoit de nouveau cette réserve, dans une autre campagne ou le prochain e-mail d’un scénario, reçoive le même code. Désactivez-le pour donner un nouveau code à chaque e-mail.

7. Sélectionnez <UiPath path="coupons.createPool" />. La page de la réserve s’ouvre, et la création est enregistrée dans le [journal d’audit](/fr/team/audit-log/).

</Steps>

<Aside type="caution">
  Les codes que ReputeCast crée dans une boutique sont de vraies réductions. Quiconque en a un peut l’utiliser une fois,
  même depuis un e-mail transféré. ReputeCast ne peut pas savoir si des codes importés fonctionnent dans votre boutique,
  ni combien de fois : importez des codes à usage unique.
</Aside>

### Ajouter des codes que vous avez

<Steps>

1. Sur la page de la réserve, sélectionnez <UiPath path="coupons.addCodes" />.

2. Sous <UiPath path="coupons.addPaste" />, collez les codes un par ligne, ou sous <UiPath path="coupons.addFile" />, choisissez un fichier CSV avec les codes dans sa première colonne (une ligne d’en-tête nommée `code` est ignorée).

3. Sélectionnez <UiPath path="coupons.addCodes" />. Un import accepte jusqu’à 100 000 codes et 6 Mo ; chaque code compte de 3 à 64 lettres, chiffres, `-` ou `_`.

</Steps>

Le résultat indique combien de codes ont été ajoutés, combien se trouvaient déjà dans la réserve (la casse ne compte pas) et quelles lignes n’étaient pas des codes, avec les trois premières d’entre elles. Le journal d’audit enregistre les nombres, jamais les codes.

### Créer des codes dans la boutique

<Steps>

1. Sur la page de la réserve, sélectionnez <UiPath path="coupons.createMore" />.

2. Sous <UiPath path="coupons.moreCount" />, saisissez de 1 à 50 000 codes.

3. Sélectionnez le bouton qui les crée, comme **Créer 500 codes**.

</Steps>

ReputeCast crée la réduction dans la boutique (dans Shopify, une seule réduction qui contient tous les codes ; dans WooCommerce, un code promo par code), puis ajoute les codes par lots : 250 à la fois via la tâche groupée de Shopify, 100 codes promo à la fois dans WooCommerce. Seuls les codes que la boutique a confirmés deviennent libres. Une carte sur la page de la réserve affiche l’avancement, comme « Création de 500 codes dans Acme Merch · 250 faits », et vous pouvez quitter la page. Quand la boutique demande à ReputeCast de ralentir, la carte l’indique et le travail reprend quelques secondes plus tard. Quand la boutique ne répond pas, ReputeCast garde les codes déjà confirmés, réessaie et propose <UiPath path="coupons.retryNow" />.

Une fois la réduction créée dans la boutique, son type, sa valeur, son minimum, sa fin et ses collections ne peuvent plus changer : créez une nouvelle réserve pour une autre réduction. Le nom, le préfixe, le seuil et le choix d’un code par contact se modifient avec <UiPath path="coupons.edit" /> dans les <UiPath path="coupons.settingsTitle" /> de la réserve.

## Placer un code dans un e-mail

<Steps>

1. Dans l’[éditeur](/fr/campaigns/composer/), faites glisser <UiPath path="coupons.composer.block" /> depuis <UiPath path="composer.canvas.groupReputecast" /> dans une colonne de l’e-mail.

2. Choisissez sa <UiPath path="coupons.composer.pool" />. Chaque réserve affiche ses codes libres, comme « Welcome 15% · 2 540 libres ». S’il n’y a pas encore de réserve, le panneau renvoie vers <UiPath path="coupons.title" /> pour en créer une.

3. Modifiez le <UiPath path="coupons.composer.label" /> au-dessus du code (80 caractères au plus, « Votre code » par défaut). Il peut contenir du Liquid, comme `Votre code, {{ first_name }}`.

4. Gardez le <UiPath path="coupons.composer.button" /> activé et modifiez son texte (40 caractères au plus, « Acheter » par défaut), ou désactivez-le. Le bouton d’une réserve Shopify ouvre l’adresse `/discount/<code>` de la boutique, qui applique le code ; celui d’une réserve WooCommerce ouvre la boutique ; celui d’une réserve importée ouvre son adresse d’application.

</Steps>

En mode Rédaction, le bloc est une carte avec <UiPath path="composer.write.editInDesign" />. Les lecteurs voient le libellé, leur propre code dans un cadre en pointillés qui se sélectionne d’un seul tenant, et le bouton. Un lecteur qui n’a pas de code, comme un visiteur qui lit l’e-mail dans les [archives](/fr/forms/public-pages/) publiques, ne voit rien : le bloc se masque.

Pour placer un code ailleurs, dans du texte, un lien, l’objet ou le mode Code, utilisez Liquid, ou choisissez-le dans <UiPath path="composer.canvas.insertToken" />, sous <UiPath path="coupons.composer.tokensGroup" /> :

| Liquid                         | Contient                                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `{{ coupons.welcome15.code }}` | Le code du lecteur issu de la réserve nommée `welcome15`.                                                         |
| `{{ coupons.welcome15.url }}`  | Le lien qui l’applique : celui de la boutique, ou l’adresse d’application de la réserve importée. Vide sans adresse. |

La page de la réserve liste les deux sous <UiPath path="coupons.liquidTitle" />, avec un bouton pour les copier. Les liens qui les contiennent restent suivis : le clic passe par ReputeCast et arrive avec le code du lecteur. Voir [personnaliser les e-mails avec Liquid](/fr/campaigns/personalization/#codes-de-réduction).

### Les aperçus et les tests affichent un exemple

L’éditeur, l’aperçu et les envois de test affichent le préfixe de la réserve suivi de `SAMPLE1`, comme `WELCOME-SAMPLE1`, et le lien correspondant. Aucun code n’est distribué avant l’envoi de l’e-mail.

## Comment les codes sont distribués

- **À l’envoi de l’e-mail.** Le moteur d’envoi donne un code libre à chaque message, une page de destinataires à la fois. Deux messages ne reçoivent jamais le même code, même depuis deux envois simultanés, et une page envoyée de nouveau récupère les mêmes codes.
- **Un code par contact.** Avec cette option activée, un contact qui a déjà reçu un code de la réserve reçoit de nouveau le même ; sans elle, chaque message prend un nouveau code.
- **Ensuite.** La version en ligne de l’e-mail et les redirections de ses liens affichent le code attribué au message. La distribution d’un code n’est pas consignée dans le journal d’audit : le message le contient.

Quand un message de campagne ne trouve plus de code, ce message n’est pas envoyé : il échoue avec « Not sent: the discount code pool … had no code left for this reader (no_codes). » Un e-mail d’automatisation attend à la place : il redemande toutes les 15 minutes, et au bout de 24 heures sans code, il est ignoré et enregistré comme `no_codes` sur le contact. La page de la réserve indique combien d’e-mails de quel scénario attendent.

## Garder assez de codes

Le [contrôle avant envoi](/fr/reference/glossary/#send-readiness) compare les codes libres d’une réserve aux destinataires de la campagne, un par destinataire, dans son groupe Contenu :

- « Codes de réduction : … restants dans … pour … destinataires » est réussi quand il y en a assez.
- Trop peu de codes importés bloquent l’envoi, avec <UiPath path="coupons.readiness.addCodes" />, qui ouvre l’ajout de codes de la réserve.
- Trop peu de codes dans une boutique le bloquent aussi, avec <UiPath path="coupons.readiness.createCodes" />, qui demande à la boutique les codes manquants plus 5 % de marge. Pendant la création des codes, la ligne nomme qui l’a lancée et passe en réussi dès que la boutique en a confirmé assez.
- Une réserve archivée, ou une réserve de boutique dont la boutique n’est pas connectée, bloque l’envoi.

Chaque réserve a un seuil, 200 codes libres par défaut (modifiable avec <UiPath path="coupons.edit" />, de 0 à 1 000 000). En dessous, les membres qui peuvent gérer les codes de réduction reçoivent une [notification](/fr/team/notifications/), <UiPath path="notify.event.coupon_codes_low" />, puis une autre seulement après que la réserve est repassée au-dessus du seuil ; la page de la réserve affiche le même avertissement. La notification d’une réserve vide indique que les messages de campagne qui affichent son code ne sont pas envoyés et que les e-mails d’automatisation attendent.

Une réserve de boutique qu’utilise une automatisation en ligne est réapprovisionnée toutes les heures : quand ses codes libres passent sous 1,2 fois l’usage des 7 derniers jours (et au moins le seuil), ReputeCast demande la différence à la boutique. Les <UiPath path="coupons.settingsTitle" /> de la réserve indiquent quand elle a été vérifiée pour la dernière fois, et les lots du réapprovisionnement affichent « Réapprovisionnement » avec le nom du scénario. Publier un scénario avertit quand une réserve qu’il utilise est sous son seuil, archivée ou introuvable.

Un code compte comme utilisé quand une commande synchronisée depuis une boutique connectée l’a utilisé, quelle que soit la casse, une fois par commande. Le chiffre d’affaires additionne ces commandes dans la devise de la boutique, remboursements déduits, sans les commandes annulées ni les commandes de test. Une réserve de boutique compte les commandes de sa propre boutique ; une réserve importée, les commandes de n’importe quelle boutique connectée.

Les <UiPath path="coupons.batchesTitle" /> de la réserve listent chaque import et chaque demande de codes, des plus récents aux plus anciens, avec qui ou quoi les a demandés (un membre, la création de la réserve ou le réapprovisionnement horaire), combien ont été demandés, créés et refusés (codes que la boutique a refusés, ou que la réserve avait déjà).

## Exporter, retirer ou archiver des codes

- <UiPath path="coupons.export" /> télécharge chaque code au format CSV : `code`, `status` (`free`, `sent`, `redeemed` ou `removed`), `assigned_at`, `redeemed_at` et `order`. Cela exige `coupons:manage` et est enregistré dans le journal d’audit avec le nombre de lignes.
- <UiPath path="coupons.removeUnused" /> retire les codes que personne n’a reçus. Les codes d’une boutique y sont aussi désactivés, pour que personne ne puisse les utiliser ; les codes déjà envoyés restent valables. Un scénario en ligne qui utilise une réserve de boutique reçoit de nouveaux codes dans l’heure ; un scénario qui utilise des codes importés attend des codes. Pour en garder une copie, exportez d’abord.
- <UiPath path="coupons.archive" /> empêche la réserve de distribuer des codes. Elle passe dans <UiPath path="coupons.filterArchived" /> avec ses chiffres, et les codes déjà envoyés restent valables. Quand un scénario en ligne l’utilise, la boîte de dialogue l’indique d’abord et propose <UiPath path="coupons.archiveAnyway" /> : les e-mails du scénario attendent alors des codes et sont ignorés au bout d’un jour. Les campagnes qui l’utilisent sont bloquées dans Vérifier et envoyer, et l’éditeur avertit, jusqu’à ce qu’elles utilisent une autre réserve. Une réserve archivée ne peut pas redevenir active.

Chaque modification est enregistrée dans le journal d’audit : `coupon_pool.created`, `coupon_pool.updated`, `coupon_pool.codes_uploaded`, `coupon_pool.codes_requested`, `coupon_pool.codes_removed`, `coupon_pool.codes_exported` et `coupon_pool.archived`. Les scripts lisent les réserves, jamais leurs codes, avec les opérations [lister les réserves de codes de réduction](/api/operations/list-coupon-pools/) et [obtenir une réserve de codes de réduction](/api/operations/get-coupon-pool/).

## Vérifier le résultat

- Le nombre <UiPath path="coupons.statFree" /> de la réserve correspond aux codes que vous avez ajoutés ou que la boutique a confirmés.
- Un e-mail de test affiche le préfixe de la réserve suivi de `SAMPLE1`.
- Le contrôle avant envoi affiche « Codes de réduction : … restants dans … pour … destinataires » comme réussi.
- Après l’envoi, le nombre <UiPath path="coupons.statSent" /> de la réserve a augmenté du nombre de messages envoyés, et <UiPath path="coupons.statRedeemed" /> suit les commandes de la boutique.

## Dépannage

- **Il n’y a pas de carte de boutique, ou elle est grisée.** Aucune boutique de cette plateforme n’est connectée, ou elle ne peut pas créer de codes : autorisez les codes de réduction sur la page de la boutique Shopify, ou donnez à la boutique WooCommerce une clé Read/Write, puis rouvrez <UiPath path="coupons.newPool" />.
- **« Une autre réserve s’appelle déjà … dans les modèles. »** Choisissez un autre nom en Liquid ; il est unique dans l’espace de travail.
- **« Importez au plus 100 000 codes à la fois. »** Découpez le fichier. Un fichier de plus de 6 Mo n’est pas ajouté du tout.
- **Des lignes n’étaient pas des codes.** Un code compte de 3 à 64 lettres, chiffres, `-` ou `_` ; les espaces et les autres caractères ne sont pas acceptés.
- **« La réduction existe déjà dans … et ne peut plus changer. »** Créez une nouvelle réserve pour une autre réduction.
- **Le bloc n’affiche pas de bouton.** La réserve importée n’a pas d’adresse d’application. Ajoutez-en une dans les paramètres de la réserve, ou désactivez le bouton.
- **« Aucune réserve de codes de réduction ne s’appelle … »** L’e-mail désigne une réserve qui n’existe pas, souvent après une faute de frappe dans le Liquid. Choisissez une réserve dans le bloc, ou corrigez le nom.
- **Le contrôle avant envoi bloque avec « Pas assez de codes de réduction ».** Ajoutez ou créez des codes, ou envoyez à moins de personnes.
- **Des contacts ont été enregistrés comme `no_codes`.** La réserve s’est épuisée pendant l’envoi. Ajoutez ou créez des codes ; les e-mails d’automatisation encore en attente les récupèrent dans les 15 minutes.
- **<UiPath path="coupons.export" /> est grisé.** Votre rôle n’a pas `coupons:manage` ; le bouton indique qui peut vous aider.
