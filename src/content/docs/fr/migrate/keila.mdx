Pour migrer depuis Keila, vous connectez ReputeCast à un projet Keila avec une clé API et importez tous ses contacts dans une seule liste ReputeCast, avec leurs données personnalisées et leurs statuts. Cela fonctionne avec Keila Cloud comme avec un serveur Keila que vous exploitez vous-même. ReputeCast se contente de lire la Keila API v1 ; rien ne change dans Keila.

## Avant de commencer

- Il vous faut l’autorisation `subscribers:import` (les rôles Propriétaire, Admin et Éditeur l’ont).
- Créez une clé API Keila dans le projet que vous migrez : sélectionnez **API Keys** dans le menu de gauche, cliquez sur **Create new API key**, nommez-la et enregistrez. Keila n’affiche la clé qu’une fois. Source : [Keila, API authentication](https://www.keila.io/docs/api/authentication) (vérifié en octobre 2026).
- Pour un Keila auto-hébergé, ReputeCast doit joindre le serveur en HTTP ou HTTPS. Un serveur situé sur un réseau privé ou interne est refusé, sauf si l’instance active `providers.allow_private_networks` (voir la [référence de la configuration](/fr/reference/configuration/)).
- Lisez [comment une migration transmet le consentement](/fr/migrate/overview/) s’il s’agit de votre premier import.

## Importer vos contacts Keila

<Steps>

1. Ouvrez <UiPath path="shell.importContacts" /> et choisissez **Keila**.

2. Vérifiez le champ <UiPath path="imports.serverAddress" />. Il vaut d’abord `https://app.keila.io` pour Keila Cloud ; remplacez-le par l’adresse de votre propre serveur si vous exploitez Keila vous-même. N’incluez ni identifiants, ni chaîne de requête, ni fragment ; ReputeCast ajoute `/api/v1` lui-même.

3. Collez la clé dans <UiPath path="imports.apiKey" /> et sélectionnez <UiPath path="imports.connect" />. Keila n’a pas de listes : l’assistant affiche donc une seule liste source, **All contacts**, avec le nombre de contacts du projet.

4. Choisissez la liste ReputeCast de destination des contacts, gardez activée la récupération des suppressions depuis vos fournisseurs d’envoi et passez à la correspondance des champs.

5. Associez les champs. `email` est obligatoire ; `first_name` et `last_name` correspondent aux champs ReputeCast, et chaque clé des données personnalisées des contacts devient un champ nommé d’après elle.

6. Vérifiez l’étape du consentement (voir la section suivante), lancez l’aperçu et démarrez l’import.

</Steps>

## Ce qui migre depuis Keila

- **Tous les contacts du projet** vont dans la seule liste ReputeCast que vous avez choisie.
- Le **prénom et le nom** vont dans les champs correspondants.
- Les **données personnalisées** (`data`) deviennent des champs de contact. L’assistant propose les clés qu’il trouve sur les 100 premiers contacts ; une clé qui n’apparaît que sur des contacts suivants n’est pas proposée.
- **Dates :** la date de création du contact dans Keila devient sa date de création dans ReputeCast. L’API de Keila ne fournit ni date ni IP d’opt-in : les contacts arrivent donc en opt-in simple.

| Statut Keila   | Devient dans ReputeCast                                                               |
| -------------- | ------------------------------------------------------------------------------------- |
| `active`       | Abonné · confirmé (ou en attente, ou Ignorer)                                         |
| `unsubscribed` | Exclu · désabonné : ni Diffusions ni Automatisations, e-mails Système autorisés (verrouillé) |
| `unreachable`  | Exclu · rebond définitif, tous les flux (verrouillé)                                  |

### Ce qui reste dans Keila

Les segments Keila ne sont pas importés, même si l’étape de la source liste leurs noms : recréez-les sous forme de [segments ReputeCast](/fr/audience/segments/), à l’aide des données personnalisées importées. Les campagnes, les modèles, les formulaires et les expéditeurs restent eux aussi dans Keila.

## Vérifier le résultat

- Le résumé indique combien de contacts ont été importés, fusionnés, exclus, laissés en attente et ignorés. <UiPath path="imports.downloadReport" /> liste chaque ligne avec ce qui lui est arrivé.
- Ouvrez <UiPath path="nav.audience > audience.tabSuppressions" /> et vérifiez que les contacts désabonnés et injoignables s’y trouvent.

## Dépannage

- **« Keila a refusé la clé API »** : la clé a été supprimée, ou elle appartient à un autre projet ou à un autre serveur Keila. Créez une clé dans le bon projet.
- **« Utilisez l’adresse complète, comme https://lists.example.com. »** ou **« Utilisez uniquement l’adresse du serveur… »** : saisissez l’adresse à laquelle vous ouvrez Keila, en commençant par `https://`, sans rien après le nom d’hôte.
- **« Cette adresse se trouve sur un réseau privé ou interne. »** : utilisez l’adresse publique du serveur, ou demandez à l’exploitant d’activer `providers.allow_private_networks`.
- **« Keila redirige vers une autre adresse (301). Saisissez l’adresse à laquelle la source répond. »** : ReputeCast ne suit pas les redirections. Saisissez l’adresse finale.
- **Une clé de données personnalisées manque dans la correspondance des champs** : aucun des 100 premiers contacts ne l’a. Après l’import, renseignez le champ avec un [import CSV](/fr/audience/import/) qui associe les contacts par adresse e-mail.
