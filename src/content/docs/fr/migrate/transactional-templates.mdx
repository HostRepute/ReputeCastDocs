Pour migrer des modèles Postmark, ou les modèles que vous gardez dans SendGrid, Mailgun ou Notifuse, vous connectez une fois ReputeCast au compte, choisissez les modèles et lisez un rapport de conversion avant que quoi que ce soit ne soit créé. Chaque modèle est réécrit en [Liquid](/fr/campaigns/personalization/) ReputeCast, ses variables sont déclarées d’après ce qu’il utilise, et il arrive en brouillon : rien n’est publié, et votre application continue d’envoyer les versions en ligne jusqu’à ce que quelqu’un publie un brouillon.

## Avant de commencer

- Il vous faut l’autorisation `transactional:edit` (les rôles Propriétaire, Admin et Éditeur l’ont). Seules des personnes peuvent lancer un import, pas des clés API.
- Procurez-vous l’identifiant de votre source. La clé est stockée chiffrée pour ce seul import et supprimée à la fin de celui-ci.

  | Source                  | Ce qu’il faut coller                                                                                                                                                                                                                                                                     |
  | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Postmark                | Un Server API token, depuis l’onglet **API Tokens** du serveur. Source : [Postmark, What are the Account and Server API Tokens](https://postmarkapp.com/support/article/1008-what-are-the-account-and-server-api-tokens)                                                                |
  | SendGrid                | Une clé API en Custom Access qui inclut l’accès en lecture à Template Engine, depuis **Settings** › **API Keys**. Source : [SendGrid, API Keys](https://www.twilio.com/docs/sendgrid/ui/account-and-settings/api-keys)                                                                  |
  | Mailgun                 | Une clé API de compte, depuis le menu du profil › **API Security**, ainsi que la région de votre compte (US ou EU). Source : [Mailgun, Where can I find my API keys](https://help.mailgun.com/hc/en-us/articles/203380100-Where-can-I-find-my-API-keys-and-SMTP-credentials)            |
  | Notifuse                | L’adresse de votre instance et une clé API d’espace de travail avec Templates read. Source : [Notifuse, Admins & API Keys](https://docs.notifuse.com/features/admins-api-keys)                                                                                                         |
  | Fichiers MJML ou HTML   | Jusqu’à 50 fichiers `.mjml`, `.html` ou `.htm` de 2 Mo au plus chacun, en UTF-8                                                                                                                                                                                                          |

  Sources vérifiées en octobre 2026.

## Importer les modèles

<Steps>

1. Ouvrez <UiPath path="nav.transactional > transactional.common.importTemplates" /> et choisissez l’endroit où se trouvent actuellement les modèles.

   <Screenshot
     id="transactional"
     alt="La page des modèles transactionnels, avec le bouton Importer des modèles à côté de Nouveau modèle en haut à droite et 16 modèles dans la liste en dessous."
   />

2. Connectez la source. Pour Postmark, collez le jeton dans <UiPath path="transactional.import.postmarkKey" /> ; pour SendGrid, collez la clé API. Pour Mailgun, collez la clé dans <UiPath path="transactional.import.mailgunKey" /> et choisissez la <UiPath path="transactional.import.mailgunRegion" /> ; renseignez <UiPath path="transactional.import.mailgunDomain" /> pour lire les modèles d’un seul domaine, ou laissez-le vide pour lire tous les domaines qui ne sont pas désactivés. Pour Notifuse, saisissez l’<UiPath path="transactional.import.notifuseAddress" />, comme `https://notifuse.example.com`, et la clé API. Pour <UiPath path="transactional.import.files" />, déposez ou choisissez les fichiers : ils sont convertis immédiatement, et l’étape suivante est le rapport.

3. Choisissez les modèles. ReputeCast présélectionne les modèles actifs de Postmark, tous les modèles SendGrid et Mailgun, et les modèles transactionnels de Notifuse ; cochez tous les autres que vous voulez.

4. Convertissez-les et lisez le rapport. Chaque modèle obtient l’un des résultats du tableau ci-dessous, avec la ligne et la construction à l’origine de chaque note.

5. Importez-les en brouillons. Le rapport indique l’ID ReputeCast que reçoit chaque brouillon ; ouvrez chacun d’eux, corrigez ce que demande le rapport et publiez-le depuis l’éditeur de modèles.

</Steps>

| Résultat                                                  | Signification                                                                                             |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| <UiPath path="transactional.import.resultConverted" />  | Rien ne demande votre attention.                                                                          |
| <UiPath path="transactional.import.resultNotes" />      | Une construction a été réécrite avec un changement visible, comme `{{#each items}}` qui devient `{% for item in items %}`. |
| <UiPath path="transactional.import.resultManual" />     | Une construction a été conservée telle quelle, et le brouillon affiche une erreur Liquid tant que vous ne l’avez pas remplacée. |
| <UiPath path="transactional.import.resultFailed" />     | La source n’a pas renvoyé le modèle ; le rapport indique pourquoi.                                       |

## Comment les modèles sont convertis

- Les **ID** viennent de l’alias ou du nom dans la source : lettres minuscules, chiffres et tirets, jusqu’à 64 caractères. Quand un ID est pris, le brouillon reçoit `-2`, `-3`, etc., et le rapport le signale.
- **Objets :** les modèles Postmark, SendGrid et Notifuse conservent leur objet. Mailgun ne conserve l’objet que lorsque la version du modèle a un en-tête `Subject` ; un fichier le prend dans le `<mj-title>` de MJML ou le `<title>` du HTML, et le `<mj-preview>` de MJML devient le texte d’aperçu. Sans cela, l’objet est vide et le rapport vous demande de le rédiger.
- **Mises en page :** un modèle Postmark qui utilise une mise en page la reçoit fusionnée à l’emplacement de `{{{ @content }}}`.
- **Versions :** SendGrid et Mailgun fournissent la version active. Un modèle SendGrid sans version active apporte sa première version, avec une note.
- Les **variables** sont déclarées d’après ce qu’utilise chaque modèle, avec un type. Les données de test de SendGrid et de Notifuse deviennent des valeurs d’exemple et le premier jeu de données de test. Un nom de variable que l’API ne peut pas accepter, comme `first-name`, est renommé (`first_name`) partout dans le modèle, et le rapport vous indique ce que votre application doit envoyer à la place.
- Les modèles **Notifuse** sont déjà en Liquid. Les champs de contact deviennent de simples variables (`contact.first_name` devient `first_name`, `contact.email` devient `to.email`), et `notification_center_url` devient `preferences_url`. Les modèles de l’éditeur visuel arrivent en MJML.

Réécritures et corrections manuelles courantes :

<TableScroll label="Comment les modèles sont convertis" wrap>

| Dans la source                                                 | Dans ReputeCast                                                                 |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `{{#each items}}` (Handlebars, Mustachio)                     | `{% for item in items %}`                                                       |
| Une section comme `{{#person}}` ou `{{#with author}}`         | `{% if person %}` ; les noms qu’elle contient commencent désormais par `person.` |
| `{{{ pm:unsubscribe }}}` de Postmark, `{{{unsubscribe}}}` de SendGrid | `{{ unsubscribe_url }}`                                                  |
| `<%asm_preferences_raw_url%>` de SendGrid                      | `{{ preferences_url }}`                                                         |
| `{{insert name "default=Customer"}}` de SendGrid               | `{{ name \| default: "Customer" }}`                                             |
| `%recipient.first_name%`, `%recipient_email%` de Mailgun       | `{{ first_name }}`, `{{ to.email }}`                                            |
| Un partial comme `{{> footer}}`, ou `{% include %}` en Liquid  | Correction manuelle : les modèles ne peuvent pas inclure d’autres fichiers. Utilisez une section enregistrée. |
| Un helper ou un filtre que ReputeCast n’a pas, comme `formatCurrency` ou `money` | Correction manuelle : remplacez-le, par exemple en envoyant la valeur déjà formatée dans les données de l’appel. |
| `view_in_browser_url`                                          | Correction manuelle : les e-mails transactionnels n’ont pas de version web. Retirez le lien. |
| Du MJML qui ne compile pas, un bloc jamais fermé               | Correction manuelle, avec le numéro de ligne                                    |

</TableScroll>

<Aside type="note">
Les brouillons importés n’atteignent jamais personne d’eux-mêmes. Tant qu’un brouillon n’est pas publié, l’API d’envoi continue d’utiliser la version en ligne du modèle, et un modèle qui n’a jamais été publié ne peut pas être envoyé du tout.
</Aside>

## Vérifier le résultat

La dernière étape liste chaque brouillon avec son ID ReputeCast et le nombre de brouillons qui nécessitent une correction manuelle. Les brouillons se trouvent dans <UiPath path="nav.transactional > transactional.common.tabTemplates" /> ; ouvrez-en un pour voir ses variables, ses données de test et toute erreur Liquid mentionnée par le rapport. Envoyez-vous un test depuis l’éditeur avant de le publier.

## Dépannage

- **« Postmark a répondu 401 : ce jeton correspond à un autre serveur ou a été révoqué. »** (ou 403) : copiez le jeton du serveur dont vous voulez les modèles.
- **« SendGrid a répondu 403 : cette clé ne peut pas lire les modèles. »** : modifiez la clé dans SendGrid et donnez-lui l’accès en lecture à Template Engine.
- **« Mailgun a répondu 401 : la clé API est incorrecte, ou le compte se trouve dans l’autre région. »** (ou 403) : changez de région, ou créez une nouvelle clé API de compte.
- **« Ce compte Mailgun n’a aucun domaine, donc aucun modèle à importer. »** : dans Mailgun, les modèles se trouvent sur des domaines ; ajoutez d’abord le domaine là-bas, ou saisissez le bon domaine d’envoi.
- **« … dépasse 2 Mo. »** ou **« Jusqu’à 50 fichiers à la fois »** : répartissez l’envoi des fichiers ; chaque envoi constitue un import.
- **« … limite le débit des requêtes (429). Réessayez dans une minute. »** : ReputeCast a réessayé trois fois, en respectant le `Retry-After` du fournisseur. Patientez une minute et relancez la conversion.
- **« Cet import n’a plus de clé API. Recommencez et collez la clé. »** : l’import a été terminé ou annulé, ce qui supprime la clé. Lancez un nouvel import.
