Configurez l’authentification à deux facteurs (clés d’accès ou application d’authentification), conservez vos codes de
récupération, et gérez votre mot de passe, vos méthodes de connexion et vos sessions depuis
<UiPath path="shell.userMenuAccount" /> dans le menu du compte. Les règles viennent de la politique d’authentification de
l’instance, que définit un [admin de l’instance](/fr/self-hosting/instance-admin/).

## Avant de commencer

- Tout ce qui figure sur cette page concerne votre propre compte ; aucune autorisation d’espace de travail n’est nécessaire.
- Si vous disposez d’une [autorisation sensible](/fr/reference/glossary/#sensitive-permission), l’authentification à deux
  facteurs est obligatoire par défaut après un délai de grâce de 7 jours. La carte de l’application d’authentification
  indique si elle est obligatoire pour vous.
- Les clés d’accès exigent que l’URL publique de l’instance utilise un nom de domaine, et non une adresse IP.

<Steps>

1. **Changer votre mot de passe.** Dans <UiPath path="account.password" />, saisissez votre mot de passe actuel et le
   nouveau deux fois, puis choisissez <UiPath path="account.changePassword" />. Le nouveau mot de passe doit respecter la
   longueur minimale, ne peut être ni votre mot de passe actuel ni l’un de vos mots de passe récents, et il est comparé
   aux fuites connues si l’instance a activé ce contrôle. Le changer déconnecte vos autres sessions. Si vous vous
   connectez uniquement par authentification unique, cette carte est masquée.

   Un compte qui n’a pas encore de mot de passe, comme un compte qui se connecte avec Google ou une clé d’accès, définit
   ici son premier mot de passe sans mot de passe actuel, mais uniquement dans les 15 minutes qui suivent la connexion.
   Depuis la version 1.5.0, un compte dont un fournisseur SSO impose le domaine e-mail ne peut pas ajouter de mot de
   passe du tout, sauf s’il appartient à un
   [Propriétaire avec compte d’urgence](/fr/self-hosting/sso/#imposer-le-sso-pour-vos-domaines).

2. **Ajouter une clé d’accès.** Dans <UiPath path="account.passkeys" />, choisissez <UiPath path="account.addPasskey" />
   et suivez l’invite de votre navigateur (Touch ID, Face ID, Windows Hello, un gestionnaire de mots de passe ou une clé de
   sécurité). Une clé d’accès vous connecte à elle seule avec <UiPath path="auth.signIn.passkeySignIn" />, et après un mot
   de passe, elle compte comme second facteur. Renommez-la pour la reconnaître plus tard. Vous pouvez en ajouter autant
   que vous le souhaitez.

3. **Configurer une application d’authentification.** Dans <UiPath path="account.authenticatorApp" />, choisissez
   <UiPath path="account.setUp" />. Scannez le code QR avec n’importe quelle application TOTP (1Password, Google
   Authenticator, Authy) ou saisissez la clé, puis entrez le code à 6 chiffres. Les codes changent toutes les 30 secondes.

4. **Enregistrer vos codes de récupération.** Une fois le code confirmé, ReputeCast affiche une seule fois 10
   [codes de récupération](/fr/reference/glossary/#recovery-code). Téléchargez-les, imprimez-les ou copiez-les, cochez
   que vous les avez enregistrés, puis terminez. Chaque code fonctionne une seule fois à la connexion, par
   <UiPath path="auth.signIn.useRecovery" />. <UiPath path="account.regenerateCodes" /> remplace tous les anciens codes
   par 10 nouveaux.

5. **Associer d’autres connexions.** Dans <UiPath path="account.connectedSignIns" />, choisissez
   <UiPath path="account.link" /> à côté de Google, Microsoft ou GitHub quand l’instance les propose.
   <UiPath path="account.unlink" /> est désactivé pour votre dernière méthode de connexion restante.

6. **Passer en revue vos sessions.** <UiPath path="account.activeSessions" /> liste chaque appareil et navigateur
   connecté avec son adresse IP et sa dernière activité. Utilisez <UiPath path="account.signOut" /> sur une ligne, ou
   <UiPath path="account.signOutAllOthers" />. Pour mettre fin à la session que vous utilisez, choisissez
   <UiPath path="shell.userMenuSignOut" /> dans le menu du compte.

7. **Modifier votre adresse e-mail.** Dans <UiPath path="account.profile" />, choisissez
   <UiPath path="account.changeEmail" />, saisissez la nouvelle adresse et votre mot de passe actuel, puis
   <UiPath path="account.sendLink" />. Ouvrez le lien depuis la nouvelle boîte de réception dans les 24 heures, en étant
   connecté au même compte. Votre ancienne adresse reçoit un message après le changement. Un compte sans mot de passe
   confirme plutôt le changement en s’étant connecté dans les 15 dernières minutes. Quand un fournisseur SSO gère votre
   compte, la nouvelle adresse doit aussi être une adresse que ce fournisseur gère ; c’est de nouveau vérifié quand vous
   ouvrez le lien.

</Steps>

<Aside type="danger">
  Vous ne pouvez pas désactiver vous-même une application d’authentification, seulement utiliser
  <UiPath path="account.replaceApp" /> ; la remplacer remplace aussi vos codes de récupération. Si vous perdez votre
  téléphone et vos codes, un admin de l’instance peut réinitialiser votre 2FA dans
  <UiPath path="shell.userMenuInstanceAdmin > admin.users" />, ou avec la CLI comme décrit dans
  [récupérer l’accès en ligne de commande](/fr/self-hosting/account-recovery/).
</Aside>

## Sessions, délais d’inactivité et blocage

- Une session prend fin après sa durée de vie, ou après le délai d’inactivité sans activité. Deux minutes avant la fin,
  un bandeau vous permet de prolonger le délai d’inactivité ; la durée de vie, elle, ne bouge jamais.
- Quand un admin de l’instance raccourcit le délai d’inactivité, les sessions existantes s’y conforment en 30 secondes
  environ. Une nouvelle durée de vie s’applique aux sessions ouvertes après le changement.
- Trop de tentatives échouées pour une adresse e-mail bloquent la connexion pour cette adresse. Les mots de passe erronés
  comptent et, depuis la version 1.5.0, les codes d’authentification et de récupération erronés saisis après un mot de
  passe correct aussi : le compteur ne se remet à zéro que lorsqu’une connexion complète réussit. Cinq codes erronés
  mettent aussi fin à cette tentative de connexion : vous recommencez alors avec votre adresse e-mail. La connexion par
  clé d’accès fonctionne toujours pendant le blocage, et <UiPath path="auth.forgotPassword" /> envoie un lien de
  réinitialisation valable une seule fois pendant 15 minutes, qui lève le blocage. L’utiliser déconnecte toutes vos
  sessions.
- Chaque code d’authentification ne fonctionne qu’une fois. Un code déjà utilisé est refusé, même pendant ses
  30 secondes ; attendez le suivant.

## Vérifier le résultat

- La carte de l’application d’authentification affiche **Activée** avec la date de configuration, et la ligne des codes
  de récupération indique 10 codes restants.
- Votre clé d’accès est listée avec « utilisée maintenant » après une connexion avec elle.
- Sur la [page Équipe](/fr/team/members/), votre colonne 2FA indique « Activée · TOTP » ou « Activée · clé d’accès ».

## Dépannage

- **Le code à 6 chiffres est refusé.** Réglez l’horloge de votre téléphone sur la mise à jour automatique et essayez le
  code suivant.
- **« Ce code a déjà été utilisé. »** Chaque code d’authentification ne permet qu’une connexion. Attendez le suivant dans
  votre application d’authentification.
- **« Pour votre sécurité, cette action demande une connexion récente. »** Ajouter un premier mot de passe, ou modifier
  l’adresse e-mail d’un compte sans mot de passe, nécessite une session connectée dans les 15 dernières minutes.
  Déconnectez-vous, reconnectez-vous, puis réessayez.
- **« Cette clé d’accès est votre seul moyen de connexion. »** Ajoutez une autre clé d’accès ou un mot de passe avant de
  la supprimer.
- **« L’authentification à deux facteurs est obligatoire pour votre compte » à la suppression d’une clé d’accès.**
  Configurez d’abord une application d’authentification ou ajoutez une autre clé d’accès.
- **Chaque page vous renvoie vers la configuration.** Votre délai de grâce est écoulé : ajoutez une clé d’accès ou une
  application d’authentification pour continuer.
- **« La connexion est bloquée ».** Attendez la fin du blocage, réinitialisez votre mot de passe ou connectez-vous avec
  une clé d’accès. Les tentatives échouées figurent dans le [journal d’audit](/fr/team/audit-log/) avec leurs adresses IP.
- **« Limite de débit de l’API atteinte ».** Votre session de navigateur a envoyé en une minute plus de requêtes que
  l’instance n’en autorise. Chaque session connectée a sa propre limite (voir
  [limites de débit](/fr/developers/api-rate-limits/)). Attendez que le bandeau indique que les requêtes peuvent
  reprendre, puis relancez ce qui n’est pas passé.
