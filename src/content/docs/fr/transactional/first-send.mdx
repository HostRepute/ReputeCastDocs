En 10 minutes environ, vous envoyez votre premier message avec l’API e-mail transactionnel : le guide du premier envoi
vous mène d’un expéditeur à un message délivré, et sa dernière étape valide toute la boucle avec un vrai appel depuis
votre application.

## Avant de commencer

- Un [fournisseur d’envoi](/fr/providers/connect/) connecté à l’espace de travail. Le guide vous demande d’en
  connecter un s’il n’y en a aucun.
- Un domaine d’envoi auquel vous pouvez ajouter des enregistrements DNS. Un sous-domaine dédié, comme
  `notify.example.com`, sépare la réputation des e-mails produit de celle de vos newsletters. Voir
  [ajouter des domaines d’envoi et des expéditeurs](/fr/providers/senders-and-domains/).
- Autorisations : `transactional:publish` pour publier le modèle et `apikeys:manage` pour créer la clé. Les rôles
  Propriétaire et Admin ont les deux.
- `curl` ou le client HTTP de votre application pour faire le premier appel.

## Envoyer le message

<Steps>

1. Ouvrez <UiPath path="nav.transactional" /> et choisissez <UiPath path="transactional.overview.startGuide" />. Le
   guide comporte cinq étapes : Expéditeur, Route, Modèle, Clé et Suivre l’arrivée. Vous pouvez le quitter à tout
   moment avec **Quitter le guide**.

2. **Expéditeur.** Saisissez un **Nom d’expéditeur** et une **Adresse d’expéditeur** sur le domaine qui envoie les
   e-mails transactionnels. Si le domaine est nouveau, le guide liste les enregistrements DNS dont il a besoin (DKIM,
   un return-path, SPF et une politique DMARC, selon le fournisseur d’envoi) et les vérifie en direct. La plupart des
   hébergeurs DNS mettent quelques minutes. Quand HostRepute est connecté, vous pouvez ajouter ici le domaine à sa
   surveillance des listes de blocage.

   <Screenshot
     id="transactional-guide"
     alt="Étape 1 sur 5 du guide du premier envoi : nom d’expéditeur Acme Cloud et adresse d’expéditeur no-reply@notify.acme.io, avec les cinq étapes listées à gauche."
   />

   Choisissez **Continuer vers la route**.

3. **Route.** Choisissez le fournisseur d’envoi **Principal** et, si vous en avez un deuxième, un fournisseur de
   **Secours**. Le secours est utilisé immédiatement quand le principal est en panne. Laissez
   **Prioritaires sur les fournisseurs partagés** activé pour que les messages transactionnels passent avant une
   campagne qui utilise le même fournisseur d’envoi. Choisissez **Continuer vers le modèle**.

4. **Modèle.** Partez d’un modèle de départ : Réinitialisation du mot de passe, Lien de connexion, Vérification de
   l’adresse e-mail, Bienvenue, Reçu ou facture, Fin de l’essai, Invitation d’équipe ou Alerte de consommation.
   Chacun arrive avec ses variables déclarées et un pied de page pour les e-mails de compte. Choisissez
   **Publier la v1 et continuer**, ou **Modifier avant de publier** pour le modifier d’abord dans
   l’[éditeur de modèles](/fr/transactional/templates/). Si vos modèles sont chez Postmark, SendGrid, Mailgun ou
   Notifuse, vous pouvez [les importer plutôt](/fr/migrate/transactional-templates/).

5. **Clé.** Nommez la clé (par exemple `Acme Cloud · production`) et choisissez
   **Créer une clé d’envoi uniquement**. Une [clé d’envoi uniquement](/fr/reference/glossary/#send-only-key) détient
   `transactional:send` et rien d’autre. Copiez-la maintenant : elle n’est affichée qu’une fois. Choisissez ensuite
   **Je l’ai copiée · suivre l’arrivée**.

6. **Suivre l’arrivée.** Le guide affiche **Votre premier appel**, rempli avec l’ID du modèle et ses données
   d’exemple. Lancez-le depuis votre ordinateur ou votre application avec la clé que vous avez copiée. La requête
   ressemble à ceci ; reprenez le corps exact dans le guide, car il contient les variables de votre modèle :

   ```sh title="Terminal"
   curl -X POST "https://reputecast.example.com/api/v1/workspaces/acme-newsletter/transactional/messages" \
     -H "Authorization: Bearer $REPUTECAST_KEY" \
     -H "Content-Type: application/json" \
     -H "Idempotency-Key: first-send-1" \
     -d @first-message.json
   ```

   La **Chronologie de la livraison** suit le message : **Appel reçu**, **Rendu effectué**, **Transmis à** (le
   fournisseur d’envoi) et **Délivré**, avec l’aller-retour entre votre appel et l’événement de livraison. Si vous
   préférez ne pas lancer l’appel, **L’envoyer plutôt d’ici** l’envoie à votre propre adresse avec les données
   d’exemple.

7. Choisissez **Terminer** une fois le premier message délivré.

</Steps>

## Ce que vous avez créé

- Un expéditeur vérifié pour les e-mails transactionnels et une route Transactionnel avec basculement automatique.
- Un modèle publié que votre application appelle par son ID. L’ID est fixé dès cette première publication.
- Une clé d’envoi uniquement pour votre application, listée sous
  <UiPath path="nav.transactional > transactional.common.tabSetup" />, où vous pouvez la renouveler ou la révoquer.
- Un premier message dans le [journal des messages](/fr/transactional/message-log/), avec sa chronologie complète.

Si l’appel a été refusé, la chronologie indique pourquoi. Un modèle qui a un brouillon mais aucune version publiée ne
peut pas envoyer : publiez-le, puis rappelez l’API avec la même clé d’idempotence.
