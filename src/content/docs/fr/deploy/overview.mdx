Chaque guide vous aide à déployer ReputeCast sur une plateforme d’hébergement : l’image de version
`ghcr.io/hostrepute/reputecast:v1.6.0` avec PostgreSQL, derrière le proxy HTTPS de la plateforme, d’un projet vide
jusqu’à la première connexion. Choisissez la plateforme que vous utilisez déjà ; sur un serveur classique, suivez plutôt
[installer avec Docker Compose](/fr/self-hosting/docker/) ou [installer le binaire](/fr/self-hosting/binary/).

| Plateforme                                 | Fonctionne sur           | PostgreSQL                                    | Bon à savoir                                                                          |
| ------------------------------------------ | ------------------------ | --------------------------------------------- | ------------------------------------------------------------------------------------- |
| [Coolify](/fr/deploy/coolify/)             | Votre serveur            | Dans le même fichier Compose (PostgreSQL 18)  | Coolify génère la clé secrète pour vous.                                              |
| [Dokploy](/fr/deploy/dokploy/)             | Votre serveur            | Dans le même fichier Compose (PostgreSQL 18)  | Fichier Compose collé, domaine Let's Encrypt.                                         |
| [Easypanel](/fr/deploy/easypanel/)         | Votre serveur            | Le service Postgres d’Easypanel               | Changez le port du domaine de 80 à 8080.                                              |
| [CapRover](/fr/deploy/caprover/)           | Votre serveur            | L’app one-click PostgreSQL, version 18        | Un réglage nginx garde le flux des mises à jour en direct.                            |
| [Railway](/fr/deploy/railway/)             | Le cloud de Railway      | Le PostgreSQL de Railway                      | Une offre payante (Hobby ou Pro) pour le volume de l’application.                     |
| [Render](/fr/deploy/render/)               | Le cloud de Render       | Render Postgres                               | Offres payantes ; les services Free se mettent en veille et les bases Free expirent. |
| [Kubernetes](/fr/deploy/kubernetes/)       | Votre cluster            | CloudNativePG ou une base de données gérée    | Un pod avec un volume, ou des pods web, worker et ingest.                             |
| [DigitalOcean](/fr/deploy/digitalocean/)   | Le cloud de DigitalOcean | La base de données d’App Platform             | Pas de disque : les fichiers importés vont dans un bucket Spaces.                     |

## Installations en un clic

Le dépôt fournit une configuration prête à l’emploi pour cinq de ces plateformes. Chacune fait tourner une instance
ReputeCast à partir de l’image de version, avec PostgreSQL à côté ; le premier démarrage applique les migrations et
crée le premier Propriétaire à partir de l’adresse e-mail que vous saisissez, et le mot de passe temporaire se trouve
dans les journaux du service (cherchez `ReputeCast is installed`). Disponible à partir de la prochaine version après la
1.6.0.

| Plateforme                               | Point de départ                                                        | Ce qu’il faut                                                                                                                            |
| ---------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| [Render](/fr/deploy/render/)             | Le Blueprint `render.yaml`, via le lien Deploy to Render               | Un web service payant pour le disque de 10 Go et une base de données Render Postgres. Render demande l’URL publique et l’adresse e-mail. |
| [Railway](/fr/deploy/railway/)           | `deploy/railway/railway.ts`, appliqué avec la CLI Railway              | Railway Postgres et un volume. L’URL publique suit le domaine que Railway génère.                                                        |
| [DigitalOcean](/fr/deploy/digitalocean/) | `.do/deploy.template.yaml`, via le lien Deploy to DigitalOcean         | Un bucket Spaces et sa clé d’accès, et une clé secrète que vous générez.                                                                 |
| [Coolify](/fr/deploy/coolify/)           | `deploy/coolify/reputecast.yaml`, collé comme ressource Docker Compose | Un serveur Coolify avec un domaine. Coolify génère l’URL et le mot de passe PostgreSQL.                                                  |
| [Kubernetes](/fr/deploy/kubernetes/)     | Le chart de `deploy/helm/reputecast`, installé avec Helm               | Kubernetes 1.29 ou ultérieur, PostgreSQL 16 à 18 et un contrôleur Ingress.                                                               |

Quand vous passez à votre propre domaine, changez l’URL publique comme l’indique le guide, puis confirmez-la dans
<UiPath path="shell.userMenuInstanceAdmin > admin.instance" /> : l’adresse enregistrée lors de la première connexion
l’emporte sur la variable, et l’enregistrer à cet endroit déplace les webhooks des fournisseurs d’envoi.

## Ce que chaque guide met en place

- **Le port 8080.** L’image sert du HTTP simple sur le port 8080 ; le proxy de la plateforme termine le TLS et lui
  transmet les requêtes. Les plateformes qui routent vers le port indiqué dans `PORT` reçoivent `PORT=8080` : l’image
  définit `REPUTECAST_HTTP__ADDR=:8080`, qui l’emporte sur `PORT`, si bien que ReputeCast écoute sur le port 8080 dans
  tous les cas. Les métriques Prometheus écoutent sur le port 9464 dans le conteneur : n’attribuez jamais de domaine à
  ce port et ne le publiez jamais.
- **Quatre paramètres.** `REPUTECAST_DATABASE__URL` (la connexion PostgreSQL), `REPUTECAST_PUBLIC_URL` (l’adresse
  `https://` que les gens ouvrent), `REPUTECAST_ADMIN_EMAIL` (le premier Propriétaire) et `REPUTECAST_SECRETS__KEY`. La
  clé est l’encodage base64 de 32 octets aléatoires (`openssl rand -base64 32`) et chiffre les identifiants des
  fournisseurs et les autres secrets dans la base de données : enregistrez-la dans votre gestionnaire de mots de passe,
  car une [sauvegarde](/fr/self-hosting/backups/) est inutilisable sans elle.
- **Un volume sur `/var/lib/reputecast`** quand la plateforme en propose un : il conserve les fichiers importés.
  Sinon, les fichiers vont dans un [bucket compatible S3](/fr/self-hosting/object-storage/).
- **La vérification de l’état intégrée à l’image.** Toutes les 15 secondes, l’image exécute `reputecast healthcheck`,
  qui interroge `/readyz` sur l’application sans shell (l’image n’a toujours ni shell, ni `curl`, ni `wget`). Docker,
  sur Coolify, Dokploy, Easypanel et CapRover, marque le conteneur comme healthy dès que ReputeCast est prêt ; Railway,
  Render, DigitalOcean et Kubernetes appellent `/readyz` eux-mêmes. Surveillez aussi `/readyz` depuis l’extérieur
  ([surveillance](/fr/self-hosting/monitoring/)).
- **Le mot de passe temporaire du premier Propriétaire** s’affiche dans les journaux de l’application à son premier
  démarrage ; la [première connexion](/fr/self-hosting/first-run/) le remplace.

## Proxys de confiance

Aucune de ces plateformes ne publie les adresses depuis lesquelles son proxy se connecte. Avec la 1.6.0, les guides
laissent `REPUTECAST_HTTP__TRUSTED_PROXIES` vide. ReputeCast voit alors l’adresse du proxy pour chaque visiteur, dans
le journal d’audit, dans les limites qu’il compte par adresse, dans les IP autorisées des clés API et dans le filtre
anti-bots qui trie les ouvertures et les clics. Quand une adresse privée transmet des requêtes de façon répétée,
ReputeCast envoie aux admins de l’instance une notification qui la nomme ; ajoutez-la uniquement s’il s’agit du proxy
de votre plateforme.

Les configurations en un clic définissent plutôt `REPUTECAST_HTTP__TRUSTED_PROXIES=private`. Ce mot-clé couvre tous les
réseaux privés (RFC 1918), partagés (`100.64.0.0/10`) et de bouclage, y compris les adresses IPv6 locales uniques et de
bouclage : le routeur placé devant ReputeCast sur ces plateformes, dont vous ne pouvez pas connaître l’adresse à
l’avance. Ne l’utilisez pas là où des clients peuvent joindre ReputeCast directement depuis un réseau privé, comme le
réseau local d’un bureau : ils pourraient se faire passer pour n’importe quelle adresse. La 1.6.0 ne connaît pas ce
mot-clé ; elle journalise `ignoring invalid trusted proxy` et ne fait confiance à personne. Disponible à partir de la
prochaine version après la 1.6.0.

Pour définir vos propres adresses à la place, consultez
[reverse proxy et TLS](/fr/self-hosting/reverse-proxy/#définir-lurl-publique-et-les-proxys-de-confiance).
