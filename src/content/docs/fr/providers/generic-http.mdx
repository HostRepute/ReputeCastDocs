Quand votre fournisseur d’envoi n’est pas intégré à ReputeCast mais dispose d’une API HTTP d’envoi et de webhooks JSON
pour les événements, l’[adaptateur HTTP générique](/fr/reference/glossary/#generic-http-adapter) est une
intégration d’API e-mail personnalisée que vous configurez dans un formulaire, sans écrire de code. Vous décrivez la requête d’envoi,
l’endroit où la réponse place l’ID du message, et la façon dont les webhooks sont lus et authentifiés ; ReputeCast
l’enregistre comme un adaptateur que chaque espace de travail de l’instance peut connecter.

## Avant de commencer

- **Choisissez le bon type d’adaptateur.** L’adaptateur HTTP générique envoie une requête par message et lit les
  webhooks. Si votre fournisseur a aussi un endpoint SMTP, [une connexion SMTP](/fr/providers/smtp/) peut être plus simple ;
  s’il vous faut l’envoi par lots, une API de domaine ou la synchronisation de la liste de suppression, écrivez un
  [adaptateur communautaire](/fr/adapters/community/). [Adaptateurs de fournisseurs](/fr/adapters/overview/) compare les trois.
- **Admin de l’instance.** Les adaptateurs s’appliquent à tous les espaces de travail de l’instance : seuls les admins
  de l’instance qui ont `providers:manage` peuvent en enregistrer un. Les autres voient le formulaire en lecture seule.
- **Dans la documentation de l’API de votre fournisseur** : l’endpoint d’envoi, son mode d’authentification (en général
  une clé API dans un en-tête), le corps JSON attendu, l’endroit où sa réponse porte l’ID du message et la forme de ses
  événements webhook.
- **Une adresse HTTPS publique** pour le webhook. ReputeCast ne peut pas interroger une correspondance HTTP : l’adresse
  doit donc être joignable depuis Internet.

## Décrire et connecter l’API

<Steps>

1. Ouvrez <UiPath path="nav.providers > providers.tabAdapters" /> et faites défiler jusqu’à
   <UiPath path="providers.adapters.httpTitle" />.

   <Screenshot
     id="providers-adapters"
     alt="L’onglet Adaptateurs : les onze adaptateurs intégrés avec leurs événements, leur configuration du domaine et leur synchronisation des suppressions, puis les adaptateurs communautaires installés sur cette instance."
   />

2. Remplissez la correspondance :
   - <UiPath path="providers.adapters.sendEndpoint" /> : la méthode et une URL `https://`, par exemple
     `POST https://api.example-esp.com/v1/messages` (POST, PUT ou PATCH).
   - <UiPath path="providers.adapters.requestHeaders" /> : un par ligne, sous la forme `Name: value`, par exemple
     `Authorization: Bearer {{ secrets.api_key }}`. `{{ secrets.api_key }}` est la clé saisie quand un espace de travail
     connecte l’adaptateur.
   - <UiPath path="providers.adapters.bodyTemplate" /> : le corps JSON avec des champs `{{ }}` comme `{{ sender }}`,
     `{{ recipient }}`, `{{ subject }}`, `{{ html }}` et `{{ headers_json }}`. Les valeurs sont échappées pour le JSON.
     Ajoutez `{{ message_id }}` si le fournisseur peut le renvoyer dans les webhooks.
   - <UiPath path="providers.adapters.messageIdPath" /> : un JSONPath dans la réponse, par exemple `$.data.id`.
   - <UiPath path="providers.adapters.webhookMapping" /> : le préréglage pour les webhooks qui portent un champ `status`,
     ou une <UiPath path="providers.adapters.mappingJsonpath" /> avec les chemins de
     <UiPath path="providers.adapters.pathType" />, <UiPath path="providers.adapters.pathRecipient" />,
     <UiPath path="providers.adapters.pathMessageId" /> et, pour les webhooks par lots,
     <UiPath path="providers.adapters.pathEvents" />.
   - <UiPath path="providers.adapters.webhookAuth" /> : <UiPath path="providers.adapters.authHmac" />,
     <UiPath path="providers.adapters.authStandard" />, <UiPath path="providers.adapters.authBasic" />,
     <UiPath path="providers.adapters.authHeader" /> ou <UiPath path="providers.adapters.authNone" />.

3. Choisissez <UiPath path="providers.adapters.testSample" />. ReputeCast produit la requête qu’il enverrait pour un
   message d’exemple, avec les secrets affichés sous la forme `••••`. Rien n’est envoyé : cela vérifie la
   correspondance, pas le fournisseur.

4. Choisissez <UiPath path="providers.adapters.saveAsAdapter" />, donnez-lui un
   <UiPath path="providers.adapters.name" />, par exemple le nom du fournisseur, et enregistrez. L’adaptateur apparaît
   dans l’ajout de fournisseur de chaque espace de travail.

5. Dans l’espace de travail qui envoie, ouvrez <UiPath path="nav.providers" />, choisissez
   <UiPath path="providers.overview.addProvider" /> et trouvez votre adaptateur sous
   <UiPath path="connect.catalog.communityTitle" />. Choisissez <UiPath path="connect.connection.connect" />, collez la
   <UiPath path="providers.fields.apiKey" /> et, si le fournisseur signe ses webhooks avec un secret à lui, son
   <UiPath path="providers.fields.webhookSigningSecret" /> dans les paramètres supplémentaires. Une correspondance créée
   par formulaire n’a pas de vérification des identifiants : une clé erronée n’apparaît qu’à l’envoi de test.

6. Dans <UiPath path="connect.connection.webhooksTitle" />, ReputeCast vérifie que son adresse de webhook est joignable
   depuis Internet. Choisissez <UiPath path="connect.connection.copyUrl" /> et ajoutez cette URL comme webhook chez votre
   fournisseur. Si vous n’avez pas saisi le secret de signature propre au fournisseur, choisissez
   <UiPath path="connect.connection.createSecret" />, copiez-le (il n’est affiché qu’une fois) et configurez-le chez le
   fournisseur comme l’indique votre authentification des webhooks.

7. Choisissez <UiPath path="connect.connection.continueDomain" /> et terminez l’étape avec les enregistrements DNS que documente votre
   fournisseur ; ReputeCast suggère DMARC si le domaine n’en a pas. Dans <UiPath path="connect.stepTest" />, envoyez un
   test : c’est un vrai message qui passe par votre correspondance, et la chronologie attend jusqu’à 30 minutes le premier
   webhook du fournisseur.

</Steps>

<Aside type="note">
  Le formulaire couvre le cas courant. Une vérification de l’état, des champs de connexion supplémentaires, des chemins
  de codes d’erreur, des conditions et des noms d’événements personnalisés demandent un manifest ; voir la
  [référence de l’adaptateur HTTP générique](/fr/adapters/generic-http/).
</Aside>

## Vérifier le résultat

- La chronologie de l’envoi de test affiche l’événement de livraison de votre fournisseur.
- La carte de votre adaptateur dans <UiPath path="nav.providers > providers.tabProviders" /> affiche
  <UiPath path="providers.statusHealthy" />, et les événements arrivent dans
  <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast envoie une requête par message, jusqu’à 20 par seconde. Un `401` ou un `403` du fournisseur le marque en
panne pour identifiants refusés, un `429` le ralentit, et un `408` ou un `5xx` compte pour une panne. Les copies et les
pièces jointes ne sont pas prises en charge par une correspondance. ReputeCast ne peut pas lire les conditions de votre
fournisseur : vérifiez sa politique d’utilisation acceptable avant de lui confier les Diffusions.

Une API mise en correspondance ne reçoit pas d’e-mails pour ReputeCast. Pour que les réponses et les rapports DMARC
arrivent dans ReputeCast, [configurez la réception des e-mails](/fr/providers/receiving-mail/) avec une boîte aux
lettres IMAP ou POP3 ou un fournisseur d’envoi qui reçoit des e-mails. Disponible à partir de la prochaine version après
la 1.6.0.

## Dépannage

- **« Saisissez une URL https://, par exemple POST https://api.example-esp.com/v1/messages. »** Le formulaire a besoin
  de la méthode et d’une adresse `https://`. Une adresse `http://` simple ne fonctionne que dans un manifest, pour un
  serveur de test en loopback.
- **« Le modèle du corps n’est pas du JSON valide une fois ses champs `{{ }}` remplis. »** Vérifiez les virgules et les
  guillemets. Dans une chaîne JSON, un champ est échappé sur place (`"subject": "{{ subject }}"`) ; hors d’une chaîne,
  il est encodé en JSON, si bien que `"headers": {{ headers_json }}` devient un objet.
- **« … est déjà enregistré sous … ».** Un autre adaptateur porte ce nom. Choisissez-en un autre.
- **L’envoi de test échoue avec « … n’a pas accepté le test ».** La réponse du fournisseur suit le message : souvent
  une clé erronée, un en-tête manquant ou un champ du corps que l’API refuse. Comparez la requête produite par
  <UiPath path="providers.adapters.testSample" /> avec la documentation du fournisseur.
- **Les webhooks reçoivent `401`.** Les requêtes du fournisseur ne correspondent pas à l’authentification des webhooks
  que vous avez choisie, ou il utilise encore un ancien secret. Après
  <UiPath path="senders.providers.rotateSecrets" /> dans <UiPath path="nav.settings > settings.providers" />, collez le
  nouveau secret chez le fournisseur, car ReputeCast ne peut pas l’y mettre à jour.
- **Vous avez déconnecté l’adaptateur.** ReputeCast ne modifie rien chez le fournisseur. Retirez-y le webhook qui pointe
  vers ReputeCast.
