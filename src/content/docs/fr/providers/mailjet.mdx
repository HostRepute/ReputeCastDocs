Pour envoyer une newsletter avec Mailjet depuis ReputeCast, vous connectez une clé API Mailjet et sa Secret key.
ReputeCast enregistre un callback d’événement pour chaque événement dont il a besoin, configure votre domaine d’envoi,
envoie jusqu’à 50 messages par appel avec le suivi de Mailjet désactivé, et garde les exclusions de campagne de Mailjet
alignées sur la liste de suppression partagée.

<ProviderMatrix family="email" id="mailjet" />

## Avant de commencer

- **Une clé API et sa Secret key**, depuis Mailjet › Account settings › API key management. Créez une clé utilisée
  uniquement par ReputeCast : Mailjet autorise une URL de callback par événement et par clé API, si bien qu’une clé
  partagée avec un autre outil entre en conflit avec ses callbacks.
- **Autorisations.** La connexion demande `providers:manage` ; ajouter un nouveau domaine d’envoi demande
  `domains:manage`.
- **Une adresse HTTPS publique** pour les callbacks : `<public URL>/hooks/mailjet/<token>`. L’Event API de Mailjet envoie
  à l’URL que vous lui donnez et recommande HTTPS avec des identifiants basic auth dans l’URL
  ([Mailjet : Event API](https://dev.mailjet.com/email/guides/webhooks/), vérifié en octobre 2026), et c’est ainsi que
  ReputeCast l’enregistre.

## Connecter Mailjet

<Steps>

1. Ouvrez <UiPath path="nav.providers" />, choisissez <UiPath path="providers.overview.addProvider" /> et sélectionnez
   Mailjet dans le catalogue. [Connecter un fournisseur d’envoi](/fr/providers/connect/) explique les étapes que partagent
   tous les fournisseurs.

2. Collez la <UiPath path="providers.fields.apiKey" /> et la <UiPath path="providers.fields.mailjet.secretKey" />.
   Mailjet n’a pas d’API pour votre forfait : saisissez votre <UiPath path="providers.fields.monthlyLimit" /> dans les
   paramètres Mailjet supplémentaires si vous voulez une barre de quota.

3. Choisissez <UiPath path="connect.connection.connect" />. ReputeCast vérifie la paire de clés par un appel en lecture
   seule et stocke les deux valeurs chiffrées. La carte indique si la clé est active.

4. Dans <UiPath path="connect.connection.webhooksTitle" />, ReputeCast vérifie que son adresse de webhook est joignable
   depuis Internet, puis enregistre un callback pour chacun des événements `sent`, `bounce`, `blocked`, `spam` et
   `unsub`. Chaque URL de callback porte des identifiants basic auth
   (`https://reputecast:<secret>@<your host>/hooks/mailjet/<token>`), car Mailjet ne signe pas ses callbacks. Les
   événements d’ouverture et de clic ne sont pas enregistrés : ReputeCast les suit lui-même.

5. Choisissez <UiPath path="connect.connection.continueDomain" /> et saisissez votre domaine d’envoi. ReputeCast ajoute
   un expéditeur de domaine (`*@<your domain>`) dans Mailjet et liste les enregistrements que demande Mailjet :
   l’enregistrement TXT de propriété, DKIM et SPF (avec `include:spf.mailjet.com`), plus DMARC si le domaine n’en a pas.

6. Dans <UiPath path="connect.stepTest" />, envoyez un test et regardez le callback `sent` revenir sous forme de
   livraison.

7. Dans <UiPath path="connect.stepStreams" /> et <UiPath path="connect.stepContacts" />, choisissez les flux et laissez
   cochée l’option qui importe les exclusions déjà présentes chez Mailjet.

</Steps>

## Vérifier le résultat

- La carte Mailjet dans <UiPath path="nav.providers > providers.tabProviders" /> affiche
  <UiPath path="providers.statusHealthy" /> et « Clé API active ».
- Dans Mailjet, les réglages de notification d’événements de cette clé API font pointer `sent`, `bounce`, `blocked`,
  `spam` et `unsub` vers votre URL ReputeCast.
- Les livraisons et les rebonds apparaissent dans <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast envoie par la Send API v3.1 de Mailjet, jusqu’à 50 messages par appel, avec le suivi des ouvertures et des
clics désactivé sur chaque message. Le total mensuel de la carte correspond à ce que cette clé a envoyé ce mois-ci, lu
dans les statistiques de Mailjet.

<Aside type="note">
  La liste d’exclusion de Mailjet ne s’applique qu’aux campagnes envoyées depuis Mailjet, pas à la Send API qu’utilise
  ReputeCast. ReputeCast vérifie sa propre [liste de suppression](/fr/reference/glossary/#suppression-list) avant chaque
  envoi ; la synchronisation aligne les propres campagnes de Mailjet sur elle.
</Aside>

## Dépannage

- **« Mailjet a refusé cette clé »** avec `401 Unauthorized`. La clé API et la Secret key vont par paire : vérifiez les
  deux, même si l’erreur s’affiche sur le champ de la clé API.
- **« Mailjet autorise une URL de callback par événement et par clé API »** lors de l’enregistrement des webhooks. Un
  autre outil (ou une ancienne adresse ReputeCast) utilise déjà ces événements sur cette clé. Utilisez une clé API
  réservée à ReputeCast, ou supprimez ces callbacks dans Mailjet, puis choisissez
  <UiPath path="connect.connection.registerAgain" />. Les événements qui n’étaient pas pris sont enregistrés malgré tout.
- **La carte indique « Clé API inactive » ou « en quarantaine ».** Mailjet a limité la clé. Réglez le problème dans
  Mailjet avant de lui confier des e-mails.
- **Le domaine affiche « n’est pas configuré dans Mailjet ».** L’expéditeur de domaine a été supprimé dans Mailjet.
  Recréez l’expéditeur `*@<your domain>` dans Mailjet.
- **Le catalogue affiche un badge « Mode sandbox ».** ReputeCast n’envoie jamais par le mode sandbox de Mailjet : chaque
  message qu’il transmet est délivré.
- **Vous avez déconnecté Mailjet.** ReputeCast supprime les callbacks qui pointent vers son URL. L’expéditeur de domaine
  et les exclusions restent dans Mailjet.
