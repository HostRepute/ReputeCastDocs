A [discount code pool](/reference/glossary/#discount-code-pool) hands out unique discount codes: every reader of a campaign or an automation email gets a code of their own as the email is sent, from codes you upload or codes ReputeCast creates in your connected Shopify or WooCommerce store. The pool then counts which codes were sent, which were redeemed and the revenue of the orders that used them. Available from the next release after 1.6.0.

## Before you begin

- Seeing pools and their numbers needs `campaigns:view`. Creating a pool, adding, creating, removing or exporting its codes and archiving it needs `coupons:manage`, which Owner, Admin and Editor have. It is a sensitive permission that only people use: API keys and agents can read pools, never change them. See [roles and permissions](/team/roles-and-permissions/).
- Putting a code in an email needs `campaigns:edit`.
- For codes created in a store, [connect the store](/integrations/shopify-woocommerce/) first. A Shopify store must allow discount codes: <UiPath path="coupons.allowDiscounts" /> asks Shopify for the `write_discounts` and `read_discounts` scopes and needs `integrations:manage`. A WooCommerce store needs a REST key with Read/Write access.

## Create a pool

<Steps>

1. Open <UiPath path="nav.campaigns" />, select <UiPath path="coupons.title" /> next to the search box, then <UiPath path="coupons.newPool" />.

2. Give it a <UiPath path="coupons.name" /> (up to 80 characters). <UiPath path="coupons.slug" /> fills itself from the name ("Spring 20%" becomes `spring_20`): 1 to 32 lowercase letters, digits or `_`, used in templates as `coupons.spring_20.code`. It can't change once the pool exists.

3. Choose the <UiPath path="coupons.source" />:

   - <UiPath path="coupons.srcUpload" />, for codes you already have.
   - **Create in Shopify** or **Create in WooCommerce**, one card per connected store. A store that can't create codes says why, with <UiPath path="coupons.allowDiscounts" /> for a Shopify store that hasn't allowed them, or <UiPath path="coupons.replaceKey" /> for a WooCommerce key that is read-only.

4. For a store, set the discount every code gives: the <UiPath path="coupons.kind" /> (<UiPath path="coupons.kindPercentage" />, <UiPath path="coupons.kindFixed" /> in the store's currency, or <UiPath path="coupons.kindFree" />), the <UiPath path="coupons.value" />, an optional <UiPath path="coupons.minimum" />, <UiPath path="coupons.endsAfter" /> a number of days (1 to 365; empty never ends) and what it <UiPath path="coupons.appliesTo" /> (<UiPath path="coupons.allProducts" /> or one collection). Every code works once, for one customer. Add a <UiPath path="coupons.prefix" /> of up to 12 capitals, digits or `-`: codes are the prefix and 8 characters without look-alikes (no 0, O, 1 or I), such as `WELCOME-7KQ4M2XA`.

5. For uploaded codes, add an optional <UiPath path="coupons.applyUrl" />: a link that applies a code in your shop, with `{code}` where the code goes, such as `https://shop.example.com/discount/{code}`. Without one, the pool's link is empty and the block shows no button.

6. Leave <UiPath path="coupons.onePerContact" /> on (the default) so a contact who gets this pool again, in another campaign or the next email of a flow, gets the same code. Turn it off to give a new code with every email.

7. Select <UiPath path="coupons.createPool" />. The pool's page opens, and the creation is recorded in the [audit log](/team/audit-log/).

</Steps>

<Aside type="caution">
  Codes ReputeCast creates in a store are real discounts. Anyone who has one can use it once, even from a forwarded
  email. ReputeCast can't tell whether uploaded codes work in your shop or how often: upload codes that work once each.
</Aside>

### Add codes you have

<Steps>

1. On the pool's page, select <UiPath path="coupons.addCodes" />.

2. Under <UiPath path="coupons.addPaste" />, paste the codes one per line, or under <UiPath path="coupons.addFile" /> pick a CSV file with the codes in its first column (a header row named `code` is skipped).

3. Select <UiPath path="coupons.addCodes" />. Up to 100,000 codes and 6 MB go in one upload; each code is 3 to 64 letters, digits, `-` or `_`.

</Steps>

The result says how many codes were added, how many were in the pool already (letter case doesn't matter) and which lines weren't codes, with the first three of them. The audit log records the counts, never the codes.

### Create codes in the store

<Steps>

1. On the pool's page, select <UiPath path="coupons.createMore" />.

2. Under <UiPath path="coupons.moreCount" />, enter 1 to 50,000 codes.

3. Select the button that creates them, such as **Create 500 codes**.

</Steps>

ReputeCast creates the discount in the store (in Shopify one discount that holds every code, in WooCommerce one coupon per code), then adds codes in batches: 250 at a time through Shopify's bulk job, 100 coupons at a time in WooCommerce. Only codes the store confirmed become free. A card on the pool's page shows the progress, such as "Creating 500 codes in Acme Merch · 250 done", and you can leave the page. When the store asks ReputeCast to slow down, the card says so and the work carries on a few seconds later. When the store doesn't answer, ReputeCast keeps the codes it had confirmed, tries again and offers <UiPath path="coupons.retryNow" />.

Once the discount exists in the store, its kind, value, minimum, end and collections can't change: create a new pool for another discount. Name, prefix, low mark and one code per contact change with <UiPath path="coupons.edit" /> in the pool's <UiPath path="coupons.settingsTitle" />.

## Put a code in an email

<Steps>

1. In the [composer](/campaigns/composer/), drag <UiPath path="coupons.composer.block" /> from <UiPath path="composer.canvas.groupReputecast" /> into a column of the email.

2. Pick its <UiPath path="coupons.composer.pool" />. Each pool shows its free codes, such as "Welcome 15% · 2,540 free". Without a pool yet, the panel links to <UiPath path="coupons.title" /> to create one.

3. Change the <UiPath path="coupons.composer.label" /> above the code (up to 80 characters, "Your code" by default). It can hold Liquid, such as `Your code, {{ first_name }}`.

4. Keep the <UiPath path="coupons.composer.button" /> on and change its text (up to 40 characters, "Shop now" by default), or switch it off. A Shopify pool's button opens the store's `/discount/<code>` address, which applies the code; a WooCommerce pool's opens the store; an uploaded pool's opens its apply address.

</Steps>

In Write mode the block is a card with <UiPath path="composer.write.editInDesign" />. Readers see the label, their own code in a dashed box that selects as one piece, and the button. A reader who has no code, such as a visitor reading the email in the public [archive](/forms/public-pages/), sees nothing: the block hides itself.

To place a code anywhere else, in text, a link, the subject or Code mode, use Liquid, or pick it from <UiPath path="composer.canvas.insertToken" />, under <UiPath path="coupons.composer.tokensGroup" />:

| Liquid                         | Holds                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `{{ coupons.welcome15.code }}` | The reader's code from the pool named `welcome15`.                                                      |
| `{{ coupons.welcome15.url }}`  | The link that applies it: the store's, or the uploaded pool's apply address. Empty without an address. |

The pool's page lists both under <UiPath path="coupons.liquidTitle" />, with Copy. Links holding them stay tracked: the click goes through ReputeCast and lands with the reader's own code. See [personalize emails with Liquid](/campaigns/personalization/#discount-codes).

### Previews and tests show a sample

The composer, the preview and test sends show the pool's prefix and `SAMPLE1`, such as `WELCOME-SAMPLE1`, and the matching link. No code is given out until the email is sent.

## How codes are given out

- **When the email is sent.** The sending engine gives each message a free code, a page of recipients at a time. Two messages never get the same code, even from two sends at once, and a page sent again gets the same codes back.
- **One code per contact.** With it on, a contact who already got a code from the pool gets the same one again; with it off, every message takes a new code.
- **Afterwards.** The online copy of the email and its link redirects show the code the message was given. Giving out a code isn't audited: the message holds it.

When a campaign message finds no code left, that message isn't sent: it fails with "Not sent: the discount code pool … had no code left for this reader (no_codes)." An automation email waits instead: it asks again every 15 minutes, and after 24 hours without a code it is skipped, recorded as `no_codes` on the contact. The pool's page says how many emails of which flow are waiting.

## Keep enough codes

[Send Readiness](/reference/glossary/#send-readiness) counts a pool's free codes against the campaign's recipients, one per recipient, in its Content group:

- "Discount codes: … left in … for … recipients" passes when there are enough.
- Too few uploaded codes block the send, with <UiPath path="coupons.readiness.addCodes" />, which opens the pool's Add codes.
- Too few codes in a store block it too, with <UiPath path="coupons.readiness.createCodes" />, which asks the store for the shortfall and 5% to spare. While codes are being created, the row names who started it and passes once the store has confirmed enough.
- An archived pool, or a store pool whose store isn't connected, blocks the send.

Each pool has a low mark, 200 free codes by default (change it with <UiPath path="coupons.edit" />, 0 to 1,000,000). Under it, the members who can manage discount codes get one [notification](/team/notifications/), <UiPath path="notify.event.coupon_codes_low" />, and another only after the pool was above the mark again; the pool's page shows the same warning. An empty pool's notification says that campaign messages showing its code aren't sent and automation emails wait.

A store pool that a live automation uses is refilled every hour: when its free codes fall under 1.2 times the last 7 days' use (and at least the low mark), ReputeCast asks the store for the difference. The pool's <UiPath path="coupons.settingsTitle" /> show when it last checked, and the refill's batches say "Refill" with the flow's name. Publishing a flow warns about a pool it uses that is under its low mark, archived or missing.

A code counts as redeemed when an order synced from a connected store used it, matched whatever the letter case, once per order. Revenue adds those orders up in the store's currency, refunds taken off and cancelled and test orders left out. A store pool counts orders in its own store; an uploaded pool, orders in any connected store.

The pool's <UiPath path="coupons.batchesTitle" /> list every upload and request for codes, newest first, with who or what asked (a member, the pool's creation or the hourly refill), how many were asked for, created and refused (codes the store refused, or the pool had already).

## Export, remove or archive codes

- <UiPath path="coupons.export" /> downloads every code as CSV: `code`, `status` (`free`, `sent`, `redeemed` or `removed`), `assigned_at`, `redeemed_at` and `order`. It needs `coupons:manage` and is recorded in the audit log with its row count.
- <UiPath path="coupons.removeUnused" /> removes the codes nobody got. A store's codes are turned off there too, so nobody can use them; codes already sent keep working. A live flow using a store pool gets new codes within the hour; one using uploaded codes waits for codes. To keep a copy, export first.
- <UiPath path="coupons.archive" /> stops the pool from giving codes. It moves to <UiPath path="coupons.filterArchived" /> with its numbers, and codes already sent keep working. When a live flow uses it, the dialog says so first and offers <UiPath path="coupons.archiveAnyway" />: the flow's emails then wait for codes and are skipped after a day. Campaigns that use it are blocked on Review & send, and the composer warns, until they use another pool. An archived pool can't be made active again.

Each change is recorded in the audit log: `coupon_pool.created`, `coupon_pool.updated`, `coupon_pool.codes_uploaded`, `coupon_pool.codes_requested`, `coupon_pool.codes_removed`, `coupon_pool.codes_exported` and `coupon_pool.archived`. Scripts read pools, never their codes, with the [list discount code pools](/api/operations/list-coupon-pools/) and [get a discount code pool](/api/operations/get-coupon-pool/) operations.

## Check that it worked

- The pool's <UiPath path="coupons.statFree" /> count matches the codes you added or the store confirmed.
- A test email shows the pool's prefix and `SAMPLE1`.
- Send Readiness shows "Discount codes: … left in … for … recipients" as passed.
- After the send, the pool's <UiPath path="coupons.statSent" /> count has grown by the messages sent, and <UiPath path="coupons.statRedeemed" /> follows the store's orders.

## Troubleshooting

- **There is no store card, or it's greyed out.** No store of that platform is connected, or it can't create codes: allow discount codes on the Shopify store's page, or give the WooCommerce store a Read/Write key, then open New pool again.
- **"Another pool is … in templates already."** Pick another name in Liquid; it is unique per workspace.
- **"Upload at most 100,000 codes at a time."** Split the file. A file over 6 MB isn't added at all.
- **Lines weren't codes.** A code is 3 to 64 letters, digits, `-` or `_`; spaces and other characters aren't allowed.
- **"The discount exists in … already, so it can't change."** Create a new pool for another discount.
- **The block shows no button.** The uploaded pool has no apply address. Add one in the pool's settings, or switch the button off.
- **"There's no discount code pool named …".** The email names a pool that doesn't exist, often after a typo in Liquid. Pick a pool in the block, or fix the name.
- **Send Readiness blocks with "Not enough discount codes".** Add or create codes, or send to fewer people.
- **Contacts were recorded as `no_codes`.** The pool ran out during the send. Add or create codes; automation emails still waiting pick them up within 15 minutes.
- **Export is greyed out.** Your role lacks `coupons:manage`; the button names who can help.
