Workspace sending rules add your own checks to [Send Readiness](/reference/glossary/#send-readiness), next to the built-in ones: a UTM tag on every link, no URL shorteners, a subject under a length, a line your footer must show. Each [sending rule](/reference/glossary/#sending-rules) warns or blocks, as you choose, on every campaign it applies to. The same page sets how every send counts and confirms its audience.

## Before you begin

- Changing rules and audience defaults needs `workspace:manage`, which the Owner and Admin roles have. Everyone who can see campaigns can read the page; it names who can change it. Only people can change them; API keys and agents can't.
- Send Readiness runs on campaigns, including [recurring digest](/campaigns/recurring-digests/) issues, which go out on the Broadcasts stream. It checks the rules that apply to Broadcasts or to both streams. Automation emails don't run Send Readiness, so ReputeCast doesn't check a rule set to Automations only yet.
- Built-in checks such as authentication, blocklists and compliance can't be turned off here. See [Send Readiness](/campaigns/send-readiness/) for what they cover.

## What a rule can check

A rule reads the web links readers click (http and https, each once; `mailto:` links, merge tags and the unsubscribe links ReputeCast adds are left out), the subject, the footer or the email's text.

## Add a rule

<Steps>

1. Open <UiPath path="nav.settings > settings.sendingRules" />.

2. Select <UiPath path="sendingRules.addRule" />. The form under the table opens on a new rule.

3. Give it a <UiPath path="sendingRules.ruleName" /> that says what it asks for, such as "Links need UTM tags". Send Readiness shows the name on the check.

4. Under the condition, pick the <UiPath path="sendingRules.check" />, the <UiPath path="sendingRules.operator" /> and the value (see [what a rule can check](#what-a-rule-can-check)).

5. Choose the <UiPath path="sendingRules.severity" />:
   - <UiPath path="sendingRules.warn" />: the sender confirms it before sending.
   - <UiPath path="sendingRules.block" />: sending stays disabled until it's fixed.

6. Choose what it <UiPath path="sendingRules.appliesTo" />: <UiPath path="sendingRules.broadcasts" />, <UiPath path="sendingRules.automations" /> or <UiPath path="sendingRules.both" /> (the default).

7. Optionally, write a <UiPath path="sendingRules.message" />, for example why the rule exists. It appears in Send Readiness next to the check and in the composer's checks. The preview under the form shows the row as Send Readiness will show it.

8. Select <UiPath path="sendingRules.addRule" />. The rule is on, and the audit log records `sending_rule.created`.

</Steps>

## Change, turn off or delete a rule

- Each row of the rules table changes the <UiPath path="sendingRules.severity" /> and what it <UiPath path="sendingRules.appliesTo" /> in place, and its switch under <UiPath path="sendingRules.colStatus" /> turns the rule on or off.
- Select <UiPath path="common.edit" /> on a row to change the rest in the form, then <UiPath path="sendingRules.saveRule" />, or <UiPath path="sendingRules.deleteRule" /> to remove it.
- Changes apply from the next check. A scheduled send picks them up at its send-time recheck, 15 minutes before it goes out. Every change is in the audit log (`sending_rule.updated`, `sending_rule.deleted`).
- <UiPath path="sendingRules.colTriggered" /> shows when a run last found the rule broken, on which campaign and how many links, or "fixed before sending" when a later run of that campaign found it kept.

## How rules appear in Send Readiness

Rules form the <UiPath path="review.groupRules" /> group, the last of the [check groups](/campaigns/send-readiness/#the-check-groups). It runs once the links are fetched, so it sees the same links the Links group does.

- A rule the campaign keeps passes, for example "No URL shorteners: none of the 14 links use one".
- A broken rule warns or blocks, as its severity says: "Workspace rule: links need UTM tags · 2 of 14 links have no utm_campaign". Your message appears under it.
- <UiPath path="review.technicalDetails" /> name the rule with its severity, scope and who added it, what it checks, and the links that broke it.
- A broken Warn rule is confirmed in the send's confirmation like any other warning.
- The composer's <UiPath path="composer.chrome.tabChecks" /> tab shows the workspace rules from the campaign's latest Send Readiness run, without running them again.

## Set the audience defaults

The <UiPath path="sendingRules.defaultsTitle" /> card decides two things for every send.

<Steps>

1. **Unengaged contacts.** The switch to exclude unengaged contacts per the sunset policy is on by default: every campaign leaves out the contacts in the Sunset tier, those with no human open or click for the sunset policy's days. A sender can include them for one send with <UiPath path="review.includeThem" /> on Review & send, which adds a warning. The number of days comes from the sunset policy in [list health](/audience/list-health/).

2. **Typed confirmation.** Under <UiPath path="sendingRules.typedLabel" />, set the multiple of the usual audience, the median of the last 5 sends to the same lists. A sender types the recipient count to confirm only when the audience is larger than that, or when the send is a first send to a list, from a sending domain or through a sending provider, or a blocklist listing above low impact applies. Every other send is confirmed with checkboxes.

3. Select <UiPath path="sendingRules.save" />. The audit log records `send_defaults.updated`.

</Steps>

<Aside type="note">
The <UiPath path="senders.providers.confirmOver" /> field in <UiPath path="nav.settings > settings.providers" /> is still saved but isn't used: the typed confirmation follows this card.
</Aside>

## Check that it worked

- The rule shows <UiPath path="sendingRules.on" /> in the table.
- On a campaign's <UiPath path="composer.reviewSend" /> page, after the checks run again, the <UiPath path="review.groupRules" /> group lists the rule, passed or with its finding.
- After a campaign broke the rule, <UiPath path="sendingRules.colTriggered" /> names it.

## Troubleshooting

- **"Your role can't change the sending rules"**: changing them needs `workspace:manage`. Ask one of the people the page names.
- **The rule doesn't appear on Review & send.** It is off, set to Automations only, or the checks haven't run since you added it: select <UiPath path="review.rerun" />.
- **"Name the query parameter, such as utm_campaign."** Enter the parameter's name alone, without `=`, `&`, `?`, `#` or spaces.
- **"“acme” isn't a domain."** Each domain needs a dot and no `/`, `:`, `@` or space. `https://` and `www.` are removed for you.
- **"Enter a number of characters from 1 to 998."** A subject length rule takes a whole number in that range.
- **"Enter a multiple from 1.1 to 20."** The typed confirmation multiple is rounded to one decimal and must stay in that range.
- **A footer rule fails though the text is in the email.** Without the composer's footer block, the rule reads only the end of the email's text. Insert the footer block, or check the text with <UiPath path="sendingRules.opBodyContains" /> instead.
