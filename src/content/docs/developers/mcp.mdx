ReputeCast includes a [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) server, so an AI assistant
can read reports, check Send Readiness, draft campaigns or pause a send in your workspace: an MCP server email
marketing teams can control. Each [MCP agent](/reference/glossary/#mcp-agent) gets its own token and permissions,
never more than the person who created it, and anything that would send mail goes to a person as a proposal instead
of running.

## Before you begin

- You need `mcp:manage` in the workspace (a [sensitive permission](/reference/glossary/#sensitive-permission)). You
  can only give an agent permissions you hold yourself.
- Your instance needs a public URL your MCP client can reach over HTTPS. The endpoint is `<public URL>/mcp`, served
  by the web role.
- If ReputeCast runs behind a reverse proxy, `/mcp` must stream responses without buffering. See
  [Reverse proxy and TLS](/self-hosting/reverse-proxy/).

## Create an agent

<Steps>

1. Open <UiPath path="nav.settings > settings.keys" />. The MCP card at the top shows the endpoint, for example
   `https://reputecast.example.com/mcp`.

2. Select <UiPath path="keys.addAgent" />. Give the agent a name that says who uses it, such as "Claude: analytics".

3. Pick its permissions. Start with read access, such as `reports:view` and `deliverability:view`, and add more
   later. A permission you don't hold is locked. Agents can never hold `subscribers:verify`, `placement:run`,
   `placement:manage`, `coupons:manage`, `comments:moderate`, `replies:view` and `replies:manage` (API keys can),
   nor `integrations:manage`, `ai:use` or the agency permissions (people only). Replies, website comments and discount
   code pools stay with people. Available from the next release after 1.6.0.

4. Optionally limit the agent to some lists, set an expiry and fill <UiPath path="keys.allowedIpsLabel" />
   ([limit an agent to allowed IPs](#limit-an-agent-to-allowed-ips)), then create it.

5. Copy the token, `rc_agent_…`. It is shown once; ReputeCast keeps only its SHA-256 hash.

</Steps>

## Connect your MCP client

The server speaks MCP's **Streamable HTTP** transport. Every request carries the agent token as a bearer token:

```http title="Request headers"
Authorization: Bearer rc_agent_…
```

ReputeCast accepts only agent tokens here: an API key (`rc_live_…`) or a session cookie is refused. Pick your client
below. The examples read the token from the `REPUTECAST_AGENT_TOKEN` environment variable; replace
`reputecast.example.com` with your public URL.

<Tabs syncKey="mcp-client">
<TabItem label="Claude Code">

```sh title="Terminal"
claude mcp add --transport http reputecast https://reputecast.example.com/mcp \
  --header "Authorization: Bearer $REPUTECAST_AGENT_TOKEN"
```

To share the server with a project, add it to `.mcp.json` at the project root instead. Claude Code needs
`"type": "http"` on a server with a `url`; an entry without `type` is read as a local command and skipped:

```json title=".mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Run `claude mcp get reputecast` to check the connection. Source:
[Claude Code MCP documentation](https://code.claude.com/docs/en/mcp), checked October 2026.

</TabItem>
<TabItem label="Cursor">

Add the server to `~/.cursor/mcp.json` (every project) or `.cursor/mcp.json` (one project):

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${env:REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Cursor fills `${env:NAME}` from your environment. Source:
[Cursor MCP documentation](https://cursor.com/docs/context/mcp), checked October 2026.

</TabItem>
<TabItem label="VS Code">

Add the server to `.vscode/mcp.json` in your workspace. VS Code asks for the token once and stores it securely:

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "reputecast-agent-token",
      "description": "ReputeCast agent token (rc_agent_…)",
      "password": true
    }
  ],
  "servers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${input:reputecast-agent-token}" }
    }
  }
}
```

Source: [VS Code MCP configuration reference](https://code.visualstudio.com/docs/copilot/reference/mcp-configuration),
checked October 2026.

</TabItem>
<TabItem label="Other clients">

Any client that connects to a remote MCP server by URL and lets you set a request header works. Most use this shape;
check your client's documentation for the file name and whether it also needs `"type": "http"`:

```json title="mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer rc_agent_…" }
    }
  }
}
```

A client that only starts local (stdio) servers needs a local bridge to a remote HTTP server; ReputeCast doesn't ship
one.

</TabItem>
</Tabs>

<Aside type="danger" title="Treat the token like a password">
Anyone with the token can act as the agent. Keep it out of shared repositories: use an environment variable or your
client's secret prompt, as above. If it leaks, revoke the agent in <UiPath path="nav.settings > settings.keys" />.
</Aside>

## What an agent can do

The server offers 61 tools, 3 resources and 2 prompts. Each tool checks one permission, exactly like an API key, and
campaigns can be named by their name or ID. The full list, with each tool's permission and effect, is in
[MCP tools, resources and prompts](/reference/mcp-tools/).

- **Read**: campaign lists and reports, Send Readiness, live send statistics, provider health, routing,
  deliverability, placement tests, a contact by ID or address, lists, signup forms, automations with the numbers of
  their <UiPath path="automations.flow.tabStats" /> tab, the approvals queue, digests, polls, growth, revenue, offers
  and website content.
- **Change**: create campaign, SMS, push, WhatsApp and website post drafts; update a campaign's content; create
  segments; add addresses to the suppression list; change routing weights; pause and resume sends; make read-only
  report links that expire, with `share_campaign_report` (needs `reports:share`).
- **Drafts like the composer's**: a campaign draft an agent creates or changes is stored the way the
  [composer](/campaigns/composer/#what-the-server-checks) stores a person's. The server compiles the MJML (an MJML
  error is refused), checks it, keeps the subject and preheader in the MJML head, and saves each change as a new
  version in the history, marked as made by an API key or agent. A change never cancels a person's approval or pending
  request: the call fails with `409 approval_would_cancel`.
- **Send a test**: `send_test_email` sends a campaign test only to members of the workspace, through the System
  stream.
- **Transactional email**: read-only. Agents list and render templates and search the message log, but never send
  transactional messages.
- **Resources**: a campaign's MJML, a report as CSV, and the latest 100 audit log entries.

`get_campaign_report` returns the report the app shows, built by the same code: human, privacy-protected and scanner
opens apart, the measurable open rate, complaints only where mailbox providers report them, links (per variant for a
content test) and the A/B decision with its confidence. An agent answers from those numbers, the way
[campaign reports](/campaigns/reports/) present them.

An agent's permissions are checked again on every call against its creator's current role. When the creator loses a
permission, the agent loses it too; when the creator leaves the workspace or is deactivated, the agent can do nothing.

Its lists follow the same rule (since 1.5.0): on every call they are cut down to the lists and sender domains its
creator reaches at that moment. An agent limited to some lists finds only the contacts on them with
`search_contacts` and `get_contact`, and `resume_campaign` resumes only a campaign within its lists and sender
domains, as a person limited the same way can in ReputeCast.

## Limit an agent to allowed IPs

An agent can be limited to the addresses its client calls from: up to 50 IPv4 or IPv6 addresses and networks, such
as `203.0.113.7` or `203.0.113.0/24` (since 1.6.0). An empty list, the default, allows any address.

<Steps>

1. In the agents matrix, select <UiPath path="keys.allowedIpsButton" /> on the agent's row.

2. Enter one address or network per line. The field shows where the token was last used and your own address as
   ReputeCast sees it, each with a link to add it.

3. Save. A list that leaves out the address the token was last used from asks first; choose
   <UiPath path="keys.saveAnyway" /> only if that client should be refused.

</Steps>

The check runs after the token is verified. A call from another address, or from one ReputeCast can't tell, answers
`401` with `this agent can't be used from <address>; add the address to its allowed IPs in Settings › Keys & MCP`,
and is counted. Behind a reverse proxy, list the proxy in `http.trusted_proxies` first, or every call seems to come
from the proxy; the dialog warns when it may. Letting the agent be called from more places needs every permission
the agent holds and its lists within your own scope, as rotating it does. A signed-in person sets the list, here or
with `PUT /api/v1/workspaces/<workspace>/mcp-agents/<keyId>/allowed-ips`; the change is in the audit log as
`agent.updated`. The rules are the same as for
[API keys](/developers/api-authentication/#limit-a-key-to-allowed-ips).

## Proposals for anything that sends

Agents don't start sends.

- `schedule_campaign` never schedules. It records a proposal for the first member who holds `campaigns:send`, who
  gets a notification ("Claude: analytics asked to schedule Weekly Digest #142") with a link to the campaign. That
  person schedules it in ReputeCast, where Send Readiness and approvals apply as usual. `propose_send` does the same
  for a text, push or WhatsApp draft, to send now or at a time you give.
- A call the agent lacks the permission for is denied. The agent gets an error that names the missing permission, the
  denial is recorded in the audit log, and a proposal goes to the first member who holds it.
- The notification states when the proposal expires: 2 hours by default, 1–168 hours under
  <UiPath path="keys.changeLimits" />. ReputeCast never carries out a proposal itself, so the expiry tells the person
  how long the request is current; nothing happens when it passes.
- `pause_campaign` needs `campaigns:pause` and pauses at once. `resume_campaign` needs `campaigns:send` and resumes
  at once: give `campaigns:send` to an agent only if it may restart a paused send.

## Audit and limits

Every tool call lands in the audit log with the agent as actor, the tool name and the result, including denied calls.
<UiPath path="keys.recentAgentActions" /> on the same page shows the latest calls; open the
[audit log](/team/audit-log/) for the rest.

<UiPath path="keys.changeLimits" /> sets the calls per minute per agent and the proposal expiry for the workspace, and
turns the MCP server off. While it is off, every agent token is refused. An agent over its limit gets `429` with
`Retry-After: 60`.

## Check that it worked

- Ask your assistant to list the tools of the `reputecast` server, or to call `list_campaigns`. It should list your
  campaigns.
- In <UiPath path="nav.settings > settings.keys" />, the agent's last call appears in the agents matrix and under
  <UiPath path="keys.recentAgentActions" />.

## Troubleshooting

- **401 "use an MCP agent token (rc_agent_…)"**: the client sends an API key or no header. Create an agent and use
  its token.
- **401 "this agent was revoked" or "… expired"**: create a new agent or rotate its token in
  <UiPath path="nav.settings > settings.keys" />.
- **401 "the MCP server is off"**: turn it on under <UiPath path="keys.changeLimits" />.
- **401 "this agent can't be used from …"**: the client calls from outside the agent's allowed IPs. Add the address
  the error names with <UiPath path="keys.allowedIpsButton" />, or list your reverse proxy in `http.trusted_proxies`
  when the address is the proxy's.
- **The client connects but every tool is denied**: the agent lacks the permission, or its creator no longer holds it.
  The error names the permission.
- **The agent finds no contacts, or fewer than expected**: the agent, or the member who created it, is limited to
  some lists.
- **Claude Code skips the server**: the `.mcp.json` entry has a `url` but no `"type": "http"`.
- **Calls hang or time out behind a proxy**: the proxy buffers `/mcp` responses. Turn off buffering for that path.
- **429 errors**: the agent made more calls than the workspace allows per minute. Raise the limit or slow the agent.
