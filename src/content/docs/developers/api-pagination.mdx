REST API pagination in ReputeCast depends on the list: most lists take `page` and `pageSize`, logs and activity
feeds take a cursor, and a few take a time or an offset. Each operation's page in the [API reference](/api/) shows its
parameters; this page groups them by style. Lists in responses are never `null`: an empty list is `[]`.

## Page lists: `page` and `pageSize`

Send `page` (from 1, default 1) and `pageSize`. The response has `items`, `total` (items that match your filters),
`page` and `pageSize`, often next to summary fields such as `counts`.

```sh title="Terminal"
curl -s -H "Authorization: Bearer $RC_KEY" \
  "$RC_URL/api/v1/workspaces/acme-newsletter/campaigns?status=sent&page=2&pageSize=50"
```

- You have every item when `page × pageSize ≥ total`.
- A page past the end answers `200` with `"items": []`.
- Send the same filters with every page.

| Operation                                                         | Default `pageSize` | Largest `pageSize` |
| ----------------------------------------------------------------- | ------------------ | ------------------ |
| [`list-campaigns`](/api/operations/list-campaigns/)               | 25                 | 100                |
| [`list-contacts`](/api/operations/list-contacts/)                 | 10                 | 100                |
| [`list-suppressions`](/api/operations/list-suppressions/)         | 10                 | 100                |
| [`list-provider-events`](/api/operations/list-provider-events/)   | 25                 | 100                |
| [`list-product-orders`](/api/operations/list-product-orders/)     | 10                 | 100                |
| [`list-paid-members`](/api/operations/list-paid-members/)         | 8                  | 100                |
| [`list-payment-events`](/api/operations/list-payment-events/)     | 8                  | 100                |

A few lists take `page` alone and choose the page size themselves:
[`list-gifts`](/api/operations/list-gifts/) (20 gifts a page), [`list-referrers`](/api/operations/list-referrers/),
[`get-partner-requests`](/api/operations/get-partner-requests/), [`list-sms-suppressions`](/api/operations/list-sms-suppressions/)
and [`list-sms-events`](/api/operations/list-sms-events/).

## Cursor lists: `cursor` and `limit`

Send `limit`, then pass the cursor from the previous answer as `cursor` to get the next page. The cursor is opaque:
store it as it is. On the last page the cursor field is left out.

```sh title="Terminal"
curl -s -H "Authorization: Bearer $RC_KEY" \
  "$RC_URL/api/v1/workspaces/acme-newsletter/audit?limit=200&cursor=<nextCursor from the previous page>"
```

<TableScroll label="Cursor lists">

| Operation                                                     | Cursor field in the answer          | Default `limit` | Largest `limit` |
| ------------------------------------------------------------- | ----------------------------------- | --------------- | --------------- |
| [`list-audit-events`](/api/operations/list-audit-events/)     | `nextCursor`, with `total`          | 50              | 200             |
| [`contact-activity`](/api/operations/contact-activity/)       | `nextCursor`, with `total`          | 8               | 100             |
| [`list-ai-activity`](/api/operations/list-ai-activity/)       | `next`                              | 50              | 100             |
| [`list-store-activity`](/api/operations/list-store-activity/) | `next`                              | 25              | 100             |
| [`list-store-products`](/api/operations/list-store-products/) | `next` (a number), with `total`     | 48              | 100             |

</TableScroll>

## Time-based lists: `before` and `limit`

Logs that grow while you read them page backwards in time, newest first.

<TableScroll label="Time-based lists">

| Operation                                                                     | How to get the next page                                                   | Default `limit` | Largest `limit` |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------- | --------------- |
| [`list-transactional-messages`](/api/operations/list-transactional-messages/) | Pass the answer's `next` as `before`                                       | 25              | 100             |
| [`list-conversions`](/api/operations/list-conversions/)                       | Pass the answer's `next` (a time) as `before`                              | 50              | 200             |
| [`list-whatsapp-events`](/api/operations/list-whatsapp-events/)               | Pass the answer's `next` (a time) as `before`                              | 50              | 200             |
| [`list-push-events`](/api/operations/list-push-events/)                       | When `more` is `true`, pass the time of the last event as `before`         | 50              | 200             |

</TableScroll>

`list-transactional-messages` also takes `after`: pass a page's `newest` value to get only the messages that arrived
since, for a live view.

## Offset lists: `offset` and `limit`

Send `offset` (the number of items to skip, from 0) and `limit`.

| Operation                                                                   | Default `limit` | Largest `limit` |
| --------------------------------------------------------------------------- | --------------- | --------------- |
| [`list-integration-calls`](/api/operations/list-integration-calls/)         | 20              | 100 (`offset` up to 10,000) |
| [`list-poll-comments`](/api/operations/list-poll-comments/)                 | 20              | 100             |
| [`list-survey-responses`](/api/operations/list-survey-responses/)           | 20              | 100             |
| [`list-survey-text-answers`](/api/operations/list-survey-text-answers/)     | 20              | 100             |
| [`list-sms-replies`](/api/operations/list-sms-replies/)                     | 50              | 100             |

## Lists with only a `limit`

These answer up to `limit` items and have no further pages:
[`list-webhook-deliveries`](/api/operations/list-webhook-deliveries/) (50, up to 200),
[`list-media`](/api/operations/list-media/) (200, up to 500),
[`list-campaign-versions`](/api/operations/list-campaign-versions/) (50, up to 300) and
[`list-agent-actions`](/api/operations/list-agent-actions/) (20, up to 100). Lists that take no paging parameter at
all, such as [`list-lists`](/api/operations/list-lists/) and [`list-segments`](/api/operations/list-segments/),
answer every item at once.

## Notes

- A value above the largest allowed answers `422` with the code `validation_failed` and the parameter in
  `errors[].location`, for example `query.pageSize` (see [errors](/developers/api-errors/)).
- Every page counts as one request against the [rate limits](/developers/api-rate-limits/). Ask for the largest
  page you can use instead of many small ones.
- To follow changes without paging through lists again, [receive webhooks](/developers/webhooks/).
