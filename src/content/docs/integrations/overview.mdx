ReputeCast's newsletter integrations connect the tools you already use: automation platforms (Zapier, Make, n8n),
WordPress, online stores (Shopify, WooCommerce), AI models, address verification services, Stripe and HostRepute.
Every integration is free and uses your own accounts. Each one gets its own key with only the permissions it needs, a
call log and a status that tells you when something needs attention.

## Before you begin

- Connecting, changing, rotating, taking over and disconnecting an integration needs `integrations:manage`. It's a
  [sensitive permission](/reference/glossary/#sensitive-permission) that only people can hold: Owner and Admin have it,
  and API keys and MCP agents never connect integrations. Everyone with `integrations:view` (all built-in roles) can see
  the catalog, the integration pages and their call logs.
- You can only give an integration permissions you hold yourself. Items that need a permission you lack are locked.
- Turning on triggers (events sent to the other tool) also needs `webhooks:manage`.
- Zapier and Make call your instance from their own servers, so ReputeCast's public URL must be reachable from the
  internet over HTTPS. Read [Reverse proxy and TLS](/self-hosting/reverse-proxy/).

### Statuses

Each card shows one status:

- <UiPath path="integrations.statusNotConnected" />: nothing is set up, or a person
  disconnected it.
- <UiPath path="integrations.statusWaiting" />: the key exists but the tool hasn't called yet (for WordPress: no site
  has reported in yet).
- <UiPath path="integrations.statusConnected" />: calls from the tool are
  arriving.
- <UiPath path="integrations.statusAttention" />: one of the reasons below applies. Members with
  `integrations:manage` get a notification for each new reason, and the catalog shows a banner with the fix.

An integration needs attention when its key was revoked, expired or will expire within 7 days, when the person who
owns the key has left, when a webhook the tool manages keeps failing, when most calls fail, or when a WordPress site
stops reporting. WordPress sites also show <UiPath path="integrations.statusUpdate" /> when a newer plugin version is
out.

## Connect an automation platform or a site

The connect dialog is the same for Zapier, Make, n8n and WordPress sites.

<Steps>

1. On the integration's card, choose <UiPath path="integrations.connect" />.

2. **Choose what the tool can do.** Switch triggers and actions on or off; the list of permissions the key gets
   updates as you go. Name the key, limit it to one list if you want, and set an expiry (none, 30 days, 90 days, a year
   or a date). Actions that need a sensitive permission, such as sending transactional email
   (`transactional:send`), start off. Choose <UiPath path="integrations.createKey" />.

3. **Paste into the tool.** Copy the instance URL and the key (`rc_live_…`) into the other tool. The key is shown once.
   For Zapier and Make, the dialog first checks that your instance is reachable from the internet (DNS, TLS and
   reachability).

4. **Wait for the first call.** The dialog shows the call when it arrives, for example
   "Zapier called at 14:31 · Test connection · 200". If nothing arrives within 10 minutes, it says so; you can keep
   waiting or close the dialog and check the tool's settings.

</Steps>

The key is an ordinary [API key](/developers/api-authentication/) owned by you and listed under
<UiPath path="nav.settings > settings.keys" /> among the keys managed by integrations. It can only call the operations
of the items you turned on, even if its permissions would allow more; anything else is refused with
`integration_operation_denied`. A workspace has one connection per platform; WordPress has one key per site.

## Manage a connected integration

Each integration has its own page with calls and errors over 7 days, the workflows (Zaps, scenarios, workflows) that
used it in the last 30 days, what it can do and the webhooks it manages.

<Screenshot
  id="integrations-zapier"
  alt="The Zapier page: calls and errors over 7 days, the last call, the three Zaps using ReputeCast with their actions, and the Change what Zapier can do and Rotate key buttons."
/>

- **Change what the tool can do**: changes the key's permissions in place, so there is nothing to paste again.
  Webhooks of triggers you turn off are deleted.
- <UiPath path="integrations.rotateKey" />: creates a new key with the same items. The old key keeps working for 24
  hours, so you can paste the new one without failed runs. <UiPath path="integrations.stopOldKey" /> ends it
  early.
- <UiPath path="integrations.takeOver" />: makes you the key's owner. Use it when the person who connected the tool has
  left: their key stops working until someone takes it over. The key's value stays the same, so nothing changes in the
  other tool, but from then on it's limited by your permissions. The dialog lists anything that stops because you
  don't hold it.
- <UiPath path="integrations.disconnect" />: revokes every key at once (including an old key still in its 24 hours)
  and deletes the webhooks the tool manages. Contacts, events and messages it created stay, and so do the call log
  (until it expires) and the [audit log](/team/audit-log/). You can add a reason for the audit log.
- <UiPath path="integrations.reconnect" />: after a key was revoked or expired, creates a new key with the same items.

### The call log

**Calls and errors** lists every call with its time, the workflow and action, the target, the result and the duration.
Show **All** or **Errors** over **24 hours** or **7 days**, and open a row's request to see what was sent (the first
16 KiB, with secrets masked). Email addresses show only to members with `subscribers:view`. Changes an integration makes
are also in the audit log, with the key as the actor.

### Webhooks managed by a tool

Zapier, Make and n8n create a webhook in ReputeCast when you turn a trigger on and remove it when you turn the trigger
off. It's listed read-only on <UiPath path="nav.settings > settings.webhooks" /> as "Managed by Zapier" (or Make, or
n8n). Read [Receive webhooks](/developers/webhooks/) for the delivery format and signatures.

## Consent is kept

An integration can't add someone back to a list they left, add a suppressed address or send transactional email to
one. ReputeCast answers with the reason ("rob@example.net left Beta Program on 2 Oct…"), and each tool treats it as a
skipped item rather than a failure, so the rest of the workflow keeps running.

## Troubleshooting

- **The connect dialog says your instance isn't reachable**: Zapier and Make need a public HTTPS address. Fix
  `http.public_url` and the proxy, or use n8n on the same network.
- **Calls fail with "Change what Zapier can do in Settings › Integrations"**: the action is off for this key. Turn it on
  with **Change what the tool can do**.
- **Calls fail because the key's owner left**: choose <UiPath path="integrations.takeOver" />.
- **A revoked or expired key**: choose <UiPath path="integrations.reconnect" /> and paste the new key into the tool.
