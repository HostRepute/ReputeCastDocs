ReputeCast's AI features run on AI models with your own key: you connect model accounts from Anthropic, OpenAI, Google
Gemini, Azure OpenAI or an OpenAI-compatible service, pick the model each feature uses, and cap what the workspace
spends in a month. The provider bills your own account, and nothing goes to a model until a person asks. These models
answer the [AI suggestions](/integrations/ai-suggestions/), [drafts from a brief](/integrations/ai-drafts/), the
[AI agent](/integrations/ai-agent/) and the [AI assistant](/integrations/ai-assistant/). Available from 1.8.0.

<Aside type="note" title="In 1.7.0">
  The page is called <UiPath path="ai.formerTitle" /> and a workspace has one model at a time: to switch provider, you
  disconnect the current one first. There are no hosted presets, no model per feature, no tool check outside
  <UiPath path="ai.agent.settings" /> and no personal keys. The monthly cap, prices, reserved requests and the activity
  log work as this page describes.
</Aside>

## Before you begin

- Adding, changing and removing model accounts needs `integrations:manage`, a
  [sensitive permission](/reference/glossary/#sensitive-permission) that only people can hold (Owner and Admin have
  it). Members with `integrations:view` see the page read-only, with the names of the people who can change it.
- Using the models needs `ai:use`: Owner, Admin and Editor hold it, a Viewer doesn't. API keys and
  [MCP agents](/developers/mcp/) can't hold it. See [Permissions and roles](/reference/permissions/).
- Have an API key from the model provider, or the address of your own server. For a model that isn't on ReputeCast's
  price list, which includes every hosted preset, also have its input and output prices per million tokens.

## Add a model account

A [model account](/reference/glossary/#model-account) is one key (or one server on your network) with one or more
models. A workspace can have several, from different providers.

<Steps>

1. Open <UiPath path="nav.settings > settings.integrations > ai.title" />. With no account yet, the page lists the
   five providers: choose <UiPath path="ai.connectModel" /> on one. Once an account is connected, choose
   <UiPath path="ai.models.addAccount" /> under <UiPath path="ai.models.accountsTitle" />. In
   <UiPath path="nav.settings > settings.integrations" />, the <UiPath path="integrations.groupAi" /> group offers
   <UiPath path="ai.models.addAccount" /> on every other provider, which opens the same dialog.

2. Pick the provider and fill in its fields:

   - **Anthropic, OpenAI, Google Gemini**: the API key and the model.
   - **Azure OpenAI**: the endpoint (HTTPS, for example `https://acme.openai.azure.com`), the deployment name, the API
     key, the API version (`2024-10-21` when you leave it empty) and the model the deployment runs, for its prices.
     Your data stays in the region of your Azure resource.
   - **OpenAI-compatible**: under <UiPath path="ai.serviceLabel" />, either
     <UiPath path="ai.serviceOwn" /> with the server's address ending in `/v1`, an optional name and, if the server
     needs one, an API key; or one of the [hosted services](#hosted-openai-compatible-services), whose address is
     filled in and whose API key is required.

   The model list comes from ReputeCast's price list first, then from the provider once the key (or the server
   address) is filled in. If your model isn't listed, choose **Type a model name…**.

3. Check both prices per million input and output tokens. ReputeCast's price list (1 October 2026) fills them in for
   the main Anthropic, OpenAI and Gemini models; change them when your contract differs. For hosted presets and your
   own servers, type them from the provider's pricing page, or 0 for a model that costs nothing. Without both prices,
   ReputeCast can't bound what a request costs and sends nothing, not even the test.

   The first account also sets the workspace's monthly cap: the dialog starts at $25 a month for hosted providers and
   at 20,000,000 tokens for your own server. Later accounts share that cap.

4. Test and connect. ReputeCast sends a fixed prompt with no workspace content ("Reply with the word Ready."), which
   counts toward the monthly cap, and saves nothing if it fails. For the first account, **Connect** with the provider's
   name runs the test and connects when it passes. For a later account, choose <UiPath path="ai.testConnection" />,
   then <UiPath path="ai.models.connect" /> once the test passed.

</Steps>

The first account's model becomes the default of every feature, <UiPath path="ai.models.featureAssistant" /> and
<UiPath path="ai.models.featureAgent" /> included; those two still need its [tool check](#the-tool-check) before they
use it. A later account's models are used only where you [pick them](#pick-the-model-for-each-feature).

### Hosted OpenAI-compatible services

The presets are OpenAI-compatible services with their address filled in. Their models come from the service's own
model list, and ReputeCast has no prices for them, so enter them yourself.

| Preset       | Address                                 |
| ------------ | --------------------------------------- |
| OpenRouter   | `https://openrouter.ai/api/v1`          |
| Mistral      | `https://api.mistral.ai/v1`             |
| Groq         | `https://api.groq.com/openai/v1`        |
| DeepSeek     | `https://api.deepseek.com/v1`           |
| xAI          | `https://api.x.ai/v1`                   |
| Together AI  | `https://api.together.xyz/v1`           |
| Fireworks AI | `https://api.fireworks.ai/inference/v1` |

### Models on your own network

An OpenAI-compatible server on a private or loopback address (such as `http://ollama.acme.internal:11434/v1`) is
refused with "Can't connect to a private address" until an operator sets
[`providers.allow_private_networks`](/reference/configuration/) to `true`
(`REPUTECAST_PROVIDERS__ALLOW_PRIVATE_NETWORKS=true`). Host names ending in `.internal` or `.localhost` count as
private. Link-local and cloud metadata addresses are always refused. The account then reads "No key · host (private
network allowed by the instance)". Read [Security and hardening](/self-hosting/security/).

## Manage an account and its models

<UiPath path="ai.models.manage" /> on an account lists its <UiPath path="ai.models.modelsHeading" />, each with its
prices, its tool check and the features that use it. From there:

- <UiPath path="ai.models.addModel" /> adds another model on the same key. Prices follow the model unless you change
  them.
- <UiPath path="ai.models.editPrices" /> changes a model's prices, and <UiPath path="ai.models.runToolCheck" /> runs
  its [tool check](#the-tool-check).
- <UiPath path="ai.models.removeModel" /> removes a model no feature uses. An account's only model stays: add another
  first, or remove the account.
- **Replace** (or **Add a key**) tests a new key before saving it, and <UiPath path="ai.testConnection" /> tests the
  current one.
- <UiPath path="ai.models.removeAccount" /> deletes the key and its models. Features that use them need another
  account's model first. The AI activity log keeps their requests.

<Screenshot
  id="ai-models-manage"
  alt="Managing the Anthropic model account: the write-only API key added by Marcus Chen, the last test with Test connection, then the model Claude Sonnet 5.5 at $2.00 input and $10.00 output per million tokens, Tool check passed and every feature that uses it, with Prices, Run tool check and Remove (unavailable for the account's only model); then Add model, and Remove account."
/>

Keys are write-only. A key is never shown after you save it; the page only says when and by whom it was set
("Workspace key set Nov 2 by Linh Nguyen"), and the [audit log](/team/audit-log/) records that it was added or
replaced, never the key. Keys are encrypted at rest with the instance's secret key, so back that key up with the
database ([backups](/self-hosting/backups/)). A saved key goes only to the address it was saved for: a new endpoint or
server address needs the key pasted again. When the provider rejects a key, the account says so, its models stop and
the members who manage integrations are told; the other accounts keep working.

## The tool check

The AI assistant and the AI agent call tools, so they only use a model that passed the
[tool check](/reference/glossary/#tool-check). <UiPath path="ai.models.runToolCheck" /> sends a fixed request that asks
the model to call one harmless tool exactly once. It has no workspace content and counts toward the monthly cap.

| The model shows                  | Meaning                                                        |
| -------------------------------- | -------------------------------------------------------------- |
| **Tool check passed** and a date | The assistant and the agent can use it.                        |
| **Failed the tool check** and a date | They can't. The one-shot AI suggestions still work.       |
| <UiPath path="ai.models.toolsUntested" /> | They can't until it passes.                           |

The result belongs to the model with its key, address and connection. Replacing the key or reconnecting the account
resets it to <UiPath path="ai.models.toolsUntested" />, so run it again. Prices, names and feature switches don't reset
it. <UiPath path="ai.agent.testTools" /> under <UiPath path="ai.agent.settings" /> runs the same check on the model of
<UiPath path="ai.models.featureAgent" />.

## Pick the model for each feature

<UiPath path="ai.models.defaultsTitle" /> has one row per feature: <UiPath path="ai.models.featureAssistant" />,
<UiPath path="ai.models.featureAgent" />, then the nine [AI suggestions](/integrations/ai-suggestions/) from Subject
ideas to Draft from a brief. Pick a model in each row's menu.

<Screenshot
  id="ai-settings"
  alt="Settings, Integrations, AI models: Model accounts with the demo's Anthropic account (Claude Sonnet 5.5) and Office Ollama, a server on a private address with qwen3-32b, both connected and each with Manage, and the workspace's total against the $25 monthly cap; below it Default model for each feature, where Assistant, Agent runs and the AI suggestions use Claude Sonnet 5.5."
/>

- A model can be a feature's default when its account is connected and its key works. Alt text also needs a model that
  reads images, and <UiPath path="ai.models.featureAssistant" /> and <UiPath path="ai.models.featureAgent" /> need a
  passed tool check. The menu says why a model can't be picked, for example "failed the tool check", "doesn't read
  images" or "key rejected".
- A feature whose model can't be used refuses its requests; it never falls back to another model.
- Changing a default affects new requests. An assistant thread keeps its model until its owner picks another, and an
  agent run keeps the model it began with.
- A [personal key's](#personal-keys) model is never a workspace default. Members pick it for their own requests under
  <UiPath path="ai.models.yourPicksTitle" />.

## Cap, usage and the activity log

Usage is the token count the provider reports times the model's prices, added up from the 1st of the month in the
workspace time zone. The workspace's cap covers every workspace model request: the AI suggestions, drafts from a brief,
the agent, the assistant, connection tests and tool checks. [Personal keys](#personal-keys) have caps of their own and
never count here.

<LimitsTable area="ai" />

- At 80% of the cap, members with `integrations:manage` get a notification (in the app and by email). At 100%,
  workspace models pause until the 1st; editing, sending and reports carry on as usual, and members with a personal key
  can go on with it. Raising the cap resumes them.
- <UiPath path="ai.byFeature" /> lists the nine AI suggestions, then <UiPath path="ai.agent.title" /> for the agent's
  requests, <UiPath path="ai.models.featureAssistant" /> for the assistant's and <UiPath path="ai.testConnection" /> for
  connection tests and tool checks.
- The <UiPath path="ai.logTitle" /> keeps who asked, when, which feature, on what, the model, tokens, cost and the
  outcome for 90 days, without the text that was sent or returned. It also lists connection tests, the agent's and the
  assistant's requests, and shows <UiPath path="ai.usageUnknown" /> instead of the tokens when the provider didn't
  report them.
- Accounts, models, prices, defaults, the cap, feature switches, the assistant's settings and personal keys are
  recorded in the [audit log](/team/audit-log/), without keys. Single suggestions are not.

### Reserved requests and unknown usage

ReputeCast reserves what a request can cost before it sends it: its input and the longest answer it allows, at the
model's prices. The request goes out only when what is left of the monthly cap covers it on top of the requests in
progress. When the provider answers, the reservation becomes the measured usage. <UiPath path="ai.usageTitle" /> shows
what is reserved: the cap meter counts it, the measured usage doesn't.

When the provider doesn't return token counts it can trust, for example after a timeout, a server error, a stopped
answer or a lost connection, ReputeCast keeps the whole reservation and never repeats the request on its own. The
<UiPath path="ai.logTitle" /> shows <UiPath path="ai.usageUnknown" />, <UiPath path="ai.usageTitle" /> says how many
requests have unknown usage, and an [agent run](/integrations/ai-agent/) with one pauses. An assistant thread doesn't
pause: it counts the request at its maximum. The reservation stays held, also after the 1st, until someone with
`integrations:manage` reconciles it:

<Steps>

1. Under <UiPath path="ai.holdsTitle" /> on this page, find the request by its model, time and ID. Only people with
   `integrations:manage` see the card, and only while a reservation is held.

2. Look up the request's input and output tokens in your model provider's usage records.

3. Choose <UiPath path="ai.reconcile" />, enter <UiPath path="ai.reconcileInput" /> and
   <UiPath path="ai.reconcileOutput" />, confirm that you checked them with the provider, and choose
   <UiPath path="ai.reconcile" /> again. Enter 0 only when the provider confirms it didn't charge for the request.

</Steps>

Reconciling replaces the reservation with the token counts you enter, at the prices the request was reserved with. It
doesn't repeat the request or recover its answer. It works only once the request can't still be running, 10 minutes
after it started; until then the dialog says from when. Each reconciliation is in the audit log as
`ai.usage_reconciled`. A member reconciles their own personal key's requests through the API
(`reconcile-ai-personal-budget`); the page doesn't list them yet.

## Personal keys

A [personal key](/reference/glossary/#personal-key) is a member's own model account: only their requests use it, within
a personal monthly cap. It suits someone who has their own provider contract or wants a model the workspace doesn't
have.

| Row                                         | Default           | Notes                                                                                                                         |
| ------------------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| <UiPath path="ai.models.personalToggle" />  | Off               | Off: personal keys are kept, and their requests are refused until managers allow them again.                                |
| <UiPath path="ai.models.personalCap" />     | $10.00 per person | <UiPath path="ai.models.editCap" />: $1 to $100,000. A person's requests on their own keys stop at it until the month resets. |
| <UiPath path="ai.models.managersSee" />     | Usage and cost    | Never content: what the card tells members.                                                                                   |

Once managers allow personal keys, a member with `ai:use`:

<Steps>

1. Opens <UiPath path="nav.settings > settings.integrations > ai.title" /> and, under
   <UiPath path="ai.models.yourTitle" />, chooses <UiPath path="ai.models.addPersonal" />. The same providers and
   presets are available.

2. Fills in the key, the model and its prices, and chooses <UiPath path="ai.models.addPersonalButton" />, which tests
   the key with a fixed prompt within their personal cap.

3. Runs the tool check on it, if they want the assistant to use it.

4. Picks it for the features they want under <UiPath path="ai.models.yourPicksTitle" />: "For your own requests.
   Everyone else keeps the workspace's models."

</Steps>

<UiPath path="ai.models.peopleTitle" /> lists, for managers, each member's personal accounts by provider and model and
this month's cost and requests. It never shows a key or what they asked. To offboard someone, remove their key there:
it deletes the key, its models and the member's picks of them, and the AI activity log keeps their requests. When a
member leaves the workspace, is removed from it or is deactivated, their personal keys there are deleted; deactivating a
person in Instance admin deletes their personal keys in every workspace.

## What leaves your instance

Only what a person works on, only when they ask, and only to the model of the feature they use:

- Each AI suggestion sends what its feature needs; [what the suggestions send](/integrations/ai-suggestions/#what-leaves-your-instance) lists it.
- The assistant sends the thread's messages and what the person attached; see
  [privacy and retention](/integrations/ai-assistant/#privacy-and-retention). MCP servers receive only the arguments of
  their own tools' calls ([what servers receive](/integrations/mcp-servers/#what-servers-receive)).
- Connection tests and tool checks send fixed text with no workspace content.

Never sent: contacts, recipient lists, exports, keys or credentials, and nothing goes to HostRepute. The model
provider's own terms decide how it stores what it receives.

## Check that it worked

- <UiPath path="ai.models.accountsTitle" /> shows the account as connected, and
  <UiPath path="ai.models.manage" /> shows **Tool check passed** for its model.
- <UiPath path="ai.models.defaultsTitle" /> names a model in every row.
- In the composer, the **Assist** menu lists the features that are on, and the
  [AI assistant](/integrations/ai-assistant/) answers with the model of <UiPath path="ai.models.featureAssistant" />.

## Troubleshooting

- **"Error · key rejected"**: the provider refused the key. That account's models stop until you replace the key or a
  <UiPath path="ai.testConnection" /> passes; other accounts keep working.
- **A model can't be picked for Assistant or Agent runs**: it failed its tool check, or the check hasn't run. Choose
  <UiPath path="ai.models.manage" /> › <UiPath path="ai.models.runToolCheck" />, or use a model that supports tool
  calling.
- **A model can't be removed**: features use it, or it's the account's only model. Pick another model for those
  features first, or remove the whole account.
- **In 1.7.0, connecting the first model fails with a validation error while all nine features are ticked**: the 1.7.0
  server accepts at most eight features when you connect (HostRepute/ReputeCast#83, fixed in 1.8.0). Untick one in the
  dialog, connect, then switch it on under <UiPath path="ai.featuresTitle" />.
- **"Can't connect to a private address"**: see [models on your own network](#models-on-your-own-network).
- **"The address changed: paste the API key again"**: ReputeCast doesn't send a saved key to a new address. Paste the
  key with the new endpoint or server address.
- **Alt text stays off**: its model doesn't read images. Pick one that does for Alt text.
- **"This month's cap is reached"**: raise the cap under **Monthly cap** › <UiPath path="common.edit" />, or wait for
  the 1st.
- **"Cost unknown. An integration manager must configure both model prices before another request can be sent."**: the
  model has no prices. Set both with <UiPath path="ai.models.editPrices" />, 0 for a model that costs nothing. After the
  upgrade to 1.7.0, a connection whose two prices were 0 and didn't come from ReputeCast's price list needs this once.
- **"The remaining monthly budget cannot cover this request and requests already in flight."**: wait for the requests
  in progress to finish, reconcile any [reserved requests](#reserved-requests-and-unknown-usage), or raise the cap.
- **A request shows <UiPath path="ai.usageUnknown" />**: the provider didn't report its usage. Look it up in the
  provider's records and [reconcile it](#reserved-requests-and-unknown-usage).
- **"Reconciliation available after …"** in the dialog, or `ai_reconcile_wait` from the API: the request may still be
  running. Reconcile it after the time shown.
- **A member's personal key is refused**: personal keys are off, or the member reached their personal cap. Turn on
  <UiPath path="ai.models.personalToggle" />, raise the cap, or wait for the month to reset.
