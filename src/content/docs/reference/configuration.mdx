This page lists every configuration key ReputeCast reads, with the ReputeCast environment variables that set them and their defaults.

ReputeCast builds its configuration from five layers; a later layer overrides an earlier one:

1. Built-in defaults (the **Default** column below).
2. The YAML file named by `--config` or `REPUTECAST_CONFIG`.
3. `REPUTECAST_*` environment variables. A double underscore separates levels: `REPUTECAST_HTTP__ADDR` sets `http.addr`.
   The public URL is the exception: `REPUTECAST_PUBLIC_URL` sets `http.public_url`, and its earlier name
   `REPUTECAST_HTTP__PUBLIC_URL` still works when `REPUTECAST_PUBLIC_URL` isn't set.
4. `DATABASE_URL`, only when `REPUTECAST_DATABASE__URL` is not set. In the same way, `PORT` sets `http.addr` to
   `:<PORT>` when `REPUTECAST_HTTP__ADDR` is not set. Available from the next release after 1.6.0.
5. Command-line flags you pass explicitly: `--role`, `--addr`, `--database-url` and `--log-level`.

For list keys (`roles`, `http.trusted_proxies`, `secrets.previous_keys`, `dns.servers`), separate the values in an environment variable with commas. ReputeCast refuses to start when a value can't be parsed, a role is not `web`, `worker` or `ingest`, `http.public_url` is not an absolute URL, `secrets.key` is not a base64-encoded 32-byte key, `auth.password_min_length` is below 8, `metrics.token` is shorter than 16 characters, `PORT` is not a port number, or the [storage](/reference/configuration/#storage) keys don't fit together. An `http.trusted_proxies` entry that is no address, range or `private` is logged and ignored. [Configure ReputeCast](/self-hosting/configuration/) explains the layers with a complete YAML example.
