What changed in each ReputeCast release, newest first. Every release on
[GitHub](https://github.com/hostrepute/reputecast/releases) has the binary for Linux, macOS and Windows (amd64 and
arm64) with a `checksums.txt`, and the Docker image `ghcr.io/hostrepute/reputecast:<tag>` (linux/amd64 and
linux/arm64). To move to a new release, follow [upgrade ReputeCast](/self-hosting/upgrades/).

## 1.5.0

10 November 2026 · [Release on GitHub](https://github.com/hostrepute/reputecast/releases/tag/v1.5.0) · image
`ghcr.io/hostrepute/reputecast:v1.5.0`

This release adds settings the server's operator manages (milestone M53), for a hosting company or an IT team that runs
an instance for someone else. It also fixes what a security review of the whole project found: three problems of high
severity, fourteen of medium and eleven of low. Upgrade soon.

**New**

- **[A public URL the server's operator pins](/self-hosting/instance-admin/#settings-the-servers-operator-manages).**
  With `http.public_url_locked` (`REPUTECAST_HTTP__PUBLIC_URL_LOCKED`), the configured public URL wins over the one
  saved in Instance admin. The field in <UiPath path="admin.instance" /> and at the first sign-in is read only with a
  note, and the API refuses another address with `409` and the code `operator_locked`. At start, a different saved
  address is replaced once (audited as `instance.public_url_pinned`) and provider webhooks move to it. The links that
  `reputecast user reset-password` prints use it, and `reputecast doctor` warns when a locked address is a loopback
  one.
- **[Who upgrades the instance](/self-hosting/upgrades/#see-which-version-you-run).** With `updates.managed_by`
  (`REPUTECAST_UPDATES__MANAGED_BY`), the <UiPath path="admin.versionCard" /> card says who manages upgrades instead of
  showing the `docker compose` command. Both settings are in [configure ReputeCast](/self-hosting/configuration/).
- **[The first sign-in's update check](/self-hosting/first-run/)** follows `updates.check`: when the configuration
  turns the check off, the box is off and can't be turned on, as in Instance admin.

**Security**

- **Templates and SQL segments.** Every Liquid render runs on a budget of steps, work, value sizes and time (two
  seconds), so a template someone previews can't stall the server or exhaust its memory. Only people who can edit a
  campaign preview its unsaved content. SQL segments can't call advisory-lock functions or run SQL given as a string,
  and their connection releases every lock before it is used again.
- **Sign-in and accounts.** Accepting an invitation with Google, Microsoft, GitHub or SSO links an identity only as
  sign-in would: an account that already uses the email accepts only with an identity it already signs in with. An
  account that signs in only through SSO adds a first password only within 15 minutes of signing in, never where its
  domain enforces SSO, and can't move its email off that domain. Wrong authenticator and recovery codes count toward the
  sign-in lockout, and each authenticator code works once. An invitation lasts only as long as its inviter could still
  send it, and removing or deactivating a member revokes the invitations they sent.
- **Permissions and scope.** A member, API key or MCP agent limited to some lists or sender domains stays within them
  in a flow's contacts, MCP contacts, poll and survey answers and automation email previews, and when they send,
  schedule, move or resume a campaign, digest, flow, text, push or WhatsApp send. Keys and agents follow their creator's
  current list scope. In an agency, only agency managers and a client's team managers change who works in the client.
- **Webhooks.** An outgoing endpoint takes only events whose data the person behind it can see, and pauses with the
  reason when they leave or lose access; `webhooks:manage` is now a
  [sensitive permission](/reference/glossary/#sensitive-permission). Amazon SES and AWS End User Messaging trust SNS
  messages only from their own topic. Each WhatsApp account gets a callback URL with a token of its own, and Mailgun's
  signature tokens are tied to their event in PostgreSQL, so no process accepts one twice.
- **Secrets, exports and logs.** A saved secret goes only to the address it was entered for: a new provider server,
  SMTP or bounce mailbox host, AI model server or SSO issuer needs the secret typed again. Every CSV export keeps cells
  from running as formulas. Request logs leave out SMS webhook tokens, WhatsApp callback tokens and short-link codes.
  Provider, webhook and model server addresses can't use IPv6 forms that lead to IPv4 hosts.
- **Public pages, forms and links.** Download limits and expiry hold whatever range a request asks for. Billing and
  cancel links expire, and pages reached from a forwarded email send fresh ones to the member instead of opening
  Stripe's portal. The preference center and the website's account page join only the lists they show. A domain another
  workspace uses can't become this workspace's custom, short-link or tracking domain, and a host a workspace holds
  carries only its own links and pages. Posts of the plain HTML form go through the signup checks, and a browser's
  report no longer turns Turnstile off.
- **Go 1.27.3** fixes GO-2026-6809 in `crypto/x509`, which passkey sign-in reaches, and `klauspost/compress` 1.20.2
  fixes GO-2026-6865.

**Fixes**

- **Transactional unsubscribe links.** Mail gateways such as Safe Links, Proofpoint and Mimecast open every link in an
  email, and opening the unsubscribe link turned a transactional email's Optional category off. The link now opens a
  page with a button; only the button, or a mail app's one-click unsubscribe, turns the category off. Read
  [one-click unsubscribe](/deliverability/one-click-unsubscribe/).
- **MCP contact search.** [`search_contacts`](/reference/mcp-tools/) found no one for an agent without a list scope.
- **Link tokens.** A link whose last character was changed could still work as the original link.

**Changes you may notice**

- WhatsApp's callback URL ends with a token. An account connected before 1.5.0 keeps its old address until Meta calls
  the new one, and its Account tab asks you to paste the new URL in Meta; read
  [upgrade to 1.5.0](/self-hosting/upgrades/#upgrade-to-150).
- A custom domain, short-link domain or tracking domain that another workspace verified first, or one under the public
  URL's own host, needs this workspace's `_reputecast.<domain>` TXT record; until then ReputeCast doesn't use it.
  Verified domains are checked again within 30 minutes of the upgrade.
- Billing links in member emails and `{{ manage_subscription_url }}` work for 30 days, and links from before 1.5.0
  count as expired: their page offers to email a fresh one. The billing buttons on the preference center, unsubscribe
  and upgrade pages email the member a fresh link instead of opening Stripe's portal.
- Changing where a saved secret is sent, such as an SMTP host or an SSO issuer, needs the secret typed again.
- Members who hold `webhooks:manage` fall under two-factor enforcement for sensitive permissions. An endpoint whose
  creator left or lost access pauses until someone resumes it; read [receive webhooks](/developers/webhooks/).
- Signing a member out or deactivating them in a workspace's team ends their sessions only when they use no other
  workspace and aren't an instance admin.
- Posts of the plain HTML form count as automated: with Turnstile keys they get the check, and without them they go
  through within a budget per address and per form and always confirm by email.
- A template over its rendering budget fails with an error instead of running on.

**API changes**

- One new operation, for the app only (a new WhatsApp callback URL), and none removed. Operations an API key can call
  are unchanged; some responses gained fields, such as `pausedReason` on webhook endpoints and the TXT record of
  tracking and short-link domains. See the [API reference](/api/).
- New error codes `operator_locked`, `identity_in_use` and `email_not_verified`; see
  [API errors](/developers/api-errors/).
- Subscribing an endpoint to an event needs the view permission of the data it carries, and a key limited to some lists
  can't subscribe to events that carry contacts.
- API keys and MCP agents reach only the lists their creator reaches now.
- A save that changes where requests go while a saved secret is left blank answers `422`, naming the secret's field.

**Upgrading.** This release adds 10 database migrations and two optional settings, `http.public_url_locked` and
`updates.managed_by`. Read [upgrade to 1.5.0](/self-hosting/upgrades/#upgrade-to-150) first: WhatsApp accounts move to
a new callback URL that you paste in Meta, and an AWS End User Messaging provider set up by hand may need SNS to confirm
its subscription again. With Docker Compose, run `docker compose pull && docker compose up -d`; with the binary, replace
it and run `reputecast migrate up`.

## 1.4.0

4 November 2026 · [Release on GitHub](https://github.com/hostrepute/reputecast/releases/tag/v1.4.0) · image
`ghcr.io/hostrepute/reputecast:v1.4.0`

This release adds German, Spanish and French as app languages (milestone M52).

**New**

- **[German, Spanish and French](/team/language-and-region/).** Deutsch, Español and Français join English and Tiếng
  Việt: every screen, the server's messages and the emails ReputeCast sends to members. Each follows its own country's
  region format until a member picks another, and invitations and the instance's default language offer the three
  too. A native speaker's review of each is still to come.
- **[Public pages](/forms/public-pages/).** Signup forms, confirmation emails, the preference center, unsubscribe and
  archive pages ship their labels in German, Spanish and French, so a workspace no longer writes them for those
  languages.

**Fixes**

- **Amounts with a decimal comma.** A sponsor booking typed as `750,00` booked 75,000, and an address verification
  price typed as `0,008` was refused. Both now take a comma or a point as the decimal mark. Read
  [sell sponsorships](/earn/sponsors/) and [verify email addresses](/audience/verification/).
- **Words outside English.** On the access-request screen, the time you asked read "on 5 min ago" in every language but
  English, and audit lines quoted names with English quotation marks. Both read right in each language now.
- **Revenue.** The MRR history in [revenue metrics](/earn/revenue/) didn't name the payment provider; it does now.
- **Layout outside English.** The Needs attention rows of [Send Readiness](/campaigns/send-readiness/) keep room for
  the finding. Block tiles in the composer and the page builder hyphenate long names, SMS chips and address
  verification pills wrap on a phone, and a transactional message's actions and the template editor fit a phone.

**Changes you may notice**

- Public pages in German, Spanish and French show ReputeCast's own labels. Labels a workspace wrote for those
  languages before 1.4.0 no longer show, and the language settings say the built-in ones can't be changed there.
- The app's first load is smaller: translations download only for the language a member reads the app in.

**Upgrading.** This release has no database migrations, no configuration changes and no changes to the API that keys
use. With Docker Compose, run `docker compose pull && docker compose up -d`; with the binary, replace it.

## 1.3.1

3 November 2026 · [Release on GitHub](https://github.com/hostrepute/reputecast/releases/tag/v1.3.1) · image
`ghcr.io/hostrepute/reputecast:v1.3.1`

This release fixes two places where the app said something the code didn't do.

**Fixes**

- **Re-permission imports.** The import screens said contacts who don't answer a re-permission email are suppressed
  after 14 days, but nothing did it. The hourly retention job now suppresses Broadcasts and Automations to them 14 days
  after their latest confirmation email; a resend from the team starts the 14 days again. The
  [suppression list](/audience/suppressions/) shows them with the source
  <UiPath path="audience.suppressionSource.repermission" />, and their confirmation link still works and lifts the
  suppression, as a new double opt-in signup does. Read [import contacts](/audience/import/).
- **Erasing contacts.** The erase dialog said erased addresses are kept on the suppression list. An erase keeps the
  suppressions an address already has and adds none, so an erased contact who unsubscribed, bounced or complained is
  still never emailed, even if an import brings them back. The dialog now says so; read
  [erase contacts](/audience/contacts/#erase-contacts).

**Changes you may notice**

- At the first hourly run after the upgrade, contacts imported with re-permission who haven't confirmed within 14 days
  of their latest re-permission email are suppressed. Each workspace gets an audit entry for this.

**Upgrading.** This release has no database migrations and no API changes. With Docker Compose, run
`docker compose pull && docker compose up -d`; with the binary, replace it.

## 1.3.0

3 November 2026 · [Release on GitHub](https://github.com/hostrepute/reputecast/releases/tag/v1.3.0) · image
`ghcr.io/hostrepute/reputecast:v1.3.0`

This release polishes every area outside the five core features (milestones M41–M51): consent and data protection,
audience, automations, campaigns, transactional mail, operations and the app itself.

**New**

- **[Consent and data protection](/deliverability/compliance/).** Erasing a contact reaches every place that holds
  their data, and the contact export streams all of it with no cap. A contact who still pays through Stripe can't be
  erased until the subscription is canceled. [Double opt-in](/audience/lists-and-consent/) links open a page with one
  Confirm button, so link scanners can't confirm signups. <UiPath path="nav.settings > settings.general" /> has a
  [data retention](/team/workspaces/) card.
- **[Audience at a million contacts](/audience/contacts/).** Contacts and suppressions page fast and count to
  "10,000+". Select all matching contacts, remove them from a list or tag, correct an address, choose columns and
  manage saved views. Exports and bulk resends run in the background. A new tab manages
  [lists and custom fields](/audience/lists-and-fields/) and says what uses a field or segment before it goes, and the
  [sunset policy](/audience/list-health/) has a dry run.
- **[Automations](/automations/overview/).** Duplicate, delete and discard flows, see and remove the contacts at each
  step, preview and test an email step, and choose what happens to overdue contacts when you resume. A flow can start
  on up to three [triggers](/automations/triggers-and-steps/), including segments and link clicks, with re-entry
  cooldowns and dates at each contact's time. One failing run no longer stalls the others, and steps count real
  delivery events.
- **[Campaigns](/campaigns/overview/).** Delete, archive, tag, filter and act on many campaigns at once. Plan and
  reschedule on the [calendar](/campaigns/calendar/), for texts, push and WhatsApp too. Send
  [follow-ups](/campaigns/reports/) to non-openers or clickers, [send at each recipient's local
  time](/campaigns/schedule-and-send/), and manage your [templates](/campaigns/templates/). The preference center's
  weekly and monthly choices are honoured. A workspace [marketing cap](/campaigns/sending-rules/) counts campaigns and
  automations together.
- **[Transactional](/transactional/message-log/), approvals and integrations.** Cancel or move scheduled messages,
  one by one or by batch key, and send a test from a template draft. The [SMTP relay](/transactional/smtp-relay/)
  limits connections and failed logins. [Approvals](/campaigns/approvals/) re-check only stale requests.
  [Webhooks](/developers/webhooks/) send every catalog event, can batch email events, and keep a rotated secret
  signing for a day. MCP agents have [seven more tools](/reference/mcp-tools/).
- **[Operations](/self-hosting/monitoring/).** Operational metrics on their own listener, `reputecast healthcheck`, a
  `/readyz` that checks the schema and request context in log lines. A binary ahead of its database serves read-only.
  `reputecast doctor`, `secrets reseal` and a restore runbook for [backups](/self-hosting/backups/),
  <UiPath path="admin.system" /> in [Instance admin](/self-hosting/instance-admin/), and monthly partitions for
  delivery events.
- **[Earn](/earn/overview/) and other channels.** Editors warn before you leave unsaved changes; gifts, conversions,
  payment events and sponsor bookings export as CSV; paid growth shows by tier and period. A gift's failed bank
  payment emails the buyer. Text, push and WhatsApp campaigns are managed like email ones.
- **The app.** A [command palette](/reference/keyboard-shortcuts/) (<kbd>⌘</kbd> <kbd>K</kbd> or <kbd>Ctrl</kbd>
  <kbd>K</kbd>) searches everything your role can open, settings included. Open tabs offer to reload after an
  upgrade. Every screen works from 320 pixels wide, and on a slow phone it paints at once.

**Changes you may notice**

- Double opt-in links open a page with a Confirm button instead of confirming on open. Links older than 30 days stop
  working, and the page offers a new one.
- By default, signups never confirmed are erased after 30 days, and the IP addresses and user agents of opens and
  clicks are cleared after 12 months. Reports don't change. Change or turn off both on
  <UiPath path="nav.settings > settings.general" />.
- Contacts who paused email no longer get automation emails; their flow continues.
- A contact with a live Stripe subscription can't be erased until it's canceled.
- Slow Audience header counts and segment previews are kept for up to a minute.

**Hardening**

- `golang.org/x/net` 0.62.0 fixes two HTML parser advisories (GO-2026-6866, GO-2026-6860) reached by published page
  content, and the web app pins `seroval` 1.6.11 for two script-injection advisories.
- Browsers are rate limited per session, and `/metrics` is no longer on the public listener.

**Fixes**

- The preference center's digest and monthly choices were ignored.
- Date triggers east of UTC fired every minute, and yearly ones fired only once.
- Automation steps showed 0 delivered, bounced and complained.
- Twelve webhook events in the catalog were never sent.
- Duplicate on sent campaigns, the Contacts Source filter, tag search letter case, wildcards in search, double import
  starts, the transactional log's search, the approvals inbox past 200 requests, and Stripe's failed bank debits and
  dispute updates.

**API changes**

- 43 new operations and none removed; no response lost a field. The 36 that an API key can call are in the
  [API reference](/api/).
- Webhook endpoints can opt in to `email.batch`, which carries up to 100 `email.*` events per request. Endpoints that
  don't opt in are unchanged. `contact.erased` and `message.cancelled` are new events; see
  [webhook events](/reference/webhook-events/).
- The contact export streams, with the same operation, path and permission.

**Upgrading.** This release adds 23 database migrations, and some build indexes concurrently. Before you upgrade:

- `/metrics` moved to its own listener on port `9464`. If Prometheus scrapes the main port, point it at `9464`, or
  set `REPUTECAST_METRICS__TOKEN` and send it as a bearer token; read [monitoring](/self-hosting/monitoring/).
- The upgrade turns `delivery_events` into monthly partitions, unless `reputecast migrate partition-events` already
  did. Nothing is copied and writes go on, but two steps read the whole table: on a very large table, run
  `reputecast migrate partition-events` first at a quiet hour. Read [upgrade ReputeCast](/self-hosting/upgrades/).
- Migrations take an advisory lock, so replicas that start together run them once.

With Docker Compose, run `docker compose pull && docker compose up -d`; with the binary, replace it and run
`reputecast migrate up`. The nginx example in [reverse proxy](/self-hosting/reverse-proxy/) now turns on HTTP/2,
which loads the app much faster on phones.

## 1.2.0

30 October 2026 · [Release on GitHub](https://github.com/hostrepute/reputecast/releases/tag/v1.2.0) · image
`ghcr.io/hostrepute/reputecast:v1.2.0`

This release hardens the five core features (milestones M33–M40): Send Readiness, guarded sending, sending providers
and routing, analytics and the composer.

**New**

- **Mailbox providers from MX records.** ReputeCast names each contact's
  [mailbox provider](/reference/glossary/#mailbox-provider) from the MX records of its domain, so Google Workspace
  counts as Gmail and Microsoft 365 as Outlook. Routing, Send Readiness, reports and warm-up read the same answer.
- **[Guarded sending](/campaigns/live-monitor/).** A message is never sent twice when a provider's answer is lost. An
  outage takes one path, where you retry, move the share or pause. Thresholds apply per bounce type and per mailbox provider, and
  deferrals slow a send down before they pause it. Mailbox provider reply rules, such as Yahoo's TSS04, come with
  defaults in every workspace on [Traffic rules](/providers/traffic-rules/). A send can start with a [canary](/reference/glossary/#canary) phase, a
  72-hour complaint watch follows it and can read Gmail's spam rate from Google Postmaster Tools, and the live monitor
  is redesigned.
- **[Sending providers, routing](/providers/routing/) and [warm-up](/providers/warm-up/).** Warm-up is enforced as
  mail goes out, with caps per mailbox provider, overflow to a warm provider and a held route you can wait on, move or
  pause. Automations wait at the cap; Transactional mail never waits and counts over it. Weighted splits are sticky.
  [Amazon SES](/providers/amazon-ses/) setup ends only after a real delivery event and can read events from an Amazon
  SQS queue. Silent webhooks raise an alarm, failover goes only to a provider that passes its checks, sending IPs are
  read from provider APIs, and the [provider chooser](/providers/choose/) prices each provider at your volume. The
  provider screens are redesigned.
- **[Send Readiness](/campaigns/send-readiness/).** Link domains are looked up live on Spamhaus DBL and SURBL, and
  sender reputation covers the parent, return-path and tracking domains. Checks run in the background with progress,
  one-click fixes can be undone, and estimates follow the sending engine's own rules. A scheduled send is checked
  again when it starts. You can run a [placement test](/deliverability/placement-tests/) per mailbox provider and set
  workspace [sending rules](/campaigns/sending-rules/), and [Review & send](/campaigns/schedule-and-send/) is
  redesigned.
- **[Analytics](/campaigns/reports/).** A/B winners are decided by a minimum sample and a significance test. Instance
  admins can edit the bot-click filter, and Apple Mail prefetch opens have their own bucket. Counters are rebuilt from
  message states. Reports add a click map per variant, each tile compared with the last six issues with a trend line,
  growth and web views per issue, verified AI summaries, share links that expire and
  <UiPath path="reports.retryTitle" />, in a redesigned report.
- **[Composer](/campaigns/composer/).** Autosave runs while you type, and a journal in the browser offers unsaved
  edits back after a crash. Edits to different sections merge, and a conflict keeps your edits as a separate version.
  The server checks the HTML it is sent. New: <UiPath path="composer.chrome.modeWrite" /> mode,
  [comments with @mentions and review links](/campaigns/comments-and-review-links/), a
  [brand kit](/campaigns/brand-kit/) with synced header and footer blocks, uploads resized and stripped of metadata,
  and real renders through Litmus or Mailgun Inspect. Drafts from MCP agents are compiled and checked, approvers can
  approve from a phone, and the composer is redesigned.

**Changes you may notice**

- Complaint rates leave out Gmail and iCloud, which never report complaints per message, and read n/a where no
  mailbox provider reports them. Read [bounces and complaints](/deliverability/bounces-and-complaints/).
- Unengaged contacts are left out of a send by default. To send to them, choose
  <UiPath path="review.includeThem" /> on <UiPath path="composer.reviewSend" />.
- A scheduled send is held at its send time when new warnings appear, the audience grew by more than 10% or the
  campaign was edited after it was scheduled.
- A send may start with a canary phase. <UiPath path="nav.providers > providers.tabTraffic" /> decides when, and you
  can switch it on or off on <UiPath path="composer.reviewSend" />.
- Warm-up plans hold mail over the day's cap instead of sending it.
- Report share links expire after 30 days by default; you can choose 1 to 90 days. Links created before 1.2.0 expire
  30 days after the upgrade.
- A refused action names who can help instead of a permission key. API key scopes, MCP agent permissions, integration
  key scopes, the roles editor and the audit log still show the keys; read
  [roles and permissions](/team/roles-and-permissions/).

**Hardening**

- Decoding an image is limited by what the decoder allocates, for uploads, AI images, digest images, avatars and the
  brand kit import.
- The composer parses HTML it didn't write in an inert document and strips anything that could run.
- Referral offer codes are 12 random characters and work only through the reader's own referral link.
- Request logs redact bearer links, and ReputeCast reads every `X-Forwarded-For` line.
- API keys and MCP agents act as themselves: for example, a Send Readiness run names the key or agent that asked for
  it.

**Fixes**

- The demo no longer shows complaints at Gmail and iCloud.
- The MCP tool [`get_campaign_report`](/reference/mcp-tools/) answers only from the campaign report.
- Seeding the demo data no longer fails between 03:00 and 03:04 New York time.

**API changes**

- 61 new operations and none removed. The 39 that an API key can call are in the [API reference](/api/), and new error
  codes are in [API errors](/developers/api-errors/).
- Warm-up plans no longer include `startDate`, `endDate`, `schedule` and `plannedToDate`; they include `startedOn`,
  `finishesOn`, `ramp`, `rows` and `counted` instead. A warm-up slowdown has `metric` (`bounce` or `complaint`) and
  `rate` instead of `bounce`.
- `GET …/campaigns/{campaignId}/review` no longer includes `largeSend` and adds `canary`, `typed` and
  `sendNowWithin`.
- `POST …/campaigns/{campaignId}/readiness/fixes` returns `running` and `batch` instead of `run`.
- `GET …/campaigns/{campaignId}/readiness/progress` returns a `ReadinessPoll` with `running`, `latest` and `failed`.

**Upgrading.** This release adds 45 database migrations. With Docker Compose, run
`docker compose pull && docker compose up -d`; the migrations run at startup. With the binary, replace it and run
`reputecast migrate up`. `REPUTECAST_PUBLIC_URL` is now the only name of the public URL; `REPUTECAST_HTTP__PUBLIC_URL`
still works when `REPUTECAST_PUBLIC_URL` isn't set (see the [configuration reference](/reference/configuration/)). The
server needs DNS access to classify contacts from MX records in the background.

## 1.1.0

25 October 2026 · [Release on GitHub](https://github.com/hostrepute/reputecast/releases/tag/v1.1.0) · image
`ghcr.io/hostrepute/reputecast:v1.1.0`

The design expansion (milestones M15–M32).

- **[Transactional email](/transactional/overview/)**: templates in the composer, a send API with idempotency keys, an
  SMTP relay and a message log.
- **[SMS](/channels/sms/), [web push](/channels/web-push/) and [WhatsApp](/channels/whatsapp/)** next to email.
- **[Integrations](/integrations/overview/)**: Zapier, Make and n8n, a WordPress plugin, and Shopify and WooCommerce
  stores.
- **[Language versions](/campaigns/languages/)** of emails, forms and pages, and
  [the app in Vietnamese](/team/language-and-region/).
- **[Recurring digests](/campaigns/recurring-digests/)**, [polls and surveys](/campaigns/polls-and-surveys/),
  [contact scoring](/audience/scoring/), [address verification](/audience/verification/),
  [placement tests](/deliverability/placement-tests/) and [accessibility checks](/campaigns/accessibility/).
- **[Referrals](/grow/referrals/)** and [recommendations](/grow/recommendations/).
- **[Paid subscriptions](/earn/paid-subscriptions/)**, [offers and gifts](/earn/offers-and-gifts/) and

**Security**

This release fixes five security advisories. Upgrade soon, especially if you use MCP agents. The advisories are listed
on [GitHub](https://github.com/HostRepute/ReputeCast/security/advisories).

- **Critical**: an MCP agent with `segments:edit` could run SQL through a crafted segment definition.
- **High**: a member with `team:invite` could copy the link of a more privileged pending invitation and raise their own
  role.
- **High**: members limited to certain lists could export, email and preview contacts outside their scope.
- **Medium**: forged delivery reports sent to an SMTP bounce mailbox could suppress any subscriber.
- **Medium**: the webhook self-test in provider setup could be redirected to internal addresses (SSRF).

**Upgrading.** This release adds 52 database migrations. With Docker Compose, run
`docker compose pull && docker compose up -d`; with the binary, replace it and run `reputecast migrate up`. Back up the
`files` directory next to the secret key (`/var/lib/reputecast/files` in Docker) together with the database; read
[back up and restore](/self-hosting/backups/).
