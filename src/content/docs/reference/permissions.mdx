This page lists every ReputeCast permission key a [role](/reference/glossary/#role), [API key](/reference/glossary/#api-key) or [MCP agent](/reference/glossary/#mcp-agent) can hold, grouped as in the role editor under <UiPath path="nav.settings > settings.roles" />.

Every API operation names the permission it needs, and members, API keys and MCP agents go through the same check. [Sensitive permissions](/reference/glossary/#sensitive-permission) are marked ⚑ in the app and trigger the two-factor policy: when the instance requires two-factor authentication for sensitive permissions, every member whose role holds one must use it. **Includes** lists the permissions that come with a key automatically.

## Who can hold a permission

The **Who can hold it** column uses four rules:

- **People, API keys and AI agents**: any role, API key or MCP agent can hold it.
- **People and API keys, not AI agents**: MCP agents never hold it, even when their creator does.
- **People only**: only members hold it, through their role. API keys and MCP agents can't.
- **Owner only**: only the built-in Owner role holds it. It can't be added to a custom role, an API key or an agent, and the Admin role has every other permission.

An API key or MCP agent never does more than the member who created it can do right now. When that member's role loses a permission, the key loses it too; when the member leaves the workspace, the key loses all its permissions.

The keys in the **Agency (instance)** group belong to the instance, not to a workspace. Agency staff hold them through the Agency manager and Account manager roles when agency mode is on.

## Built-in roles

Built-in roles can't be edited; duplicate one to make a [custom role](/reference/glossary/#custom-role).
