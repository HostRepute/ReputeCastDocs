This page lists the webhook event types an endpoint in <UiPath path="nav.settings > settings.webhooks" /> can subscribe to, and the envelope every delivery uses. [Receive webhooks](/developers/webhooks/) shows how to create an endpoint and verify signatures.

## Envelope

Every delivery is a `POST` with a JSON body of five fields:

| Field        | Value                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------- |
| `id`         | The event ID (UUID). Every endpoint that receives the event gets the same ID; use it to skip duplicates. |
| `type`       | The event type, for example `email.bounced`.                                                  |
| `created_at` | When the event happened, in UTC (RFC 3339).                                                   |
| `workspace`  | The workspace slug.                                                                           |
| `data`       | The event's payload. Its shape depends on the type; six events that integrations use have a sample payload in their row below. |

Testing an endpoint sends a `webhook.test` event:

```json title="webhook.test"
{
  "id": "01934f6e-8b2a-7c3d-9e4f-5a6b7c8d9e0f",
  "type": "webhook.test",
  "created_at": "2026-10-22T09:30:00.482913Z",
  "workspace": "acme-newsletter",
  "data": {
    "message": "Test event from ReputeCast. Verify the signature, then answer 2xx."
  }
}
```

## Headers

| Header                   | Value                                                                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `Content-Type`           | `application/json`                                                                                                                     |
| `User-Agent`             | `ReputeCast-Webhooks/<version>`                                                                                                        |
| `X-ReputeCast-Event`     | The event type.                                                                                                                        |
| `X-ReputeCast-Delivery`  | The delivery ID: one per endpoint and event, unchanged across retries.                                                                 |
| `X-ReputeCast-Timestamp` | Unix time in seconds when this attempt was made.                                                                                       |
| `X-ReputeCast-Signature` | Lowercase hex HMAC-SHA256 of `<timestamp>.<raw body>`, keyed with the whole `whsec_…` secret. Reject timestamps more than 5 minutes off. |

## Delivery and retries

- A `2xx` answer within 10 seconds counts as delivered. Any other status, a timeout or a connection error is retried.
- An event is tried up to 8 times, waiting 1, 2, 4, 8, 30, 90 and 225 minutes between attempts (about six hours in total). After the eighth failure it moves to the dead-letter queue, where you can replay it.
- A paused endpoint keeps queuing events; when you resume it, the queued events are delivered in order.
- The `webhook.test` event is tried once and never retried.

## Subscribing to events

An endpoint subscribes to 1–40 entries. Each entry is an exact event type (`email.bounced`), every event of a group (`email.*`, matching the part before the first dot) or every event (`*`).
