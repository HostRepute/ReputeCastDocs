This ReputeCast FAQ answers the questions people ask before they install it: what it costs, what it needs, what leaves
your server and what it does not support. For the product itself, start with
[What is ReputeCast](/getting-started/introduction/).

## How much does ReputeCast cost?

Nothing. Every feature is free, and there is no paid edition, no seat limit and no workspace limit. You pay only for what
you run it on: your server, your PostgreSQL database and your [sending provider](/reference/glossary/#sending-provider)
(Amazon SES, Postmark, your own Postal server or any other). Compare providers in
[Choose a sending provider](/providers/choose/).

## What is the license?

ReputeCast is licensed under the
[GNU Affero General Public License v3.0](https://www.gnu.org/licenses/agpl-3.0.html) (AGPL-3.0). You can run, study,
change and share it. If you change the code and let other people use your changed version over a network, the license
requires you to offer them its source code. The full text is in the `LICENSE` file of the
[ReputeCast repository](https://github.com/hostrepute/reputecast).

## Is there a hosted version?

No. ReputeCast has no hosted edition: you run it on your own server or cloud account. The
[quickstart](/getting-started/quickstart/) gets it running with Docker, and
[System requirements](/self-hosting/requirements/) lists what a production server needs.

## What do I need to run it?

PostgreSQL 16, 17 or 18, and the ReputeCast app: one binary for Linux, macOS or Windows, or the Docker image. For
real sending you also need a public HTTPS address that your sending providers can reach, so their delivery reports come
back.

## Do I need Redis?

No. ReputeCast does not use Redis or any other queue. Background jobs, such as sends, imports and reports, queue in
PostgreSQL through [River](https://riverqueue.com), so PostgreSQL is the only service next to the app.

## Which sending providers does it support?

Amazon SES, Postmark, Mailgun, SendGrid, Resend, SparkPost, Mailjet, Brevo, Azure Communication Services, your own
Postal server and any SMTP server have built-in adapters. The generic HTTP adapter maps other email APIs without code,
and [community adapters](/adapters/overview/) run in their own process. You can connect several providers at once and
split or fail over mail between them; read [Route mail across providers](/providers/routing/). The full list of
supported services, including SMS and payment providers, is in [Supported services](/reference/supported-services/).

## Do I need a HostRepute account?

No. ReputeCast is built by HostRepute, but every check works without a HostRepute account. Connecting one is optional
and adds more blocklist sources, Google Postmaster Tools, Microsoft SNDS data and DMARC reports; read
[Connect HostRepute](/deliverability/hostrepute/).

## Does ReputeCast send data about my installation anywhere?

ReputeCast collects no usage data or telemetry. The only call it makes on its own is a daily check for a newer version:
it reads the latest ReputeCast release from GitHub and the latest WordPress plugin version from WordPress.org, and
sends nothing about your instance.

You can turn the check off in three places:

- During the first setup, in the <UiPath path="setup.instanceBasics" /> step:
  <UiPath path="setup.updateCheck" />.
- Later, in <UiPath path="shell.userMenuInstanceAdmin > admin.instance > admin.updateCheck" />.
- For the whole server, with the configuration key `updates.check: false` (environment variable
  `REPUTECAST_UPDATES__CHECK=false`). Instance admins can't turn the check back on while it is off here. See the
  [configuration reference](/reference/configuration/).

Everything else that leaves your server is something you set up: mail to your sending providers, DNS and blocklist
lookups for the deliverability checks, and the integrations you connect. If you connect HostRepute, it receives your
sending domains and dedicated IP addresses, never contacts, email content or campaign statistics.

## Which languages is the app available in?

The app is in English. A Vietnamese translation is in progress: it shows only in development builds until it is
complete, so a release build offers English. Each member picks their language in
<UiPath path="shell.userMenuAccount > language.title" />; read
[Change the app language and region format](/team/language-and-region/).

The language of your emails, forms and public pages is separate: a workspace can send each reader a version in their
own language. Right-to-left languages are not supported yet. Read [Send each reader their language](/campaigns/languages/).

## Does it support SAML or SCIM?

No. ReputeCast does not support SAML single sign-on or SCIM provisioning. It supports single sign-on with OpenID Connect
(OIDC), for example with Google Workspace, Microsoft Entra ID, Okta, Keycloak or Authentik, including accounts created
at first sign-in and group-to-role mapping; read [Single sign-on with OIDC](/self-hosting/sso/). Members can also sign in with
Google, Microsoft or GitHub.

## Can I move my list from another platform?

Yes. ReputeCast imports contacts, lists, fields and consent from Mailchimp, Brevo, MailerLite, listmonk, Keila,
Notifuse and CSV or XLSX files. Unsubscribed, bounced and complained contacts become suppressions and are never subscribed
again. Read [Move to ReputeCast without losing consent](/migrate/overview/).

## Where do I report a bug or a security issue?

Open an issue in the [ReputeCast repository](https://github.com/hostrepute/reputecast/issues). Report security
vulnerabilities by email to security@hostrepute.com instead of opening an issue. For problems with these docs, use the
"Report a problem with this page" link at the bottom of every page.
