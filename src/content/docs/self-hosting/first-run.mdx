The ReputeCast first setup turns the account that `reputecast install` created into a protected Owner and the
installation into a named [instance](/reference/glossary/#instance) with its first
[workspace](/reference/glossary/#workspace). It takes six steps and about ten minutes; each finished step is saved, so
you can stop and continue later.

## Before you begin

- ReputeCast runs, installed with [Docker Compose](/self-hosting/docker/) or [the binary](/self-hosting/binary/).
- You have the install banner: the email and the temporary password (`xxxx-xxxx-xxxx-xxxx`). With Docker:
  `docker compose logs app | grep -A4 "ReputeCast is installed"`.
- The public URL opens ReputeCast over HTTPS through your [reverse proxy](/self-hosting/reverse-proxy/). Passkeys and
  secure cookies need HTTPS.
- A phone or computer with a passkey (Touch ID, Face ID, Windows Hello, a security key) or an authenticator app.

## Set up the instance

<Steps>

1. Open the public URL. On the sign-in page, enter the Owner's email, select
   <UiPath path="auth.signIn.continue" />, then enter the temporary password.

   <Screenshot
     id="sign-in"
     alt="The sign-in page asks for a work email first, with Continue, Sign in with a passkey and the Google and GitHub buttons below."
   />

   ReputeCast opens the setup at `/setup`. The steps on the left show where you are.

2. **<UiPath path="setup.stepPassword" />.** Enter the temporary password, then your new password twice. It needs at
   least 12 characters (the instance policy's minimum; passphrases are fine). The temporary password stops working
   once you save.

   <Screenshot
     id="setup-password"
     alt="Step 1 of 6, Replace the temporary password: fields for the temporary password, the new password and its confirmation, with the six setup steps listed on the left."
   />

3. **<UiPath path="setup.stepSecondFactor" />.** Two-factor authentication is required for the first Owner and can't
   be skipped. Add a passkey (recommended), or set up an authenticator app: scan the QR code and enter the code the app
   shows. You can add more passkeys later in your account settings.

4. **<UiPath path="setup.stepRecoveryCodes" />.** Generate the codes and store them in a password manager or print
   them. You get 10 codes, each signs you in once if you lose your passkey or authenticator, and they are shown only
   now.

5. **<UiPath path="setup.instanceBasics" />.** These settings apply to every workspace on the instance:

   - **Instance name**, shown on the sign-in page and in emails to your team.
   - **Default timezone**, which new workspaces start with. It starts as your browser's timezone.
   - **Default language** of the app, for the sign-in page, invitations and members who haven't picked one.
   - **Public URL**, the address used for provider webhooks, SSO redirect URIs, public pages and the links in every
     email. ReputeCast checks it as soon as the step opens, and again each time you ask after a fix.
   - <UiPath path="setup.updateCheck" />: only the version number is fetched. Turn it off for offline servers.

   Then save; the next step opens.

6. **<UiPath path="setup.stepWorkspace" />.** Give it a name (shown in the workspace switcher and on public pages
   until you set a brand) and a timezone for its schedules and reports. A workspace has its own lists, campaigns,
   automations, sending providers and team; you can create more later.

7. **<UiPath path="setup.stepProvider" />.** Continue to [connect a sending provider](/providers/connect/), or skip
   it and open the workspace. Invitations, password resets and notifications by email start working once a sending
   provider handles the workspace's System [stream](/reference/glossary/#stream).

</Steps>

## The public URL check

The <UiPath path="setup.instanceBasics" /> step runs three checks from the server against the URL you enter:

| Check     | Passes when                                                                                       | What a warning or failure means                                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DNS       | The host name resolves; the result lists its addresses.                                           | `… doesn't resolve`: add an `A` or `AAAA` record for the host.                                                                                                        |
| TLS       | The server presents a valid certificate (TLS 1.2 or later); the result shows issuer and expiry.  | A warning when the certificate expires within 14 days, or when the URL is plain `http://` (passkeys, secure cookies and most providers' webhooks need HTTPS). |
| Reachable | `GET <public URL>/healthz` answers `200` within 6 seconds.                                        | Another status: the proxy answers but doesn't forward to ReputeCast. No answer: DNS, firewall or proxy.                                                             |

The checks run from the ReputeCast server itself, so the server must be able to reach its own public address. A pass
means that path works; sending providers reach the same address from the internet.

Saving a public URL that differs from `http.public_url` makes it the address for links, public pages and provider
webhooks on every process within 30 seconds. Session cookies and HSTS still follow `http.public_url`, so set the
configuration to the same address ([configure ReputeCast](/self-hosting/configuration/)).

## Troubleshooting

- **The temporary password is lost**: print a one-time reset link on the server with
  `reputecast user reset-password --email you@company.com` ([recover access](/self-hosting/account-recovery/)).
- **The setup asks you to sign in again**: your session ended. Sign in again; the steps you finished are kept.
- **Adding a passkey fails**: the page isn't served over HTTPS, or the browser has no passkey
  provider. Use an authenticator app, then add a passkey later.
- **Reachable fails while the site opens in your browser**: the server can't reach its own public address, often
  because of a firewall rule or a DNS name that resolves differently on the server. Fix it before you connect sending
  providers, which deliver events to the same address.
- **The banner showed `Sign in at http://localhost:8080`**: `http.public_url` was not set. Enter the right address in
  the <UiPath path="setup.instanceBasics" /> step and set the same value in the configuration.

<Aside type="tip">
  The Owner that `reputecast install` creates keeps a break-glass sign-in (password and two-factor) even when the
  instance later requires SSO. Each use is logged.
</Aside>
