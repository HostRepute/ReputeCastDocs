Instance administration is everything that applies to the whole server rather than to one workspace: who has an
account, which workspaces exist, how people sign in, the public URL, updates, and the bot filter that keeps machines'
opens and clicks out of every workspace's numbers. It lives in
<UiPath path="shell.userMenuInstanceAdmin" />, which only [instance admins](/reference/glossary/#instance-admin) can
open.

## Before you begin

- You need the instance admin flag. The first Owner created at install has it; an instance admin can give it to others
  (see [manage users](#manage-users)), and `reputecast user make-admin` gives it from the server
  ([recover access from the command line](/self-hosting/account-recovery/)).
- The flag is separate from workspace roles: making someone an instance admin doesn't change their workspace roles or
  add them to any workspace. Anyone without the flag who opens the page sees "Only instance admins can open Instance
  admin".
- Open it from the account menu at the top right: <UiPath path="shell.userMenuInstanceAdmin" />. It has seven tabs:
  <UiPath path="admin.users" />, <UiPath path="admin.workspaces" />, <UiPath path="admin.authentication" />,
  <UiPath path="admin.sso" />, <UiPath path="admin.instance" />, <UiPath path="admin.botFilter" /> and
  <UiPath path="admin.audit" />.

## Manage users

<Screenshot
  id="instance-users"
  alt="The Users tab lists seven accounts with their workspaces and roles, sign-in methods, two-factor status, last sign-in and status; one account is deactivated."
/>

<UiPath path="shell.userMenuInstanceAdmin > admin.users" /> lists every account on the instance, with filters for
workspace, status and two-factor status. Below the list, a sign-in policy summary and the most recent sign-in events
link to the other tabs. Each row's **⋯** menu has these actions:

<TableScroll label="User actions">

| Action                                     | What it does                                                                                                                                                                                                                  |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <UiPath path="admin.forceSignOut" />       | Ends every session of the account.                                                                                                                                                                                            |
| <UiPath path="admin.resetTwoFactor" />     | Removes their authenticator app and recovery codes; passkeys stay. Asks for a reason (written to the audit log) and your password, restarts the policy's grace period, signs them out and notifies them. Only for accounts with an authenticator app. |
| <UiPath path="admin.sendPasswordReset" />  | Emails a one-time link that works for 15 minutes, on the System stream. <UiPath path="admin.showCliReset" /> shows `reputecast user reset-password --email …` for when no System-stream provider exists. |
| <UiPath path="admin.unlockSignIn" />       | Shown while the account is locked after failed sign-ins; lifts the lock now.                                                                                                                                                  |
| <UiPath path="admin.makeInstanceAdmin" />, <UiPath path="admin.removeInstanceAdmin" /> | Gives or takes the instance admin flag. The last instance admin can't be removed.                                                                                    |
| <UiPath path="admin.deactivateAccount" />  | Signs the person out of every workspace and blocks sign-in. Asks for a reason; by default also revokes the API keys and agents they created. Their history, campaigns and audit entries stay.                                |
| <UiPath path="admin.reactivateAccount" />  | Lets a deactivated person sign in again and brings back the workspace memberships that were deactivated with the account.                                                                                                    |

</TableScroll>

Guards: you can't deactivate your own account, the last instance admin, or the only Owner of a workspace (transfer
ownership in that workspace's settings first). ReputeCast has no way to delete an account or change its email from
here; people change their own email in <UiPath path="shell.userMenuAccount" />.

## Manage workspaces

<UiPath path="shell.userMenuInstanceAdmin > admin.workspaces" /> lists every workspace with its members, contacts,
sending providers and creation date. The same list also sits at the bottom of <UiPath path="admin.instance" />.

<Steps>

1. To add one, choose <UiPath path="admin.createWorkspace" />, then enter a name (up to 80 characters), pick the Owner
   (any active account) and the timezone. The Owner invites everyone else.

2. To delete one, choose <UiPath path="admin.deleteWorkspace" /> on its row and type its name. Scheduled sends stop at
   once, and the workspace's API keys and MCP agents stop working. Export the workspace first if you need its data; the
   dialog links to the export for members of the workspace.

3. To bring a deleted workspace back, choose <UiPath path="admin.restoreWorkspace" /> within 7 days. After that it is
   deleted for good. The shared suppression list, the audit log and the members' accounts are kept either way.

</Steps>

From this list you can open a workspace's settings only if you are one of its members. See
[workspaces](/team/workspaces/) for what each workspace holds.

## Set the sign-in policy

<Screenshot
  id="instance-auth"
  alt="The Authentication tab with the allowed sign-in methods (password, passkeys, Google, Microsoft, GitHub and single sign-on), the password policy and the session and lockout settings."
/>

<UiPath path="shell.userMenuInstanceAdmin > admin.authentication" /> holds the policy for every account. Nothing
applies until you choose <UiPath path="admin.savePolicies" />.

- In <UiPath path="admin.signInMethods" />, turn <UiPath path="admin.methodPassword" />,
  <UiPath path="admin.methodPasskeys" />, Google, Microsoft, GitHub and <UiPath path="admin.methodSso" /> on or off.
  ReputeCast does not support SAML or SCIM. See [Google, Microsoft and GitHub sign-in](/self-hosting/social-sign-in/)
  and [single sign-on with OIDC](/self-hosting/sso/).
- In <UiPath path="admin.passwordPolicy" />, set the minimum length, the re-use of recent passwords and the check
  against known breaches.
- In <UiPath path="admin.twoFactorEnforcement" />, require two-factor authentication from everyone, from members with
  a [sensitive permission](/reference/glossary/#sensitive-permission), or from nobody, and set the grace period to set
  it up.
- In <UiPath path="admin.sessionsLockout" />, set the session lifetime, the idle timeout and the lockout after failed
  passwords.
- In <UiPath path="admin.domainAllowlist" />, list the email domains that may get an account automatically through
  SSO.

ReputeCast refuses a policy that would lock you out (`This would leave you no way to sign in. Add a passkey or link a
sign-in that stays on, then save again.`), one with every method off, and turning off single sign-on while a provider
enforces a domain. A new session lifetime applies to sessions started after the change; a shorter idle timeout
reaches existing sessions within about 30 seconds.

## Set the instance name, public URL and defaults

<Screenshot
  id="instance-settings"
  alt="The Instance & updates tab: the Instance card with name, default timezone, language, region format and public URL with its DNS, TLS and reachability check, next to the Version & updates card."
/>

In <UiPath path="shell.userMenuInstanceAdmin > admin.instance" />, the <UiPath path="admin.instanceCard" /> card sets:

- The instance name and logo, shown on the sign-in page and in team emails.
- The default timezone, language and region format, used on the sign-in page, for invitations and for members who
  haven't chosen their own ([language and region](/team/language-and-region/)).
- The <UiPath path="admin.publicUrl" />, used for provider webhooks, SSO redirect URIs, public pages and links in
  emails. <UiPath path="admin.publicUrlCheck" /> tests three things: DNS (the host resolves), TLS (a valid certificate,
  with a warning under 14 days or on plain `http://`) and reachability (`/healthz` answers from outside).

<Aside type="caution" title="Changing the public URL">
  Saving a new address re-registers the webhook at every sending provider that supports it and lists the providers
  where you paste the new address yourself. Also set `REPUTECAST_PUBLIC_URL` to the same address and restart:
  HTTPS-only cookies and HSTS follow the server setting, not the saved one.
</Aside>

The other cards on this tab:

- The <UiPath path="admin.versionCard" /> card shows the installed and latest version, the upgrade command and the
  daily release check. See [upgrade ReputeCast](/self-hosting/upgrades/).
- The <UiPath path="transactional.relayAdmin.title" /> card turns on the relay for apps that send by SMTP. See
  [send through the SMTP relay](/transactional/smtp-relay/).
- The <UiPath path="agency.adminTitle" /> card turns on agency mode. See
  [run client workspaces as an agency](/team/agencies/).

## Edit the bot filter

<Screenshot
  id="bot-filter"
  alt="The Bot filter tab of Instance admin: only people's opens and clicks count; Networks · 12 with Add network, no network added yet and 12 built-in ones; User agents · 28 with Add user agent and 28 built-in ones, CUBOT phones listed as people's; and How the filter decides for opens, clicks, rules and changes."
/>

The [bot filter](/reference/glossary/#bot-filter) decides which opens and clicks are machines' (mail scanners, scripts,
link previews) or privacy-protected (a privacy proxy such as Apple Mail Privacy Protection). Reports, segments,
automations and scores in every workspace leave them out. Built-in entries come with ReputeCast releases and can't be
removed; in <UiPath path="shell.userMenuInstanceAdmin > admin.botFilter" /> you add the ones your recipients' mail goes
through, such as a company's mail gateway or a new link checker.

To add a network:

<Steps>

1. In <UiPath path="admin.botfilter.networksTitle" />, select <UiPath path="admin.botfilter.addNetwork" />.

2. Enter the <UiPath path="admin.botfilter.cidrLabel" />: an address or a network such as `203.0.113.0/24` or
   `2001:db8::/48`.

3. Say <UiPath path="admin.botfilter.runByLabel" />, for example "Our mail gateway".

4. Under <UiPath path="admin.botfilter.kindLegend" />, choose <UiPath path="admin.botfilter.netScanner" /> (its opens
   and clicks when mail arrives are a machine's; later ones can be people behind the gateway and count) or
   <UiPath path="admin.botfilter.netPrivacy" /> (it fetches images when mail arrives whether or not anyone reads, so its
   opens are privacy-protected), then select <UiPath path="admin.botfilter.addNetwork" />.

</Steps>

To add a user agent:

<Steps>

1. In <UiPath path="admin.botfilter.agentsTitle" />, select <UiPath path="admin.botfilter.addAgent" />.

2. Under <UiPath path="admin.botfilter.itIsLegend" />, choose <UiPath path="admin.botfilter.aMachine" /> (a scanner,
   link checker or script: its opens and clicks are left out wherever the text is in the user agent) or
   <UiPath path="admin.botfilter.aPerson" /> (a device or app whose user agent has a word the rules take for a
   machine's, such as one ending in "bot": its opens and clicks count as people's).

3. Enter the <UiPath path="admin.botfilter.patternLabel" />. It isn't case-sensitive; a person's device is one word of
   letters and digits. ReputeCast refuses text found in the user agents of browsers and mail clients people read email
   with.

4. Fill in <UiPath path="admin.botfilter.whoLabel" /> and select <UiPath path="admin.botfilter.addAgent" />.

</Steps>

To take off an entry an admin added, select <UiPath path="admin.botfilter.remove" /> on its row and confirm. A change
applies to new opens and clicks in every workspace within minutes; the ones counted already stay as they are. Every
change is in the instance audit log. <UiPath path="admin.botfilter.rulesTitle" /> at the bottom of the tab sums up the
rules; [read campaign reports](/campaigns/reports/#how-clicks-are-counted) explains them with the report's numbers.

## Fix requests through an untrusted proxy

Behind a reverse proxy or load balancer that `http.trusted_proxies` doesn't list, every open and click carries the
proxy's address instead of the reader's, so the bot filter can't tell a scanner network or Apple's privacy proxy from a
person, and rate limits treat every reader as one. ReputeCast notices requests that carry forwarding headers
(`X-Forwarded-For`, `X-Real-IP`, `Forwarded`) from an address it doesn't trust, and tells every instance admin with a
notification that links to <UiPath path="admin.instance" />:

- "Requests come through a proxy ReputeCast doesn't trust" names a private address that behaved like your proxy. Add
  it to `http.trusted_proxies` (`REPUTECAST_HTTP__TRUSTED_PROXIES`) and restart ReputeCast.
- "Most requests carry forwarding headers from a public address" names a public address. If it belongs to your CDN or
  load balancer, add the address ranges its provider publishes, not the address itself. If you don't recognize it,
  change nothing: anyone can send these headers, and a trusted address can make up readers' addresses.

A burst of forwarded requests never triggers a notice. The notice comes back while the proxy keeps forwarding, and a
proxy that becomes trusted or goes quiet is forgotten. See
[reverse proxy and TLS](/self-hosting/reverse-proxy/#set-the-public-url-and-trusted-proxies) for the setting; the
timing is in the instance table above.

## Review the instance audit log

<UiPath path="shell.userMenuInstanceAdmin > admin.audit" /> shows sign-ins, SSO, policy and user changes, and the events
of every workspace. Filter by workspace, actor type, result and date; export with <UiPath path="audit.exportCsv" /> or
<UiPath path="audit.exportJson" />. Sign-in rejections carry the reference ID people see on the error page.

- <UiPath path="admin.auditRetention" />: instance-level entries are kept 365 days by default (90 days to 10 years);
  each workspace keeps its own entries for its own period. An hourly cleanup removes older ones.
- <UiPath path="admin.streamInstanceEvents" />: posts instance-level entries to your SIEM or warehouse in batches of up
  to 500, signed with HMAC-SHA256 like [outgoing webhooks](/developers/webhooks/). The signing secret is shown once.

See [audit log](/team/audit-log/) for what each entry records.

## Check that it worked

- Policy changes show the toast "Policies saved" and apply at the next sign-in.
- Every action on this page appears in <UiPath path="admin.audit" /> with you as the actor.

## Troubleshooting

- **"You can't deactivate your own account"**: ask another instance admin.
- **The last instance admin can't be removed or deactivated**: make someone else an instance admin first.
- **"…is the only Owner of…"** when deactivating: transfer ownership of those workspaces first.
- **A deleted workspace has no** <UiPath path="admin.restoreWorkspace" /> **button**: the 7-day hold is over and the
  workspace is gone.
- **The public URL check reports a problem next to Reachable**: the address doesn't answer from outside. Check DNS,
  the firewall and your [reverse proxy](/self-hosting/reverse-proxy/).
- **"A network this wide would take ordinary readers for machines."**: add a narrower network, within the limit in the
  bot filter table.
- **"… is in the user agents of browsers and mail clients people read email with"**: enter a word only the machine's
  user agent has.
- **A built-in network or user agent has no** <UiPath path="admin.botfilter.remove" /> **button**: built-in entries
  come with ReputeCast releases and stay. <UiPath path="admin.botfilter.aPerson" /> overrides the rules (a word ending
  in "bot", "crawler" and the like), not a machine's user agent on the list.
- **Every open and click in the live monitor comes from one address**: ReputeCast doesn't trust your proxy. See
  [fix requests through an untrusted proxy](#fix-requests-through-an-untrusted-proxy).
