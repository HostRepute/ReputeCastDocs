Each guide deploys the release image `ghcr.io/hostrepute/reputecast:v1.6.0` with PostgreSQL behind the platform's HTTPS
proxy, from an empty project to the first sign-in. Pick the platform you already use; on a plain server, follow
[install with Docker Compose](/self-hosting/docker/) or [install the binary](/self-hosting/binary/) instead.

| Platform                                  | Runs on                | PostgreSQL                                | Worth knowing                                              |
| ----------------------------------------- | ---------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| [Coolify](/deploy/coolify/)               | Your server            | In the same Compose file (PostgreSQL 18)  | Coolify generates the secret key for you.                  |
| [Dokploy](/deploy/dokploy/)               | Your server            | In the same Compose file (PostgreSQL 18)  | Pasted Compose file, Let's Encrypt domain.                 |
| [Easypanel](/deploy/easypanel/)           | Your server            | Easypanel's Postgres service              | Change the domain's port from 80 to 8080.                  |
| [CapRover](/deploy/caprover/)             | Your server            | PostgreSQL one-click app, version 18      | One nginx setting keeps live updates streaming.            |
| [Railway](/deploy/railway/)               | Railway's cloud        | Railway's PostgreSQL                      | A paid plan (Hobby or Pro) for the app's volume.           |
| [Render](/deploy/render/)                 | Render's cloud         | Render Postgres                           | Paid plans; Free services sleep and Free databases expire. |
| [Kubernetes](/deploy/kubernetes/)         | Your cluster           | CloudNativePG or a managed database       | One pod with a volume, or web, worker and ingest pods.     |
| [DigitalOcean](/deploy/digitalocean/)     | DigitalOcean's cloud   | App Platform's database                   | No disks: uploaded files go to a Spaces bucket.            |

## One-click installs

The repository has a ready-made setup for five of these platforms. Each runs one ReputeCast instance from the release
image with PostgreSQL beside it; the first start applies the migrations and creates the first Owner from the email you
enter, and the temporary password is in the service's logs (search for `ReputeCast is installed`). Available from the
next release after 1.6.0.

| Platform                              | Start from                                                                                              | What it needs                                                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| [Render](/deploy/render/)             | The Blueprint `render.yaml`, through the Deploy to Render link                                          | A paid web service for the 10 GB disk and a Render Postgres database. Render asks for the public URL and the email. |
| [Railway](/deploy/railway/)           | `deploy/railway/railway.ts`, applied with the Railway CLI                                               | Railway Postgres and a volume. The public URL follows the domain Railway generates.                                 |
| [DigitalOcean](/deploy/digitalocean/) | `.do/deploy.template.yaml`, through the Deploy to DigitalOcean link                                     | A Spaces bucket and its access key, and a secret key you generate.                                                  |
| [Coolify](/deploy/coolify/)           | `deploy/coolify/reputecast.yaml`, pasted as a Docker Compose resource                                   | A Coolify server with a domain. Coolify generates the URL and the PostgreSQL password.                              |
| [Kubernetes](/deploy/kubernetes/)     | The chart in `deploy/helm/reputecast`, installed with Helm                                              | Kubernetes 1.29 or later, PostgreSQL 16–18 and an Ingress controller.                                               |

When you move to your own domain, change the public URL as the guide says, then confirm it in
<UiPath path="shell.userMenuInstanceAdmin > admin.instance" />: the address saved at the first sign-in wins over the
variable, and saving there moves the provider webhooks.

## What every guide sets up

- **Port 8080.** The image serves plain HTTP on port 8080; the platform's proxy terminates TLS and forwards to it.
  Platforms that route to the port in `PORT` get `PORT=8080`: the image sets `REPUTECAST_HTTP__ADDR=:8080`, which wins
  over `PORT`, so ReputeCast listens on 8080 either way. Prometheus metrics listen on port 9464 inside the container:
  never give that port a domain or publish it.
- **Four settings.** `REPUTECAST_DATABASE__URL` (the PostgreSQL connection), `REPUTECAST_PUBLIC_URL` (the
  `https://` address people open), `REPUTECAST_ADMIN_EMAIL` (the first Owner) and `REPUTECAST_SECRETS__KEY`. The key is
  the base64 of 32 random bytes (`openssl rand -base64 32`) and encrypts provider credentials and other secrets in the
  database: save it in your password manager, because a [backup](/self-hosting/backups/) is useless without it.
- **A volume at `/var/lib/reputecast`** where the platform offers one: it keeps uploaded files. Where it doesn't, the
  files go to an [S3-compatible bucket](/self-hosting/object-storage/).
- **The image's health check.** Every 15 seconds the image runs `reputecast healthcheck`, which asks the app's
  `/readyz` without a shell (the image still has no shell, `curl` or `wget`). Docker on Coolify, Dokploy, Easypanel and
  CapRover marks the container healthy once ReputeCast is ready; Railway, Render, DigitalOcean and Kubernetes call
  `/readyz` themselves. Watch `/readyz` from outside too ([monitoring](/self-hosting/monitoring/)).
- **The first Owner's temporary password** is printed in the app's logs on its first start; the
  [first sign-in](/self-hosting/first-run/) replaces it.

## Trusted proxies

None of these platforms publishes the addresses its proxy connects from. With 1.6.0, the guides leave
`REPUTECAST_HTTP__TRUSTED_PROXIES` unset. ReputeCast then sees the proxy's address for every visitor, in the audit log,
in the limits it counts per address, in the allowed IPs of API keys and in the bot filter that sorts opens and clicks.
When a private address keeps forwarding requests, ReputeCast sends instance admins a notification that names it; add it
only if it is your platform's proxy.

The one-click setups set `REPUTECAST_HTTP__TRUSTED_PROXIES=private` instead. The keyword stands for every private
(RFC 1918), shared (`100.64.0.0/10`) and loopback network, IPv6 unique local and loopback included: the router in front
of ReputeCast on these platforms, whose address you can't know in advance. Don't use it where clients can reach
ReputeCast directly from a private network, such as an office LAN: they could claim any address. 1.6.0 doesn't know
the keyword; it logs `ignoring invalid trusted proxy` and trusts nobody. Available from the next release after 1.6.0.

To set your own addresses instead, see
[reverse proxy and TLS](/self-hosting/reverse-proxy/#set-the-public-url-and-trusted-proxies).
