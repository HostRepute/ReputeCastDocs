Um einen Newsletter mit Mailgun aus ReputeCast zu versenden, verbinden Sie einen Private API key, die Region, in der
Ihr Mailgun-Konto liegt, und die Mailgun-Domain, von der Sie senden. ReputeCast registriert die Webhooks auf dieser
Domain, fügt Versand-Domains hinzu und verifiziert sie, erkennt Sandbox-Domains und hält die Sperreinträge in beide
Richtungen synchron.

<ProviderMatrix family="email" id="mailgun" />

## Bevor Sie beginnen

- **Eine Mailgun-Domain** (zum Beispiel `mg.acme.io`), die in Ihrem Mailgun-Konto bereits existiert, und zwar in der
  Region, die Sie verbinden. Die Verbindung wird gegen sie geprüft; legen Sie sie also zuerst in Mailgun an oder
  verbinden Sie zum Ausprobieren die Sandbox-Domain.
- **Ein Private API key** aus Mailgun › API Security. Ein Domain Sending key oder der HTTP webhook signing key
  funktionieren nicht.
- **Berechtigungen.** Zum Verbinden brauchen Sie `providers:manage`; um eine neue Versand-Domain hinzuzufügen,
  `domains:manage`.
- **Eine öffentliche HTTPS-Adresse** für Webhooks: `<public URL>/hooks/mailgun/<token>`. Ist ReputeCast noch nicht aus
  dem Internet erreichbar, kann es stattdessen jede Minute die Event-API von Mailgun abfragen.

Mailgun signiert jeden Webhook mit Ihrem kontoweiten HTTP webhook signing key, der nicht Ihr API-Schlüssel ist
([Mailgun: Securing webhooks](https://documentation.mailgun.com/docs/mailgun/user-manual/webhooks/securing-webhooks),
geprüft im Oktober 2026). ReputeCast liest diesen Schlüssel über die API, Sie müssen ihn also nur einfügen, wenn Ihr
API-Schlüssel ihn nicht lesen kann.

## Mailgun verbinden

<Steps>

1. Öffnen Sie <UiPath path="nav.providers" />, wählen Sie <UiPath path="providers.overview.addProvider" /> und im
   Katalog Mailgun. [Versandanbieter verbinden](/de/providers/connect/) erklärt die Schritte, die alle Anbieter
   gemeinsam haben.

2. Fügen Sie den <UiPath path="providers.fields.mailgun.apiKey" /> ein, wählen Sie die
   <UiPath path="providers.fields.region" /> (`US · api.mailgun.net` oder `EU · api.eu.mailgun.net`, je nachdem, wo die
   Domain angelegt wurde) und geben Sie die <UiPath path="providers.fields.mailgun.domain" /> ein. Die zusätzlichen
   Mailgun-Einstellungen enthalten <UiPath path="providers.fields.monthlyLimit" /> (für die Kontingentanzeige, wenn das
   Konto kein individuelles Sendelimit hat) und den <UiPath path="providers.fields.mailgun.webhookSigningKey" />.

3. Wählen Sie <UiPath path="connect.connection.connect" />. ReputeCast liest mit Ihrem Schlüssel die Domain aus, danach
   das monatliche Sendelimit des Kontos, und speichert den Schlüssel verschlüsselt. Schlägt die Prüfung fehl, wird nichts
   gespeichert.

4. Unter <UiPath path="connect.connection.webhooksTitle" /> registriert ReputeCast seine Webhook-URL auf der Domain für
   `delivered`, `permanent_fail`, `temporary_fail`, `complained` und `unsubscribed`. Öffnungen und Klicks werden nicht
   registriert: Die erfasst ReputeCast selbst. Zuerst prüft es, ob die Adresse überhaupt aus dem Internet erreichbar
   ist; Mailgun kann nicht auf Anfrage einen Test-Webhook senden, daher bestätigt das Zustellereignis des Testversands,
   dass seine Ereignisse ankommen. Ist die Adresse nicht erreichbar, wählen Sie
   <UiPath path="connect.connection.usePolling" /> und korrigieren Sie die öffentliche URL später.

   <Screenshot
     id="connect-mailgun-error"
     alt="Eine fehlgeschlagene Mailgun-Verbindung: Der Private API key wurde mit 401 Unauthorized abgelehnt, und die Webhook-Adresse auf localhost ist aus dem Internet nicht erreichbar, daher wird die Registrierung übersprungen, mit drei Lösungswegen: eine öffentliche URL, ein Tunnel oder Abfrage."
   />

5. Wählen Sie <UiPath path="connect.connection.continueDomain" /> und geben Sie Ihre Versand-Domain ein. Ist sie noch
   nicht in Mailgun, fügt ReputeCast sie hinzu (automatische Sender Security, DKIM mit 2048 Bit) und listet die
   SPF-, DKIM- und MX-Einträge auf, die Sie veröffentlichen müssen. Der Tracking-CNAME von Mailgun fehlt, weil
   ReputeCast Öffnungen und Klicks selbst erfasst.

6. Senden Sie unter <UiPath path="connect.stepTest" /> einen Test und verfolgen Sie, wie der Webhook `delivered`
   ankommt.

7. Wählen Sie unter <UiPath path="connect.stepStreams" /> und <UiPath path="connect.stepContacts" /> die Streams und
   lassen Sie die Option zum Abrufen der bestehenden Bounces, Beschwerden und Abmeldungen von Mailgun angehakt.

</Steps>

## Prüfen, ob es funktioniert hat

- Die Mailgun-Karte unter <UiPath path="nav.providers > providers.tabProviders" /> zeigt
  <UiPath path="providers.statusHealthy" /> mit Ihrer Domain und ihrem Zustand (zum Beispiel
  „Domain mg.acme.io · active“). Eine Sandbox-Domain zeigt stattdessen <UiPath path="providers.statusSandbox" />.
- In Mailgun listen die Webhooks der Domain Ihre ReputeCast-URL für die fünf Ereignisse.
- Zustellungen und Bounces erscheinen unter <UiPath path="nav.providers > providers.tabEvents" />.

ReputeCast sendet einen API-Aufruf pro Nachricht, wobei das Öffnungs-, Klick- und Abmelde-Tracking von Mailgun bei
jeder Nachricht ausgeschaltet ist. Ist das Abmelde-Tracking für die Domain eingeschaltet, fügt Mailgun neben dem von
ReputeCast einen eigenen Abmeldelink und eine eigene Fußzeile hinzu; die
[Versandbereitschaft](/de/reference/glossary/#send-readiness) warnt davor, und die
<UiPath path="providers.events.trackingTitle" /> im Tab Ereignisse & Sync kann es ausschalten. Aus der gemeinsamen
[Sperrliste](/de/reference/glossary/#suppression-list) überträgt ReputeCast die Hard Bounces und Beschwerden, die für
alle E-Mails gelten, in die Unsubscribes-Tabelle der Versand-Domain (für alle Tags) und entfernt sie dort, wenn sie die
gemeinsame Liste verlassen; Abmeldungen und andere Einträge, die nur für Marketing gelten, bleiben in ReputeCast.
ReputeCast liest außerdem beim Verbinden und täglich die dedizierten IPs des Kontos aus, die der Domain der Verbindung
zugewiesen sind, und zeigt sie als [Versand-IPs](/de/providers/senders-and-domains/#versand-ips-prüfen) der Karte; ohne
dedizierte IPs sendet die Domain aus dem gemeinsamen Pool von Mailgun.

Die Sandbox-Domain von Mailgun stellt nur an autorisierte Empfänger zu, höchstens 5
([Mailgun: Sandbox domain](https://documentation.mailgun.com/docs/mailgun/user-manual/domains/domains-sandbox),
geprüft im Oktober 2026). Solange Mailgun mit einer Sandbox-Domain verbunden ist, blockiert die Versandbereitschaft
Massenversand darüber.

## Fehlerbehebung

- **„Mailgun hat diesen Schlüssel abgelehnt“** mit `401 Unauthorized`. Verwenden Sie einen Private API key aus
  demselben Konto, keinen Sending key und nicht den Webhook signing key.
- **„Mailgun hat diesen Schlüssel abgelehnt“** mit `404 Not Found · domain_not_found`. Der Schlüssel ist in Ordnung,
  aber Mailgun kennt die Versand-Domain in der gewählten Region nicht. Prüfen Sie die Schreibweise der Domain und die
  Region, oder legen Sie die Domain zuerst in Mailgun an.
- **„Mailgun erlaubt drei URLs pro Ereignis“** beim Registrieren der Webhooks. Eines der Ereignisse sendet bereits an
  drei Adressen. Entfernen Sie in Mailgun eine alte URL und wählen Sie dann
  <UiPath path="connect.connection.registerAgain" />.
- **Die Webhook-Adresse ist aus dem Internet nicht erreichbar** (zum Beispiel „localhost funktioniert nur auf diesem
  Rechner“). Setzen Sie `REPUTECAST_PUBLIC_URL` auf die HTTPS-Adresse, die Ihr Reverse Proxy bereitstellt, verwenden Sie
  beim Testen einen Tunnel oder nutzen Sie vorerst die Abfrage. Siehe
  [Reverse Proxy und TLS](/de/self-hosting/reverse-proxy/).
- **Webhooks kommen an, bestehen aber die Verifizierung nicht, und der Anbieter wechselt auf „Webhooks stumm“.** Ihr
  API-Schlüssel kann den Webhook signing key des Kontos nicht lesen. Kopieren Sie ihn in Mailgun aus Settings › API
  Security › HTTP webhook signing key in
  <UiPath path="providers.overview.settings > providers.overview.credentials" /> auf der Anbieterkarte.
- **Testempfänger werden mit `unauthorized_recipient` abgelehnt.** Die Domain ist die Sandbox von Mailgun: Fügen Sie
  die Adresse in Mailgun als autorisierten Empfänger hinzu oder verbinden Sie eine verifizierte Domain.
- **Transaktions-E-Mails mit Cc, Bcc oder Anhängen schlagen fehl.** Der Mailgun-Adapter kann keine Kopien oder Anhänge
  senden; leiten Sie diese Vorlagen über einen anderen Anbieter.
- **Sie haben Mailgun getrennt.** ReputeCast entfernt seine URL von jedem Webhook-Ereignis. Die Domain und die
  übertragenen Abmeldungen bleiben in Mailgun.
