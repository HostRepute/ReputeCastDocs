Um einen Newsletter mit SparkPost aus ReputeCast zu versenden, verbinden Sie einen API-Schlüssel und die Region Ihres
SparkPost-Kontos (US oder EU). ReputeCast registriert einen mit Basic Auth geschützten Webhook, richtet DKIM für Ihre
Versand-Domain ein, schaltet das Tracking von SparkPost bei jeder Nachricht aus und hält beide Sperrlisten synchron.

<ProviderMatrix family="email" id="sparkpost" />

## Bevor Sie beginnen

- **Ein SparkPost-Konto** unter `app.sparkpost.com` (US) oder `app.eu.sparkpost.com` (EU). Der Adapter spricht die API
  von SparkPost; Konten bei Bird Email nutzen eine andere API und lassen sich damit nicht verbinden.
- **Ein API-Schlüssel** mit den Berechtigungen Transmissions, Webhooks, Sending Domains, Suppression Lists, Account,
  Metrics und Message Events, erstellt unter Configuration › API Keys in SparkPost
  ([SparkPost: Create API keys](https://support.sparkpost.com/docs/getting-started/create-api-keys), geprüft im
  Oktober 2026). EU-Konten erstellen Schlüssel in der EU-App.
- **Berechtigungen.** Zum Verbinden brauchen Sie `providers:manage`; um eine neue Versand-Domain hinzuzufügen,
  `domains:manage`.
- **Eine öffentliche HTTPS-Adresse** für den Webhook: `<public URL>/hooks/sparkpost/<token>`. SparkPost sendet einen
  Test-Batch an die Adresse, bevor es einen Webhook speichert, daher muss die Adresse erreichbar sein. Bis dahin kann
  ReputeCast die Event-API von SparkPost jede Minute abfragen.

## SparkPost verbinden

<Steps>

1. Öffnen Sie <UiPath path="nav.providers" />, wählen Sie <UiPath path="providers.overview.addProvider" /> und im
   Katalog SparkPost. [Versandanbieter verbinden](/de/providers/connect/) erklärt die Schritte, die alle Anbieter
   gemeinsam haben.

2. Fügen Sie den <UiPath path="providers.fields.apiKey" /> ein und wählen Sie die
   <UiPath path="providers.fields.region" />: `us` für `api.sparkpost.com`, `eu` für `api.eu.sparkpost.com`. Unter den
   zusätzlichen SparkPost-Einstellungen können Sie einen <UiPath path="providers.fields.ipPool" /> mit dedizierten IPs
   angeben, über den gesendet wird.

3. Wählen Sie <UiPath path="connect.connection.connect" />. ReputeCast liest mit dem Schlüssel Ihr Konto und dessen
   Nutzung aus und speichert ihn dann verschlüsselt. Die Karte zeigt die Konto-ID, ihren Status und Ihren Tarif.

4. Unter <UiPath path="connect.connection.webhooksTitle" /> prüft ReputeCast, ob seine Webhook-Adresse aus dem Internet erreichbar ist, und legt dann einen
   Webhook namens „ReputeCast“ mit Basic Auth an (Benutzer `reputecast`, ein Kennwort, das ReputeCast erzeugt) oder
   aktualisiert ihn, und zwar für Zustellungen, Bounces, Out-of-Band-Bounces, Verzögerungen, Spam-Beschwerden,
   Richtlinien-Ablehnungen, Generierungsfehler und Abmeldungen. Öffnungs- und Klickereignisse werden nicht abonniert.
   Ist der Endpunkt noch nicht erreichbar, wählen Sie <UiPath path="connect.connection.usePolling" />.

5. Wählen Sie <UiPath path="connect.connection.continueDomain" /> und geben Sie Ihre Versand-Domain ein. ReputeCast
   legt sie als Sending Domain in SparkPost mit einem DKIM-Schlüssel von 2048 Bit an und listet den DKIM-TXT-Eintrag
   auf. Bei einer Subdomain wie `news.acme.io` listet es außerdem den Bounce-CNAME auf (auf `sparkpostmail.com` bzw. in
   der EU auf `eu.sparkpostmail.com`); eine Apex-Domain wie `acme.io` kann keinen CNAME haben und erhält daher nur DKIM.
   ReputeCast schlägt DMARC vor, wenn die Domain keinen Eintrag hat.

6. Senden Sie unter <UiPath path="connect.stepTest" /> einen Test und verfolgen Sie, wie das Zustellereignis ankommt.

7. Wählen Sie unter <UiPath path="connect.stepStreams" /> und <UiPath path="connect.stepContacts" /> die Streams und
   lassen Sie die Option zum Abrufen der bestehenden Sperreinträge von SparkPost angehakt.

</Steps>

## Prüfen, ob es funktioniert hat

- Die SparkPost-Karte unter <UiPath path="nav.providers > providers.tabProviders" /> zeigt
  <UiPath path="providers.statusHealthy" /> und Ihr monatliches oder tägliches Sendelimit mit seiner Nutzung.
- In SparkPost enthält die Webhook-Liste einen Webhook „ReputeCast“, der mit Basic Auth auf `/hooks/sparkpost/…` zeigt.
- Zustellungen und Bounces erscheinen unter <UiPath path="nav.providers > providers.tabEvents" />.

SparkPost signiert keine Webhooks, daher verlässt sich ReputeCast auf die Basic-Auth-Zugangsdaten und die nicht
erratbare URL. ReputeCast sendet eine Transmission pro Nachricht, mit ausgeschaltetem Öffnungs- und Klick-Tracking und
einem Idempotenzschlüssel aus der ReputeCast-ID der Nachricht. SparkPost bewahrt den Schlüssel 24 Stunden lang auf,
sodass eine Nachricht, die in dieser Zeit nach einer Zeitüberschreitung oder einer verlorenen Antwort erneut gesendet
wird, erkannt und nie doppelt zugestellt wird; der [Live-Monitor](/de/campaigns/live-monitor/) zeigt, welcher Anbieter
eine erneute Sendung erkennt und bis wann. Jede Nachricht geht nach den Begriffen von SparkPost als transaktional
hinaus, weil SparkPost anderen E-Mails einen eigenen `List-Unsubscribe`-Header hinzufügt und ReputeCast bereits einen
mit Abmeldung mit einem Klick hinzufügt. Aus demselben Grund überträgt ReputeCast die Hard Bounces und Beschwerden, die
für alle E-Mails gelten, auf beide Sperrlisten von SparkPost, entfernt sie aus beiden, wenn sie die gemeinsame Liste
verlassen, und ruft die Bounce-, Spam-Beschwerde- und Abmeldeeinträge von SparkPost zurück.

Beim Verbinden bittet ReputeCast SparkPost, den Webhook mit einem Test-Batch zu validieren, und macht weiter, sobald er
ankommt. Außerdem liest es beim Verbinden und täglich die dedizierten Versand-IPs des Kontos im IP-Pool der Verbindung
(oder im Standard-Pool) aus und zeigt sie als [Versand-IPs](/de/providers/senders-and-domains/#versand-ips-prüfen) der
Karte; ein Konto ohne dedizierte IPs sendet von den gemeinsamen IPs von SparkPost.

## Fehlerbehebung

- **„SparkPost hat diesen Schlüssel abgelehnt“** mit `401 Unauthorized`. Der Schlüssel ist falsch, ihm fehlen
  Berechtigungen, oder er gehört zur anderen Region. Prüfen Sie die Berechtigungen des Schlüssels und ob die Region zu
  der App passt, in der Sie ihn erstellt haben.
- **Die Webhook-Registrierung schlägt fehl.** SparkPost testet die URL, bevor es einen Webhook speichert, daher schlägt
  die Registrierung fehl, solange SparkPost ReputeCast nicht erreichen kann. Korrigieren Sie die öffentliche URL (siehe
  [Reverse Proxy und TLS](/de/self-hosting/reverse-proxy/)) und wählen Sie dann
  <UiPath path="connect.connection.registerAgain" />.
- **Der Domain-Schritt listet nur einen DKIM-Eintrag.** Sie haben eine Apex-Domain eingegeben. Senden Sie von einer
  Subdomain, wenn die Bounce-Domain von SparkPost mit Ihrer ausgerichtet sein soll.
- **Der Versand wird mit HTTP-Fehlern 420 langsamer.** SparkPost antwortet mit 420, wenn Ihr tägliches oder
  monatliches Sendelimit aufgebraucht ist. ReputeCast behandelt das als Drosselung und versucht es später erneut;
  erhöhen Sie das Limit in SparkPost oder leiten Sie einen Teil des Verkehrs über einen anderen Anbieter.
- **Der Katalog zeigt ein Kennzeichen „Sandbox-Domain“.** ReputeCast hat keinen Sandbox-Modus für SparkPost: Verbinden
  Sie eine echte Versand-Domain.
- **Tracking auf Kontoebene ist eingeschaltet.** Die Tracking-Prüfung im Tab Ereignisse & Sync meldet das, obwohl
  ReputeCast das Tracking bei jeder gesendeten Nachricht ausschaltet. Um die Standardwerte des Kontos über die API zu
  ändern, braucht der Schlüssel Schreibzugriff auf Account.
- **Sie haben SparkPost getrennt.** ReputeCast löscht die Webhooks, die auf seine URL zeigen. Die Versand-Domain und
  die übertragenen Sperreinträge bleiben in SparkPost.
