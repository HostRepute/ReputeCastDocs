In etwa 10 Minuten können Sie Transaktions-E-Mails per API senden: Der Leitfaden für den ersten Versand führt Sie vom
Absender bis zur zugestellten Nachricht, und sein letzter Schritt prüft den ganzen Ablauf mit einem echten Aufruf aus
Ihrer App.

## Bevor Sie beginnen

- Ein [Versandanbieter](/de/providers/connect/), der mit dem Arbeitsbereich verbunden ist. Gibt es noch keinen,
  fordert der Leitfaden Sie auf, einen zu verbinden.
- Eine Versand-Domain, für die Sie DNS-Einträge anlegen können. Eine eigene Subdomain wie `notify.example.com` hält die
  Reputation der Produkt-E-Mails von Ihren Newslettern getrennt. Siehe
  [Versand-Domains und Absender hinzufügen](/de/providers/senders-and-domains/).
- Berechtigungen: `transactional:publish`, um die Vorlage zu veröffentlichen, und `apikeys:manage`, um den Schlüssel
  zu erstellen. Die Rollen Inhaber und Admin haben beide.
- `curl` oder der HTTP-Client Ihrer App für den ersten Aufruf.

## Senden

<Steps>

1. Öffnen Sie <UiPath path="nav.transactional" /> und wählen Sie <UiPath path="transactional.overview.startGuide" />.
   Der Leitfaden hat fünf Schritte: Absender, Route, Vorlage, Schlüssel und Ankunft verfolgen. Mit
   **Leitfaden verlassen** können Sie ihn jederzeit beenden.

2. **Absender.** Geben Sie einen **Absendernamen** und eine **Absenderadresse** auf der Domain ein, die
   Transaktions-E-Mails sendet. Ist die Domain neu, listet der Leitfaden die nötigen DNS-Einträge auf (DKIM, einen
   Return-Path, SPF und eine DMARC-Richtlinie, je nach Versandanbieter) und prüft sie live. Bei den meisten
   DNS-Hostern dauert das einige Minuten. Ist HostRepute verbunden, können Sie die Domain hier zur
   Blocklisten-Überwachung von HostRepute hinzufügen.

   <Screenshot
     id="transactional-guide"
     alt="Schritt 1 von 5 des Leitfadens für den ersten Versand: Absendername Acme Cloud und Absenderadresse no-reply@notify.acme.io, links die fünf Schritte."
   />

   Wählen Sie **Weiter zur Route**.

3. **Route.** Wählen Sie den **Hauptanbieter** und, falls Sie einen zweiten Versandanbieter haben, einen
   **Ersatzanbieter**. Der Ersatzanbieter wird sofort verwendet, wenn der Hauptanbieter ausfällt. Lassen Sie
   **Vorrang bei gemeinsam genutzten Anbietern** eingeschaltet, damit Transaktionsnachrichten vor einer Kampagne
   gesendet werden, die denselben Versandanbieter nutzt. Wählen Sie **Weiter zur Vorlage**.

4. **Vorlage.** Beginnen Sie mit einer Startvorlage: Passwort zurücksetzen, Anmeldelink, E-Mail-Bestätigung,
   Willkommen, Beleg oder Rechnung, Testphase endet, Teameinladung oder Nutzungswarnung. Jede enthält deklarierte
   Variablen und eine Fußzeile für Konto-E-Mails. Wählen Sie **v1 veröffentlichen und weiter** oder
   **Vor dem Veröffentlichen bearbeiten**, um sie zuerst im [Vorlageneditor](/de/transactional/templates/) zu ändern.
   Liegen Ihre Vorlagen bei Postmark, SendGrid, Mailgun oder Notifuse, können Sie sie
   [stattdessen importieren](/de/migrate/transactional-templates/).

5. **Schlüssel.** Benennen Sie den Schlüssel (zum Beispiel `Acme Cloud · Produktion`) und wählen Sie
   **Nur-Senden-Schlüssel erstellen**. Ein [Nur-Senden-Schlüssel](/de/reference/glossary/#send-only-key) hat
   `transactional:send` und sonst nichts. Kopieren Sie ihn jetzt: Er wird nur einmal angezeigt. Wählen Sie dann
   **Ich habe ihn kopiert · Ankunft verfolgen**.

6. **Ankunft verfolgen.** Der Leitfaden zeigt **Ihr erster Aufruf**, ausgefüllt mit der Vorlagen-ID und ihren
   Beispieldaten. Führen Sie ihn mit dem kopierten Schlüssel von Ihrem Laptop oder Ihrer App aus. Für Node.js, Python
   und Go ruft das Beispiel des Leitfadens das [ReputeCast-SDK](/de/developers/sdks/) auf; sein Schalter
   <UiPath path="transactional.codeStyleSdk" /> · <UiPath path="transactional.codeStyleHttp" /> zeigt stattdessen die
   einfache Anfrage. Verfügbar ab der nächsten Version nach 1.6.0. Mit cURL sieht die Anfrage so aus; übernehmen Sie
   den genauen Body aus dem Leitfaden, denn er enthält die Variablen Ihrer Vorlage:

   ```sh title="Terminal"
   curl -X POST "https://reputecast.example.com/api/v1/workspaces/acme-newsletter/transactional/messages" \
     -H "Authorization: Bearer $REPUTECAST_KEY" \
     -H "Content-Type: application/json" \
     -H "Idempotency-Key: first-send-1" \
     -d @first-message.json
   ```

   Der **Zustellverlauf** verfolgt die Nachricht: **Aufruf empfangen**, **Gerendert**, **An** den Versandanbieter
   **übergeben** und **Zugestellt**, mit der Zeit hin und zurück von Ihrem Aufruf bis zum Zustellereignis. Möchten Sie
   den Aufruf nicht selbst ausführen, sendet **Stattdessen von hier senden** die Nachricht mit den Beispieldaten an Ihre
   eigene Adresse.

7. Wählen Sie **Abschließen**, sobald die erste Nachricht zugestellt ist.

</Steps>

## Was Sie erstellt haben

- Einen verifizierten Absender für Transaktions-E-Mails und eine Route Transaktional mit automatischem Failover.
- Eine veröffentlichte Vorlage, die Ihre App über ihre ID aufruft. Die ID steht nach dieser ersten Veröffentlichung
  fest.
- Einen Nur-Senden-Schlüssel für Ihre App, aufgeführt unter
  <UiPath path="nav.transactional > transactional.common.tabSetup" />, wo Sie ihn rotieren oder widerrufen können.
- Eine erste Nachricht im [Nachrichtenprotokoll](/de/transactional/message-log/) mit ihrem vollständigen Verlauf.

Wurde der Aufruf abgelehnt, nennt der Verlauf den Grund. Eine Vorlage mit einem Entwurf, aber ohne veröffentlichte
Version kann nicht senden: Veröffentlichen Sie sie und rufen Sie dann erneut mit demselben Idempotenzschlüssel auf.
