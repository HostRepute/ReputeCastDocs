Diese Seite listet die Endpunkte von ReputeCast, die ein Browser, ein Versandanbieter, ein Monitoring-Tool oder ein anderer Dienst erreicht, gruppiert nach der Serverrolle, die sie ausliefert.

Pfade sind relativ zu Ihrer öffentlichen URL (`http.public_url`). Ein `serve`-Prozess führt die Rollen aus `--role` aus (standardmäßig alle drei, siehe [mit den Rollen web, ingest und worker skalieren](/de/self-hosting/scaling/)): **web** liefert die API, MCP, die öffentlichen Seiten, das Tracking und die Web-App aus; **ingest** liefert `/hooks/…` aus; ein Prozess nur mit **worker** hat keinen HTTP-Listener. `<token>` steht für einen signierten Wert, den ReputeCast in den Link setzt; behandeln Sie jede URL, die einen enthält, als vertraulich.

## Zustand und Metriken

Ausgeliefert von jedem Prozess mit der Rolle web oder ingest und vom Metrik-Listener unter `metrics.addr` ([Konfiguration](/de/reference/configuration/)).

| Pfad            | Wofür                                                                                                                                                                                                                 |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /healthz`  | Liveness: `200 ok`, solange der Prozess läuft.                                                                                                                                                                        |
| `GET /readyz`   | Readiness: `200 ready` oder `503`, wenn die Datenbank nicht innerhalb von 2 Sekunden antwortet, das Datenbankschema hinter diesem Release zurückliegt (führen Sie `reputecast migrate up` aus) oder die Worker noch nicht gestartet sind. |
| `GET /metrics`  | Prometheus-Metriken auf dem Metrik-Listener, ohne Authentifizierung; halten Sie diesen Port vom Internet fern. Auf dem Hauptport nur mit `metrics.token`, gesendet als `Authorization: Bearer <token>`; sonst `404`. |

Ein Prozess, der nur die Rolle worker ausführt, hat keinen Haupt-Listener und öffnet daher immer den Metrik-Listener für
`/healthz` und `/readyz`, auch wenn die Metriken ausgeschaltet sind.

[Zustandsprüfungen, Metriken und Protokolle](/de/self-hosting/monitoring/) listet die Metrikreihen.

| `/api/reference`                         | Die eigene API-Referenz dieser Instanz: jede Operation ihres OpenAPI-Dokuments, nach Tag gruppiert, mit der Berechtigung, die sie braucht. Ohne Authentifizierung; gesendet mit `noindex`. |

## Öffentliche Seiten

Ausgeliefert von der Rolle web unter `/p/<workspace>/…`, wobei `<workspace>` der URL-Pfad des Arbeitsbereichs ist. Auf einer verifizierten eigenen Domain antworten dieselben Seiten im Stammverzeichnis (siehe [eigene Domains](#eigene-domains)). Die Pfade in dieser Tabelle sind relativ zu `/p/<workspace>`.

| Pfad                                                       | Wofür                                                                                                                  |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `/`                                                        | Die Startseite der Website, wenn die Newsletter-Website eingeschaltet ist; sonst eine Weiterleitung auf `/subscribe`.  |
| `/subscribe`, `/subscribe/<form>`                          | Anmeldeseite auf ReputeCast, für das Standardformular oder ein bestimmtes Formular.                                    |
| `/forms/<id>.js`                                           | Einbettungsskript eines Anmeldeformulars. Es ruft `/forms/<id>/session` und `/forms/<id>/submit` auf und sendet bei einem Formular mit [Schritten](/de/forms/form-steps/) ein Beacon an `/forms/<id>/step`, wenn ein späterer Schritt erscheint (der Endpunkt antwortet immer `204`). Verfügbar ab der nächsten Version nach 1.6.0. |
| `/confirm/<token>`                                         | Bestätigungsseite für das Double-Opt-in. Das Öffnen des Links zeigt den Button <UiPath path="pagelabels.confirm.ask.button" />; erst dessen `POST` bestätigt. Die Seite eines abgelaufenen Links bietet einen neuen Link an ([Grenzen und Standardwerte](/de/reference/limits-and-defaults/)). |

| `/unsubscribe/<token>`                                     | Abmeldeseite. Ein `POST` mit dem Body `List-Unsubscribe=One-Click` ist das Ziel der Abmeldung mit einem Klick nach RFC 8058. |
| `/view/<token>`                                            | Die E-Mail im Browser.                                                                                                 |
| `/archive`, `/archive/<issue>`, `/archive.rss`, `/sitemap.xml` | Öffentliches Archiv, eine Ausgabe, sein RSS-Feed und die Sitemap.                                                  |
| `/llms.txt`                                                | Titel, Beschreibung und Beiträge der Website in Markdown für Sprachmodelle ([llmstxt.org](https://llmstxt.org/), geprüft im November 2026). Die Datei listet, was die Sitemap listet, und antwortet `404`, solange die Website ausgeschaltet ist oder Suchmaschinen sie nicht indexieren dürfen. |
| `/sms-terms`                                               | Seite mit den SMS-Bedingungen.                                                                                         |
| `/poll/<token>/<answer>`, `/s/<slug>`                      | Antwortseite einer Abstimmung (die Stimme erfasst der `POST` der Seite, nicht das Öffnen des Links); Seite einer Umfrage. |
| `/join/<code>`, `/referrals`, `/referrals/<token>`, `/leaderboard`, `/rewards/<token>` | Einladungsseite einer Weiterempfehlung, Prämienseite, Bestenliste und Downloads von Prämien. |
| `/recommends`, `/recommends/<token>`                       | Seite mit Empfehlungen.                                                                                                |
| `/upgrade`, `/upgrade/<tier>`, `/billing/<token>`, `/cancel/<token>` | Upgrade-Seite und Stripe Checkout, das Abrechnungsportal von Stripe und die Kündigungsseite. | `POST /billing`                                            | Sendet einem zahlenden Mitglied neue Links zur Abrechnung und Kündigung, nur an die hinterlegte Adresse und höchstens einmal alle zehn Minuten; die Antwort ist immer dieselbe, was auch geschieht. |

| `/resume/<token>`                                          | Ein pausiertes Bezahlabo fortsetzen. Das Öffnen des Links ändert nichts; das tut erst der Button der Seite. Verfügbar ab der nächsten Version nach 1.6.0. |
| `/sponsor`, `/sponsor/request`, `/sponsor/b/<token>`       | Die Sponsorenseite mit dem Media-Kit, das [Formular für Buchungsanfragen](/de/earn/sponsor-self-booking/) und die Statusseite einer Anfrage, deren `POST /sponsor/b/<token>/pay` Stripe Checkout öffnet. Verfügbar ab der nächsten Version nach 1.6.0. |

| `/<slug>`                                                  | Eine veröffentlichte Landing- oder Verkaufsseite (`/<slug>/event.ics` ist ihre Kalenderdatei).                         |

| `POST /posts/<slug>/comments`, `…/comments/<id>/edit`, `…/comments/<id>/delete` | Der [Kommentar](/de/forms/post-comments/) oder die Antwort eines angemeldeten Mitglieds und deren Bearbeiten oder Löschen. Nur Anfragen von der Website selbst werden angenommen. Verfügbar ab der nächsten Version nach 1.6.0. |
| `/signin`, `/account`                                      | Anmeldung und Konto für Mitglieder der Website. `POST /account/comments` speichert die Kommentar-Einstellungen der Kontoseite. Verfügbar ab der nächsten Version nach 1.6.0. |
| `/comments/mute/<token>`                                   | Die Seite, die die E-Mails abschaltet, die ein Mitglied zu Antworten auf seine Kommentare erhält. Das Öffnen des Links ändert nichts; das tut nur der Button der Seite. Verfügbar ab der nächsten Version nach 1.6.0. |
| `/push/…`                                                  | Endpunkte, über die die Abfrage für Web-Push einen Browser an- und abmeldet.                                           |

Zwei Pfade liegen außerhalb eines Arbeitsbereichs:

- `/p/_/…` liefert das gemeinsame CSS, die Skripte und Schriften der Seiten aus. `GET /p/_/tls-check?domain=<host>` antwortet `200`, wenn der Host eine verifizierte eigene Domain ist, und sonst `404`, für die Einstellung `ask` des On-Demand-TLS von Caddy.
- `/p/<code>` mit einem Partnercode (`XXXX-XXXX-XXXX`) erklärt, wie Sie den Code in eine andere ReputeCast-Instanz einfügen; das Öffnen verbraucht den Code nicht.

Seiten, die über einen signierten Link erreicht werden, sind `noindex`. Eine `HEAD`-Anfrage an eine Token-Seite bewirkt nichts, daher können Link-Scanner weder bestätigen noch abmelden noch abstimmen, und sie können weder ein Abo fortsetzen noch E-Mails abschalten. Die `robots.txt` der Instanz sperrt alles außer `/p/`.

## Eigene Domains

Ist die eigene Domain eines Arbeitsbereichs verifiziert (ein `CNAME` auf den Host der Instanz, passende `A`/`AAAA`-Einträge oder der TXT-Eintrag `_reputecast.<domain>`), antworten die öffentlichen Seiten im Stammverzeichnis dieser Domain: `https://news.acme.io/subscribe` ist dieselbe Seite wie `/p/acme-newsletter/subscribe`. ReputeCast erkennt den Arbeitsbereich am Header `Host`, daher muss Ihr Proxy ihn unverändert weitergeben.

- Links auf Seiten, die von der eigenen Domain ausgeliefert werden, lassen `/p/<workspace>` weg. Skripte, Theme-Dateien und gemeinsame Assets behalten ihre Pfade `/p/<workspace>/…` und `/p/_/…`.
- Die eigene Domain erhält eine eigene `robots.txt`, `sitemap.xml` und `llms.txt`.
- E-Mails verlinken weiterhin auf die öffentliche URL.
- Auf dem eigenen Host der Instanz gehören Stammpfade wie `/subscribe` zur Web-App.
- Auf der eigenen Domain der Website funktionieren die Adressen einer [aus Substack, Ghost oder WordPress importierten](/de/migrate/posts/) Website weiter: Die alte Adresse eines Beitrags antwortet mit `301` auf den Beitrag, die alten Feed-Adressen antworten mit `301` auf `/feed`, und jeder andere Pfad, auf den nichts antwortet, zeigt die eigene 404-Seite der Website statt der der Web-App. Verfügbar ab der nächsten Version nach 1.6.0.

### Welcher Host welche Links ausliefert

Seit Version 1.5.0 liefert ein Host, den ein Arbeitsbereich hält, nur die Links und Seiten dieses Arbeitsbereichs aus. Ein Arbeitsbereich hält seine verifizierte eigene Domain, seine Kurzlink-Domain für SMS, seine Tracking-Domain für Links und den Host der Website seiner Publikation. Auf einem solchen Host antworten Tracking-Links (`/t/o`, `/t/c`, `/t/h`), Kurzlinks (`/t/s`), Push-Klicks (`/t/p`) und `/p/<workspace>`-Seiten eines anderen Arbeitsbereichs mit `404`, damit nichts so aussehen kann, als hätte der Arbeitsbereich, dem der Host gehört, es gesendet oder veröffentlicht. Der eigene Host der Instanz und ein Host, den niemand hält, liefern die Links aller Arbeitsbereiche aus, damit Links in bereits gesendeten E-Mails weiter funktionieren. Ein Host, den ein Arbeitsbereich verifiziert oder freigibt, antwortet innerhalb einer Minute entsprechend.

[Branding der Seiten festlegen und eigene Domain nutzen](/de/forms/branding-and-domain/) behandelt den DNS-Schritt, [Reverse Proxy und TLS](/de/self-hosting/reverse-proxy/#eigene-domains) die Zertifikate.

## Tracking und Kurzlinks

Ausgeliefert von der Rolle web.

| Pfad                  | Wofür                                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------------- |
| `/t/o/<token>`        | Tracking-Pixel für Öffnungen (ein GIF mit 1×1 Pixel).                                                       |
| `/t/c/<token>`        | Klick-Tracking: erfasst den Klick und leitet auf den Link in der Nachricht weiter. Das Ziel steckt im signierten Token, daher lässt sich der Pfad nicht als offene Weiterleitung missbrauchen. |
| `/t/p/<id>.<token>`   | Klick auf eine Web-Push-Benachrichtigung: leitet auf den Link der Benachrichtigung weiter.                  |
| `/t/h/<token>`        | Der versteckte Link in einer E-Mail mit Tracking. Kein Mensch kann ihn sehen, daher wird alles, was ihm folgt, als Klick eines Bots erfasst; er antwortet `204`. |
| `/t/s/<code>`         | SMS-Kurzlink auf dem Host der Instanz. Auf einer verifizierten Kurzlink-Domain für SMS funktioniert der sechsstellige Code im Stammverzeichnis: `/<code>`. |
| `/t/cd/<token>.gif`   | Das Bild eines [Countdown-Timers](/de/campaigns/countdown-timers/): für die aktuelle Sekunde gezeichnet, solange der Countdown läuft, und nie zwischengespeichert; nach dem Ende ein einzelnes Bild, das eine Stunde lang zwischengespeichert bleibt. Verfügbar ab der nächsten Version nach 1.6.0. |
| `/track/v1/rc.js`     | Das Skript des [Website-Trackings](/de/integrations/website-tracking/), das getrackte Websites laden. Verfügbar ab der nächsten Version nach 1.6.0. |
| `POST /p/<workspace>/track/<site>/e` | Der Sammel-Endpunkt des Trackings: bis zu 20 Ereignisse und 8 KB pro Anfrage, 240 Anfragen pro Minute je Adresse und Website. Browsern antwortet er nur vom Origin der getrackten Website aus (`OPTIONS` ist sein CORS-Preflight). Verfügbar ab der nächsten Version nach 1.6.0. |

## Prüflinks

Ausgeliefert von der Rolle web. Mitglieder erstellen diese Links im Editor; siehe
[Kommentare und Prüflinks](/de/campaigns/comments-and-review-links/).

| Pfad                                    | Wofür                                                                                                                                                                  |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/review/<token>`                       | Ein Prüflink aus dem Editor: eine Version einer Kampagne, personalisiert für einen Beispielleser. Wer den Link hat, liest die E-Mail und kommentiert ohne Anmeldung, bis der Link abläuft oder jemand ihn widerruft. Gesendet mit `noindex`. |
| `GET /api/v1/review/<token>`            | Die E-Mail und die Kommentare hinter dem Link, die die Seite liest. Kein API-Schlüssel; begrenzt je Client-Adresse.                                                    |
| `POST /api/v1/review/<token>/comments`  | Ein Kommentar über den Link, unterzeichnet mit dem Namen, den die prüfende Person angibt. Kein API-Schlüssel; begrenzt je Link.                                         |

Die Gültigkeitsdauer eines Prüflinks und das Kommentarlimit stehen unter [Grenzen und Standardwerte](/de/reference/limits-and-defaults/).

## Webhooks

Ausgeliefert von der Rolle ingest. ReputeCast zeigt die genaue URL mit ihrem Token, wenn Sie den Dienst verbinden. Ein unbekanntes Token erhält `404` und eine ungültige Signatur `401` (`400` bei Stripe).

| Pfad                                                          | Wofür                                                                                                  |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `POST /hooks/<adapter>/<token>`                               | Ereignisse von Versandanbietern. `<adapter>` ist `ses`, `postmark`, `postal`, `brevo`, `resend`, `sparkpost`, `mailjet`, `mailgun`, `sendgrid`, `azureacs`, `smtp`, `httpgeneric` oder `community:<id>`. |
| `POST /hooks/sms/<adapter>/<token>`                           | Zustellbestätigungen für SMS und eingehende SMS (`twilio`, `vonage`, `plivo`, `telnyx`, `aws_eum`).    |
| `POST /hooks/stripe/<token>`                                  | Zahlungsereignisse von Stripe.                                                                         |
| `POST /hooks/shopify/<token>`, `POST /hooks/woocommerce/<token>` | Ereignisse von Shops.                                                                               |
| `GET`, `POST /hooks/whatsapp/<workspace>/<token>`             | Der WhatsApp-Webhook von Meta: `GET` verifiziert das Abonnement, `POST` liefert Ereignisse. Seit Version 1.5.0 hat die Callback-URL jedes Kontos ein eigenes Token; das alte `/hooks/whatsapp/<workspace>` antwortet, bis Meta das neue aufruft. |
| `POST /hooks/inbound/<token>`                                 | [E-Mails empfangen](/de/providers/receiving-mail/): die E-Mails, die ein Versandanbieter für die Empfangsdomain des Arbeitsbereichs empfängt, bis zu 25 MiB pro Anfrage. Manche Anbieter hängen hinter dem Token einen eigenen Pfad an. Verfügbar ab der nächsten Version nach 1.6.0. |
| `GET`, `POST /hooks/meta-leads/<token>`                       | [Meta Lead Ads](/de/integrations/meta-lead-ads/): `GET` beantwortet die Verifizierung von Meta mit dem Verifizierungstoken der Verbindung, `POST` liefert Leads, die mit dem App-Secret signiert sind. Verfügbar ab der nächsten Version nach 1.6.0. |

[Zustellereignisse und Sperrlisten-Synchronisierung](/de/providers/events-and-sync/) erklärt, was mit den Ereignissen von Versandanbietern geschieht.
