Wer ein Newsletter-Anmeldeformular einbinden möchte, fügt zwei Zeilen HTML ein, die ein ReputeCast-Formular auf der
eigenen Website darstellen. Sie erstellen das Formular einmal, wählen, ob es in der Seite steht, sich als Pop-up öffnet
oder auf einer eigenen Seite auf ReputeCast liegt, und ReputeCast speichert den genauen Text der
[Einwilligung](/de/reference/glossary/#consent), dem jede Person zugestimmt hat.

## Bevor Sie beginnen

- Um Formulare zu erstellen, zu ändern und zu veröffentlichen, benötigen Sie die Berechtigung `forms:edit`. Inhaber,
  Admins und Bearbeiter haben sie.
- Legen Sie zuerst die Listen an, denen Personen beitreten können. Siehe
  [Listen, Einwilligung und Double-Opt-in](/de/audience/lists-and-consent/).
- Leiten Sie den Stream System an einen Versandanbieter, damit Bestätigungen für das
  [Double-Opt-in](/de/reference/glossary/#double-opt-in) hinausgehen können. Siehe
  [E-Mails über mehrere Anbieter leiten](/de/providers/routing/).
- Legen Sie Logo, Farben und Schrift im [Branding](/de/forms/branding-and-domain/) fest: Jedes Formular verwendet sie.

## Formular erstellen und veröffentlichen

Die Anmeldeseite Ihres Arbeitsbereichs auf ReputeCast funktioniert, bevor Sie ein Formular erstellen. Mit einem
eigenen Formular wählen Sie seine Felder, Listen und Art.

<Steps>

1. Öffnen Sie <UiPath path="nav.forms > forms.tabs.signupForms" /> und wählen Sie
   <UiPath path="forms.builder.newForm" />.

2. Benennen Sie das Formular, wählen Sie seine Art und wählen Sie <UiPath path="forms.builder.createForm" />:

   - Ein Formular vom Typ <UiPath path="forms.builder.kindEmbedded" /> erscheint innerhalb einer Seite Ihrer Website.
   - Ein Formular vom Typ <UiPath path="forms.builder.kindPopup" /> öffnet sich über Ihrer Website. Legen Sie mit
     <UiPath path="forms.builder.opensAfter" /> (standardmäßig 8) und <UiPath path="forms.builder.orScrolled" /> fest,
     wann, je nachdem, was zuerst eintritt. Nachdem jemand es geschlossen hat, bleibt es in diesem Browser für die
     Tage unter <UiPath path="forms.builder.closedFor" /> geschlossen (standardmäßig 14).
   - Ein Formular vom Typ <UiPath path="forms.builder.kindHosted" /> liegt auf einer eigenen Seite unter
     `/subscribe/<form-slug>` (der URL-Pfad ergibt sich aus dem Namen des Formulars), sodass Sie ohne Code von überall
     darauf verlinken können.

   Ein neues Formular beginnt mit den Feldern E-Mail und Vorname, Ihrer ersten öffentlichen Liste, Double-Opt-in sowie
   Honeypot und Zeitprüfung. Es bleibt ein Entwurf, bis Sie es veröffentlichen.

3. Wählen Sie unter <UiPath path="forms.builder.fields" />, was das Formular abfragt. E-Mail ist immer erforderlich.
   Haken Sie „Vorname“ oder „Firma“ an, oder verwenden Sie <UiPath path="forms.builder.addCustomField" /> für
   „Nachname“ und die eigenen Felder Ihres Arbeitsbereichs. Ein Formular enthält bis zu 20 Felder.

4. Haken Sie unter <UiPath path="forms.builder.lists" /> jede Liste an, die das Formular anbietet. Schalten Sie
   <UiPath path="forms.builder.pickLists" /> ein, um je Liste ein Kontrollkästchen zu zeigen; ist die Option aus, tritt
   eine Anmeldung jeder angebotenen Liste bei. Welche Listen vorausgewählt sind, legen Sie fest, indem Sie ihre
   Kästchen in der Live-Vorschau anhaken.

5. Bearbeiten Sie unter <UiPath path="forms.builder.consent" /> den <UiPath path="forms.builder.consentText" />. Das
   Wort „Datenschutzerklärung“ (in englischen Texten „privacy policy“) verlinkt auf die Adresse der
   Datenschutzerklärung aus Ihrem Branding. Jede Änderung beginnt eine neue Einwilligungsversion, und frühere
   Anmeldungen behalten den Text, dem sie zugestimmt haben. ReputeCast speichert die IP-Adresse, die Uhrzeit und den
   genauen Text als Einwilligungsnachweis.

6. Lassen Sie <UiPath path="forms.builder.doubleOptIn" /> eingeschaltet (Standard), es sei denn, Ihnen sind die
   Personen, die sich anmelden, bereits bekannt. Ist es eingeschaltet, bleiben Kontakte ausstehend, bis sie über die
   Bestätigungs-E-Mail bestätigen (siehe [Double-Opt-in-Bestätigung](#double-opt-in-bestätigung)). Ein Kontakt, der
   sich früher abgemeldet hat, muss auch bei einem Formular ohne Double-Opt-in bestätigen.

7. Wählen Sie die Prüfungen unter <UiPath path="forms.builder.spam" /> (siehe [Spamschutz](#spamschutz)).

8. Zeigen Sie unter <UiPath path="forms.builder.afterSubmit" /> die Standardmeldung („Prüfen Sie Ihren Posteingang“
   mit Double-Opt-in, „Sie sind angemeldet“ ohne) oder leiten Sie auf eine eigene Adresse weiter, etwa
   `https://acme.io/thanks`.

9. Wählen Sie unter <UiPath path="forms.builder.allowedDomains" /> für jede Website, in die das Formular eingebettet
   wird, <UiPath path="forms.builder.addDomain" />, zum Beispiel für `acme.io`. Geben Sie nur den Host ein. Subdomains
   brauchen einen eigenen Eintrag.

10. Wählen Sie <UiPath path="forms.builder.savePublish" />.

</Steps>

## Formular in Ihre Website einbetten

Wählen Sie unter <UiPath path="forms.builder.embedCode" /> die Option <UiPath path="forms.builder.copyScript" /> und
fügen Sie den Code dort in Ihre Website ein, wo das Formular erscheinen soll:

```html title="Einbettungscode"
<div data-reputecast-form="frm_8c2e1a"></div>
<script async
  src="https://news.acme.io/p/acme-newsletter/forms/frm_8c2e1a.js">
</script>
```

Das Skript wird von `/p/<workspace>/forms/<form id>.js` auf Ihrer eigenen Domain ausgeliefert oder, wenn Sie keine
haben, von der öffentlichen URL Ihres ReputeCast-Servers. Es stellt das Formular innerhalb des `<div>` mit den Schriften
Ihrer Website dar. Es lädt keinen Code von Drittanbietern, verwendet kein iframe und setzt keine Cookies; es speichert
zwei Markierungen im lokalen Speicher des Browsers, eine nach einer Anmeldung und eine, wenn jemand ein Pop-up
schließt.

- **Pop-ups:** Fügen Sie nur das `<script>`-Element ein. Das Skript öffnet ein Pop-up nur, wenn die Seite kein
  `data-reputecast-form`-Element hat; ist das `<div>` vorhanden, erscheint das Formular stattdessen in der Seite.
- **Sprache:** Das Formular folgt dem `lang`-Attribut, das dem `<div>` am nächsten ist (oder einem
  `data-reputecast-lang`-Attribut darauf). Ist das Formular in dieser Sprache nicht live, zeigt es seine Ersatzsprache.
- **Aktualisierungen:** Browser können das Skript 5 Minuten lang zwischenspeichern, daher kann es so lange dauern, bis
  eine veröffentlichte Änderung auf Ihrer Website ankommt.

### Reines HTML-Formular verwenden

Für eine Website, die keine Skripte laden kann, wählen Sie <UiPath path="forms.builder.copyHtml" />. Sie erhalten das
Formular als reines HTML in einer Sprache. Es sendet an die Seite des Formulars auf ReputeCast, die das Ergebnis zeigt:

```html title="Reines HTML-Formular"
<form action="https://news.acme.io/p/acme-newsletter/subscribe/newsletter-signup" method="post" accept-charset="utf-8" lang="en">
  <input type="hidden" name="_plain" value="1">
  <input type="hidden" name="_lang" value="en">
  <label>Email <input type="email" name="email" autocomplete="email" required></label>
  <label>First name <input type="text" name="first_name" autocomplete="given-name"></label>
  <fieldset>
    <legend>What would you like?</legend>
    <label><input type="checkbox" name="list" value="01a1637b-5a5f-75a9-9c7b-b2786b3c5968" checked> Weekly Digest</label>
    <label><input type="checkbox" name="list" value="01a1637b-5a60-7ea9-9b79-848e29771b81"> Product Updates</label>
  </fieldset>
  <label><input type="checkbox" name="consent" value="1" required> I agree to receive emails from Acme. Unsubscribe any time with one click. See the <a href="https://acme.io/privacy">privacy policy</a>.</label>
  <div style="position:absolute;left:-10000px" aria-hidden="true"><input type="text" name="website" tabindex="-1" autocomplete="off"></div>
  <button type="submit">Subscribe</button>
</form>
```

Kopieren Sie das HTML erneut, nachdem Sie Felder, Listen oder Einwilligungstext des Formulars geändert haben: Die Kopie
auf Ihrer Website aktualisiert sich nicht von selbst. Das reine Formular überspringt die Zeitprüfung, daher übernehmen
die erlaubten Domains und das Honeypot-Feld den Spamschutz.

### Die Seite auf ReputeCast verlinken

Jedes Formular hat unter <UiPath path="forms.builder.hostedPage" /> eine Seite auf ReputeCast, unter
`/p/<workspace>/subscribe/<form-slug>` oder unter `/subscribe/<form-slug>` auf Ihrer eigenen Domain. Das Formular, das
für die Anmeldeseite Ihres Arbeitsbereichs gewählt ist, antwortet unter `/subscribe`. Wie Sie ändern, welches Formular
das ist, steht unter [Anmeldeseite, Präferenzcenter und Abmeldeseite](/de/forms/public-pages/).

## Spamschutz

<UiPath path="forms.builder.spam" /> hat drei Prüfungen:

- **Honeypot-Feld und Zeitprüfung** (standardmäßig an). Ein verstecktes Feld fängt Bots ab, die jedes Eingabefeld
  ausfüllen, und eine Einsendung, die weniger als 3 Sekunden nach dem Laden des Formulars gesendet wird, wirkt
  automatisiert. Bots, die das Honeypot-Feld ausfüllen, sehen eine Erfolgsmeldung, und nichts wird gespeichert.
- **Cloudflare Turnstile** (standardmäßig aus). ReputeCast zeigt die Turnstile-Prüfung nur für Einsendungen, die
  bereits automatisiert wirken, und hält sie 30 Minuten zurück, während die Person die Prüfung abschließt. Die
  Schlüssel gelten für alle Formulare des Arbeitsbereichs: Fügen Sie den Website-Schlüssel und den geheimen Schlüssel
  aus dem Cloudflare-Dashboard ein und wählen Sie <UiPath path="forms.builder.saveKeys" />. Der geheime Schlüssel wird
  verschlüsselt gespeichert und nie wieder angezeigt.
- **Wegwerf-Domains und Rollenadressen ablehnen** (standardmäßig an). Wegwerfpostfächer und Adressen wie `info@`
  werden mit einer Meldung abgelehnt, die den Grund erklärt.

Für jedes Formular gelten Ratenlimits: 5 Einsendungen pro Minute von einer IP-Adresse über alle Formulare des
Arbeitsbereichs und 120 pro Minute je Formular. Eine IPv6-Adresse zählt nach ihrem /64-Netz, sodass ein Bot, der
Adressen darin wechselt, ein einziger Absender bleibt. Überschreitet ein Formular sein Limit je Formular, muss jede
Einsendung die Turnstile-Prüfung bestehen, bis die Flut abebbt, auch bei Formularen, die sie nicht verlangen, sofern
der Arbeitsbereich Turnstile-Schlüssel hat; ohne Schlüssel werden die zusätzlichen Einsendungen abgelehnt. Wie Sie
jede Adresse schon bei der Anmeldung mit einem Prüfdienst prüfen, steht unter
[E-Mail-Adressen prüfen](/de/audience/verification/).

## Double-Opt-in-Bestätigung

Der Button <UiPath path="pagelabels.email.button" /> der Bestätigungs-E-Mail öffnet eine Seite, die die Adresse und die
Listen nennt und noch einmal nachfragt. Erst ihr Button <UiPath path="pagelabels.confirm.ask.button" /> bestätigt.
Sicherheitsscanner für E-Mails öffnen jeden Link in einer E-Mail, daher würde ein Link, der schon beim Öffnen
bestätigt, Adressen bestätigen, die Bots eingegeben haben.

- Ein Link aus einem Formular bestätigt nur die Listen dieser Anmeldung; Listen, die auf einem anderen Formular gewählt
  wurden, warten auf den Link jenes Formulars.
- Ein Link läuft ab. Ein abgelaufener Link öffnet „Dieser Link ist abgelaufen“ mit
  <UiPath path="pagelabels.confirm.expired.button" />, das einen neuen Link sendet, wenn die Adresse noch auf die
  Bestätigung wartet.
- Jede Adresse erhält eine begrenzte Zahl von Bestätigungs-E-Mails, egal was sie sendet: Formulare, Erinnerungen, die
  Opt-in-E-Mails des Teams, Importe und Anmeldungen über Partner. Das Formular zeigt trotzdem „Prüfen Sie Ihren
  Posteingang“. Eine zweite Anmeldung für dieselben Listen innerhalb eines Tages braucht keine neue E-Mail, weil der
  erste Link sie abdeckt; jede andere zurückgehaltene E-Mail geht hinaus, sobald das Limit es erlaubt.
- Die Bestätigungs-E-Mail verwendet Ihr [Branding](/de/forms/branding-and-domain/), die Sprache des Kontakts und die
  Namen der Listen, die noch ausstehen. Die Opt-in-E-Mails, die Ihr Team aus der App sendet
  (<UiPath path="audience.contacts.addContact" />, <UiPath path="audience.contacts.resendOptin" />, auch für viele
  Kontakte auf einmal, oder die Re-Permission eines Imports), sind dieselbe E-Mail.
- Anmeldungen, die niemand bestätigt, werden nach einer Weile endgültig gelöscht; siehe
  [Aufbewahrungsdauer festlegen](/de/team/workspaces/#aufbewahrungsdauer-festlegen).

Wie lange ein Link gilt und wie viele E-Mails eine Adresse erhält, steht in der Tabelle unten.

## Standardwerte und Grenzen

<LimitsTable area="forms" />

Bestätigungs-E-Mails gehen über den Stream System hinaus. Kann noch kein Versandanbieter System-E-Mails senden, warten
Anmeldungen bis zu 3 Tage. Der Editor listet dann die Personen, die noch warten, und mit
<UiPath path="forms.builder.copyLinks" /> kann jemand mit der Berechtigung `subscribers:edit` jeder Person ihren Link
von Hand senden. Jeder kopierte Link wird protokolliert.

## Prüfen, ob es funktioniert hat

1. Öffnen Sie eine Seite Ihrer Website mit dem Formular und melden Sie sich mit einer Adresse an, deren E-Mails Sie
   lesen können.
2. Öffnen Sie die Bestätigungs-E-Mail, wählen Sie ihren Button und dann
   <UiPath path="pagelabels.confirm.ask.button" />. Die Seite, die Ihre Anmeldung bestätigt, öffnet sich.
3. Suchen Sie in ReputeCast die Adresse in der Zielgruppe: Der Kontakt ist in den Listen des Formulars, und sein
   Einwilligungsverlauf zeigt das Formular, die Einwilligungsversion und den Text. Siehe
   [Kontakte verwalten](/de/audience/contacts/).
4. Im Editor zeigen die letzten 30 Tage den Aufruf, die Einsendung und das bestätigte Opt-in.

## Fehlerbehebung

- **Das Formular zeigt „Dieses Formular kann auf dieser Website nicht verwendet werden.“** Die Website steht nicht in
  den erlaubten Domains. Fügen Sie ihren Host unter <UiPath path="forms.builder.allowedDomains" /> hinzu, speichern
  und veröffentlichen Sie. Der Editor zeigt außerdem einen Hinweis mit der Zahl der abgelehnten Einsendungen je
  Website, mit Buttons, um die Website zu erlauben, oder <UiPath path="forms.builder.keepBlocked" />.
- **Das Skript antwortet mit 404.** Das Formular ist noch ein Entwurf. Veröffentlichen Sie es.
- **Ein Pop-up erscheint innerhalb der Seite.** Die Seite enthält das Element `<div data-reputecast-form>`. Entfernen
  Sie es und behalten Sie nur das `<script>`-Element.
- **Ein Pop-up öffnet sich bei Ihnen nicht mehr.** Nachdem Sie es geschlossen haben, bleibt es für die Tage unter
  <UiPath path="forms.builder.closedFor" /> geschlossen (standardmäßig 14), und in einem Browser, in dem bereits eine
  Anmeldung erfolgt ist, öffnet es sich nie wieder. Versuchen Sie es in einem privaten Fenster.
- **Besucher sehen „Dieses Formular nimmt derzeit keine Anmeldungen an.“** Jemand hat
  <UiPath path="forms.builder.pauseSignups" /> gewählt. Setzen Sie die Anmeldungen im selben Menü fort.
- **Bestätigungs-E-Mails kommen nie an.** Für den Stream System ist kein Versandanbieter geroutet. Verbinden Sie einen
  und leiten Sie System-E-Mails an ihn: Bestätigungen, die weniger als 3 Tage gewartet haben, gehen dann hinaus. Für
  ältere Anmeldungen verwenden Sie <UiPath path="forms.builder.copyLinks" />.
- **Ein Leser hat sich zweimal angemeldet, aber nur eine Bestätigungs-E-Mail erhalten.** Jede Adresse erhält eine
  begrenzte Zahl von Bestätigungs-E-Mails (siehe [Standardwerte und Grenzen](#standardwerte-und-grenzen)). Der Link der
  ersten E-Mail funktioniert weiterhin.
- **Der Bestätigungslink eines Lesers ist laut Seite abgelaufen.** Die Person wählt auf dieser Seite
  <UiPath path="pagelabels.confirm.expired.button" />, und ein neuer Link geht an die Adresse, wenn sie noch auf die
  Bestätigung wartet.
