Jede Anleitung zeigt, wie Sie ReputeCast auf einer Hosting-Plattform bereitstellen: mit dem Release-Image
`ghcr.io/hostrepute/reputecast:v1.6.0` und PostgreSQL hinter dem HTTPS-Proxy der Plattform, vom leeren Projekt bis zur
ersten Anmeldung. Wählen Sie die Plattform, die Sie bereits nutzen; auf einem einfachen Server folgen Sie stattdessen
[Installation mit Docker Compose](/de/self-hosting/docker/) oder [Installation der Binärdatei](/de/self-hosting/binary/).

| Plattform                                   | Läuft auf                  | PostgreSQL                                   | Gut zu wissen                                                                       |
| ------------------------------------------- | -------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------- |
| [Coolify](/de/deploy/coolify/)              | Ihrem Server               | In derselben Compose-Datei (PostgreSQL 18)   | Coolify generiert den geheimen Schlüssel für Sie.                                   |
| [Dokploy](/de/deploy/dokploy/)              | Ihrem Server               | In derselben Compose-Datei (PostgreSQL 18)   | Eingefügte Compose-Datei, Domain mit Let's Encrypt.                                 |
| [Easypanel](/de/deploy/easypanel/)          | Ihrem Server               | Postgres-Service von Easypanel               | Den Port der Domain von 80 auf 8080 ändern.                                         |
| [CapRover](/de/deploy/caprover/)            | Ihrem Server               | One-Click-App PostgreSQL, Version 18         | Eine nginx-Einstellung hält Live-Updates im Fluss.                                  |
| [Railway](/de/deploy/railway/)              | Der Cloud von Railway      | PostgreSQL von Railway                       | Ein kostenpflichtiger Tarif (Hobby oder Pro) für das Volume der App.                |
| [Render](/de/deploy/render/)                | Der Cloud von Render       | Render Postgres                              | Kostenpflichtige Tarife; Free-Services schlafen ein und Free-Datenbanken laufen ab. |
| [Kubernetes](/de/deploy/kubernetes/)        | Ihrem Cluster              | CloudNativePG oder eine verwaltete Datenbank | Ein Pod mit Volume oder Pods für web, worker und ingest.                            |
| [DigitalOcean](/de/deploy/digitalocean/)    | Der Cloud von DigitalOcean | Datenbank der App Platform                   | Keine Disks: Hochgeladene Dateien landen in einem Spaces-Bucket.                    |

## Installation mit einem Klick

Das Repository enthält für fünf dieser Plattformen eine fertige Einrichtung. Jede betreibt eine ReputeCast-Instanz aus
dem Release-Image mit PostgreSQL daneben; der erste Start führt die Migrationen aus und legt den ersten Inhaber mit der
E-Mail-Adresse an, die Sie eingeben, und das temporäre Passwort steht in den Logs des Service (suchen Sie nach
`ReputeCast is installed`). Verfügbar ab der nächsten Version nach 1.6.0.

| Plattform                                | Ausgangspunkt                                                            | Was sie braucht                                                                                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Render](/de/deploy/render/)             | Der Blueprint `render.yaml` über den Link „Deploy to Render“             | Einen kostenpflichtigen Web-Service für die 10-GB-Disk und eine Datenbank in Render Postgres. Render fragt nach der öffentlichen URL und der E-Mail-Adresse. |
| [Railway](/de/deploy/railway/)           | `deploy/railway/railway.ts`, angewendet mit der Railway-CLI              | Railway Postgres und ein Volume. Die öffentliche URL folgt der Domain, die Railway generiert.                                                          |
| [DigitalOcean](/de/deploy/digitalocean/) | `.do/deploy.template.yaml` über den Link „Deploy to DigitalOcean“        | Einen Spaces-Bucket mit seinem Zugriffsschlüssel und einen geheimen Schlüssel, den Sie generieren.                                                    |
| [Coolify](/de/deploy/coolify/)           | `deploy/coolify/reputecast.yaml`, eingefügt als Docker-Compose-Ressource | Einen Coolify-Server mit Domain. Coolify generiert die URL und das PostgreSQL-Passwort.                                                                |
| [Kubernetes](/de/deploy/kubernetes/)     | Das Chart in `deploy/helm/reputecast`, installiert mit Helm              | Kubernetes 1.29 oder neuer, PostgreSQL 16–18 und einen Ingress-Controller.                                                                              |

Wenn Sie auf Ihre eigene Domain umziehen, ändern Sie die öffentliche URL, wie es die Anleitung beschreibt, und
bestätigen Sie sie dann unter <UiPath path="shell.userMenuInstanceAdmin > admin.instance" />: Die bei der ersten
Anmeldung gespeicherte Adresse hat Vorrang vor der Variable, und das Speichern dort zieht die Webhooks der Anbieter mit
um.

## Was jede Anleitung einrichtet

- **Port 8080.** Das Image liefert einfaches HTTP auf Port 8080; der Proxy der Plattform terminiert TLS und leitet
  dorthin weiter. Plattformen, die an den Port in `PORT` weiterleiten, erhalten `PORT=8080`: Das Image setzt
  `REPUTECAST_HTTP__ADDR=:8080`, das Vorrang vor `PORT` hat, daher lauscht ReputeCast in jedem Fall auf 8080.
  Prometheus-Metriken lauschen im Container auf Port 9464: Geben Sie diesem Port nie eine Domain und veröffentlichen
  Sie ihn nie.
- **Vier Einstellungen.** `REPUTECAST_DATABASE__URL` (die PostgreSQL-Verbindung), `REPUTECAST_PUBLIC_URL` (die
  `https://`-Adresse, die alle öffnen), `REPUTECAST_ADMIN_EMAIL` (der erste Inhaber) und `REPUTECAST_SECRETS__KEY`. Der
  Schlüssel ist das Base64 von 32 zufälligen Bytes (`openssl rand -base64 32`) und verschlüsselt die Zugangsdaten der
  Anbieter und andere vertrauliche Daten in der Datenbank: Speichern Sie ihn in Ihrem Passwortmanager, denn ein
  [Backup](/de/self-hosting/backups/) ist ohne ihn nutzlos.
- **Ein Volume unter `/var/lib/reputecast`**, wo die Plattform eines anbietet: Es bewahrt hochgeladene Dateien auf. Wo
  nicht, landen die Dateien in einem [S3-kompatiblen Bucket](/de/self-hosting/object-storage/).
- **Die Zustandsprüfung des Images.** Alle 15 Sekunden führt das Image `reputecast healthcheck` aus, das `/readyz` der
  App ohne Shell abfragt (das Image hat weiterhin keine Shell, kein `curl` und kein `wget`). Docker auf Coolify, Dokploy,
  Easypanel und CapRover markiert den Container als healthy, sobald ReputeCast bereit ist; Railway, Render,
  DigitalOcean und Kubernetes rufen `/readyz` selbst auf. Überwachen Sie `/readyz` auch von außen
  ([Monitoring](/de/self-hosting/monitoring/)).
- **Das temporäre Passwort des ersten Inhabers** steht beim ersten Start in den Logs der App; die
  [erste Anmeldung](/de/self-hosting/first-run/) ersetzt es.

## Vertrauenswürdige Proxys

Keine dieser Plattformen veröffentlicht die Adressen, von denen ihr Proxy aus verbindet. Mit 1.6.0 lassen die
Anleitungen `REPUTECAST_HTTP__TRUSTED_PROXIES` leer. ReputeCast sieht dann für jeden Besucher die Adresse des Proxys:
im Audit-Protokoll, in den Limits, die es je Adresse zählt, in den erlaubten IPs von API-Schlüsseln und im Bot-Filter,
der Öffnungen und Klicks sortiert. Wenn eine private Adresse immer wieder Anfragen weiterleitet, schickt ReputeCast den
Instanz-Admins eine Benachrichtigung, die sie nennt; fügen Sie sie nur hinzu, wenn es der Proxy Ihrer Plattform ist.

Die Einrichtungen mit einem Klick setzen stattdessen `REPUTECAST_HTTP__TRUSTED_PROXIES=private`. Das Schlüsselwort steht für
alle privaten (RFC 1918), gemeinsam genutzten (`100.64.0.0/10`) und Loopback-Netze, einschließlich IPv6 Unique Local
und Loopback: den Router vor ReputeCast auf diesen Plattformen, dessen Adresse Sie nicht im Voraus kennen können.
Verwenden Sie es nicht, wo Clients ReputeCast direkt aus einem privaten Netz erreichen, etwa aus einem Büro-LAN: Sie
könnten jede beliebige Adresse vorgeben. 1.6.0 kennt das Schlüsselwort nicht; es protokolliert
`ignoring invalid trusted proxy` und vertraut niemandem. Verfügbar ab der nächsten Version nach 1.6.0.

Wie Sie stattdessen Ihre eigenen Adressen festlegen, steht unter
[Reverse Proxy und TLS](/de/self-hosting/reverse-proxy/#öffentliche-url-und-vertrauenswürdige-proxys-festlegen).
