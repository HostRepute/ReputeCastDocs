Jede Anleitung zeigt, wie Sie ReputeCast auf einer Hosting-Plattform bereitstellen: mit dem Release-Image
`ghcr.io/hostrepute/reputecast:v1.4.0` und PostgreSQL hinter dem HTTPS-Proxy der Plattform, vom leeren Projekt bis zur
ersten Anmeldung. Wählen Sie die Plattform, die Sie bereits nutzen; auf einem einfachen Server folgen Sie stattdessen
[Installation mit Docker Compose](/de/self-hosting/docker/) oder [Installation der Binärdatei](/de/self-hosting/binary/).

| Plattform                           | Läuft auf               | PostgreSQL                                    | Gut zu wissen                                                    |
| ----------------------------------- | ----------------------- | --------------------------------------------- | ---------------------------------------------------------------- |
| [Coolify](/de/deploy/coolify/)      | Ihrem Server            | In derselben Compose-Datei (PostgreSQL 18)    | Coolify generiert den geheimen Schlüssel für Sie.                |
| [Dokploy](/de/deploy/dokploy/)      | Ihrem Server            | In derselben Compose-Datei (PostgreSQL 18)    | Eingefügte Compose-Datei, Domain mit Let's Encrypt.              |
| [Easypanel](/de/deploy/easypanel/)  | Ihrem Server            | Postgres-Service von Easypanel                | Den Port der Domain von 80 auf 8080 ändern.                      |
| [CapRover](/de/deploy/caprover/)    | Ihrem Server            | One-Click-App PostgreSQL, Version 18          | Eine nginx-Einstellung hält Live-Updates im Fluss.               |
| [Railway](/de/deploy/railway/)      | Der Cloud von Railway   | PostgreSQL von Railway                        | Ein kostenpflichtiger Tarif (Hobby oder Pro) für das Volume der App. |
| [Render](/de/deploy/render/)        | Der Cloud von Render    | Render Postgres                               | Kostenpflichtige Tarife; Free-Services schlafen ein und Free-Datenbanken laufen ab. |

## Was jede Anleitung einrichtet

- **Port 8080.** Das Image liefert einfaches HTTP auf Port 8080; der Proxy der Plattform terminiert TLS und leitet
  dorthin weiter. Prometheus-Metriken lauschen im Container auf Port 9464: Geben Sie diesem Port nie eine Domain und
  veröffentlichen Sie ihn nie.
- **Vier Einstellungen.** `REPUTECAST_DATABASE__URL` (die PostgreSQL-Verbindung), `REPUTECAST_PUBLIC_URL` (die
  `https://`-Adresse, die alle öffnen), `REPUTECAST_ADMIN_EMAIL` (der erste Inhaber) und `REPUTECAST_SECRETS__KEY`. Der
  Schlüssel ist das Base64 von 32 zufälligen Bytes (`openssl rand -base64 32`) und verschlüsselt die Zugangsdaten der
  Anbieter und andere vertrauliche Daten in der Datenbank: Speichern Sie ihn in Ihrem Passwortmanager, denn ein
  [Backup](/de/self-hosting/backups/) ist ohne ihn nutzlos.
- **Ein Volume unter `/var/lib/reputecast`**, wo die Plattform eines anbietet: Es bewahrt hochgeladene Dateien auf.
- **Die Zustandsprüfung des Images.** Alle 15 Sekunden führt das Image `reputecast healthcheck` aus, das `/readyz` der
  App ohne Shell abfragt (das Image hat weiterhin keine Shell, kein `curl` und kein `wget`). Docker auf Coolify, Dokploy,
  Easypanel und CapRover markiert den Container als healthy, sobald ReputeCast bereit ist; Railway und Render rufen
  `/readyz` selbst auf. Überwachen Sie `/readyz` auch von außen ([Monitoring](/de/self-hosting/monitoring/)).
- **Das temporäre Passwort des ersten Inhabers** steht beim ersten Start in den Logs der App; die
  [erste Anmeldung](/de/self-hosting/first-run/) ersetzt es.

Keine dieser Plattformen veröffentlicht die Adressen, von denen ihr Proxy aus verbindet, daher lassen die Anleitungen
`REPUTECAST_HTTP__TRUSTED_PROXIES` leer. ReputeCast sieht dann für jeden Besucher die Adresse des Proxys: im
Audit-Protokoll, in den Limits, die es je Adresse zählt, und im Bot-Filter, der Öffnungen und Klicks sortiert. Wenn eine
private Adresse immer wieder Anfragen weiterleitet, schickt ReputeCast den Instanz-Admins eine Benachrichtigung, die sie
nennt; fügen Sie sie nur hinzu, wenn es der Proxy Ihrer Plattform ist. Dokumentiert Ihre Plattform den Adressbereich
ihres Proxys später, setzen Sie ihn wie unter
[Reverse Proxy und TLS](/de/self-hosting/reverse-proxy/#öffentliche-url-und-vertrauenswürdige-proxys-festlegen)
beschrieben.
