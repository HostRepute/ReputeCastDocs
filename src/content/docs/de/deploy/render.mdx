Diese Anleitung betreibt ReputeCast auf Render als zwei Ressourcen, die Sie im Render Dashboard anlegen: eine Datenbank
in Render Postgres und einen Web-Service, der das Docker-Image von ReputeCast lädt und über HTTPS auf Ihrer eigenen
Domain ausgeliefert wird.

## Bevor Sie beginnen

- Ein Render-Konto. Nutzen Sie kostenpflichtige Compute-Tarife: Ein Free-Web-Service fährt nach 15 Minuten ohne Traffic
  herunter und kann keine Disk haben, und eine Free-Datenbank in Render Postgres läuft 30 Tage nach dem Anlegen ab.
- OpenSSL oder Docker auf Ihrem Computer, um den geheimen Schlüssel zu generieren. Siehe auch die
  [Systemanforderungen](/de/self-hosting/requirements/).
- Eine Domain für ReputeCast wie `news.example.com` bei einem DNS-Anbieter, bei dem Sie einen `CNAME`-Eintrag anlegen
  können.

## ReputeCast bereitstellen

<Steps>

1. Generieren Sie den geheimen Schlüssel und speichern Sie ihn in Ihrem Passwortmanager. Beide Befehle geben einen
   Schlüssel im selben Format aus (44 Zeichen, endet auf `=`): `openssl rand -base64 32` oder
   `docker run --rm ghcr.io/hostrepute/reputecast:v1.5.0 secrets generate-key`.

2. Klicken Sie im Render Dashboard auf **+ New** → **Postgres**. Geben Sie einen **Name** wie `reputecast-db` ein,
   wählen Sie eine **Region**, lassen Sie **PostgreSQL Version** auf 18, wählen Sie einen anderen Compute-Tarif als
   **Free** und klicken Sie auf **Create Database**. Lassen Sie **Database** und **User** leer: Render generiert sie.

3. Sobald die Datenbank den Status **Available** hat, klicken Sie oben auf ihrer Seite auf **Connect** und kopieren auf
   dem Tab **Internal** die **Internal Database URL**. Sie funktioniert nur für Services in derselben Region. Lassen Sie
   sie unverändert (ReputeCast nutzt TLS, wenn die Datenbank es anbietet), oder hängen Sie `?sslmode=require` an, um
   unverschlüsselte Verbindungen abzulehnen.

4. Klicken Sie auf **+ New** → **Web Service**. Klicken Sie unter **Source Code** auf **Existing Image**, geben Sie als
   **Image URL** `ghcr.io/hostrepute/reputecast:v1.5.0` ein und klicken Sie auf **Connect**. Das Image ist öffentlich:
   Es braucht keine Zugangsdaten.

5. Geben Sie einen **Name** wie `reputecast` ein (er wird Teil der `onrender.com`-Adresse des Service), wählen Sie die
   **Region** der Datenbank und einen anderen **Compute Plan** als **Free**.

6. Fügen Sie unter **Environment Variables** jede Zeile unten als **Key** und **Value** mit Ihren eigenen Werten hinzu:

   ```sh title="Environment Variables"
   PORT=8080
   REPUTECAST_DATABASE__URL=paste-the-internal-database-url
   REPUTECAST_PUBLIC_URL=https://news.example.com
   REPUTECAST_ADMIN_EMAIL=you@company.com
   REPUTECAST_SECRETS__KEY=paste-the-key-from-step-1
   ```

   - `PORT=8080` teilt Render mit, wo ReputeCast lauscht; der Standard von Render ist 10000. ReputeCast selbst liest
     `PORT` nicht. Es lauscht außerdem auf 9464 für Prometheus-Metriken, die privat bleiben: Render leitet nur den Port
     aus `PORT` weiter ([Port Binding](https://render.com/docs/web-services#port-binding), geprüft im November 2026).
   - `REPUTECAST_PUBLIC_URL` ist die URL Ihrer Domain, ohne abschließenden Schrägstrich. Um stattdessen die
     `onrender.com`-Adresse zu nutzen, kopieren Sie sie oben von der Seite des Service, sobald er existiert, und ändern
     die Variable.
   - `REPUTECAST_ADMIN_EMAIL` ist die E-Mail-Adresse des ersten Inhabers und wird nur genutzt, solange die Datenbank
     keine Benutzer hat. Ist `REPUTECAST_SECRETS__KEY` gesetzt, liest und schreibt ReputeCast nie eine Datei
     `secret.key`.
   - Render dokumentiert den Adressbereich nicht, von dem aus sein Load Balancer verbindet, lassen Sie
     `REPUTECAST_HTTP__TRUSTED_PROXIES` daher leer
     ([vertrauenswürdige Proxys](/de/self-hosting/docker/#vertrauenswürdige-proxys)). Weitere Einstellungen:
     [Konfiguration](/de/self-hosting/configuration/).

7. Klappen Sie unten im Formular **Advanced** auf und setzen Sie **Health Check Path** auf `/readyz`. Optional klicken
   Sie auf **Add disk**, setzen **Mount path** auf `/var/lib/reputecast` und **Size** auf 1 GB. Die Disk bewahrt die
   Dateien auf, die Sie für digitale Produkte und Lead-Magnete hochladen und die sonst bei jedem Deployment und
   Neustart verloren gehen. Mit einer Disk stoppt Render die laufende Instanz, bevor es eine neue startet (keine
   Deployments ohne Ausfallzeit), und der Service kann nicht horizontal skalieren.

8. Klicken Sie auf **Deploy Web Service**. Render lädt das Image und startet ReputeCast, das die Datenbankmigrationen
   ausführt und den ersten Inhaber anlegt. Render schickt Traffic an die neue Instanz, sobald `/readyz` mit `200`
   antwortet.

9. Öffnen Sie die Seite **Logs** des Service und suchen Sie nach `temporary`. Die passende Zeile enthält das temporäre
   Passwort des ersten Inhabers und gehört zu diesem Banner:

   ```txt title="Logs"
     ReputeCast is installed.

     Sign in at  https://news.example.com
     Email       you@company.com
     Password    SHLn-zHfR-cf6j-NEm5   (temporary: you'll replace it at first sign-in)
   ```

10. Klicken Sie auf der Seite **Settings** des Service unter **Custom Domains** auf **+ Add Custom Domain**, geben Sie
    `news.example.com` ein und klicken Sie auf **Save**. Legen Sie bei Ihrem DNS-Anbieter den `CNAME`-Eintrag an, den
    Render anzeigt (er zeigt auf den `onrender.com`-Hostnamen des Service), und entfernen Sie alle `AAAA`-Einträge für
    den Namen. Klicken Sie auf **Verify**: Render stellt das TLS-Zertifikat aus und leitet HTTP auf HTTPS um.

11. Öffnen Sie die öffentliche URL und melden Sie sich an. Bei der [ersten Anmeldung](/de/self-hosting/first-run/)
    ersetzen Sie das Passwort, fügen einen Passkey oder eine Authenticator-App hinzu, speichern
    Wiederherstellungscodes, bestätigen die Grunddaten der Instanz und legen einen Arbeitsbereich an.

</Steps>

<Aside type="caution">
  Bewahren Sie eine Kopie von `REPUTECAST_SECRETS__KEY` außerhalb von Render auf: Ohne sie lassen sich die in der
  Datenbank gespeicherten Zugangsdaten der Anbieter nicht entschlüsseln.
</Aside>

## Prüfen, ob es funktioniert hat

- Die Seite **Deploys** des Service markiert das Deployment als **Live**: Die Zustandsprüfung über `/readyz` war
  erfolgreich.
- `https://news.example.com/readyz` antwortet `ready` oder 503 mit dem Grund, etwa `database unavailable`, wenn
  ReputeCast PostgreSQL nicht erreicht. `/healthz` antwortet `ok`.
- Render ruft `/readyz` weiterhin alle paar Sekunden auf. Nach 15 Sekunden mit Fehlern schickt es keinen Traffic mehr an
  die Instanz; nach 60 Sekunden startet es sie neu ([Monitoring](/de/self-hosting/monitoring/)).

## Aktualisieren

1. Lesen Sie die Versionshinweise und erstellen Sie ein [Backup](/de/self-hosting/backups/). Kostenpflichtige Datenbanken in
   Render Postgres bieten außerdem eine Point-in-Time-Wiederherstellung.
2. Ändern Sie auf der Seite **Settings** des Service im Abschnitt **Deploy** das Tag der Image-URL, zum Beispiel auf
   `ghcr.io/hostrepute/reputecast:v1.5.0`, und speichern Sie.
3. Startet kein Deployment, klicken Sie auf **Manual Deploy** → **Deploy latest reference**: Render lädt das Image des
   jetzt gesetzten Tags. ReputeCast führt beim Start neue Migrationen aus. Mit einer Disk rechnen Sie mit einigen
   Sekunden Ausfallzeit. Das Upgrade auf 1.3.0 wandelt `delivery_events` in monatliche Partitionen um und hält
   währenddessen die Migrationssperre ([Upgrade auf 1.3.0](/de/self-hosting/upgrades/#upgrade-auf-130)).

Siehe [ReputeCast aktualisieren](/de/self-hosting/upgrades/).

## Fehlerbehebung

- **Das Deployment schlägt fehl, weil Render keinen offenen Port findet, oder die Website antwortet
  `404 page not found`**: `PORT` ist nicht `8080`, daher fand Render keinen nutzbaren Port oder leitet an einen anderen
  weiter, etwa den Metrik-Port 9464. Korrigieren Sie den Wert auf der Seite **Environment** des Service und wählen Sie
  **Save and deploy**.
- **Das Deployment geht nie live**: `/readyz` antwortet nicht mit `ready`, und nach 15 Minuten bricht Render das
  Deployment ab ([Health Checks](https://render.com/docs/health-checks), geprüft im November 2026). Lesen Sie die Logs:
  Die Migrationen laufen vielleicht noch (ein großes Upgrade wie das auf 1.3.0), oder die Worker sind nicht gestartet.
  `database unavailable` bedeutet meist, dass die Datenbank in einer anderen Region liegt, und ihre interne URL
  funktioniert nur innerhalb ihrer eigenen Region. Eine Region lässt sich nicht ändern: Legen Sie den Web-Service in der
  Region der Datenbank neu an.
- **Die Logs zeigen keine Zeile mit `temporary`**: Der Log-Explorer zeigt standardmäßig **Last hour**; wählen Sie einen
  längeren Zeitraum. Hobby-Arbeitsbereiche bewahren Logs 7 Tage lang auf. ReputeCast gibt das Banner nur beim ersten
  Start aus, solange die Datenbank keine Benutzer hat.
- **Ein SMTP-Versandanbieter kann keine Verbindung herstellen**: Render sperrt ausgehenden Port 25 für alle Services und
  die Ports 465 und 587 für Free-Web-Services. Nutzen Sie Port 587 oder 465 mit einem kostenpflichtigen Tarif oder
  einen Anbieter mit HTTPS-API. Render leitet pro Web-Service einen HTTP-Port weiter, daher kann das
  [SMTP-Relay](/de/transactional/smtp-relay/) auf Render keine Verbindungen annehmen.
