Wenn Sie von listmonk migrieren, geben Sie ReputeCast die Adresse Ihres listmonk-Servers und einen API-Benutzer und importieren dann jede listmonk-Liste in eine Liste in ReputeCast, mit den Attributen und Status ihrer Abonnenten. ReputeCast liest nur aus der API von listmonk; auf Ihrem listmonk-Server ändert sich nichts.

## Bevor Sie beginnen

- Sie brauchen die Berechtigung `subscribers:import` (Inhaber, Admin und Bearbeiter haben sie).
- Legen Sie in listmonk 4.0 oder neuer unter **Admin** › **Users** einen API-Benutzer an. API-Benutzer erhalten statt eines Passworts ein generiertes Token. Geben Sie dem Benutzer eine Rolle, die jede Liste und jeden Abonnenten lesen kann (`lists:get_all` und `subscribers:get_all`). Quellen: [listmonk, User roles and permissions](https://listmonk.app/docs/roles-and-permissions/) und [listmonk API introduction](https://listmonk.app/docs/apis/apis/) (geprüft im Oktober 2026).
- ReputeCast muss den listmonk-Server über HTTP oder HTTPS erreichen. Ein Server in einem privaten oder internen Netzwerk (etwa `10.0.0.5` oder ein `.internal`-Name, der zu einer solchen Adresse aufgelöst wird) wird abgelehnt, sofern die Instanz nicht `providers.allow_private_networks` einschaltet (siehe die [Konfigurationsreferenz](/de/reference/configuration/)).
- Lesen Sie [wie eine Migration die Einwilligung übernimmt](/de/migrate/overview/), wenn dies Ihr erster Import ist.

## Ihre listmonk-Listen importieren

<Steps>

1. Öffnen Sie <UiPath path="shell.importContacts" /> und wählen Sie **listmonk**.

2. Geben Sie unter <UiPath path="imports.serverAddress" /> die Adresse ein, unter der Sie listmonk öffnen, etwa `https://lists.example.com`, ohne Zugangsdaten, Query-String oder Fragment; ReputeCast hängt `/api` selbst an. Geben Sie den Namen des API-Benutzers unter <UiPath path="imports.apiUser" /> und sein Token unter <UiPath path="imports.apiToken" /> ein und wählen Sie dann <UiPath path="imports.connect" />.

   Der Assistent listet jede listmonk-Liste mit der Anzahl abonnierter, abgemeldeter und ausstehender Kontakte.

3. Setzen Sie Häkchen bei den Listen, die Sie importieren möchten, und wählen Sie für jede die Liste in ReputeCast, in die sie geht. Lassen Sie das Abrufen der Sperren von Ihren Versandanbietern eingeschaltet und gehen Sie dann weiter zur Feldzuordnung.

4. Ordnen Sie die Felder zu. `email` ist erforderlich; `name` geht in Vor- und Nachname, und jedes Attribut wird zu einem Feld, das nach seinem Schlüssel benannt ist.

5. Prüfen Sie im Schritt zur Einwilligung, was aus jedem Status wird (siehe nächster Abschnitt).

6. Starten Sie die Vorschau und dann den Import.

</Steps>

## Was aus listmonk umzieht

- **Listen** werden zu den Listen in ReputeCast, die Sie gewählt haben.
- **Name** wird in Vor- und Nachname aufgeteilt.
- **Attribute** (`attribs`) werden zu Kontaktfeldern. Der Assistent bietet die Attributschlüssel an, die er bei den ersten 100 Abonnenten jeder gewählten Liste findet; ein Schlüssel, der nur bei späteren Abonnenten vorkommt, wird nicht angeboten.
- **Daten:** Das Erstellungsdatum des Abonnenten wird zum Erstellungsdatum des Kontakts. listmonk hat keine Opt-in-IP, daher wird keine gespeichert.

| Status in listmonk                                      | Wird in ReputeCast                                                                                   |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `confirmed` in der Liste                                | Abonniert · bestätigt (oder ausstehend oder Überspringen)                                            |
| `unconfirmed` in einer Liste mit Single-Opt-in          | Abonniert · bestätigt (oder ausstehend oder Überspringen)                                            |
| `unconfirmed` in einer Liste mit Double-Opt-in          | Abonniert · ausstehend, mit einer Re-Permission-E-Mail (oder Überspringen)                           |
| `unsubscribed` von der Liste                            | Gesperrt · abgemeldet: kein Massenversand und keine Automationen, System-E-Mails erlaubt (fixiert)   |
| Abonnent in listmonk `blocklisted`                      | Gesperrt · abgemeldet (fixiert)                                                                      |

Eine Sperre gehört zur Adresse: Ein Abonnent, der sich von einer listmonk-Liste abgemeldet hat, erhält in keiner Liste in ReputeCast Massenversand oder Automationen.

listmonk hat keinen eigenen Status für Adressen mit Bounce, daher kommt eine Adresse, die listmonk nach Bounces auf die Blockliste gesetzt hat, als Abmeldung an, die weiterhin System-E-Mails erlaubt. Um solche Adressen in jedem Stream zu blockieren, fügen Sie sie nach dem Import mit <UiPath path="audience.suppressions.addAddress" /> der [Sperrliste](/de/audience/suppressions/) hinzu: Dort hinzugefügte Adressen erhalten in keinem Stream E-Mails.

### Was in listmonk bleibt

Kampagnen und ihre Statistiken, Vorlagen, Bounce-Einträge, Medien und Einstellungen werden nicht importiert. Bauen Sie Vorlagen im [Editor](/de/campaigns/composer/) neu auf.

## Fehlerbehebung

- **„Verwenden Sie die vollständige Adresse, etwa https://lists.example.com.“**: Der Adresse fehlt `http://` oder `https://`.
- **„Verwenden Sie nur die Adresse des Servers … ohne Zugangsdaten, Query oder Fragment.“**: Entfernen Sie `user:password@`, `?…` oder `#…` aus der Adresse.
- **„Diese Adresse liegt in einem privaten oder internen Netzwerk.“**: Der Server wird zu einer privaten, Loopback-, Link-Local- oder Metadaten-Adresse aufgelöst. Nutzen Sie seine öffentliche Adresse, oder lassen Sie den Betreiber `providers.allow_private_networks` einschalten. Die Prüfung läuft bei jeder Verbindung erneut, daher wird auch ein öffentlicher Name abgelehnt, der später zu einer privaten Adresse aufgelöst wird.
- **„listmonk leitet auf eine andere Adresse weiter (301). Geben Sie die Adresse ein, unter der die Quelle antwortet.“**: ReputeCast folgt keinen Weiterleitungen. Geben Sie die endgültige Adresse ein, oft die mit `https://`.
- **„listmonk hat den API-Schlüssel abgelehnt“**: Der API-Benutzer oder das Token ist falsch, oder die Rolle des Benutzers kann Listen und Abonnenten nicht lesen.
- **„listmonk konnte nicht erreicht werden: …“**: ReputeCast kann keine Verbindung zum Server herstellen. Prüfen Sie DNS, die Firewall und das TLS-Zertifikat.
