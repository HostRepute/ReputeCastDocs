Um Postmark-Vorlagen zu migrieren, oder die Vorlagen, die Sie in SendGrid, Mailgun oder Notifuse pflegen, verbinden Sie ReputeCast einmal mit dem Konto, wählen die Vorlagen aus und lesen einen Umwandlungsbericht, bevor irgendetwas angelegt wird. Jede Vorlage wird in [Liquid](/de/campaigns/personalization/) von ReputeCast umgeschrieben, ihre Variablen werden aus dem deklariert, was sie nutzt, und sie kommt als Entwurf an: Nichts wird veröffentlicht, und Ihre App sendet weiter die Live-Versionen, bis jemand einen Entwurf veröffentlicht.

## Bevor Sie beginnen

- Sie brauchen die Berechtigung `transactional:edit` (Inhaber, Admin und Bearbeiter haben sie). Nur Personen können einen Import ausführen, keine API-Schlüssel.
- Besorgen Sie die Zugangsdaten für Ihre Quelle. Der Schlüssel wird für diesen einen Import verschlüsselt gespeichert und verworfen, wenn er endet.

  | Quelle                  | Was Sie einfügen                                                                                                                                                                                                                                                                         |
  | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Postmark                | Ein Server API token vom Tab **API Tokens** des Servers. Quelle: [Postmark, What are the Account and Server API Tokens](https://postmarkapp.com/support/article/1008-what-are-the-account-and-server-api-tokens)                                                                         |
  | SendGrid                | Ein API-Schlüssel mit Custom Access, der Lesezugriff auf Template Engine umfasst, unter **Settings** › **API Keys**. Quelle: [SendGrid, API Keys](https://www.twilio.com/docs/sendgrid/ui/account-and-settings/api-keys)                                                                 |
  | Mailgun                 | Ein Konto-API-Schlüssel aus dem Profilmenü › **API Security**, dazu die Region Ihres Kontos (US oder EU). Quelle: [Mailgun, Where can I find my API keys](https://help.mailgun.com/hc/en-us/articles/203380100-Where-can-I-find-my-API-keys-and-SMTP-credentials)                      |
  | Notifuse                | Die Adresse Ihrer Instanz und ein API-Schlüssel des Arbeitsbereichs mit Templates read. Quelle: [Notifuse, Admins & API Keys](https://docs.notifuse.com/features/admins-api-keys)                                                                                                      |
  | MJML- oder HTML-Dateien | Bis zu 50 Dateien vom Typ `.mjml`, `.html` oder `.htm` mit je bis zu 2 MB, in UTF-8                                                                                                                                                                                                      |

  Quellen geprüft im Oktober 2026.

## Die Vorlagen importieren

<Steps>

1. Öffnen Sie <UiPath path="nav.transactional > transactional.common.importTemplates" /> und wählen Sie, wo die Vorlagen jetzt liegen.

   <Screenshot
     id="transactional"
     alt="Die Seite der Transaktionsvorlagen mit dem Button Vorlagen importieren neben Neue Vorlage oben rechts und 16 Vorlagen in der Liste darunter."
   />

2. Verbinden Sie die Quelle. Für Postmark fügen Sie das Token unter <UiPath path="transactional.import.postmarkKey" /> ein; für SendGrid fügen Sie den API-Schlüssel ein. Für Mailgun fügen Sie den Schlüssel unter <UiPath path="transactional.import.mailgunKey" /> ein und wählen die <UiPath path="transactional.import.mailgunRegion" />; füllen Sie <UiPath path="transactional.import.mailgunDomain" /> aus, um die Vorlagen einer Domain zu lesen, oder lassen Sie das Feld leer, um jede nicht deaktivierte Domain zu lesen. Für Notifuse geben Sie die <UiPath path="transactional.import.notifuseAddress" /> ein, etwa `https://notifuse.example.com`, und den API-Schlüssel. Für <UiPath path="transactional.import.files" /> ziehen Sie die Dateien hinein oder wählen sie aus: Sie werden sofort umgewandelt, und der nächste Schritt ist der Bericht.

3. Wählen Sie die Vorlagen aus. ReputeCast wählt die aktiven Vorlagen von Postmark, jede Vorlage aus SendGrid und Mailgun und die Transaktionsvorlagen von Notifuse vorab aus; setzen Sie Häkchen bei allen weiteren, die Sie möchten.

4. Wandeln Sie sie um und lesen Sie den Bericht. Jede Vorlage erhält eines der Ergebnisse in der Tabelle unten, mit der Zeile und dem Konstrukt hinter jedem Hinweis.

5. Importieren Sie sie als Entwürfe. Der Bericht zeigt die ID in ReputeCast, die jeder Entwurf erhält; öffnen Sie jeden, korrigieren Sie, was der Bericht verlangt, und veröffentlichen Sie ihn aus dem Vorlageneditor.

</Steps>

| Ergebnis                                                  | Bedeutung                                                                                                 |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| <UiPath path="transactional.import.resultConverted" />  | Nichts braucht Ihre Aufmerksamkeit.                                                                       |
| <UiPath path="transactional.import.resultNotes" />      | Ein Konstrukt wurde mit einer sichtbaren Änderung umgeschrieben, etwa `{{#each items}}` zu `{% for item in items %}`. |
| <UiPath path="transactional.import.resultManual" />     | Ein Konstrukt wurde unverändert gelassen, und der Entwurf zeigt einen Liquid-Fehler, bis Sie es ersetzen. |
| <UiPath path="transactional.import.resultFailed" />     | Die Quelle hat die Vorlage nicht geliefert; der Bericht nennt den Grund.                                  |

## Wie Vorlagen umgewandelt werden

- **IDs** stammen aus dem Alias oder Namen in der Quelle: Kleinbuchstaben, Ziffern und Bindestriche, bis zu 64 Zeichen. Ist eine ID vergeben, erhält der Entwurf `-2`, `-3` usw., und der Bericht sagt das.
- **Betreffzeilen:** Vorlagen aus Postmark, SendGrid und Notifuse behalten ihren Betreff. Mailgun behält den Betreff nur, wenn die Vorlagenversion einen Header `Subject` hat; eine Datei übernimmt ihn aus `<mj-title>` in MJML oder `<title>` in HTML, und `<mj-preview>` in MJML wird zum Vorschautext. Fehlt beides, bleibt der Betreff leer, und der Bericht bittet Sie, ihn zu schreiben.
- **Layouts:** Eine Postmark-Vorlage, die ein Layout nutzt, erhält das Layout bei `{{{ @content }}}` eingefügt.
- **Versionen:** SendGrid und Mailgun liefern die aktive Version. Eine SendGrid-Vorlage ohne aktive Version bringt ihre erste Version mit, mit einem Hinweis.
- **Variablen** werden aus dem deklariert, was jede Vorlage nutzt, mit einem Typ. Die Testdaten von SendGrid und Notifuse werden zu Beispielwerten und zum ersten Testdatensatz. Ein Variablenname, den die API nicht annimmt, etwa `first-name`, wird in der ganzen Vorlage umbenannt (`first_name`), und der Bericht sagt Ihnen, was Ihre App stattdessen senden muss.
- **Notifuse**-Vorlagen sind bereits Liquid. Kontaktfelder werden zu einfachen Variablen (`contact.first_name` wird zu `first_name`, `contact.email` zu `to.email`), und `notification_center_url` wird zu `preferences_url`. Vorlagen aus dem visuellen Editor kommen als MJML an.

Häufige Umschreibungen und manuelle Korrekturen:

| In der Quelle                                                  | In ReputeCast                                                                   |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `{{#each items}}` (Handlebars, Mustachio)                     | `{% for item in items %}`                                                       |
| Ein Abschnitt wie `{{#person}}` oder `{{#with author}}`       | `{% if person %}`; Namen darin beginnen jetzt mit `person.`                     |
| `{{{ pm:unsubscribe }}}` von Postmark, `{{{unsubscribe}}}` von SendGrid | `{{ unsubscribe_url }}`                                               |
| `<%asm_preferences_raw_url%>` von SendGrid                     | `{{ preferences_url }}`                                                         |
| `{{insert name "default=Customer"}}` von SendGrid              | `{{ name \| default: "Customer" }}`                                             |
| `%recipient.first_name%`, `%recipient_email%` von Mailgun      | `{{ first_name }}`, `{{ to.email }}`                                            |
| Ein Partial wie `{{> footer}}` oder `{% include %}` in Liquid   | Manuelle Korrektur: Vorlagen können keine anderen Dateien einbinden. Nutzen Sie einen gespeicherten Abschnitt. |
| Ein Helper oder Filter, den ReputeCast nicht hat, etwa `formatCurrency` oder `money` | Manuelle Korrektur: Ersetzen Sie ihn, zum Beispiel indem Sie den formatierten Wert in den Daten des Aufrufs senden. |
| `view_in_browser_url`                                          | Manuelle Korrektur: Transaktions-E-Mails haben keine Webversion. Entfernen Sie den Link. |
| MJML, das sich nicht kompilieren lässt, ein nie geschlossener Block | Manuelle Korrektur, mit der Zeilennummer                                   |

<Aside type="note">
Importierte Entwürfe erreichen nie von selbst jemanden. Bis ein Entwurf veröffentlicht ist, nutzt die Sende-API weiter die Live-Version der Vorlage, und eine Vorlage, die nie veröffentlicht wurde, lässt sich gar nicht senden.
</Aside>

## Prüfen, ob es funktioniert hat

Der letzte Schritt listet jeden Entwurf mit seiner ID in ReputeCast und wie viele eine manuelle Korrektur brauchen. Die Entwürfe stehen unter <UiPath path="nav.transactional > transactional.common.tabTemplates" />; öffnen Sie einen, um seine Variablen, Testdaten und jeden Liquid-Fehler zu sehen, den der Bericht erwähnt hat. Senden Sie sich aus dem Editor einen Test, bevor Sie ihn veröffentlichen.

## Fehlerbehebung

- **„Postmark antwortete mit 401: Dieses Token gehört zu einem anderen Server oder wurde widerrufen.“** (oder 403): Kopieren Sie das Token des Servers, dessen Vorlagen Sie möchten.
- **„SendGrid antwortete mit 403: Dieser Schlüssel kann keine Vorlagen lesen.“**: Bearbeiten Sie den Schlüssel in SendGrid und geben Sie ihm Lesezugriff auf Template Engine.
- **„Mailgun antwortete mit 401: Der API-Schlüssel ist falsch, oder das Konto liegt in der anderen Region.“** (oder 403): Wechseln Sie die Region oder erstellen Sie einen neuen Konto-API-Schlüssel.
- **„Dieses Mailgun-Konto hat keine Domains und daher keine Vorlagen zum Importieren.“**: Vorlagen liegen in Mailgun bei Domains; fügen Sie die Domain dort zuerst hinzu oder geben Sie die richtige Versand-Domain ein.
- **„… ist größer als 2 MB.“** oder **„Bis zu 50 Dateien gleichzeitig“**: Teilen Sie den Upload auf; jeder Upload ist ein Import.
- **„… begrenzt die Anfragen (429). Versuchen Sie es in einer Minute erneut.“**: ReputeCast hat es dreimal erneut versucht und dabei `Retry-After` des Anbieters beachtet. Warten Sie eine Minute und wandeln Sie erneut um.
- **„Dieser Import hat keinen API-Schlüssel mehr. Beginnen Sie erneut und fügen Sie den Schlüssel ein.“**: Der Import wurde abgeschlossen oder abgebrochen, wodurch der Schlüssel verworfen wird. Starten Sie einen neuen Import.
