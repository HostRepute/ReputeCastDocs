Wenn Sie von Keila migrieren, verbinden Sie ReputeCast mit einem API-Schlüssel mit einem Keila-Projekt und importieren alle seine Kontakte in eine Liste in ReputeCast, mit ihren eigenen Daten und Status. Das funktioniert mit Keila Cloud und mit einem Keila-Server, den Sie selbst betreiben. ReputeCast liest nur aus der Keila API v1; in Keila ändert sich nichts.

## Bevor Sie beginnen

- Sie brauchen die Berechtigung `subscribers:import` (Inhaber, Admin und Bearbeiter haben sie).
- Erstellen Sie in dem Projekt, das umziehen soll, einen API-Schlüssel in Keila: Wählen Sie im Menü links **API Keys**, klicken Sie auf **Create new API key**, geben Sie einen Namen ein und speichern Sie. Keila zeigt den Schlüssel einmal an. Quelle: [Keila, API authentication](https://www.keila.io/docs/api/authentication) (geprüft im Oktober 2026).
- Bei einem selbst gehosteten Keila muss ReputeCast den Server über HTTP oder HTTPS erreichen. Ein Server in einem privaten oder internen Netzwerk wird abgelehnt, sofern die Instanz nicht `providers.allow_private_networks` einschaltet (siehe die [Konfigurationsreferenz](/de/reference/configuration/)).
- Lesen Sie [wie eine Migration die Einwilligung übernimmt](/de/migrate/overview/), wenn dies Ihr erster Import ist.

## Ihre Keila-Kontakte importieren

<Steps>

1. Öffnen Sie <UiPath path="shell.importContacts" /> und wählen Sie **Keila**.

2. Prüfen Sie die <UiPath path="imports.serverAddress" />. Sie beginnt mit `https://app.keila.io` für Keila Cloud; ersetzen Sie sie durch die Adresse Ihres eigenen Servers, wenn Sie Keila selbst betreiben. Lassen Sie Zugangsdaten, Query-String und Fragment weg; ReputeCast hängt `/api/v1` selbst an.

3. Fügen Sie den Schlüssel unter <UiPath path="imports.apiKey" /> ein und wählen Sie <UiPath path="imports.connect" />. Keila hat keine Listen, daher zeigt der Assistent eine einzige Liste der Quelle, **All contacts**, mit der Anzahl der Kontakte im Projekt.

4. Wählen Sie die Liste in ReputeCast, in die die Kontakte gehen, lassen Sie das Abrufen der Sperren von Ihren Versandanbietern eingeschaltet und gehen Sie weiter zur Feldzuordnung.

5. Ordnen Sie die Felder zu. `email` ist erforderlich; `first_name` und `last_name` passen zu den Feldern in ReputeCast, und jeder Schlüssel in den eigenen Daten der Kontakte wird zu einem Feld, das nach ihm benannt ist.

6. Prüfen Sie den Schritt zur Einwilligung (siehe nächster Abschnitt), starten Sie die Vorschau und dann den Import.

</Steps>

## Was aus Keila umzieht

- **Jeder Kontakt des Projekts** geht in die eine Liste in ReputeCast, die Sie gewählt haben.
- **Vor- und Nachname** gehen in die passenden Felder.
- **Eigene Daten** (`data`) werden zu Kontaktfeldern. Der Assistent bietet die Schlüssel an, die er bei den ersten 100 Kontakten findet; ein Schlüssel, der nur bei späteren Kontakten vorkommt, wird nicht angeboten.
- **Daten:** Das Erstellungsdatum des Kontakts in Keila wird zu seinem Erstellungsdatum in ReputeCast. Die API von Keila liefert kein Opt-in-Datum und keine IP, daher kommen die Kontakte als Single-Opt-in an.

| Status in Keila | Wird in ReputeCast                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `active`        | Abonniert · bestätigt (oder ausstehend oder Überspringen)                                            |
| `unsubscribed`  | Gesperrt · abgemeldet: kein Massenversand und keine Automationen, System-E-Mails erlaubt (fixiert)   |
| `unreachable`   | Gesperrt · Hard Bounce, alle Streams (fixiert)                                                       |

### Was in Keila bleibt

Segmente aus Keila werden nicht importiert, auch wenn der Schritt zur Quelle ihre Namen auflistet: Bauen Sie sie als [Segmente in ReputeCast](/de/audience/segments/) mit den importierten eigenen Daten neu auf. Kampagnen, Vorlagen, Formulare und Absender bleiben ebenfalls in Keila.

- Die Zusammenfassung zeigt, wie viele Kontakte importiert, zusammengeführt, gesperrt, als ausstehend belassen und übersprungen wurden. <UiPath path="imports.downloadReport" /> listet jede Zeile mit dem, was mit ihr geschehen ist.

## Fehlerbehebung

- **„Keila hat den API-Schlüssel abgelehnt“**: Der Schlüssel wurde gelöscht, oder er gehört zu einem anderen Projekt oder einem anderen Keila-Server. Erstellen Sie einen Schlüssel im richtigen Projekt.
- **„Verwenden Sie die vollständige Adresse, etwa https://lists.example.com.“** oder **„Verwenden Sie nur die Adresse des Servers …“**: Geben Sie die Adresse ein, unter der Sie Keila öffnen, beginnend mit `https://` und ohne etwas nach dem Hostnamen.
- **„Diese Adresse liegt in einem privaten oder internen Netzwerk.“**: Nutzen Sie die öffentliche Adresse des Servers, oder lassen Sie den Betreiber `providers.allow_private_networks` einschalten.
- **„Keila leitet auf eine andere Adresse weiter (301). Geben Sie die Adresse ein, unter der die Quelle antwortet.“**: ReputeCast folgt keinen Weiterleitungen. Geben Sie die endgültige Adresse ein.
- **Ein Schlüssel der eigenen Daten fehlt in der Feldzuordnung**: Keiner der ersten 100 Kontakte hat ihn. Setzen Sie das Feld nach dem Import mit einem [CSV-Import](/de/audience/import/), der Kontakte über die E-Mail-Adresse zuordnet.
