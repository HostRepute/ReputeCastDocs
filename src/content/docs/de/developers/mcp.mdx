ReputeCast enthält einen Server für das [Model Context Protocol](https://modelcontextprotocol.io/) (MCP), sodass ein
KI-Assistent in Ihrem Arbeitsbereich Berichte lesen, die Versandbereitschaft prüfen, Kampagnen entwerfen oder einen
Versand pausieren kann: ein MCP-Server für E-Mail-Marketing, den Ihr Team steuern kann. Jeder
[MCP-Agent](/de/reference/glossary/#mcp-agent) erhält ein eigenes Token und eigene Berechtigungen, nie mehr als die
Person, die ihn erstellt hat, und alles, was E-Mails senden würde, geht als Vorschlag an einen Menschen, statt
ausgeführt zu werden.

## Bevor Sie beginnen

- Sie brauchen `mcp:manage` im Arbeitsbereich (eine [sensible Berechtigung](/de/reference/glossary/#sensitive-permission)).
  Sie können einem Agenten nur Berechtigungen geben, die Sie selbst haben.
- Ihre Instanz braucht eine öffentliche URL, die Ihr MCP-Client über HTTPS erreichen kann. Der Endpunkt ist
  `<public URL>/mcp` und wird von der Rolle web bereitgestellt.
- Läuft ReputeCast hinter einem Reverse Proxy, muss `/mcp` Antworten ohne Pufferung streamen. Siehe
  [Reverse Proxy und TLS](/de/self-hosting/reverse-proxy/).

## Agenten erstellen

<Steps>

1. Öffnen Sie <UiPath path="nav.settings > settings.keys" />. Die MCP-Karte oben zeigt den Endpunkt, zum Beispiel
   `https://reputecast.example.com/mcp`.

2. Wählen Sie <UiPath path="keys.addAgent" />. Geben Sie dem Agenten einen Namen, der sagt, wer ihn verwendet, etwa
   „Claude: analytics“.

3. Wählen Sie seine Berechtigungen. Beginnen Sie mit Lesezugriff, etwa `reports:view` und `deliverability:view`, und
   ergänzen Sie später mehr. Eine Berechtigung, die Sie nicht haben, ist gesperrt. Agenten können nie
   `subscribers:verify`, `placement:run`, `placement:manage`, `coupons:manage`, `comments:moderate`, `replies:view` und
   `replies:manage` haben (API-Schlüssel können das), ebenso wenig `integrations:manage`, `ai:use` oder die
   Agentur-Berechtigungen (nur Personen). Antworten, Website-Kommentare und Pools von Rabattcodes bleiben bei Personen.
   Verfügbar ab der nächsten Version nach 1.6.0.

4. Beschränken Sie den Agenten optional auf einige Listen, legen Sie ein Ablaufdatum fest und füllen Sie
   <UiPath path="keys.allowedIpsLabel" /> aus
   ([Agenten auf erlaubte IPs beschränken](#agenten-auf-erlaubte-ips-beschränken)); erstellen Sie ihn dann.

5. Kopieren Sie das Token, `rc_agent_…`. Es wird nur einmal angezeigt; ReputeCast speichert nur seinen SHA-256-Hash.

</Steps>

## MCP-Client verbinden

Der Server spricht den Transport **Streamable HTTP** von MCP. Jede Anfrage trägt das Token des Agenten als
Bearer-Token:

```http title="Anfrage-Header"
Authorization: Bearer rc_agent_…
```

ReputeCast akzeptiert hier nur Tokens von Agenten: Ein API-Schlüssel (`rc_live_…`) oder ein Sitzungscookie wird
abgewiesen. Wählen Sie unten Ihren Client. Die Beispiele lesen das Token aus der Umgebungsvariablen
`REPUTECAST_AGENT_TOKEN`; ersetzen Sie `reputecast.example.com` durch Ihre öffentliche URL.

<Tabs syncKey="mcp-client">
<TabItem label="Claude Code">

```sh title="Terminal"
claude mcp add --transport http reputecast https://reputecast.example.com/mcp \
  --header "Authorization: Bearer $REPUTECAST_AGENT_TOKEN"
```

Um den Server mit einem Projekt zu teilen, fügen Sie ihn stattdessen der Datei `.mcp.json` im Projektstamm hinzu.
Claude Code braucht `"type": "http"` bei einem Server mit `url`; ein Eintrag ohne `type` wird als lokaler Befehl
gelesen und übersprungen:

```json title=".mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Führen Sie `claude mcp get reputecast` aus, um die Verbindung zu prüfen. Quelle:
[Dokumentation zu MCP in Claude Code](https://code.claude.com/docs/en/mcp), geprüft im Oktober 2026.

</TabItem>
<TabItem label="Cursor">

Fügen Sie den Server zu `~/.cursor/mcp.json` (alle Projekte) oder `.cursor/mcp.json` (ein Projekt) hinzu:

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${env:REPUTECAST_AGENT_TOKEN}" }
    }
  }
}
```

Cursor füllt `${env:NAME}` aus Ihrer Umgebung. Quelle:
[Dokumentation zu MCP in Cursor](https://cursor.com/docs/context/mcp), geprüft im Oktober 2026.

</TabItem>
<TabItem label="VS Code">

Fügen Sie den Server zu `.vscode/mcp.json` in Ihrem Workspace hinzu. VS Code fragt einmal nach dem Token und speichert
es sicher:

```json title=".vscode/mcp.json"
{
  "inputs": [
    {
      "type": "promptString",
      "id": "reputecast-agent-token",
      "description": "ReputeCast agent token (rc_agent_…)",
      "password": true
    }
  ],
  "servers": {
    "reputecast": {
      "type": "http",
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer ${input:reputecast-agent-token}" }
    }
  }
}
```

Quelle: [Referenz zur MCP-Konfiguration in VS Code](https://code.visualstudio.com/docs/copilot/reference/mcp-configuration),
geprüft im Oktober 2026.

</TabItem>
<TabItem label="Andere Clients">

Jeder Client funktioniert, der sich per URL mit einem entfernten MCP-Server verbindet und Ihnen erlaubt, einen
Anfrage-Header festzulegen. Die meisten verwenden diese Form; prüfen Sie in der Dokumentation Ihres Clients den
Dateinamen und ob er zusätzlich `"type": "http"` braucht:

```json title="mcp.json"
{
  "mcpServers": {
    "reputecast": {
      "url": "https://reputecast.example.com/mcp",
      "headers": { "Authorization": "Bearer rc_agent_…" }
    }
  }
}
```

Ein Client, der nur lokale Server (stdio) startet, braucht eine lokale Bridge zu einem entfernten HTTP-Server;
ReputeCast liefert keine mit.

</TabItem>

## Was ein Agent tun kann

Der Server bietet 61 Tools, 3 Ressourcen und 2 Prompts. Jedes Tool prüft eine Berechtigung, genau wie ein
API-Schlüssel, und Kampagnen können über ihren Namen oder ihre ID angegeben werden. Die vollständige Liste mit der
Berechtigung und Wirkung jedes Tools steht unter [MCP-Tools, Ressourcen und Prompts](/de/reference/mcp-tools/).

- **Lesen**: Kampagnenlisten und Berichte, Versandbereitschaft, Live-Statistiken eines Versands, Anbieterzustand,
  Routing, Zustellbarkeit, Platzierungstests, ein Kontakt nach ID oder Adresse, Listen, Anmeldeformulare, Automationen
  mit den Zahlen ihres Tabs <UiPath path="automations.flow.tabStats" />, die Freigabe-Warteschlange, wiederkehrende
  Newsletter, Abstimmungen, Zuwachs, Umsatz, Angebote und Website-Inhalte.
- **Ändern**: Entwürfe für Kampagnen, SMS, Push, WhatsApp und Website-Beiträge erstellen; den Inhalt einer Kampagne
  aktualisieren; Segmente erstellen; Adressen zur Sperrliste hinzufügen; Routing-Gewichtungen ändern; Versände
  pausieren und fortsetzen; mit `share_campaign_report` ablaufende Ansichtslinks zu Berichten erstellen (erfordert
  `reports:share`).
- **Entwürfe wie im Editor**: Ein Kampagnenentwurf, den ein Agent erstellt oder ändert, wird so gespeichert, wie der
  [Editor](/de/campaigns/composer/#was-der-server-prüft) den einer Person speichert. Der Server kompiliert das MJML
  (ein MJML-Fehler wird abgewiesen), prüft es, behält Betreff und Vorschautext im MJML-Kopf und speichert jede Änderung
  als neue Version im Verlauf, markiert als von einem API-Schlüssel oder Agenten vorgenommen. Eine Änderung bricht nie
  die Freigabe oder offene Anfrage einer Person ab: Der Aufruf schlägt mit `409 approval_would_cancel` fehl.
- **Test senden**: `send_test_email` sendet einen Kampagnentest nur an Mitglieder des Arbeitsbereichs, über den
  Stream System.
- **Transaktions-E-Mails**: nur lesen. Agenten listen und rendern Vorlagen und durchsuchen das Nachrichtenprotokoll,
  senden aber nie Transaktionsnachrichten.
- **Ressourcen**: das MJML einer Kampagne, ein Bericht als CSV und die neuesten 100 Einträge des Audit-Protokolls.

`get_campaign_report` liefert den Bericht, den die App zeigt, mit demselben Code erstellt: menschliche,
datenschutzgeschützte und Scanner-Öffnungen getrennt, die messbare Öffnungsrate, Beschwerden nur dort, wo
Postfachanbieter sie melden, Links (je Variante bei einem Inhaltstest) und die A/B-Entscheidung mit ihrer Konfidenz. Ein
Agent antwortet aus diesen Zahlen, so wie [Kampagnenberichte](/de/campaigns/reports/) sie darstellen.

Die Berechtigungen eines Agenten werden bei jedem Aufruf erneut gegen die aktuelle Rolle der Person geprüft, die ihn
erstellt hat. Verliert diese Person eine Berechtigung, verliert sie auch der Agent; verlässt sie den Arbeitsbereich
oder wird sie deaktiviert, kann der Agent nichts mehr tun.

Für seine Listen gilt dieselbe Regel (seit Version 1.5.0): Bei jedem Aufruf werden sie auf die Listen und
Absenderdomains beschränkt, die die Person, die ihn erstellt hat, in diesem Moment erreicht. Ein Agent, der auf
bestimmte Listen beschränkt ist, findet mit `search_contacts` und `get_contact` nur die Kontakte auf diesen Listen, und
`resume_campaign` setzt nur eine Kampagne innerhalb seiner Listen und Absenderdomains fort, so wie es eine Person mit
derselben Beschränkung in ReputeCast kann.

## Agenten auf erlaubte IPs beschränken

Ein Agent lässt sich auf die Adressen beschränken, von denen sein Client aufruft: bis zu 50 IPv4- oder IPv6-Adressen
und -Netze, etwa `203.0.113.7` oder `203.0.113.0/24` (seit Version 1.6.0). Eine leere Liste, der Standard, erlaubt jede
Adresse.

<Steps>

1. Wählen Sie in der Matrix der Agenten in der Zeile des Agenten <UiPath path="keys.allowedIpsButton" />.

2. Geben Sie eine Adresse oder ein Netz pro Zeile ein. Das Feld zeigt, von wo das Token zuletzt verwendet wurde, und
   Ihre eigene Adresse, wie ReputeCast sie sieht, jeweils mit einem Link, um sie hinzuzufügen.

3. Speichern Sie. Lässt die Liste die Adresse weg, von der das Token zuletzt verwendet wurde, fragt ReputeCast zuerst
   nach; wählen Sie <UiPath path="keys.saveAnyway" /> nur, wenn dieser Client abgewiesen werden soll.

</Steps>

Die Prüfung läuft, nachdem das Token verifiziert ist. Ein Aufruf von einer anderen Adresse oder von einer, die
ReputeCast nicht erkennen kann, antwortet mit `401` und
`this agent can't be used from <address>; add the address to its allowed IPs in Settings › Keys & MCP` und wird
gezählt. Hinter einem Reverse Proxy tragen Sie den Proxy zuerst in `http.trusted_proxies` ein, sonst scheint jeder
Aufruf vom Proxy zu kommen; der Dialog warnt, wenn das der Fall sein kann. Damit der Agent von mehr Orten aufgerufen
werden darf, brauchen Sie jede Berechtigung des Agenten, und seine Listen müssen in Ihrem eigenen Bereich liegen, wie
beim Rotieren. Die Liste legt eine angemeldete Person fest, hier oder mit
`PUT /api/v1/workspaces/<workspace>/mcp-agents/<keyId>/allowed-ips`; die Änderung steht im Audit-Protokoll als
`agent.updated`. Es gelten dieselben Regeln wie für
[API-Schlüssel](/de/developers/api-authentication/#schlüssel-auf-erlaubte-ips-beschränken).

## Vorschläge für alles, was sendet

Agenten starten keine Versände.

- `schedule_campaign` plant nie. Es erfasst einen Vorschlag für das erste Mitglied mit `campaigns:send`, das eine
  Benachrichtigung erhält („Claude: analytics schlägt vor, Weekly Digest #142 zu planen“) mit einem Link zur Kampagne.
  Diese Person plant sie in ReputeCast, wo Versandbereitschaft und Freigaben wie gewohnt gelten. `propose_send` tut
  dasselbe für einen Entwurf für SMS, Push oder WhatsApp, zum sofortigen Senden oder zu einem angegebenen Zeitpunkt.
- Ein Aufruf, für den dem Agenten die Berechtigung fehlt, wird verweigert. Der Agent erhält einen Fehler, der die
  fehlende Berechtigung nennt, die Verweigerung wird im Audit-Protokoll erfasst, und ein Vorschlag geht an das erste
  Mitglied, das sie hat.
- Die Benachrichtigung nennt, wann der Vorschlag verfällt: standardmäßig nach 2 Stunden, 1–168 Stunden unter
  <UiPath path="keys.changeLimits" />. ReputeCast führt einen Vorschlag nie selbst aus; der Ablauf sagt der Person also,
  wie lange die Anfrage aktuell ist; danach passiert nichts.
- `pause_campaign` erfordert `campaigns:pause` und pausiert sofort. `resume_campaign` erfordert `campaigns:send` und
  setzt sofort fort: Geben Sie einem Agenten `campaigns:send` nur, wenn er einen pausierten Versand neu starten darf.

## Audit und Limits

Jeder Tool-Aufruf landet im Audit-Protokoll mit dem Agenten als Akteur, dem Namen des Tools und dem Ergebnis, auch
verweigerte Aufrufe. <UiPath path="keys.recentAgentActions" /> auf derselben Seite zeigt die letzten Aufrufe; den Rest
finden Sie im [Audit-Protokoll](/de/team/audit-log/).

<UiPath path="keys.changeLimits" /> legt die Aufrufe pro Minute je Agent und den Ablauf von Vorschlägen für den
Arbeitsbereich fest und schaltet den MCP-Server aus. Solange er aus ist, wird jedes Token eines Agenten abgewiesen. Ein
Agent über seinem Limit erhält `429` mit `Retry-After: 60`.

## Prüfen, ob es funktioniert hat

- Bitten Sie Ihren Assistenten, die Tools des Servers `reputecast` aufzulisten oder `list_campaigns` aufzurufen. Er
  sollte Ihre Kampagnen auflisten.
- Unter <UiPath path="nav.settings > settings.keys" /> erscheint der letzte Aufruf des Agenten in der Matrix der Agenten
  und unter <UiPath path="keys.recentAgentActions" />.

## Fehlerbehebung

- **401 „use an MCP agent token (rc_agent_…)“**: Der Client sendet einen API-Schlüssel oder keinen Header. Erstellen
  Sie einen Agenten und verwenden Sie sein Token.
- **401 „this agent was revoked“ oder „… expired“**: Erstellen Sie einen neuen Agenten oder rotieren Sie sein Token
  unter <UiPath path="nav.settings > settings.keys" />.
- **401 „the MCP server is off“**: Schalten Sie ihn unter <UiPath path="keys.changeLimits" /> ein.
- **401 „this agent can't be used from …“**: Der Client ruft von außerhalb der erlaubten IPs des Agenten auf. Fügen Sie
  die Adresse, die der Fehler nennt, mit <UiPath path="keys.allowedIpsButton" /> hinzu, oder tragen Sie Ihren Reverse
  Proxy in `http.trusted_proxies` ein, wenn es die Adresse des Proxys ist.
- **Der Client verbindet sich, aber jedes Tool wird verweigert**: Dem Agenten fehlt die Berechtigung, oder die Person,
  die ihn erstellt hat, hat sie nicht mehr. Der Fehler nennt die Berechtigung.
- **Der Agent findet keine Kontakte oder weniger als erwartet**: Der Agent oder das Mitglied, das ihn erstellt hat, ist
  auf bestimmte Listen beschränkt.
- **Claude Code überspringt den Server**: Der Eintrag in `.mcp.json` hat eine `url`, aber kein `"type": "http"`.
- **Aufrufe hängen oder laufen hinter einem Proxy in eine Zeitüberschreitung**: Der Proxy puffert die Antworten von
  `/mcp`. Schalten Sie die Pufferung für diesen Pfad aus.
- **Fehler 429**: Der Agent hat mehr Aufrufe gemacht, als der Arbeitsbereich pro Minute erlaubt. Erhöhen Sie das Limit
  oder verlangsamen Sie den Agenten.
