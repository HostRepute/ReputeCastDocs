Die Oberfläche von ReputeCast gibt es auf Englisch, Deutsch, Spanisch, Französisch und Vietnamesisch (Deutsch, Spanisch
und Französisch seit Version 1.4.0): die App, die Anmelde- und Einladungsseiten, die Meldungen des Servers an Mitglieder
(Fehler mit ihrer Lösung, „wer helfen kann“, Benachrichtigungen) und die E-Mails, die ReputeCast an Mitglieder sendet.
Diese Anleitung zeigt allen, die übersetzen oder entwickeln, wie sie ReputeCast übersetzen, also eine weitere Sprache
hinzufügen oder eine vervollständigen, und wie sie das Ergebnis prüfen.

Was ein Arbeitsbereich an seine Kontakte sendet (Kampagnen, Transaktions-E-Mails, öffentliche Seiten und Formulare),
übersetzt der Arbeitsbereich selbst, als Sprachversionen im Editor. Siehe
[Jedem Leser seine Sprache senden](/de/campaigns/languages/).

## Bevor Sie beginnen

- Eine lokale Kopie von ReputeCast, die aus dem Quellcode läuft
  ([ReputeCast aus dem Quellcode ausführen](/de/developers/contributing/)).
- Das Glossar Ihrer Sprache, falls es eines gibt. Das vietnamesische,
  [`docs/i18n/glossary-vi.md`](https://github.com/hostrepute/reputecast/blob/main/docs/i18n/glossary-vi.md), legt die
  Wörter für jeden Bildschirm fest; das deutsche, spanische und französische (`glossary-de.md`, `glossary-es.md`,
  `glossary-fr.md`) folgen seinen Abschnitten. Übersetzen Sie zuerst die Begriffe des Glossars, dann die Bildschirme.

<Aside type="note" title="Welche Sprachen Personen wählen können">
Release-Builds bieten nur die Sprachen an, die vollständig sind: nichts fehlt, und kein fest codierter Text ist übrig.
Seit Version 1.4.0 sind das Englisch, Deutsch, Spanisch, Französisch und Vietnamesisch. Siehe
[App-Sprache und Regionsformat ändern](/de/team/language-and-region/).
</Aside>

## Wo die Texte liegen

| Was                                        | Englische Quelle                                             | Übersetzung                            |
| ------------------------------------------ | ------------------------------------------------------------ | -------------------------------------- |
| Die Web-App                                | `web/src/**/messages.ts`, `web/src/**/<screen>.messages.ts`  | `messages.<code>.ts` neben der Quelle  |
| Server-Meldungen und E-Mails an Mitglieder | `internal/<package>/messages/en.json`                        | `internal/<package>/messages/<code>.json` |
| Die Wörter, die ReputeCast verwendet       |                                                              | `docs/i18n/glossary-<code>.md`         |

Eine Web-Quelle deklariert ihre Nachrichten mit einer ID (`namespace.key`):

```ts title="web/src/features/campaigns/messages.ts"
export const m = defineMessages('campaigns', {
  newCampaign: 'New campaign',
  blockingIssues: '{count, plural, one {# blocking issue} other {# blocking issues}}',
})
```

Ihre Übersetzung wiederholt die Schlüssel, die sie übersetzt:

```ts title="web/src/features/campaigns/messages.vi.ts"
export default translate(m, {
  newCampaign: 'Chiến dịch mới',
  blockingIssues: '{count} lỗi chặn gửi',
})
```

Eine Quelle, die mehrere Gruppen definiert (`mb`, `m`, `mp`), erhält je Gruppe ein `translate()`, zusammengeführt:
`export default { ...translate(mb, { … }), ...translate(m, { … }) }`.

Ein Server-Katalog ist ein JSON-Objekt aus `"key": "text"` oder `"key": { "message": "text", "note": "for translators" }`,
wenn das Englische eine Erklärung braucht. Lesen Sie die Hinweise: Sie sagen, was ein Argument enthält. Einige
Schlüssel entstehen aus Daten, etwa `short.<event type>` in `internal/notify/messages`. Ein neuer Ereignistyp zeigt
sein Englisch aus dem Code, bis sein Schlüssel in `en.json` ergänzt ist; ergänzen Sie ihn dort also, wenn Sie den Typ
hinzufügen.

Ein Schlüssel, der in einer Übersetzung fehlt, erscheint auf Englisch, sodass ein Bildschirm nie leer ist.

## Übersetzung schreiben

Nachrichten verwenden [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/):

- **Argumente** in geschweiften Klammern füllt die App aus: `{name}`, `{count}`, `{date}`. Schreiben Sie sie genau wie
  im Englischen und setzen Sie sie dorthin, wo Ihre Sprache sie hinstellt: Aus `edited {time} by {name}` wird
  `{name} sửa lúc {time}`.
- **Plurale**: `{count, plural, one {# day} other {# days}}`. Verwenden Sie die Pluralkategorien Ihrer Sprache (CLDR).
  Vietnamesisch hat nur `other`, daher genügt `{count} ngày`. `=1 {…}` trifft eine genaue Zahl, wenn sich der Wortlaut
  ändert.
- **Auswahlen**: `{status, select, drafts {…} sent {…} other {…}}`. Behalten Sie die Werte links (`drafts`, `sent`,
  `other`) und übersetzen Sie den Text in den Klammern.
- **Tags** markieren Text, den die App gestaltet oder verlinkt: `<b>…</b>`, `<link>…</link>`, `<mono>…</mono>`,
  `<k>…</k>`, `<kbd>…</kbd>`. Setzen Sie jedes Tag um die Wörter, die dieselbe Rolle spielen.
- Eine Nachricht ist ein ganzer Satz oder ein ganzes Label. Teilen Sie keine auf, und verlassen Sie sich nicht darauf,
  dass zwei Nachrichten in einer bestimmten Reihenfolge nebeneinander erscheinen.
- **Sprachnamen** (`{language}`, `{languages}`) kommen in der Label-Form, die Ihre Sprache für sich allein verwendet.
  Vietnamesisch schreibt „tiếng“ innerhalb eines Satzes klein, und die App tut das anhand der Stelle des Arguments;
  schreiben Sie also `{language}`, nie `tiếng {language}`.
- Ein Apostroph kann bleiben, wie er ist (`isn't`, `l'été`). Um eine geschweifte Klammer als Text zu zeigen, setzen Sie
  sie in Anführungszeichen: `'{'`.

**Nie übersetzt** werden Inhalte des Arbeitsbereichs (Namen von Kampagnen, Listen, Segmenten, Vorlagen, Formularen und
eigenen Rollen), Namen und E-Mail-Adressen von Personen, Berechtigungsschlüssel (`campaigns:send`), Namen von
Audit-Aktionen, API-Fehlercodes, Namen und Codes von Anbietern (Amazon SES, Postal, Postmark), Produktnamen
(ReputeCast, HostRepute, Gmail, Outlook), DNS-Einträge und Eintragstypen (SPF, DKIM, DMARC, BIMI, CNAME), Header
(`List-Unsubscribe`), Codebeispiele, CLI-Ausgaben und die Begriffe MCP, 2FA, TOTP, IdP, SSO, JIT, A/B, HTML, CSS, API
und Webhook.

**Zahlen, Daten und Uhrzeiten** kommen aus dem Regionsformat des Mitglieds, nie aus einer Übersetzung: Schreiben Sie
`{date}`, kein Datum. Regionsformate sind von der Sprache getrennt, sodass ein Mitglied Englisch mit vietnamesischen
Formaten lesen kann.

## Übersetzung prüfen

<Steps>

1. Führen Sie die Prüfung im Ordner `web` aus:

   ```sh title="Terminal"
   cd web
   pnpm run i18n:check              # every missing message, by file
   pnpm run i18n:check --lang vi    # one language
   pnpm run i18n:check --summary    # one line per language
   pnpm run i18n:check --hardcoded  # every hard-coded string, with its line
   ```

   Sie liest die Web-Quellen und -Übersetzungen und die Kataloge des Servers. Sie listet die Nachrichten, die jeder
   Sprache fehlen, gruppiert nach der Datei, die ihr Englisch definiert, und zählt den fest codierten Text, der in den
   Bildschirmen übrig ist (JSX-Text und einfache Strings in Attributen, die Personen lesen, etwa `title`, `label`,
   `placeholder` und `aria-label`). Ein Literal, das kein zu übersetzender Text ist, etwa ein Format, gehört in einen
   Ausdruck: `placeholder={'xxxx-xxxx-xxxx'}`.

2. Beheben Sie, was fehlschlägt. Die Prüfung schlägt fehl bei einer Nachricht, die kein gültiges ICU ist, bei einem
   übersetzten Schlüssel, den das Englische nicht hat, und bei einem Argument oder Tag, das das Englische nicht
   verwendet. Ein Server-Katalog wird außerdem beim Laden seines Pakets geprüft, sodass eine fehlerhafte Übersetzung
   den Server und jeden Go-Test sofort stoppt.

3. Committen Sie `web/src/i18n/status.gen.ts`, wenn sich die Datei ändert. Die Prüfung schreibt sie mit den Sprachen,
   die in diesem Build vollständig sind, und jeder Build führt zuerst die Prüfung aus.

4. Sehen Sie sich die Bildschirme an. Wechseln Sie Ihre eigene App-Sprache unter
   <UiPath path="shell.userMenuAccount > language.title" /> und lesen Sie die Belastungstest-Bildschirme
   (<UiPath path="nav.campaigns" />, <UiPath path="composer.reviewSend" /> und
   <UiPath path="nav.settings > settings.team" />) bei 1440 und 390 px. Lange Wörter müssen umbrechen oder kürzer
   werden, nie überlaufen oder abgeschnitten werden; der Abschnitt „Text expansion“ in `docs/dev/CONVENTIONS.md` zeigt,
   wie.

</Steps>

### Unübersetzte Texte mit der Pseudo-Locale finden

Die Pseudo-Locale <UiPath path="language.pseudoLocale" /> versieht jeden Buchstaben mit einem Akzent, macht jede
Nachricht etwa 40 % länger und setzt sie in ⟦ ⟧:
„⟦Šçĥéðûļé šéñð ţö 31,604 ŕéçîþîéñţš ·········⟧“. Text ohne die Klammern ist nicht durch das Übersetzungssystem
gelaufen; ein fehlendes ⟧ ist Text, der abgeschnitten wurde.

Sie steht in der Entwicklung in der Sprachauswahl. Auf einem Staging-Server schalten Sie sie mit `i18n.pseudo_locale`
ein (`REPUTECAST_I18N__PSEUDO_LOCALE=true`; siehe die [Konfigurationsreferenz](/de/reference/configuration/)).

## Sprache hinzufügen

<Steps>

1. Schreiben Sie zuerst das Glossar, `docs/i18n/glossary-<code>.md`, nach den Abschnitten des vietnamesischen.

2. Fügen Sie die Sprache zu `web/src/i18n/languages.ts` (`APP_LANGUAGES`, mit ihrem Namen in ihrer eigenen Sprache)
   und zu `internal/i18n/locale.go` (`appLocales`) hinzu, und wählen Sie das Regionsformat, das sie standardmäßig
   verwendet (`defaultRegionFor` in der Web-App, `DefaultRegion` auf dem Server). Pluralregeln kommen auf beiden Seiten
   aus CLDR.

3. Fehlt ihr Regionsformat, fügen Sie es zu `internal/i18n/region.go` und `web/src/i18n/regions.ts` hinzu, mit
   Testvektoren in `internal/i18n/testdata/regions.json`, die beide Seiten bestehen müssen.

4. Fügen Sie Dateien `messages.<code>.ts` für die Web-App und `messages/<code>.json` für die Server-Pakete hinzu und
   führen Sie `pnpm run i18n:check --lang <code>` aus, bis es nichts mehr auflistet.

5. Prüfen Sie die Schriften. IBM Plex deckt Lateinisch, Vietnamesisch, Kyrillisch und Griechisch ab; eine andere
   Schrift braucht ein Font-Subset in `web/src/styles/fonts.css`.

</Steps>

Eine Person mit dieser Muttersprache prüft eine Sprache, bevor sie in einem Release erscheint. ReputeCast
unterstützt noch keine Sprachen, die von rechts nach links geschrieben werden.

## Prüfen, ob es funktioniert hat

- `pnpm run i18n:check --lang <code> --summary` meldet nichts Fehlendes und keinen fest codierten Text.
- Ist Ihre Sprache unter <UiPath path="shell.userMenuAccount > language.title" /> gewählt, zeigen die übersetzten
  Bildschirme kein Englisch und nichts in ⟦ ⟧.

## Fehlerbehebung

- **Ein Bildschirm zeigt noch Englisch**: Sein Schlüssel fehlt in Ihrer Datei (die Prüfung listet ihn auf), oder der
  Text ist im Bildschirm fest codiert (`--hardcoded` listet ihn auf).
- **Der Server startet nach einer Änderung an einem `.json`-Katalog nicht**: Der Katalog enthält ungültiges ICU, einen
  unbekannten Schlüssel oder ein Argument, das das Englische nicht hat. Der Fehler nennt den Schlüssel.
- **Ihre Sprache fehlt in einem Release-Build in der Auswahl**: Sie ist noch nicht vollständig. Entwicklungs-Builds
  zeigen jede Sprache.
