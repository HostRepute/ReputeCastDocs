Die ReputeCast Ersteinrichtung macht aus dem Konto, das `reputecast install` angelegt hat, einen geschützten Inhaber
und aus der Installation eine benannte [Instanz](/de/reference/glossary/#instance) mit ihrem ersten
[Arbeitsbereich](/de/reference/glossary/#workspace). Sie umfasst sechs Schritte und dauert etwa zehn Minuten; jeder
abgeschlossene Schritt wird gespeichert, sodass Sie unterbrechen und später weitermachen können.

## Bevor Sie beginnen

- ReputeCast läuft, installiert mit [Docker Compose](/de/self-hosting/docker/) oder
  [als Binärdatei](/de/self-hosting/binary/).
- Sie haben das Installationsbanner: die E-Mail-Adresse und das temporäre Passwort (`xxxx-xxxx-xxxx-xxxx`). Mit Docker:
  `docker compose logs app | grep -A4 "ReputeCast is installed"`.
- Die öffentliche URL öffnet ReputeCast über HTTPS durch Ihren [Reverse Proxy](/de/self-hosting/reverse-proxy/).
  Passkeys und sichere Cookies brauchen HTTPS.
- Ein Smartphone oder Computer mit einem Passkey (Touch ID, Face ID, Windows Hello, ein Sicherheitsschlüssel) oder
  einer Authenticator-App.

## Instanz einrichten

<Steps>

1. Öffnen Sie die öffentliche URL. Geben Sie auf der Anmeldeseite die E-Mail-Adresse des Inhabers ein, wählen Sie
   <UiPath path="auth.signIn.continue" /> und geben Sie dann das temporäre Passwort ein.

   <Screenshot
     id="sign-in"
    alt="Die Anmeldeseite fragt zuerst nach einer geschäftlichen E-Mail-Adresse, darunter Weiter, Mit Passkey anmelden und die Buttons für Google und GitHub, unter der Karte die Sprachauswahl."
   />

   ReputeCast öffnet die Einrichtung unter `/setup`. Die Schritte links zeigen, wo Sie gerade sind.

2. **<UiPath path="setup.stepPassword" />.** Geben Sie das temporäre Passwort ein, dann zweimal Ihr neues Passwort. Es
   braucht mindestens 12 Zeichen (das Minimum der Richtlinie der Instanz; Passphrasen sind in Ordnung). Das temporäre
   Passwort funktioniert nicht mehr, sobald Sie speichern.

   <Screenshot
     id="setup-password"
     alt="Schritt 1 von 6, Temporäres Passwort ersetzen: Felder für das temporäre Passwort, das neue Passwort und seine Bestätigung, links die sechs Einrichtungsschritte."
   />

3. **<UiPath path="setup.stepSecondFactor" />.** Die Zwei-Faktor-Authentifizierung ist für den ersten Inhaber
   erforderlich und kann nicht übersprungen werden. Fügen Sie einen Passkey hinzu (empfohlen), oder richten Sie eine
   Authenticator-App ein: Scannen Sie den QR-Code und geben Sie den Code ein, den die App anzeigt. Weitere Passkeys
   können Sie später in Ihren Kontoeinstellungen hinzufügen.

4. **<UiPath path="setup.stepRecoveryCodes" />.** Erzeugen Sie die Codes und bewahren Sie sie in einem Passwortmanager
   auf oder drucken Sie sie aus. Sie erhalten 10 Codes; mit jedem können Sie sich einmal anmelden, wenn Sie Ihren
   Passkey oder Ihre Authenticator-App verlieren, und sie werden nur jetzt angezeigt.

5. **<UiPath path="setup.instanceBasics" />.** Diese Einstellungen gelten für jeden Arbeitsbereich der Instanz:

   - **Name der Instanz**, angezeigt auf der Anmeldeseite und in E-Mails an Ihr Team.
   - **Standard-Zeitzone**, mit der neue Arbeitsbereiche starten. Anfangs ist es die Zeitzone Ihres Browsers.
   - **Standardsprache** der App, für die Anmeldeseite, Einladungen und Mitglieder, die keine eigene gewählt haben.
   - **Öffentliche URL**, die Adresse für die Webhooks der Anbieter, SSO-Umleitungs-URIs, öffentliche Seiten und die
     Links in jeder E-Mail. ReputeCast prüft sie, sobald sich der Schritt öffnet, und erneut, wann immer Sie nach einer
     Korrektur darum bitten. Hat der Serverbetreiber sie festgelegt (`http.public_url_locked`), ist das Feld
     schreibgeschützt und weist darauf hin; die Prüfung läuft trotzdem.
   - <UiPath path="setup.updateCheck" />: Abgerufen wird nur die Versionsnummer. Schalten Sie die Prüfung für Server
     ohne Internetzugang ab. Steht in der Konfiguration des Servers `updates.check: false`, ist das Kontrollkästchen
     deaktiviert und lässt sich nicht aktivieren.

   Speichern Sie dann; der nächste Schritt öffnet sich.

6. **<UiPath path="setup.stepWorkspace" />.** Geben Sie ihm einen Namen (angezeigt in der Arbeitsbereichsauswahl und
   auf öffentlichen Seiten, bis Sie eine Marke festlegen) und eine Zeitzone für seine Zeitpläne und Berichte. Ein
   Arbeitsbereich hat eigene Listen, Kampagnen, Automationen, Versandanbieter und ein eigenes Team; weitere können Sie
   später anlegen.

7. **<UiPath path="setup.stepProvider" />.** Fahren Sie fort, um
   [einen Versandanbieter zu verbinden](/de/providers/connect/), oder überspringen Sie den Schritt und öffnen Sie den
   Arbeitsbereich. Die meisten Einrichtungen dauern 10–15 Minuten; Amazon SES dauert länger, wenn ReputeCast nicht auf
   AWS läuft, und ein neues AWS-Konto kann bis zu 24 Stunden auf den Produktionszugriff warten. Einladungen, das
   Zurücksetzen von Passwörtern und Benachrichtigungen per E-Mail funktionieren, sobald ein Versandanbieter den
   [Stream](/de/reference/glossary/#stream) System des Arbeitsbereichs übernimmt.

   Solange kein Versandanbieter verbunden ist, bietet die Übersicht des Arbeitsbereichs
   <UiPath path="overview.exploreDemo" /> an. Das lädt Beispieldaten von Acme in einen separaten Demo-Arbeitsbereich
   neben Ihrem und sendet nichts (siehe [Arbeitsbereiche](/de/team/workspaces/)). Es funktioniert erst, wenn die
   Einrichtung abgeschlossen ist.

</Steps>

## Die Prüfung der öffentlichen URL

Der Schritt <UiPath path="setup.instanceBasics" /> führt vom Server aus drei Prüfungen gegen die eingegebene URL aus:

| Prüfung   | Bestanden, wenn | Was eine Warnung oder ein Fehlschlag bedeutet |
| --------- | --------------- | --------------------------------------------- |
| DNS       | Der Hostname wird aufgelöst; das Ergebnis listet seine Adressen. | `… wird nicht aufgelöst`: Fügen Sie einen `A`- oder `AAAA`-Eintrag für den Host hinzu. |
| TLS       | Der Server legt ein gültiges Zertifikat vor (TLS 1.2 oder neuer); das Ergebnis zeigt Aussteller und Ablaufdatum. | Eine Warnung, wenn das Zertifikat innerhalb von 14 Tagen abläuft oder die URL ein reines `http://` ist (Passkeys, sichere Cookies und die Webhooks der meisten Anbieter brauchen HTTPS). |
| Erreichbar | `GET <public URL>/healthz` antwortet innerhalb von 6 Sekunden mit `200`. | Ein anderer Status: Der Proxy antwortet, leitet aber nicht an ReputeCast weiter. Keine Antwort: DNS, Firewall oder Proxy. |

Die Prüfungen laufen vom ReputeCast-Server selbst, daher muss der Server seine eigene öffentliche Adresse erreichen
können. Ein Bestehen bedeutet, dass dieser Weg funktioniert; Versandanbieter erreichen dieselbe Adresse aus dem
Internet.

Wenn Sie eine öffentliche URL speichern, die von `http.public_url` abweicht, wird sie innerhalb von 30 Sekunden in jedem
Prozess zur Adresse für Links, öffentliche Seiten und die Webhooks der Versandanbieter. Sitzungscookies und HSTS richten
sich weiterhin nach `http.public_url`, setzen Sie die Konfiguration daher auf dieselbe Adresse
([ReputeCast konfigurieren](/de/self-hosting/configuration/)). Mit `http.public_url_locked` behält der Schritt die
konfigurierte Adresse, und die API lehnt eine andere mit `409` und dem Code `operator_locked` ab.

## Fehlerbehebung

- **Das temporäre Passwort ist verloren**: Geben Sie auf dem Server mit
  `reputecast user reset-password --email you@company.com` einen einmaligen Link zum Zurücksetzen aus
  ([Zugriff wiederherstellen](/de/self-hosting/account-recovery/)).
- **Die Einrichtung verlangt eine erneute Anmeldung**: Ihre Sitzung ist abgelaufen. Melden Sie sich erneut an; die
  abgeschlossenen Schritte bleiben erhalten.
- **Das Hinzufügen eines Passkeys schlägt fehl**: Die Seite wird nicht über HTTPS ausgeliefert, oder der Browser hat
  keinen Passkey-Anbieter. Verwenden Sie eine Authenticator-App und fügen Sie später einen Passkey hinzu.
- **Erreichbar schlägt fehl, obwohl die Website in Ihrem Browser öffnet**: Der Server kann seine eigene öffentliche
  Adresse nicht erreichen, oft wegen einer Firewall-Regel oder eines DNS-Namens, der auf dem Server anders aufgelöst
  wird. Beheben Sie das, bevor Sie Versandanbieter verbinden, die Ereignisse an dieselbe Adresse liefern.
- **Das Banner zeigte `Sign in at http://localhost:8080`**: `http.public_url` war nicht gesetzt. Geben Sie im Schritt
  <UiPath path="setup.instanceBasics" /> die richtige Adresse ein und setzen Sie denselben Wert in der Konfiguration.
- **Das Feld für die öffentliche URL ist schreibgeschützt**: Die Konfiguration des Servers legt sie mit
  `http.public_url_locked` fest. Wer den Server betreibt, setzt `REPUTECAST_PUBLIC_URL` und startet ReputeCast neu;
  `reputecast doctor` warnt, wenn die festgelegte Adresse nur vom Server selbst erreichbar ist, etwa
  `http://localhost:8080`.

<Aside type="tip">
  Der Inhaber, den `reputecast install` anlegt, behält eine Notfallanmeldung (Passwort und Zwei-Faktor-Authentifizierung),
  auch wenn die Instanz später SSO verlangt. Jede Verwendung wird protokolliert.
</Aside>
