Das sind die ReputeCast Systemanforderungen: was ein Server braucht, um eine [Instanz](/de/reference/glossary/#instance)
mit der Binärdatei oder dem Docker-Image zu betreiben.

## Software

| Komponente      | Anforderung |
| --------------- | ----------- |
| Binärdatei      | Linux, macOS oder Windows auf `amd64` oder `arm64`. Eine einzige statische Datei (ohne cgo gebaut), die die Web-App und die Datenbankmigrationen enthält. Jedes Release liefert sie als `.tar.gz` (`.zip` für Windows) mit `checksums.txt` aus. |
| Container-Image | `ghcr.io/hostrepute/reputecast` für `linux/amd64` und `linux/arm64`. Basiert auf `gcr.io/distroless/static-debian13:nonroot`: keine Shell, läuft als Benutzer `nonroot` (UID 65532), lauscht auf Port 8080, speichert seine Daten im Volume `/var/lib/reputecast` und deklariert eine Zustandsprüfung, die `reputecast healthcheck` ausführt. |
| Datenbank       | PostgreSQL 16, 17 oder 18. Die Tests von ReputeCast laufen gegen alle drei Versionen; die mitgelieferte Compose-Datei verwendet PostgreSQL 18. Die Migrationen legen eine Extension an, `pg_trgm`, die mit PostgreSQL ausgeliefert wird ([PostgreSQL](/de/self-hosting/postgres/#verwaltetes-postgresql)). Hintergrundjobs werden in PostgreSQL eingereiht, daher ist kein weiterer Dienst nötig. |
| Laufzeit        | Nichts weiter. Node.js und Go brauchen Sie nur, um [ReputeCast aus dem Quellcode zu bauen](/de/developers/contributing/). |

## Netzwerk

| Richtung   | Was |
| ---------- | --- |
| Eingehend  | Eine öffentliche HTTPS-Adresse (`http.public_url`), die Versandanbieter erreichen können: Sie liefern Ereignisse an `<public URL>/hooks/…`, und Zapier und Make rufen dieselbe Adresse auf. Beenden Sie TLS in einem [Reverse Proxy](/de/self-hosting/reverse-proxy/). |
| Eingehend  | Port 8080 (`http.addr`) nur vom Reverse Proxy aus. Port 9464 (`metrics.addr`) nur von Prometheus aus, niemals öffentlich. Die Ports 587 und 465, wenn das [SMTP-Relay](/de/transactional/smtp-relay/) eingeschaltet ist; standardmäßig sind sie geschlossen. |
| Ausgehend  | HTTPS zu den APIs Ihrer Versandanbieter und zu jedem anderen Dienst, den Sie verbinden (Zahlungen, Shops, KI-Modelle, HostRepute). |
| Ausgehend  | DNS-Abfragen für Authentifizierungsprüfungen, Blocklisten und die MX-Einträge, die zeigen, welcher [Postfachanbieter](/de/reference/glossary/#mailbox-provider) die Domain eines Kontakts hostet (Google Workspace zählt als Gmail, Microsoft 365 als Outlook). Ohne DNS bleiben Firmendomains für Routing, Drosselung und Berichte bei „Andere“. Spamhaus lehnt Abfragen ab, die über öffentliche Resolver kommen; richten Sie `dns.servers` daher auf einen eigenen Resolver aus, wenn Sie sich auf Blocklisten-Prüfungen verlassen (siehe [Blocklisten](/de/deliverability/blocklists/)). |
| Ausgehend  | `https://api.github.com` einmal täglich für die Release-Prüfung. Schalten Sie sie mit `updates.check: false` oder unter <UiPath path="shell.userMenuInstanceAdmin > admin.instance" /> ab. |

## Speicher

| Was                                       | Wo |
| ----------------------------------------- | -- |
| PostgreSQL-Daten                          | Kontakte, Kampagnen, Ereignisse, die Job-Warteschlange und das Audit-Protokoll. Bemessen Sie die Größe nach Ihrer Kontaktzahl und Ihrem Ereignisaufkommen; [Grenzen und Standardwerte](/de/reference/limits-and-defaults/) zeigt, wie lange jede Art von Daten aufbewahrt wird. |
| Geheimer Schlüssel (`secrets.key_file`)   | `/var/lib/reputecast/secret.key` im Image, `data/secret.key` im Arbeitsverzeichnis bei der Binärdatei. Wird beim ersten Start angelegt, sofern Sie nicht `secrets.key` setzen. Ohne ihn lassen sich gespeicherte Zugangsdaten der Versandanbieter nicht entschlüsseln: [Sichern Sie ihn](/de/self-hosting/backups/). |
| Hochgeladene Dateien (`files.dir`)        | Ein Ordner `files` neben dem geheimen Schlüssel (`/var/lib/reputecast/files` im Image): digitale Produkte und Lead-Magneten. Jeder Web- und Worker-Prozess braucht denselben Ordner. |

## Hinweise

- Images von PostgreSQL 18 speichern ihre Daten in `/var/lib/postgresql`, nicht in `/var/lib/postgresql/data`; binden
  Sie das Volume dort ein.
- Das Image hat keine Shell; seine Zustandsprüfung führt die ReputeCast-Binärdatei aus. Load Balancer prüfen `/healthz`
  und `/readyz` über HTTP ([Zustandsprüfungen, Metriken und Protokolle](/de/self-hosting/monitoring/)).
- Standardmäßig führt ein Prozess alle Rollen aus. [Skalieren Sie mit den Rollen web, ingest und
  worker](/de/self-hosting/scaling/), wenn Sie mehr Durchsatz brauchen.
- [PostgreSQL](/de/self-hosting/postgres/) behandelt verwaltete Datenbanken, Verbindungspools und die Rolle, die
  SQL-Segmente brauchen.
