Registrieren Sie eine Google-OAuth-App für die Anmeldung, eine App-Registrierung bei Microsoft oder eine GitHub-OAuth-App,
fügen Sie deren Client ID und Secret in ReputeCast ein, und Personen, die bereits ein Konto haben, können sich statt
mit einem Passwort über diesen Anbieter anmelden.

<Aside type="note" title="Social Login legt nie Konten an">
  Er meldet Personen an, die eingeladen wurden oder bereits ein Konto haben. Um Konten für Ihre Organisation
  automatisch anzulegen, verwenden Sie stattdessen [Single Sign-on mit OIDC](/de/self-hosting/sso/).
</Aside>

## Bevor Sie beginnen

- Sie sind [Instanz-Admin](/de/reference/glossary/#instance-admin).
- Die öffentliche URL ist endgültig und über `https://` erreichbar
  (<UiPath path="shell.userMenuInstanceAdmin > admin.instance > admin.publicUrl" />). Die Umleitungs-URIs werden aus
  ihr gebildet.
- Sie können OAuth-Apps in der Google Cloud Console, im Microsoft Entra Admin Center oder in GitHub anlegen.

Jeder Anbieter hat seine eigene Umleitungs-URI:

<TableScroll label="Umleitungs-URIs und Scopes je Anbieter" wrap>

| Anbieter  | Umleitungs-URI                                  | Scopes, die ReputeCast anfordert                         |
| --------- | ----------------------------------------------- | -------------------------------------------------------- |
| Google    | `<public URL>/auth/social/google/callback`      | `openid email profile`                                   |
| Microsoft | `<public URL>/auth/social/microsoft/callback`   | `openid email profile`                                   |
| GitHub    | `<public URL>/auth/social/github/callback`      | `read:user user:email`, dazu `read:org` bei einer Beschränkung auf eine Organisation |

</TableScroll>

## Anbieter einrichten

<Screenshot
  id="instance-auth"
  alt="Erlaubte Anmeldemethoden in der Instanzverwaltung, Authentifizierung: Google ist an, Microsoft ist aus, GitHub ist an und auf eine Organisation beschränkt; jeder hat einen Stift-Button für seine Einstellungen."
/>

<Steps>

1. Öffnen Sie <UiPath path="shell.userMenuInstanceAdmin > admin.authentication" />. Wählen Sie unter
   <UiPath path="admin.signInMethods" /> den Stift-Button neben Google, Microsoft oder GitHub. Der Dialog zeigt die
   <UiPath path="sso.redirectUri" /> zum Kopieren.

2. Legen Sie die App beim Anbieter an:

   <Tabs syncKey="social">
   <TabItem label="Google">

   Öffnen Sie in der Google Cloud Console APIs & Services › Credentials und legen Sie eine **OAuth client ID** vom Typ
   **Web application** an. Tragen Sie die Umleitungs-URI unter **Authorized redirect URIs** ein und kopieren Sie die
   Client ID und das Secret ([Google Cloud: setting up OAuth 2.0](https://support.google.com/cloud/answer/6158849),
   geprüft im Oktober 2026).

   ReputeCast verwendet OpenID Connect mit `https://accounts.google.com` und akzeptiert nur E-Mail-Adressen, die
   Google als verifiziert kennzeichnet.

   </TabItem>
   <TabItem label="Microsoft">

   Öffnen Sie im Microsoft Entra Admin Center App registrations › **New registration**, wählen Sie die Plattform Web
   und geben Sie die Umleitungs-URI ein; legen Sie dann ein Client Secret an
   ([Anwendung in Microsoft Entra ID registrieren](https://learn.microsoft.com/entra/identity-platform/quickstart-register-app),
   geprüft im Oktober 2026). Wählen Sie die **Supported account types** passend zur Einstellung
   <UiPath path="admin.socialAccounts" /> in ReputeCast:

   - Private und Geschäftskonten (der Standard)
   - Nur Geschäfts- und Schulkonten
   - Nur private Microsoft-Konten
   - Ein Mandant (geben Sie seine Mandanten-ID ein)

   </TabItem>
   <TabItem label="GitHub">

   Öffnen Sie in GitHub Settings › Developer settings › OAuth Apps › **New OAuth App**. Geben Sie die Umleitungs-URI als
   **Authorization callback URL** ein und erzeugen Sie dann ein Client Secret
   ([GitHub: creating an OAuth app](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app),
   geprüft im Oktober 2026).

   Optional geben Sie in ReputeCast eine Organisation ein: Dann können sich nur aktive Mitglieder dieser
   GitHub-Organisation anmelden, und ReputeCast fordert zur Prüfung zusätzlich `read:org` an. Schränkt die Organisation
   OAuth-Apps ein, muss ein Inhaber der Organisation die App genehmigen. Es zählt nur die primäre, verifizierte
   E-Mail-Adresse des Kontos.

   </TabItem>
   </Tabs>

3. Fügen Sie im Dialog von ReputeCast die Client ID und das Client Secret ein und speichern Sie. Das Secret wird
   verschlüsselt und kann nur ersetzt, nie wieder ausgelesen werden.

4. Schalten Sie den Schalter des Anbieters ein und wählen Sie <UiPath path="admin.savePolicies" />. Ein Anbieter ohne
   Client ID und Secret lässt sich nicht einschalten.

</Steps>

## Wie Personen ihr Konto verknüpfen

- **Google und GitHub:** Bestätigt der Anbieter eine E-Mail-Adresse, die zu einem bestehenden Konto gehört, verknüpft
  die erste Anmeldung beides und meldet die Person an.
- **Microsoft:** Microsoft verifiziert die gesendete E-Mail-Adresse nicht, daher verknüpft ReputeCast nie anhand der
  E-Mail-Adresse. Personen verknüpfen das Konto über einen Einladungslink oder unter
  <UiPath path="shell.userMenuAccount > account.connectedSignIns" /> mit <UiPath path="account.link" />.
- **Einladungen:** Die Einladungsseite bietet die aktivierten Anbieter an; die E-Mail-Adresse beim Anbieter muss mit
  der eingeladenen Adresse übereinstimmen.
- Jede Person kann einen Anbieter unter <UiPath path="account.connectedSignIns" /> trennen, sofern es nicht ihre einzige
  Anmeldemöglichkeit ist.

Bei Domains, für die [SSO erzwungen wird](/de/self-hosting/sso/#sso-für-ihre-domains-erzwingen), ist der Social Login
für alle außer Inhabern mit Notfallzugang ausgeschaltet und schickt Personen stattdessen zum Identitätsanbieter.

## Apps für Testpostfächer wiederverwenden

[Platzierungstests](/de/deliverability/placement-tests/) können Testpostfächer bei Gmail und Microsoft 365 über
dieselben Apps von Google und Microsoft lesen, auch wenn deren Schalter für die Anmeldung aus ist. Fügen Sie eine zweite
Umleitungs-URI hinzu, `<public URL>/api/v1/placement/oauth/callback`, sowie den E-Mail-Zugriff, den die Seite für
Platzierungstests anfordert: den Scope `https://mail.google.com/` für Google, die delegierte Microsoft-Graph-Berechtigung
`Mail.ReadWrite` für Microsoft.

## Prüfen, ob es funktioniert hat

- Melden Sie sich ab. Die Anmeldeseite zeigt den Button des Anbieters unter „oder weiter mit“.
- Melden Sie sich damit an und öffnen Sie dann <UiPath path="shell.userMenuAccount > account.connectedSignIns" />: Beim
  Anbieter steht „Verknüpft als …“.

## Fehlerbehebung

- **„Kein Konto für …“**: Die Person hat kein Konto bei ReputeCast. Laden Sie sie zuerst ein; Social Login legt nie
  ein Konto an.
- **Eine Anmeldung über Microsoft findet das Konto nicht**: Verknüpfen Sie Microsoft zuerst, über die Einladung oder
  unter <UiPath path="account.connectedSignIns" />.
- **„Die Anmeldung über GitHub ist auf Mitglieder der Organisation … beschränkt.“**: Die Person ist kein aktives
  Mitglied der in ReputeCast festgelegten Organisation.
- **„… Ein Inhaber von … muss die OAuth-App von ReputeCast genehmigen.“**: Die Organisation beschränkt OAuth-Apps von
  Drittanbietern. Ein Inhaber der Organisation genehmigt die App in GitHub.
- **„Ihr GitHub-Konto hat keine verifizierte primäre E-Mail-Adresse.“**: Die Person verifiziert ihre primäre
  E-Mail-Adresse in GitHub.
- **Der Anbieter meldet eine abweichende Umleitungs-URI**: Die öffentliche URL hat sich geändert, oder die URI enthält
  einen Tippfehler. Kopieren Sie sie erneut aus dem Dialog.
