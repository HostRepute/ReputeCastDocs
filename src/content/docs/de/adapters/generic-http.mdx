Diese Seite listet jedes Feld, das Sie im generischen HTTP-Adapter für E-Mail zuordnen: das `http`-Objekt, das ReputeCast mitteilt, wie es die HTTP-API eines [Versandanbieters](/de/reference/glossary/#sending-provider) aufruft und dessen Webhooks liest, ohne dass Sie Code schreiben. Die Schritte in der App finden Sie unter [Beliebige HTTP-E-Mail-API verbinden](/de/providers/generic-http/).

Eine Zuordnung gelangt auf einem von drei Wegen zu ReputeCast:

- **Das Formular** unter <UiPath path="nav.providers > providers.tabAdapters > providers.adapters.httpTitle" />. <UiPath path="providers.adapters.saveAsAdapter" /> speichert sie als installierten Adapter vom Typ `http` für jeden Arbeitsbereich der Instanz. Es umfasst Sende-Endpunkt, Anfrage-Header, Body-Vorlage, Pfad der Nachrichten-ID, Webhook-Zuordnung und Webhook-Authentifizierung. Jedes andere Feld auf dieser Seite braucht ein Manifest.
- **Ein Manifest** vom Typ `http`, installiert von seiner `https://`-URL mit <UiPath path="nav.providers > providers.tabAdapters > providers.adapters.installFromRegistry" />. `reputecast adapter install` installiert nur [Community-Adapter](/de/adapters/community/) vom Typ `remote`.
- **Die eigenen Einstellungen eines Anbieters** (`{"http": {…}}`) für einen Anbieter, der über den integrierten Adapter `httpgeneric` verbunden ist.

Zum Speichern, Installieren und Testen einer Zuordnung braucht es einen [Instanz-Admin](/de/reference/glossary/#instance-admin) mit `providers:manage`. Arbeitsbereiche verbinden darüber dann Anbieter unter <UiPath path="nav.providers > providers.overview.addProvider" /> mit ihren eigenen Zugangsdaten.

## Manifest

Ein installierter HTTP-Adapter ist ein JSON-Manifest, dessen `http`-Objekt die Zuordnung ist.

| Feld                                          | Regeln                                                                                                                                                                                                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                                        | Erforderlich. Der Registry-Schlüssel ist `community:` plus der Name in Kleinbuchstaben und Ziffern, durch Bindestriche verbunden: Aus „Example ESP“ wird `community:example-esp`. Der Schlüssel erscheint in Webhook-URLs. Das Formular akzeptiert 2 bis 60 Zeichen. |
| `version`                                     | Erforderlich für die Installation von einer URL. Wird im Tab Adapter angezeigt. Das Formular speichert `0.1.0`.                                                                                                                                             |
| `maintainer`                                  | Wird als `community · <maintainer>` angezeigt; `unknown`, wenn leer. Das Formular speichert `local · <your name>`.                                                                                                                                          |
| `kind`                                        | `"http"`.                                                                                                                                                                                                                                                   |
| `capabilities`                                | Optionale Liste von Labels für den Tab Adapter, etwa `["webhooks"]`. Die Badges im Katalog ergeben sich aus der Zuordnung selbst.                                                                                                                           |
| `source_url`, `latest_version`, `last_release` | Optional. Eine neuere `latest_version` zeigt ein Update an. Ein `last_release` (RFC 3339), das mehr als 365 Tage zurückliegt, markiert den Adapter als „Nicht mehr gepflegt“, und er wird für neue Verbindungen nicht mehr angeboten.                   |
| `terms`                                       | `bulk` ist `allowed`, `broadcast_streams_only`, `forbidden` oder `your_policy` (Standard). `note` und `url` (die Nutzungsrichtlinie des Anbieters) werden daneben angezeigt. Bei `forbidden` oder `broadcast_streams_only` wird der Anbieter nur für die Streams Automationen und System angeboten. |
| `pricing`                                     | Optionaler Text für den Katalog, etwa „$0.80 per 1,000“. Standard: „von Ihrem Anbieter festgelegt“.                                                                                                                                                         |
| `http`                                        | Die Zuordnung: alle Felder unten.                                                                                                                                                                                                                           |

ReputeCast kann die Bedingungen eines zugeordneten Anbieters nicht lesen, daher fordert Sie der Routing-Bildschirm ohne `terms` auf, die Nutzungsrichtlinie des Anbieters zu prüfen, bevor Sie Massenversand darüber leiten. Ein Manifest, das von einer URL installiert wird, muss unter einer öffentlichen `https://`-Adresse liegen und darf höchstens 256 KiB groß sein.

Die Texte des Manifests (`name`, `terms.note`, `pricing` sowie `label` und `help` seiner `fields`) erscheinen so, wie Sie sie
geschrieben haben, in jeder Sprache. Ohne `terms.note` oder `pricing` erscheinen stattdessen die eigenen Formulierungen von
ReputeCast, in der Sprache der jeweiligen Person, wie alles andere, was ReputeCast über die Zuordnung sagt.

## Sendeanfrage

| Feld                 | Regeln                                                                                                                                                                                                                                                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `method`             | `POST` (Standard), `PUT` oder `PATCH`.                                                                                                                                                                                                                                                                          |
| `url`                | Eine `https://`-URL. Schreiben Sie den Host aus; Vorlagenfelder dürfen nur in Pfad und Query stehen. Kein `#fragment`. Ein Manifest darf `http://` für einen Loopback-Testserver verwenden (`localhost`, `127.0.0.1`), den die Instanz nur mit `providers.allow_private_networks` erreicht. Das Formular akzeptiert nur `https://`. |
| `headers`            | Header-Name → Wertvorlage, etwa `"Authorization": "Bearer {{ secrets.api_key }}"`. `Content-Type` ist standardmäßig `application/json`. `Host`, `Content-Length`, `Transfer-Encoding` und `Connection` lassen sich nicht setzen. Das Formular akzeptiert bis zu 20 Header.                                    |
| `body`               | Erforderlich. Die Vorlage für den JSON-Body. Sie muss gültiges JSON ergeben, sobald ihre Felder ausgefüllt sind: Beim Speichern wird sie gegen eine Beispielnachricht geprüft, und eine Nachricht, deren Body sich nicht zu JSON rendern lässt, wird mit dem Code `Template` abgelehnt. Das Formular akzeptiert bis zu 20.000 Zeichen. |
| `message_id_path`    | Pfad der Nachrichten-ID des Anbieters in einem 2xx-Antwort-Body, etwa `$.data.id`.                                                                                                                                                                                                                              |
| `message_id_header`  | Ein Antwort-Header, der stattdessen die Nachrichten-ID trägt. Verwenden Sie eines von beiden, nicht beide. Spitze Klammern um die ID werden entfernt. Ohne beides tritt die Nachrichten-ID von ReputeCast an ihre Stelle.                                                                                      |
| `error_code_path`    | Pfad des Fehlercodes des Anbieters in einer fehlgeschlagenen Antwort.                                                                                                                                                                                                                                           |
| `error_message_path` | Pfad der Fehlermeldung des Anbieters. Ohne diese beiden Pfade ist der Antwort-Body die Fehlermeldung.                                                                                                                                                                                                          |
| `check.url`          | Optionaler `GET`, der mit 2xx antwortet, solange die Zugangsdaten gültig sind. ReputeCast ruft ihn auf, wenn ein Anbieter verbunden wird, und aus der Zustandsprüfung der Anbieter. Ohne ihn ergibt sich der Zustand allein aus den Sendeergebnissen.                                                        |
| `check.headers`      | Header der Prüfanfrage. Standard: die Header der Sendeanfrage.                                                                                                                                                                                                                                                  |
| `fields`             | Zusätzliche Verbindungsfelder: `key`, `label`, `secret`, `required`, `options`, `help`. Vorlagen lesen ein geheimes Feld als `secrets.<key>` und jedes andere Feld als `settings.<key>`.                                                                                                                       |

Das Verbindungsformular hat immer zwei optionale geheime Felder: **API-Schlüssel** (`secrets.api_key`) und **Signaturschlüssel für Webhooks** (`secrets.webhook_signing_key`). Geheime Werte sind nicht auslesbar: Sie werden versiegelt gespeichert und nie zurückgegeben.

ReputeCast sendet eine Anfrage pro Nachricht und wertet die Antwort so aus:

| Antwort         | Was ReputeCast tut                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 2xx             | Angenommen. Die Nachrichten-ID kommt aus `message_id_path` oder `message_id_header`.                                     |
| 401, 403        | Die Zugangsdaten wurden abgelehnt: Der Versand schlägt fehl, und der Zustand des Anbieters meldet es.                    |
| 429             | Gedrosselt: Diese Nachricht wird später erneut versucht.                                                                 |
| 408, 5xx        | Ein Ausfall des Anbieters: siehe [Zustand und Ausfälle von Anbietern](/de/providers/health-and-outages/).                |
| Jedes andere 4xx | Diese Nachricht ist endgültig fehlgeschlagen, mit dem Code und der Meldung, die die Fehlerpfade lesen.                  |

## Vorlagenfelder

Vorlagen verwenden nur Ausgabe-Tags im Liquid-Stil: `{{ name }}`, optional mit Filtern. Es gibt keine `{% %}`-Tags; eine Zuordnung beschreibt eine feste Anfrage.

| Feld                                                 | Wert                                                                                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `sender`                                             | From als `"Name" <address>` oder nur die Adresse, wenn es keinen Namen gibt.                                                |
| `sender_email`, `sender_name`                        | Adresse und Name von From.                                                                                                  |
| `recipient`, `recipient_name`, `recipient_formatted` | Adresse, Name und `"Name" <address>` von To.                                                                                |
| `reply_to`, `reply_to_name`                          | Adresse und Name von Reply-To, leer, wenn es keine gibt.                                                                    |
| `subject`, `html`, `text`                            | Die gerenderte, personalisierte Nachricht.                                                                                  |
| `headers`, `headers_json`                            | Die Header der Nachricht als Objekt: `List-Unsubscribe`, `List-Unsubscribe-Post` und die anderen, die ReputeCast setzt, dazu `X-ReputeCast-Message`. |
| `headers_list`                                       | Dieselben Header als `[{"name": …, "value": …}]`, nach Name sortiert.                                                       |
| `tags`                                               | Die Tags der Nachricht als Objekt.                                                                                          |
| `message_id`                                         | Die Nachrichten-ID von ReputeCast. Senden Sie sie an den Anbieter, damit seine Webhooks sie zurückgeben können.             |
| `stream`                                             | `broadcast`, `automation` oder `system`.                                                                                    |
| `settings.<key>`, `secrets.<key>`                    | Die Einstellungen und Zugangsdaten des verbundenen Anbieters.                                                               |

Senden Sie jeden Header aus `headers_json` oder `headers_list` mit: Postfachanbieter verlangen die Header für die [Abmeldung mit einem Klick](/de/deliverability/one-click-unsubscribe/). Schalten Sie das eigene Öffnungs- und Klick-Tracking des Anbieters im Body ab, wenn seine API das erlaubt, denn ReputeCast trackt Öffnungen und Klicks selbst.

### Filter

Schreiben Sie einen Filter nach einem senkrechten Strich: `{{ settings.region | default: 'eu' }}`. Filter laufen von links nach rechts, und ein Argument ist ein String in Anführungszeichen (`'…'` oder `"…"`) oder ein Feldname.

| Filter          | Argument | Ergebnis                                                                                       |
| --------------- | -------- | ---------------------------------------------------------------------------------------------- |
| `default`       | 1        | Das Argument, wenn der Wert fehlt oder ein leerer String, ein leeres Objekt oder eine leere Liste ist. |
| `prepend`       | 1        | Das Argument, dann der Wert.                                                                   |
| `append`        | 1        | Der Wert, dann das Argument.                                                                   |
| `base64_encode` | keins    | Standard-Base64.                                                                               |
| `url_encode`    | keins    | URL-Query-Kodierung.                                                                           |
| `downcase`      | keins    | Kleinbuchstaben.                                                                               |
| `upcase`        | keins    | Großbuchstaben.                                                                                |
| `strip`         | keins    | Führende und nachgestellte Leerzeichen entfernt.                                               |
| `json`          | keins    | Der Wert als JSON-Text kodiert.                                                                |

Jeder andere Filter wird beim Speichern abgelehnt. Dieser Header baut aus dem API-Schlüssel einen Basic-Auth-Wert:

```json title="Basic-Auth-Header"
"Authorization": "Basic {{ 'api:' | append: secrets.api_key | base64_encode }}"
```

### Maskierung

Werte werden passend zu ihrer Position maskiert, sodass die Daten die Anfrage nicht beschädigen können:

- **In einem JSON-String** (`"subject": "{{ subject }}"`) wird der Wert JSON-maskiert.
- **Außerhalb eines Strings** (`"headers": {{ headers_json }}`) wird der Wert JSON-kodiert: Objekte bleiben Objekte, und ein fehlender Wert wird zu `null`.
- **In der URL** werden Werte für den Pfad maskiert, nach `?` für die Query.
- **In Headern** werden Zeilenumbrüche zu Leerzeichen.

Um ein wörtliches `{{` in einem JSON-String zu senden (die eigenen Platzhalter einer API), schreiben Sie `\{{`: `"Hi \{{first_name}}"` sendet `"Hi {{first_name}}"`. `{{ '{{' }}` bewirkt dasselbe an jeder Stelle.

<UiPath path="providers.adapters.testSample" /> rendert die Anfrage für eine Beispielnachricht (von Acme Newsletter an Linh Nguyen) und zeigt jeden geheimen Wert als `••••`. Es wird nichts gesendet.

## Pfadsyntax

Die Felder `*_path` verwenden eine Teilmenge von JSONPath:

| Syntax                         | Wählt aus                              |
| ------------------------------ | -------------------------------------- |
| `$`                            | Die Wurzel.                            |
| `.name`, `['name']`, `["name"]` | Ein Objektfeld.                       |
| `[0]`                          | Ein Array-Element (ab 0).              |
| `[*]`, `.*`                    | Jedes Element eines Arrays oder Objekts. |

Filter (`[?(…)]`), rekursiver Abstieg (`..`), Slices und negative Indizes werden beim Speichern abgelehnt. Wählt ein Pfad mehrere Werte aus, wird der erste verwendet, außer bei `events_path`. Zahlen werden exakt gelesen, sodass Anbieter-IDs über 2^53 jede Ziffer behalten.

## Webhook-Authentifizierung

`webhook.auth` legt fest, wie eine Webhook-Anfrage nachweist, dass sie vom Anbieter stammt. Das Formular bietet dieselben fünf Modi unter <UiPath path="providers.adapters.webhookAuth" />.

| `auth`           | Die Anfrage wird angenommen, wenn                                                                                                                                                                                                                                                                                                                                                             |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hmac` (Standard) | `signature_header` (Standard `X-Signature`) den HMAC von `signed_payload` enthält, gebildet mit dem geheimen Schlüssel. `signed_payload` verwendet `{body}` und `{timestamp}`; Standard ist `{body}`, oder `{timestamp}.{body}`, wenn `timestamp_header` gesetzt ist. `algorithm` ist `sha256` (Standard), `sha1` oder `sha512`. `encoding` ist `hex` (Standard) oder `base64`. `signature_prefix` (etwa `sha256=`) wird zuerst entfernt. Der Header darf mehrere Signaturen enthalten, getrennt durch Kommas oder Leerzeichen; ein Treffer genügt. |
| `standard`       | die Anfrage eine gültige Signatur nach [Standard Webhooks](https://www.standardwebhooks.com/) trägt (`webhook-id`, `webhook-timestamp`, `webhook-signature` oder die `svix-`-Header), erstellt mit einem `whsec_`-Schlüssel.                                                                                                                                                                  |
| `basic`          | ihr Basic-Auth-Benutzer `username` ist (Standard `reputecast`) und ihr Passwort der geheime Schlüssel.                                                                                                                                                                                                                                                                                        |
| `header`         | `token_header` den geheimen Schlüssel unverändert enthält. ReputeCast speichert diesen Header nie mit dem Rohereignis.                                                                                                                                                                                                                                                                         |
| `none`           | sie an die Webhook-URL geht, die nicht zu erraten ist; mehr wird nicht geprüft. Verwenden Sie diesen Modus nur, wenn der Anbieter keine der obigen Möglichkeiten bietet.                                                                                                                                                                                                                      |

Bei `hmac` mit `timestamp_header` oder bei `standard` wird ein Zeitstempel (Unix-Sekunden oder -Millisekunden), der mehr als fünf Minuten in der Vergangenheit oder Zukunft liegt, als Replay abgelehnt.

Der geheime Schlüssel ist die Vorlage `secret`, wenn sie gesetzt ist (sie kann `secrets.<key>` und `settings.<key>` lesen). Andernfalls ist es der **Signaturschlüssel für Webhooks** der Verbindung und andernfalls der Webhook-Schlüssel, den ReputeCast für den Anbieter erzeugt hat. Gibt es gar keinen Schlüssel, wird jede Anfrage abgelehnt.

Richten Sie den Webhook des Anbieters auf die URL auf der Karte des Anbieters: `<public URL>/hooks/community:<name>/<token>` für einen Anbieter, der über einen installierten HTTP-Adapter verbunden ist, sonst `<public URL>/hooks/httpgeneric/<token>`. Webhook-Bodys sind auf 5 MiB begrenzt.

## Webhook-Payloads

`webhook_mapping` legt fest, wie Ereignisse gelesen werden: `status` (Standard) oder `jsonpath`. Im Formular bietet <UiPath path="providers.adapters.webhookMapping" /> `status → delivered | bounced | complained` und <UiPath path="providers.adapters.mappingJsonpath" /> an.

Eine Zuordnung ganz ohne Webhook-Felder (`webhook_mapping`, `webhook.auth`, `webhook.signature_header`, `webhook.type_path`, `webhook.types`) hat keine Webhooks: Der Anbieter sendet, meldet aber keine Zustellungen, Bounces oder Beschwerden.

| Feld                         | Liest                                                   | Standard bei `status`          |
| ---------------------------- | ------------------------------------------------------- | ------------------------------ |
| `webhook.events_path`        | Die Ereignisse in einer Anfrage                         | `$` (beide Zuordnungsarten)    |
| `webhook.type_path`          | Den Ereignistyp (erforderlich bei `jsonpath`)           | `$.status`                     |
| `webhook.recipient_path`     | Den Empfänger                                           | `$.recipient`, dann `$.email`  |
| `webhook.message_id_path`    | Die Nachrichten-ID des Anbieters                        | `$.message_id`                 |
| `webhook.reputecast_id_path` | Die zurückgegebene Nachrichten-ID von ReputeCast        | `$.reputecast_id`              |
| `webhook.code_path`          | Die SMTP-Antwort oder den eigenen Code des Anbieters    | `$.code`                       |
| `webhook.diagnostic_path`    | Den Diagnosetext                                        | `$.reason`                     |
| `webhook.time_path`          | Den Zeitpunkt des Ereignisses                           | `$.timestamp`                  |
| `webhook.url_path`           | Den Link eines Klicks                                   | `$.url`                        |
| `webhook.user_agent_path`    | Den User-Agent einer Öffnung oder eines Klicks          | `$.user_agent`                 |

Bei `jsonpath` werden nur die Pfade gelesen, die Sie setzen. Die eigene Zuordnung im Formular setzt <UiPath path="providers.adapters.pathEvents" />, <UiPath path="providers.adapters.pathType" />, <UiPath path="providers.adapters.pathRecipient" /> und <UiPath path="providers.adapters.pathMessageId" />.

`events_path` kann ein Ereignis, ein Array von Ereignissen oder mehrere davon auswählen; Arrays werden abgeflacht. Der Empfänger wird kleingeschrieben. Die zurückgegebene ReputeCast-ID muss eine Nachrichten-ID von ReputeCast sein (eine UUID), damit sie zugeordnet wird. Zeitangaben sind Unix-Sekunden oder -Millisekunden, RFC 3339 oder `YYYY-MM-DD hh:mm:ss`; ohne Zeitangabe gilt der Zeitpunkt, zu dem das Ereignis eingetroffen ist.

### Ereignistypen

Bei `status` wird der Typwert (unabhängig von Groß- und Kleinschreibung) einem [normalisierten Ereignis](/de/providers/events-and-sync/) zugeordnet:

| Wert des Anbieters                                                    | Ereignis                       |
| --------------------------------------------------------------------- | ------------------------------ |
| `delivered`, `delivery`                                               | `delivered`                    |
| `deferred`, `delayed`, `delivery_delayed`                             | `deferred`                     |
| `bounced`, `bounce`, `failed`                                         | nach seinem Code entschieden (siehe unten) |
| `hard_bounce`, `hard_bounced`, `hardbounce`, `permanent_failure`      | `hard_bounce`                  |
| `soft_bounce`, `soft_bounced`, `softbounce`, `temporary_failure`      | `soft_bounce`                  |
| `complained`, `complaint`, `spam`, `spam_report`, `spamreport`        | `complaint`                    |
| `rejected`, `dropped`, `blocked`                                      | `rejected`                     |
| `opened`, `open`                                                      | `open`                         |
| `clicked`, `click`                                                    | `click`                        |
| `unsubscribed`, `unsubscribe`                                         | `unsubscribe`                  |

Jeder andere Wert wird ignoriert. Bei `jsonpath` ordnet `webhook.types` die Typen des Anbieters (unabhängig von Groß- und Kleinschreibung) `delivered`, `deferred`, `hard_bounce`, `soft_bounce`, `bounce`, `complaint`, `rejected`, `open`, `click`, `unsubscribe` oder `ignore` zu. Ein Typ, den Sie nicht aufführen, fällt auf die Tabelle oben zurück und wird sonst ignoriert.

### Bounces

ReputeCast sperrt eine Adresse nur auf Basis von Belegen, denn [Hard Bounces](/de/reference/glossary/#hard-bounce) und Beschwerden kommen auf die gemeinsame [Sperrliste](/de/audience/suppressions/):

- Ein einfacher Bounce (`bounced` oder `bounce`) zählt als Hard Bounce, sofern sein Code nichts anderes sagt. Eine SMTP-Antwort entscheidet nach ihrer Klasse: 5xx ist ein Hard Bounce, 4xx ein Soft Bounce. Ein eigener Code des Anbieters (`invalid_recipient`, `mailbox_full`) zählt nur als Hard Bounce, wenn er ein unbekanntes Postfach oder eine unbekannte Domain nennt oder „hard“ oder „permanent“ enthält; jeder andere Code ergibt einen Soft Bounce. Ohne Code ist es ein Hard Bounce.
- Ein `hard_bounce` mit einer 4xx-SMTP-Antwort wird zum Soft Bounce.
- Ein Hard Bounce, den der Absender verursacht hat (als Blockierung wegen Spam, Reputation oder Richtlinien klassifiziert), wird unabhängig von seinem Code zum Soft Bounce.

Bounces, Zurückstellungen und Ablehnungen erhalten aus ihrem Code und ihrer Diagnose eine [Bounce-Klasse](/de/reference/glossary/#bounce-class).

## Vollständiges Beispiel

Dieses Manifest bildet einen fiktiven Anbieter ab, Example ESP. Es sendet eine Nachricht pro `POST`, liest die Nachrichten-ID aus der Antwort, prüft Zugangsdaten gegen einen Konto-Endpunkt, fragt beim Verbinden eines Anbieters nach einer Konto-ID und liest HMAC-signierte Webhooks mit einer eigenen Typzuordnung.

```json title="example-esp.manifest.json"
{
  "name": "Example ESP",
  "version": "1.0.0",
  "maintainer": "you@example.com",
  "kind": "http",
  "source_url": "https://github.com/you/example-esp-mapping",
  "terms": {
    "bulk": "allowed",
    "note": "Opted-in lists only.",
    "url": "https://example-esp.com/aup"
  },
  "pricing": "$0.80 per 1,000",
  "http": {
    "method": "POST",
    "url": "https://api.example-esp.com/v1/{{ settings.account }}/messages",
    "headers": {
      "Authorization": "Bearer {{ secrets.api_key }}"
    },
    "body": "{\"from\": \"{{ sender }}\", \"to\": [{\"email\": \"{{ recipient }}\", \"name\": \"{{ recipient_name }}\"}], \"reply_to\": {{ reply_to | default: sender_email }}, \"subject\": \"{{ subject }}\", \"html\": \"{{ html }}\", \"text\": \"{{ text }}\", \"headers\": {{ headers_json }}, \"metadata\": {\"reputecast_id\": \"{{ message_id }}\", \"stream\": \"{{ stream }}\"}, \"tracking\": {\"opens\": false, \"clicks\": false}}",
    "message_id_path": "$.data.id",
    "error_code_path": "$.error.code",
    "error_message_path": "$.error.message",
    "check": {
      "url": "https://api.example-esp.com/v1/{{ settings.account }}/me"
    },
    "fields": [
      {
        "key": "account",
        "label": "Account ID",
        "required": true,
        "help": "Example ESP › Settings › Account."
      }
    ],
    "webhook_mapping": "jsonpath",
    "webhook": {
      "auth": "hmac",
      "signature_header": "X-Example-Signature",
      "signature_prefix": "sha256=",
      "timestamp_header": "X-Example-Timestamp",
      "events_path": "$.events[*]",
      "type_path": "$.event",
      "recipient_path": "$.recipient",
      "message_id_path": "$.message_id",
      "reputecast_id_path": "$.metadata.reputecast_id",
      "code_path": "$.smtp.code",
      "diagnostic_path": "$.smtp.message",
      "time_path": "$.ts",
      "url_path": "$.link",
      "types": {
        "delivered": "delivered",
        "delayed": "deferred",
        "bounce_permanent": "hard_bounce",
        "bounce_temporary": "soft_bounce",
        "complaint": "complaint",
        "click": "click",
        "sent": "ignore"
      }
    }
  }
}
```

Für die Beispielnachricht wird der Body so gerendert:

```json title="Gerenderter Anfrage-Body"
{
  "from": "\"Acme Newsletter\" <news@news.acme.io>",
  "to": [{ "email": "linh@example.com", "name": "Linh Nguyen" }],
```

Example ESP signiert jeden Webhook mit `X-Example-Timestamp: <Unix seconds>` und `X-Example-Signature: sha256=<hex HMAC-SHA256 of "<timestamp>.<body>">`, mit dem Schlüssel, der als **Signaturschlüssel für Webhooks** der Verbindung eingegeben wurde. Diese Anfrage:

Das Ereignis `sent` wird ignoriert. Die ersten beiden Ereignisse werden ihren Nachrichten über die zurückgegebene ReputeCast-ID zugeordnet, die anderen über die Nachrichten-ID des Anbieters.

## Hinweise

- Der generische HTTP-Adapter sendet eine Nachricht pro Anfrage, richtet Domains über manuelle DNS-Einträge ein und setzt die [Sperrliste](/de/reference/glossary/#suppression-list) lokal durch („Nur lokal“); er hat keine Kontingent-Erkennung. Braucht ein Anbieter Batches, eine Domain-API, Sperrlisten-Synchronisierung oder mehrere Aufrufe pro Nachricht, schreiben Sie einen [Community-Adapter](/de/adapters/community/).
- Beim Speichern wird eine Zuordnung mit einem Problem abgelehnt und das betroffene Feld genannt (`body`, `url`, `webhook.type_path`…). Das Audit-Protokoll erfasst Methode, URL, Header-Namen, Webhook-Zuordnung und Authentifizierungsmodus, nie Header-Werte.
- Jeder installierte Adapter erscheint in <UiPath path="nav.providers > providers.overview.addProvider" /> in jedem Arbeitsbereich, mit seinen Bedingungen, Preisen und Verbindungsfeldern. Jeder Prozess liest die installierten Adapter alle 15 Sekunden neu ein.

<Aside type="danger">
  Header-Vorlagen enthalten oft Zugangsdaten. Lesen Sie sie aus `secrets.<key>` (beim Verbinden eines Anbieters eingegeben, versiegelt gespeichert), statt einen Schlüssel in die Zuordnung zu tippen, die jeder Instanz-Admin lesen kann.
</Aside>
