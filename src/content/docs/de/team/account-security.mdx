Richten Sie die Zwei-Faktor-Authentifizierung per Passkey oder Authenticator-App ein, bewahren Sie
Wiederherstellungscodes auf und verwalten Sie Passwort, Anmeldemethoden und Sitzungen unter
<UiPath path="shell.userMenuAccount" /> im Kontomenü. Die Regeln stammen aus der Authentifizierungsrichtlinie der
Instanz, die ein [Instanz-Admin](/de/self-hosting/instance-admin/) festlegt.

## Bevor Sie beginnen

- Alles auf dieser Seite betrifft Ihr eigenes Konto; Sie brauchen keine Berechtigung im Arbeitsbereich.
- Haben Sie eine [sensible Berechtigung](/de/reference/glossary/#sensitive-permission), ist die
  Zwei-Faktor-Authentifizierung standardmäßig nach einer Schonfrist von 7 Tagen erforderlich. Die Karte für die
  Authenticator-App zeigt, ob sie für Sie erforderlich ist.
- Passkeys setzen voraus, dass die öffentliche URL der Instanz einen Domainnamen verwendet, keine IP-Adresse.

<Steps>

1. **Ändern Sie Ihr Passwort.** Geben Sie unter <UiPath path="account.password" /> Ihr aktuelles Passwort und zweimal
   das neue ein und wählen Sie dann <UiPath path="account.changePassword" />. Das neue Passwort muss die Mindestlänge
   erfüllen, darf weder Ihr aktuelles noch eines Ihrer letzten Passwörter sein und wird mit bekannten Datenlecks
   abgeglichen, wenn die Instanz das aktiviert hat. Die Änderung meldet Ihre anderen Sitzungen ab. Melden Sie sich nur
   über Single Sign-on an, ist diese Karte ausgeblendet.

   Ein Konto, das noch kein Passwort hat, etwa eines, das sich mit Google oder einem Passkey anmeldet, legt sein erstes
   Passwort hier ohne aktuelles Passwort fest, aber nur innerhalb von 15 Minuten nach der Anmeldung. Seit Version 1.5.0
   kann ein Konto, dessen E-Mail-Domain ein SSO-Anbieter erzwingt, überhaupt kein Passwort hinzufügen, es sei denn, es
   gehört einem [Inhaber mit Notfallzugang](/de/self-hosting/sso/#sso-für-ihre-domains-erzwingen).

2. **Fügen Sie einen Passkey hinzu.** Wählen Sie unter <UiPath path="account.passkeys" /> die Option
   <UiPath path="account.addPasskey" /> und folgen Sie der Abfrage Ihres Browsers (Touch ID, Face ID, Windows Hello, ein
   Passwortmanager oder ein Sicherheitsschlüssel). Ein Passkey meldet Sie allein über
   <UiPath path="auth.signIn.passkeySignIn" /> an, und nach einem Passwort zählt er als Ihr zweiter Faktor. Benennen Sie
   ihn um, damit Sie ihn später wiedererkennen. Sie können beliebig viele hinzufügen.

3. **Richten Sie eine Authenticator-App ein.** Wählen Sie unter <UiPath path="account.authenticatorApp" /> die Option
   <UiPath path="account.setUp" />. Scannen Sie den QR-Code mit einer beliebigen TOTP-App (1Password, Google
   Authenticator, Authy) oder tippen Sie den Schlüssel ein, und geben Sie dann den 6-stelligen Code ein. Die Codes
   wechseln alle 30 Sekunden.

4. **Speichern Sie Ihre Wiederherstellungscodes.** Nachdem der Code bestätigt ist, zeigt ReputeCast einmalig 10
   [Wiederherstellungscodes](/de/reference/glossary/#recovery-code). Laden Sie sie herunter, drucken oder kopieren Sie
   sie, bestätigen Sie per Häkchen, dass Sie sie gespeichert haben, und schließen Sie ab. Jeder Code funktioniert einmal
   bei der Anmeldung über <UiPath path="auth.signIn.useRecovery" />. <UiPath path="account.regenerateCodes" /> ersetzt
   alle alten Codes durch 10 neue.

5. **Verknüpfen Sie weitere Anmeldungen.** Wählen Sie unter <UiPath path="account.connectedSignIns" /> die Option
   <UiPath path="account.link" /> neben Google, Microsoft oder GitHub, wenn die Instanz sie anbietet.
   <UiPath path="account.unlink" /> ist für Ihre letzte verbleibende Anmeldemethode deaktiviert.

6. **Prüfen Sie Ihre Sitzungen.** <UiPath path="account.activeSessions" /> listet jedes angemeldete Gerät und jeden
   Browser mit IP-Adresse und letzter Aktivität. Nutzen Sie <UiPath path="account.signOut" /> in einer Zeile oder
   <UiPath path="account.signOutAllOthers" />. Um die Sitzung zu beenden, die Sie gerade nutzen, wählen Sie
   <UiPath path="shell.userMenuSignOut" /> im Kontomenü.

7. **Ändern Sie Ihre E-Mail-Adresse.** Wählen Sie unter <UiPath path="account.profile" /> die Option
   <UiPath path="account.changeEmail" />, geben Sie die neue Adresse und Ihr aktuelles Passwort ein und wählen Sie
   <UiPath path="account.sendLink" />. Öffnen Sie den Link aus dem neuen Postfach innerhalb von 24 Stunden, während Sie
   im selben Konto angemeldet sind. Ihre alte Adresse erhält nach der Änderung einen Hinweis. Ein Konto ohne Passwort
   bestätigt die Änderung stattdessen dadurch, dass es sich in den letzten 15 Minuten angemeldet hat. Verwaltet ein
   SSO-Anbieter Ihr Konto, muss die neue Adresse eine sein, die dieser Anbieter ebenfalls verwaltet; das wird beim
   Öffnen des Links erneut geprüft.

</Steps>

<Aside type="danger">
  Eine Authenticator-App können Sie nicht selbst abschalten, nur <UiPath path="account.replaceApp" />; dabei werden auch
  Ihre Wiederherstellungscodes ersetzt. Verlieren Sie Ihr Telefon und Ihre Codes, kann ein Instanz-Admin die
  Zwei-Faktor-Authentifizierung für Sie unter <UiPath path="shell.userMenuInstanceAdmin > admin.users" /> zurücksetzen
  oder über die CLI, wie unter [Zugriff über die Befehlszeile wiederherstellen](/de/self-hosting/account-recovery/)
  beschrieben.
</Aside>

## Sitzungen, Zeitlimits und Anmeldesperre

- Eine Sitzung endet nach ihrer maximalen Dauer oder nach dem Inaktivitäts-Timeout ohne Aktivität. Zwei Minuten vor dem
  Ende können Sie die Inaktivitätszeit über ein Banner verlängern; die maximale Dauer verschiebt sich nie.
- Verkürzt ein Instanz-Admin das Inaktivitäts-Timeout, folgen bestehende Sitzungen innerhalb von etwa 30 Sekunden. Eine
  neue maximale Dauer gilt für Sitzungen, die nach der Änderung beginnen.
- Zu viele fehlgeschlagene Versuche für eine E-Mail-Adresse sperren die Anmeldung für diese Adresse. Falsche
  Passwörter zählen und, seit Version 1.5.0, auch falsche Codes aus der Authenticator-App und Wiederherstellungscodes,
  die nach einem richtigen Passwort eingegeben werden: Der Zähler wird erst zurückgesetzt, wenn eine ganze Anmeldung
  gelingt. Fünf falsche Codes beenden außerdem diesen Anmeldeversuch, sodass Sie wieder mit Ihrer E-Mail-Adresse
  beginnen. Die Anmeldung per Passkey funktioniert weiterhin, solange die Sperre dauert, und
  <UiPath path="auth.forgotPassword" /> sendet einen Link zum Zurücksetzen, der einmal und 15 Minuten lang funktioniert
  und die Sperre aufhebt. Wenn Sie ihn verwenden, werden alle Ihre Sitzungen abgemeldet.
- Jeder Code aus der Authenticator-App funktioniert einmal. Ein bereits verwendeter Code wird abgelehnt, auch innerhalb
  seiner 30 Sekunden; warten Sie auf den nächsten.

## Prüfen, ob es funktioniert hat

- Die Karte für die Authenticator-App zeigt **An** mit dem Einrichtungsdatum, und die Zeile der Wiederherstellungscodes
  zeigt 10 verbleibende.
- Ihr Passkey steht nach der Anmeldung damit mit „jetzt verwendet“ in der Liste.
- Auf der [Teamseite](/de/team/members/) zeigt Ihre 2FA-Spalte „An · TOTP“ oder „An · Passkey“.

## Fehlerbehebung

- **Der 6-stellige Code wird abgelehnt.** Stellen Sie die Uhr Ihres Telefons auf automatische Aktualisierung und
  versuchen Sie den nächsten Code.
- **„Dieser Code wurde bereits verwendet.“** Jeder Code aus der Authenticator-App meldet einmal an. Warten Sie auf den
  nächsten in Ihrer Authenticator-App.
- **„Zu Ihrer Sicherheit ist dafür eine aktuelle Anmeldung nötig.“** Ein erstes Passwort hinzuzufügen oder die
  E-Mail-Adresse eines Kontos ohne Passwort zu ändern, braucht eine Sitzung, die sich in den letzten 15 Minuten
  angemeldet hat. Melden Sie sich ab, wieder an und versuchen Sie es dann erneut.
- **„Dieser Passkey ist Ihre einzige Anmeldemethode.“** Fügen Sie einen weiteren Passkey oder ein Passwort hinzu, bevor
  Sie ihn entfernen.
- **„Für Ihr Konto ist die Zwei-Faktor-Authentifizierung erforderlich“ beim Entfernen eines Passkeys.** Richten Sie
  zuerst eine Authenticator-App ein oder fügen Sie einen weiteren Passkey hinzu.
- **Jede Seite leitet Sie zur Einrichtung.** Ihre Schonfrist ist abgelaufen: Fügen Sie einen Passkey oder eine
  Authenticator-App hinzu, um fortzufahren.
- **„Anmeldung gesperrt“.** Warten Sie, bis die Sperre endet, setzen Sie Ihr Passwort zurück oder melden Sie sich mit
  einem Passkey an. Die fehlgeschlagenen Versuche stehen mit ihren IP-Adressen im
  [Audit-Protokoll](/de/team/audit-log/).
- **„API-Ratenlimit erreicht“.** Ihre Browsersitzung hat in einer Minute mehr Anfragen gesendet, als die Instanz
  erlaubt. Jede angemeldete Sitzung hat ihr eigenes Limit (siehe [Ratenlimits](/de/developers/api-rate-limits/)).
  Warten Sie, bis das Banner meldet, dass Anfragen wieder möglich sind, und wiederholen Sie dann, was nicht
  durchgegangen ist.
