Mit `n8n-nodes-reputecast`, dem n8n-Node-Paket für ReputeCast, können Sie Ihren Newsletter mit n8n automatisieren: Der
Node **ReputeCast Trigger** startet Workflows bei Ereignissen in ReputeCast, und der Node **ReputeCast** fügt Kontakte
hinzu, vergibt Tags, erfasst Ereignisse und sendet Transaktions-E-Mails. Die Nodes sind kostenlos, funktionieren mit
selbst gehostetem n8n (und mit n8n Cloud, sobald n8n sie verifiziert hat) und nutzen nur die öffentliche API von
ReputeCast.

## Bevor Sie beginnen

- Sie brauchen `integrations:manage` (Inhaber oder Admin). Wie Schlüssel, Status und das Aufrufprotokoll funktionieren,
  lesen Sie unter [Andere Tools verbinden](/de/integrations/overview/).
- n8n muss Ihre Instanz nur für Aktionen erreichen, daher können n8n und ReputeCast ein privates Netzwerk teilen.
  Trigger laufen in die andere Richtung (ReputeCast sendet Ereignisse an n8n): siehe
  [n8n in einem privaten Netzwerk](#n8n-in-einem-privaten-netzwerk).

## Was die Nodes können

**ReputeCast Trigger** startet einen Workflow bei:

| Ereignis | ReputeCast-Ereignis | Benötigt |
|---|---|---|
| Contact Subscribed | `contact.subscribed` | `subscribers:view` |
| Contact Unsubscribed | `contact.unsubscribed` | `subscribers:view` |
| Contact Updated | `contact.updated` | `subscribers:view` |
| Form Submitted (jedes Formular oder ein bestimmtes) | `form.submitted` | `subscribers:view` |
| Campaign Sent | `campaign.completed` | `campaigns:view` |
| Transactional Message Bounced | `message.bounced` | `transactional:view` |

Wenn Sie den Workflow aktivieren, entsteht in ReputeCast ein Webhook, der schreibgeschützt als „Verwaltet von n8n“
unter <UiPath path="nav.settings > settings.webhooks" /> steht; wenn Sie ihn deaktivieren, wird der Webhook entfernt.
Jede Zustellung wird gegen den Signaturschlüssel des Webhooks geprüft: Eine Zustellung, die nicht passt oder älter als
5 Minuten ist, wird abgelehnt und startet nichts.

**ReputeCast** kann:

| Resource › Operation | Was sie tut | Benötigt |
|---|---|---|
| Contact › Create or Update | Abgleich über die E-Mail-Adresse; setzt Namen, eigene Felder, Sprache und Tags; fügt mit Single- oder Double-Opt-in zu Listen hinzu | `subscribers:create`, `subscribers:edit` |
| Contact › Add to List | Single- oder Double-Opt-in | `subscribers:edit` |
| Contact › Add Tag | Ein oder mehrere Tags | `subscribers:edit` |
| Event › Record | Ein API-Ereignis mit Eigenschaften; startet die Automationen, die darauf warten | `subscribers:edit` |
| Transactional Email › Send | Eine veröffentlichte Vorlage, ein Empfänger, die zugehörigen Variablen (Feld für Feld zugeordnet) und optional eine Sprache | `transactional:send` (sensibel) |

Der AI Agent von n8n kann den ReputeCast-Node als Tool nutzen. Er kann nur, was der Schlüssel darf, und das Senden von
Transaktions-E-Mails ist beim Verbinden von n8n anfangs aus.

## Nodes installieren

Öffnen Sie in n8n **Settings › Community nodes › Install**, geben Sie `n8n-nodes-reputecast` ein und bestätigen Sie.
Selbst gehostetes n8n kann die Nodes auch mit `npm install n8n-nodes-reputecast` in `~/.n8n/nodes` installieren. Bei
n8n Cloud erscheinen die Nodes im Nodes-Panel, sobald n8n sie verifiziert hat.

## n8n verbinden

<Steps>

1. Öffnen Sie in ReputeCast <UiPath path="nav.settings > settings.integrations" />, suchen Sie n8n unter
   <UiPath path="integrations.groupAutomation" /> und wählen Sie <UiPath path="integrations.connect" />.

2. Legen Sie fest, was n8n darf. „Transaktions-E-Mail senden“ ist anfangs aus, weil es die sensible Berechtigung
   `transactional:send` braucht. Wählen Sie <UiPath path="integrations.createKey" /> und kopieren Sie den Schlüssel
   (`rc_live_…`); er wird einmalig angezeigt.

3. Fügen Sie in n8n eine Credential **ReputeCast API** hinzu mit:

   - **Instance URL**: Ihre ReputeCast-Adresse, zum Beispiel `https://reputecast.acme.io`.
   - **Key**: der Schlüssel aus Schritt 2.

4. Speichern Sie. n8n testet die Verbindung (`GET /api/v1/integration`), und der Dialog zum Verbinden in ReputeCast
   zeigt, wie der Aufruf eintrifft. Die Credential erfährt, zu welchem Arbeitsbereich der Schlüssel gehört, und merkt
   ihn sich.

</Steps>

### n8n in einem privaten Netzwerk

Läuft n8n unter einer privaten Adresse (zum Beispiel `n8n.acme.internal`), sendet ReputeCast keine Trigger-Ereignisse
dorthin, bis ein Serverbetreiber Webhooks an private Adressen mit
[`webhooks.allow_private_networks`](/de/reference/configuration/) (`REPUTECAST_WEBHOOKS__ALLOW_PRIVATE_NETWORKS=true`)
erlaubt. Aktionen funktionieren in beiden Fällen. Lesen Sie [Sicherheit und Härtung](/de/self-hosting/security/),
bevor Sie die Einstellung einschalten.

## Gut zu wissen

- **Namen der Workflows.** Jeder Aufruf trägt `X-ReputeCast-Workflow: <workflow name>; id=<workflow ID>`, damit
  ReputeCast auf seiner n8n-Seite die Workflows auflisten kann, die es nutzen, mit ihren Aufrufen und Fehlern.
- **Die Einwilligung bleibt gewahrt.** ReputeCast fügt niemanden einer Liste wieder hinzu, die die Person verlassen hat,
  fügt keine gesperrte Adresse hinzu und sendet keine Transaktions-E-Mail an eine gesperrte Adresse. Ein solcher
  Eintrag kommt als
  `{ "skipped": true, "code": "unsubscribed", "reason": "rob@example.net left Beta Program on 2 Oct…" }` zurück, und
  der Workflow macht mit den übrigen Einträgen weiter.
- **Fehler in den Worten von ReputeCast.** Andere Ablehnungen lassen den Node mit dem Satz von ReputeCast fehlschlagen:
  eine fehlende Vorlagenvariable, eine ausgeschaltete Aktion („Ändern Sie die Rechte von n8n unter Einstellungen ›
  Integrationen“), ein widerrufener Schlüssel („Verbinden Sie n8n … erneut …“) oder ein Schlüssel, dessen Besitzer
  gegangen ist („… übernehmen …“). Schalten Sie **Continue On Fail** ein, damit es stattdessen weitergeht.
- **Idempotenz.** Transactional Email › Send nimmt einen optionalen **Idempotency Key** an, etwa die ID des auslösenden
  Ereignisses. ReputeCast sendet nichts Neues, wenn derselbe Wert innerhalb von 24 Stunden erneut kommt.
- **Wenn Sie den Schlüssel** in ReputeCast **rotieren**, funktioniert der alte noch 24 Stunden: Fügen Sie den neuen in
  der Zwischenzeit in die Credential ein.
- **Schlüssel, die auf eine Liste beschränkt sind,** können die Trigger für Kontakte und Formulare nicht einschalten:
  Deren Ereignisse enthalten Kontakte aus jeder Liste. Ein Trigger braucht außerdem die Ansichtsberechtigung für das,
  was sein Ereignis enthält, wie jeder Webhook.

## Fehlerbehebung

- **Ein Trigger löst nie aus**: Prüfen Sie, ob der Workflow aktiv ist und der Webhook unter
  <UiPath path="nav.settings > settings.webhooks" /> steht. Für n8n unter einer privaten Adresse siehe
  [n8n in einem privaten Netzwerk](#n8n-in-einem-privaten-netzwerk).
- **„Verbinden Sie n8n … erneut …“**: Der Schlüssel wurde widerrufen oder ist abgelaufen. Wählen Sie in ReputeCast
  <UiPath path="integrations.reconnect" /> und fügen Sie den neuen Schlüssel in die Credential ein.
- **„… übernehmen …“**: Die Person, die n8n verbunden hat, ist gegangen. Wählen Sie
  <UiPath path="integrations.takeOver" />. Die Webhooks der Workflows, die ReputeCast pausiert hat, als diese Person
  gegangen ist, laufen wieder und senden, was gewartet hat.
