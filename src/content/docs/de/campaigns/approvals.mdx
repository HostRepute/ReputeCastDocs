Ein Freigabeprozess für E-Mails in ReputeCast lässt eine zweite Person einen Versand prüfen, bevor er hinausgeht, aber nur, wenn er riskant ist: eine große Zielgruppe, ein neuer Versandanbieter oder einer im Warm-up, ein Autor ohne Sendeberechtigung. Jeder Arbeitsbereich hat eine Richtlinie für [Freigaben](/de/reference/glossary/#approval). Trifft eine ihrer Regeln zu, fragt der Autor eine Freigabe an, statt zu senden, und eine freigebende Person gibt genau das frei, was gesendet wird.

## Bevor Sie beginnen

- Um die Richtlinie zu ändern, brauchen Sie `workspace:manage`. Alle anderen sehen sie schreibgeschützt.
- Freigebende Personen sind alle, deren Rolle Kampagnen freigeben darf (`campaigns:approve`): Die Rollen Inhaber und Admin dürfen das, Bearbeiter und Betrachter nicht. Im Kunden-Arbeitsbereich einer Agentur darf es auch die Rolle Freigeber (Kunde). Die Richtlinienseite nennt die derzeitigen freigebenden Personen mit Namen.
- Um eine Freigabe anzufragen, brauchen Sie `campaigns:edit`. Ein Autor gibt nie seine eigene Kampagne frei.
- Eine Freigabe sendet selbst nichts: Wer die freigegebene Kampagne plant oder sie ohne Freigabe sendet, sendet sie. Seit Version 1.5.0 sendet ein Mitglied, das auf bestimmte Listen beschränkt ist, nur an diese Listen, und eines, das auf bestimmte Absenderdomains beschränkt ist, nur von diesen, gleich wer die Zielgruppe oder die Absenderadresse gewählt hat.
- Wird eine Aktion verweigert, nennt ReputeCast die Personen, die sie ausführen dürfen, oder was ihrer Rolle fehlt, nicht einen Berechtigungsschlüssel.

## Festlegen, wann eine Freigabe nötig ist

<Steps>

1. Öffnen Sie <UiPath path="nav.settings > settings.approvals" />. Eine Freigabe ist erforderlich, wenn eine aktive Regel zutrifft.

2. Aktivieren Sie die gewünschten Regeln:

   | Regel                                                                                                  | In einem neuen Arbeitsbereich |
   | ------------------------------------------------------------------------------------------------------ | ----------------------------- |
   | Eine Zielgruppe im Massenversand von mindestens N Empfängern, gezählt nach Ausschlüssen                | An, 10.000                    |
   | Die Route enthält einen Anbieter im Warm-up oder einen, der in den letzten 14 Tagen verbunden wurde    | An                            |
   | Die Versandbereitschaft ist „Bereit mit Warnungen“ (blockierte Versände starten ohnehin nie)          | Aus                           |
   | Dem Autor fehlt die Sendeberechtigung (`campaigns:send` oder `sms:send` für SMS)                       | An                            |
   | Die Zielgruppe enthält eine als „Erfordert Freigabe“ markierte Liste                                   | Aus                           |
   | Die geschätzten Kosten einer SMS- oder WhatsApp-Kampagne betragen mindestens N $                       | Aus (50 $, wenn aktiv)        |
   | Auch das Veröffentlichen einer Automation erfordert eine Freigabe                                      | Aus                           |
   | Auch das Veröffentlichen einer Transaktionsvorlage erfordert eine Freigabe                             | Aus                           |
   | Das Veröffentlichen eines Beitrags oder einer Seite erfordert eine Freigabe                            | Aus                           |

   Die Regeln gelten auch für jede Ausgabe eines [wiederkehrenden Newsletters](/de/campaigns/recurring-digests/). Im Kunden-Arbeitsbereich einer Agentur gibt es eine weitere Regel: Jeder Versand braucht eine Freigabe durch einen Freigeber (Kunde).

3. Wählen Sie unter <UiPath path="approvals.policy.requiredLegend" /> entweder <UiPath path="approvals.policy.oneApproval" /> oder <UiPath path="approvals.policy.twoApprovals" />. Zwei Freigaben kommen von zwei verschiedenen freigebenden Personen, von denen keine der Autor ist; die Option steht zur Verfügung, sobald zwei Mitglieder Kampagnen freigeben dürfen.

4. Legen Sie unter <UiPath path="approvals.policy.bypassTitle" /> fest, ob Inhaber mit Angabe eines Grundes ohne Freigabe senden dürfen (siehe [Notfall-Umgehung](#notfall-umgehung)).

5. Wählen Sie <UiPath path="approvals.policy.savePolicy" />. Die Änderung wird im Audit-Protokoll festgehalten.

</Steps>

## Freigabe anfragen

<Steps>

1. Auf der Seite <UiPath path="composer.reviewSend" /> der Kampagne zeigt die Freigabekarte <UiPath path="review.requiredTitle" />, das Ergebnis der Versandbereitschaft und die zutreffenden Regeln, verständlich formuliert: „Ihre Rolle (Content Writer) braucht zum Senden eine Freigabe: Marcus Chen oder Linh Nguyen kann freigeben“. Hat jemand entschieden, ohne Prüfungen zu senden, die nicht laufen konnten, nennt das Ergebnis, welche übersprungen wurden, zum Beispiel „Bereit mit Warnungen · 1 Prüfung übersprungen“.

2. Beheben Sie zuerst jede Blockade: Eine blockierte Kampagne kann nicht zur Freigabe gesendet werden. Wählen Sie, wann sie hinausgehen soll. Sind die Prüfungen veraltet, laufen sie zuerst erneut: Fragen Sie die Freigabe noch einmal an, wenn sie fertig sind.

3. Fügen Sie bei Bedarf eine Notiz für die freigebenden Personen hinzu und wählen Sie dann <UiPath path="review.requestApproval" />. ReputeCast lehnt die Anfrage ab, wenn es außer Ihnen nicht genug freigebende Personen gibt.

4. Die Karte wechselt zu <UiPath path="review.waitingTitle" />. Die freigebenden Personen erhalten eine Benachrichtigung in der App und per E-Mail.

5. Hat niemand geantwortet, wählen Sie <UiPath path="review.remind" />. Erinnerungen werden nie automatisch gesendet, und Sie können höchstens einmal pro Stunde erinnern. Um die Anfrage zurückzuziehen, wählen Sie <UiPath path="review.cancelRequest" />.

</Steps>

## Anfrage prüfen

<Steps>

1. Öffnen Sie die Anfrage über die Benachrichtigung, über <UiPath path="review.reviewRequest" /> auf der Seite Prüfen & senden der Kampagne oder im Freigabe-Eingang unter `/w/<workspace>/approvals` (er befindet sich unter <UiPath path="nav.campaigns" />). Freigebende Personen sehen jede Anfrage, alle anderen ihre eigenen. Im Eingang findet <UiPath path="approvals.searchByName" /> eine Anfrage anhand dessen, worum es geht, und die Tabs zählen innerhalb von Suche und Filtern; Anfragen werden seitenweise geladen, und <UiPath path="approvals.showOlder" /> lädt weitere. Auf einem Smartphone bietet die Schnellprüfung im Editor außerdem <UiPath path="composer.chrome.approve" /> an, wenn eine Anfrage auf Ihre Entscheidung wartet (siehe [auf dem Smartphone freigeben](#auf-dem-smartphone-freigeben)).

2. Lesen Sie, was Sie freigeben: die E-Mail, den Betreff, den Absender, die Links, die Zielgruppe und ihre Anzahl, die Route, den Zeitplan, die Schwellenwerte und das Ergebnis der Versandbereitschaft zum Zeitpunkt der Anfrage, einschließlich aller Prüfungen, die der Autor übersprungen hat.

3. Entscheiden Sie unter „Ihre Entscheidung“:
   - Wählen Sie <UiPath path="approvals.review.approve" /> (ein Kommentar ist optional).
   - Wählen Sie <UiPath path="approvals.review.requestChanges" /> und sagen Sie, was sich ändern soll.
   - Wählen Sie <UiPath path="approvals.review.reject" /> und sagen Sie, warum.

4. Nach einer Freigabe plant der Autor oder ein Mitglied, das Kampagnen senden darf, die Kampagne mit <UiPath path="review.actionApproved" />, innerhalb der eigenen Listen und Absenderdomains. Bei angeforderten Änderungen oder einer Ablehnung wird die Kampagne wieder zum Entwurf, und der Autor wird benachrichtigt.

</Steps>

Die Status einer Anfrage sind <UiPath path="approvals.statusPending" />, <UiPath path="approvals.statusApproved" />, <UiPath path="approvals.statusChangesRequested" />, <UiPath path="approvals.statusRejected" /> und <UiPath path="approvals.statusInvalidated" />.

Beim Öffnen des Eingangs werden nur die offenen Anfragen erneut geprüft, die veraltet sein könnten, damit er auch bei vielen Anfragen schnell bleibt; ein Hintergrundjob hält die übrigen aktuell. Welche das sind, steht in der Tabelle unter [Standardwerte und Grenzen](#standardwerte-und-grenzen).

## Auf dem Smartphone freigeben

Auf einem Smartphone öffnet der [Editor](/de/campaigns/composer/) eine Schnellprüfung der Kampagne. Wartet eine Anfrage auf Ihre Entscheidung, nennt sie <UiPath path="composer.chrome.approve" />: Das Blatt sagt, wer für welche Version gefragt hat und wie viele Freigaben noch nötig sind. Wählen Sie <UiPath path="composer.chrome.approve" />, um freizugeben, oder <UiPath path="composer.chrome.reviewRequest" />, um die Anfrage zu öffnen, wo Sie Änderungen anfordern oder ablehnen können.

## Was eine Freigabe umfasst

Eine Freigabe umfasst eine Momentaufnahme des Versands, nicht die Kampagne allgemein. Sie wird ungültig, mit genauer Anzeige des Unterschieds, wenn sich nach der Anfrage eines davon ändert: Betreff, Vorschautext, Links, Inhalt, Absender, Definition der Zielgruppe, Route, Zeitplan oder Sprachversionen. Sie wird außerdem ungültig, wenn die Größe der Zielgruppe um mehr als 10 % von der Anzahl zum Zeitpunkt der Anfrage abweicht.

Das Bearbeiten einer freigegebenen Kampagne fragt zuerst nach. Der Editor zeigt, wer welche Version freigegeben hat und dass das Bearbeiten die Freigabe aufhebt; die erste Bearbeitung öffnet einen Dialog, und <UiPath path="composer.banners.editAnyway" /> hebt die Freigabe auf, danach zeigt die Kopfzeile nicht mehr <UiPath path="approvals.statusApproved" />. Das Bearbeiten einer Kampagne, die auf eine Freigabe wartet, zieht die Anfrage auf dieselbe Weise zurück. Der Entwurf eines Agenten hebt nie die Freigabe einer Person auf: Sein Speichern wird stattdessen abgelehnt.

Wird eine Freigabe ungültig, wird die Kampagne wieder zum Entwurf, und Autor und freigebende Personen werden benachrichtigt. Eine geplante Kampagne behält ihren Termin, startet aber nicht ohne neue Freigabe. Wird die freigegebene Version von Inhalt, Zielgruppe oder Zeitplan wiederhergestellt, bleibt die Freigabe bestehen.

Da der Zeitpunkt Teil der Freigabe ist, lässt sich eine freigegebene Kampagne im [Kampagnenkalender](/de/campaigns/calendar/#wenn-eine-freigabe-den-zeitpunkt-umfasst) nicht verschieben: Heben Sie die Planung auf und fragen Sie für den neuen Zeitpunkt eine Freigabe an. Wird eine Kampagne gelöscht, wird ihre offene Anfrage geschlossen.

Zum Versandzeitpunkt prüft ReputeCast erneut: Die Versandbereitschaft läuft 15 Minuten vor dem Versand und bei seinem Start, und eine fehlende, abgelehnte oder ungültige Freigabe hält den Versand genauso zurück wie eine Blockade. Siehe [wann die Prüfungen laufen](/de/campaigns/send-readiness/#wann-die-prüfungen-laufen).

### Die Kontrollgruppe

Ob der Versand die [Kontrollgruppe](/de/reference/glossary/#holdout-group) einbezieht, gehört zur Definition seiner Zielgruppe. Wer <UiPath path="review.includeHoldout" /> auf Prüfen & senden nach der Anfrage ankreuzt oder abwählt, macht die Freigabe ungültig, mit angezeigter Änderung, wie bei jeder anderen Änderung der Zielgruppe. Verfügbar ab der nächsten Version nach 1.6.0.

## Notfall-Umgehung

Wenn die Richtlinie es erlaubt, kann ein Inhaber auf Prüfen & senden bei einem Versand, auf den eine Regel zutrifft, <UiPath path="review.moreActions" /> › <UiPath path="review.sendWithoutApproval" /> nutzen; für alle anderen nennt der Menüeintrag, wer es darf. Er schreibt einen Grund (mindestens 10 Zeichen) und bestätigt, falls sein Konto ein Passwort hat, dieses. Die Umgehung wird als `campaign.approval_bypassed` mit Grund, IP-Adresse und der Momentaufnahme der Kampagne festgehalten, und jede freigebende Person wird benachrichtigt. Warnungen müssen trotzdem bestätigt werden, und ein Ergebnis Blockiert der Versandbereitschaft stoppt den Versand weiterhin. Die Richtlinienseite zeigt, wie oft die Umgehung in den letzten 90 Tagen genutzt wurde.

## Prüfen, ob es funktioniert hat

- Eine Kampagne, auf die eine Regel zutrifft, zeigt auf Prüfen & senden „Freigabe erforderlich“ mit den zutreffenden Regeln.
- Die Anfrage erscheint im Eingang unter Ausstehend, und die freigebenden Personen haben eine Benachrichtigung.
- Integrationen können mit den [Webhook-Ereignissen](/de/reference/webhook-events/) `approval.requested` und `approval.decided` mitverfolgen.

## Fehlerbehebung

- **„Niemand sonst kann Kampagnen freigeben. Ein Inhaber kann einer weiteren Rolle die Freigabe erlauben.“** Sie brauchen außer dem Autor mindestens ein Mitglied, dessen Rolle Kampagnen freigeben darf (`campaigns:approve`; zwei bei 2 Freigaben). Bitten Sie einen Inhaber, unter <UiPath path="nav.settings > settings.roles" /> eine Rolle zu ändern.
- **„Die freigebenden Personen wurden vor weniger als einer Stunde erinnert.“** Erinnerungen sind auf eine pro Stunde begrenzt; die Meldung nennt, wann Sie erneut erinnern können.
- **Die Freigabe wurde ungültig, obwohl niemand die E-Mail angefasst hat.** Die Größe der Zielgruppe hat sich um mehr als 10 % verändert, etwa nach einem großen Import. Der Eingang zeigt „Zielgruppe um … verändert“ mit dem Unterschied; fragen Sie die Freigabe erneut an.
- **Die Option 2 Freigaben ist ausgegraut.** Weniger als zwei Mitglieder dürfen Kampagnen freigeben.
- **Die Richtlinienseite ist schreibgeschützt und zeigt „Ihre Rolle kann sie nicht ändern.“** Zum Ändern brauchen Sie `workspace:manage`.
- **Die Freigabe ist nach einer Bearbeitung verschwunden.** Das Bearbeiten des Inhalts einer freigegebenen Kampagne hebt die Freigabe auf; stellen Sie die freigegebene Version über Prüfen & senden wieder her oder fragen Sie die Freigabe erneut an.
